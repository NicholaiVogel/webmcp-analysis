Users have to search through pages, apply filters, compare products, check availability, and manually manage their carts. \n\n We wanted to explore a different model: \n\n What if an AI agent could interact with an e-commerce website through structured, browser-native tools instead of relying on brittle UI automation? \n\n That question led us to build ShopMate , an agent-native shopping experience powered by WebMCP. \n\n What we built \n\n ShopMate exposes the core capabilities of an e-commerce application as WebMCP tools through document.modelContext . \n\n The application currently exposes 10 tools : \n\n \n search_products \n filter_products \n get_product_details \n compare_products \n check_stock \n calculate_cart_total \n add_to_cart \n remove_from_cart \n update_cart \n build_bundle \n \n\n Read-only operations can be performed autonomously, while state-changing operations require human approval. \n\n This creates a human-in-the-loop shopping experience where an agent can perform useful work while the user remains in control of consequential actions. \n\n For example, an agent can: \n\n \n Search for laptops. \n Filter them by price, brand, category, or stock. \n Retrieve detailed specifications. \n Compare multiple products. \n Check inventory. \n Ask the user for approval. \n Add the selected product to the cart. \n Calculate the resulting cart total. \n \n\n How we built it \n\n ShopMate was built with: \n\n \n Next.js 16 \n React 19 \n TypeScript \n Tailwind CSS \n React Context for application state \n Browser-native WebMCP APIs through document.modelContext \n \n\n A major part of the implementation was making WebMCP registration reliable inside React's rendering lifecycle. \n\n We designed the registration system to be idempotent so that React re-renders and Strict Mode do not create duplicate tool registrations. \n\n We also added a diagnostics and activity system so that WebMCP availability, registered tools, tool changes, and agent activity can be observed directly inside the application. \n\n Challenges \n\n One of our biggest challenges was that WebMCP registration interacts with the React lifecycle in ways that are easy to get wrong. \n\n Our initial browser implementation encountered a Maximum update depth exceeded error. The underlying problem was not duplicate WebMCP registration itself, but the interaction between registration, diagnostics state updates, effects, and event listeners. \n\n We investigated the lifecycle, added dedicated React lifecycle tests, and fixed the ownership of the WebMCP toolchange listener. We also eliminated a race involving the approval state reference. \n\n Another interesting issue was the browser-generated toolchange event during initial registration. Since the browser emits a tool-change event for each registered tool, registering 10 tools produced unnecessary activity-panel noise. We kept the listener but suppressed those expected initialization events and retained logging for genuine post-registration tool changes. \n\n What we learned \n\n This project taught us that making an application "agent-compatible" is more than exposing a list of functions. \n\n The tools need: \n\n \n Clear schemas and descriptions. \n Predictable inputs and outputs. \n Safe boundaries around state-changing actions. \n Idempotent registration. \n Correct lifecycle management. \n Human approval for consequential actions. \n Observability so developers can understand what the agent is doing. \n \n\n We also learned how important it is to test both the tool layer and the actual React/browser lifecycle. Our standalone WebMCP tests passed while the real browser initially exposed a lifecycle issue, which led us to add dedicated React and Strict Mode tests. \n\n Final result \n\n ShopMate now exposes all 10 intended WebMCP tools, supports human approval for cart mutations, and has automated tests covering registration, discovery, execution, approval, diagnostics, Strict Mode behavior, and listener lifecycle. \n\n The project demonstrates how existing web applications can evolve from interfaces that humans click into interfaces that AI agents can understand and operate through structured browser-native capabilities . \n\n What it does \n\n How we built it \n\n Challenges we ran into \n\n Accomplishments that we're proud of \n\n What we learned \n\n What's next for ShopMate — Agent-Native Shopping with WebMCP \n\n \n\n \n Built With \n\n html javascript next.js react tailwind-css typescript webmcp \n \n\n \n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Abdullah Usman \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Abdullah Usman \n started this project\n \n —\n \n a day ago \n \n \n\n
