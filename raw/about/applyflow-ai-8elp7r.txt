Finding a relevant position is only the first step — candidates still have to open different job portals, fill out the same information repeatedly, answer application questions, and deal with different workflows. \n\n We wanted to build an AI agent that could help with this process while keeping the candidate in control of the final decision. \n\n That led us to ApplyFlow AI — a job application agent designed around WebMCP. \n\n What It Does \n\n ApplyFlow AI helps users go from job discovery to a prepared application: \n\n \n Find Jobs — discovers real job listings from sources such as RemoteOK and Arbeitnow. \n Smart Matching — compares jobs with the user's resume and preferences and explains why a job is a good match. \n Prepare Application — creates an application using the user's profile and resume information. \n WebMCP Automation — uses WebMCP tools to interact with supported application workflows in a real browser session. \n Human Review — stops before final submission so the user can review the completed application. \n Approve & Submit — the final submission requires an explicit human action. \n \n\n The key design principle is simple: \n\n \n The agent can prepare the application, but the human controls the final submission. \n \n\n How We Built It \n\n The application is built around an AI-agent workflow with WebMCP as the interface between the agent and browser-based tools. \n\n The system includes: \n\n \n Job discovery and normalization \n Resume/profile-based job matching \n Match explanations \n Application preparation \n WebMCP tool integration \n Browser-based form automation \n Application state and automation tracking \n Human approval before submission \n Safety handling for login, MFA, and CAPTCHA situations \n \n\n The Agent page provides a natural-language interface where users can give commands such as: \n\n \n "Find jobs matching my profile." \n \n\n or \n\n \n "Prepare an application for the best match." \n \n\n These requests are translated into authorized WebMCP tool calls such as get_top_matches and prepare_application . \n\n The same backend authorization and application state are used by both the normal user interface and the agent workflow. \n\n Human-in-the-Loop by Design \n\n We intentionally did not expose the final submission action as a WebMCP tool. \n\n The agent can discover a job, prepare the application, open the application page, and fill the form. \n\n But when the application is ready, the workflow stops and asks the user to review it. \n\n Only the user can click Approve & Submit . \n\n This creates a clear boundary between AI automation and an irreversible external action. \n\n Safety \n\n Real job portals can require authentication, MFA, or CAPTCHA challenges. \n\n ApplyFlow AI does not attempt to bypass these protections. \n\n When such a step is detected, the automation pauses and explains why it stopped. The user can then handle the step directly in the real browser session. \n\n This keeps the automation useful without attempting to circumvent website security controls. \n\n Challenges We Faced \n\n One of the biggest challenges was designing an agent that could interact with real application workflows without turning the system into an uncontrolled automation tool. \n\n We had to think carefully about: \n\n \n Tool authorization \n Application state \n Human approval boundaries \n Form validation \n Handling different application workflows \n Login and CAPTCHA interruptions \n Keeping the agent's actions observable \n \n\n Another challenge was making the agent's behavior understandable. Instead of hiding tool execution, we added a WebMCP Activity panel so users can see which tools are being called and what is happening during the workflow. \n\n What We Learned \n\n This project taught us that building an AI agent is not only about making the model capable of taking actions. \n\n The more important question is: \n\n Which actions should the agent be allowed to take? \n\n WebMCP provides a powerful way for agents to interact with web-based tools, but that power needs clear authorization boundaries. \n\n For ApplyFlow AI, we chose to automate the repetitive work while keeping the final consequential action under human control. \n\n What's Next \n\n Future versions could support more job sources, richer resume customization, better application-question handling, additional WebMCP-enabled sites, and stronger application tracking. \n\n Our goal is to make job applications dramatically less repetitive while keeping the candidate — not the agent — in control. \n\n \n\n \n Built With \n\n fastapi postgresql python react superbase vite webmcp \n \n\n \n Try it out \n\n \n \n \n apply-flow-ai-web.vercel.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Malesh Kumar Prajapati \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Malesh Kumar Prajapati \n started this project\n \n —\n \n 2 days ago \n \n \n\n
