Nothing changed, the agent knows why Inspiration We run QuePlan, a health-insurance comparator that has been live in Chile for ten years and later in Peru and Colombia. About 4.5 million people used it in the last twelve months, and more than 165,000 policies contracted through it are active today. For months we had been watching AI agents try to use our site. They do fine on a blog and badly on a comparator, because there is no price to read: every price depends on who is asking (age, sex, dependants, Fonasa or Isapre) and our engine calculates it per family. An agent scraping our HTML picks up the "from" price and confidently gives people the wrong number. So the question for the challenge was simple: what if the page told the agent what it can do, and did the work itself? What it does Our comparator now exposes 13 WebMCP tools. A person opens the page in ChatGPT's in-app browser (or Chrome with WebMCP on) and just talks: "I'm 34, two kids of 5 and 8, complementary or catastrophic plans under 120,000 pesos". The agent sets the profile and applies the filters, and the page moves exactly as if the person had clicked through the forms. From there it can ask for an explained top three (we return structured reasons and open the podium on screen), compare two plans head to head, open a detail sheet, page forward, and produce a link that restores the whole state so the family can look at it together later. One decision we made early: the agent never contracts anything. The last tool, preparar_solicitud , scrolls to the plan and highlights the Contratar button. That click, and everything after it, stays with the person. Health insurance is a consequential decision and we wanted the boundary to be visible in the UI, not buried in a disclaimer. There is also a small panel on the right that narrates every tool call in plain Spanish and lights up the part of the page that changed. It started as a debugging aid and became the thing testers liked most: you can see what the agent is doing to your screen. How we built it The production app is Angular. Registering tools was the easy part; getting them to run inside ChatGPT's browser was not. zone.js patches Promise and the native WebMCP API only accepts real ones, so at first ChatGPT registered one tool out of thirteen. We wrote a "native boundary" wrapper that hands the browser V8-real promises (via Zone.__symbol__('Promise') ), keeps descriptors structured-clone safe and returns errors in band. After that: 13/13. Every tool has an inputSchema with enums, an outputSchema with structuredContent , readOnlyHint / untrustedContentHint annotations, and one shared set of outcomes: ok , timeout , error_backend , input_invalido , sin_cambios , limite_excedido , circuito_abierto . We added that after catching the agent telling a user "filters applied" while the backend was still thinking. A slow answer is not a success. We could not ask judges to poke at a production site full of real insurers, so we also built an open replica: same 13 tools, same contracts (a test checks they match production verbatim), synthetic plans with made-up insurers, MIT license, 63 tests. That is the live URL. The production integration is linked as well for anyone who wants the real thing, in Spanish. Challenges we ran into Our own agent testing gave us the scare of the week. One session fired 586 identical quote requests in 70 seconds, twelve per second, because each re-quote cancelled the previous one in the browser but not on the server. An agent can hurt your backend without meaning to. The layer now de-duplicates in-flight requests, rate-limits per tool, detects duplicate retries and opens a circuit breaker after consecutive backend failures. The agent gets a clear error with how long to wait instead of a timeout. Other things that bit us: ChatGPT's runtime clones the registerTool options bag, so passing an AbortSignal silently broke registration; ids that came back as strings in one environment and integers in another; and a profile helper that "invented" a dependant's sex when the agent only gave the age. Fixing that last one mattered to us. The agent should ask, not guess. Accomplishments that we're proud of It works in every runtime we could get our hands on: ChatGPT's in-app browser, Chrome's native API, and Claude through a local MCP relay, with an end-to-end harness that runs all 13 tools. The layer is live in the real comparator, not only in the demo. It was a team effort in Santiago: product, engineering and QA all had a hand in it, with review rounds on every PR. We used AI coding agents for implementation and, separately, for adversarial review, and the second model kept finding things the first one missed. What we learned WebMCP turned out to be less about exposing functions and more about deciding what the human should still see and still do. Most of our time went into contracts, errors and on-screen feedback, not into the tool bodies. And "agent-safe by default" (dedup, limits, breakers) belongs inside the layer, not in a later hardening sprint. What's next Roll the same tools out to queplan.pe and queseguro.co (the layer is already parameterised by country), add needs-based recommendation ("I have a chronic condition, what should I look at?"), and measure the agent channel like any other: tool calls, quotes, requests, policies. Prior work The comparator and an older 7-tool prototype predate the challenge. The six new tools, the contract system, the native boundary, the guards, the activity panel and the public demo were built during it. PRIOR_WORK.md in the repo has the dated commits.
