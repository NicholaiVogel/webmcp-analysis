and type blindly into DOM elements, which break the moment a CSS class, layout, or modal changes. \n Walled-Garden Aggregators : Agents restricted to closed ecosystem APIs where independent neighborhood businesses must surrender 30% take rates and hand over customer relationships to centralized platforms. \n \n\n When the W3C and Chrome WebMCP standard ( document.modelContext ) emerged, we saw the foundation for a third, better future: the open web itself as the native agent runtime . \n\n We asked ourselves: Could an AI agent coordinate a real-world multi-stop morning errand across three completely independent, standalone neighborhood businesses—a specialty coffee shop, a boutique grooming studio, and an indie bookstore—with zero backend integration, zero proprietary API keys, and pure on-page tool discovery? \n\n That question led to Open Web Concierge . \n\n \n\n What It Does \n\n Open Web Concierge is an autonomous multi-vendor assistant that plans, negotiates, and executes unified errands across the open web while keeping the human firmly in control. \n\n \n Dynamic Instruction-Driven Scoping : The user speaks naturally (e.g., "I want an iced cold brew with oat milk" , "Book a haircut with Marcus at 11:15" , or a multi-stop Saturday routine). The agent dynamically parses intent and activates only the merchant services requested, gracefully omitting non-relevant stops with zero wasted spend. \n User Identity Profile & Live Form Reflection : The Concierge maintains the user's default credentials (Name, Email, Mobile No., Gender). As the agent navigates each merchant website, it emits live synchronization events over a shared errand bus—allowing the user to watch the merchant's counter form or booking calendar populate live on screen with an active sync indicator. \n Human-in-the-Loop (HITL) Security Gates : The agent never silently commits funds. Before finalizing any transaction, a modal confirmation gate halts execution, presenting itemized pricing, timing, and merchant verification for explicit user approval. \n Live Cross-Side Checkout Reflection : Once authorized, dual-layer real-time synchronization ( BroadcastChannel and reactive storage) immediately posts the confirmed order to the merchant's Active Barista Queue , Client Appointment Log , and Front Register Holds across independent windows and tabs. \n Auditable Receipts : Upon completion, the Concierge compiles an itemized trip log with verifiable order IDs and costs, exportable as Markdown or JSON. \n \n\n \n\n How We Built It \n\n We built the application as a production-grade multi-page web ecosystem using React 19 , Vite 6 , and Tailwind CSS , adhering strictly to the Chrome & W3C WebMCP specification: \n\n \n Merchant Tool Registration on document.modelContext :\n\n \n Artisan Roast Café ( /cafe/ ) : Exposes check_menu ( readOnlyHint: true ) and order_coffee (with strict parameter schemas and customer contact info). \n Luxe Grooming Studio ( /salon/ ) : Exposes check_availability ( readOnlyHint: true ) and book_slot for stylist and calendar scheduling. \n Paper & Ink Bookstore ( /bookstore/ ) : Exposes search_catalog ( untrustedContentHint: true ) and reserve_book for front-desk holds. \n Concierge Orchestration Hub ( / ) : Exposes get_errand_briefing and log_completed_step . \n \n Prompt Injection Defense via Chrome Hints :\n\n \n Following WebMCP security guidelines, search_catalog marks query results with untrustedContentHint: true . This informs the consuming LLM that merchant book blurbs and user reviews are untrusted third-party content, neutralizing indirect prompt injection vectors. \n \n Idempotency Protection :\n\n \n Implemented client request tokens ( clientRequestId ) cached in a 15-second sliding window to prevent accidental double-billing or duplicate holds from rapid agent loops. \n \n Bi-Directional Errand Bus :\n\n \n Combined the HTML5 BroadcastChannel API ( webmcp_errand_bus ) with reactive window storage listeners to ensure sub-millisecond, cross-tab synchronization between the Concierge hub and open merchant tabs without requiring an intermediary WebSocket server. \n \n Built-in WebMCP Inspector :\n\n \n Included an interactive on-page drawer allowing judges and developers to inspect live registered schemas, test parameter validation, and trigger manual tool executions. \n \n \n\n \n\n Challenges We Faced \n\n \n Contextual Linguistic Disambiguation : Natural language is messy. In a prompt like "Book a haircut with Marcus" , the word "book" is a scheduling verb, not a request for literature. We engineered a contextual parser that accurately distinguishes verbal actions ( "book an appointment" ) from literary nouns ( "read a book" , "buy a novel" ) to prevent erroneous merchant activations. \n Zero-Flicker Live Form Population : Connecting cross-tab React state to live agent actions without causing form resets or race conditions required decoupling tool discovery from UI input bindings, synchronizing through a predictable broadcast event contract. \n Eliminating "AI Slop" Aesthetics : We committed to an authentic, human-crafted design language. We eliminated all emojis, avoided generic gradient pills, and designed a neutral, high-contrast dark palette ( #0C0C0C , #121110 , #141414 ) inspired by Swiss editorial typography and physical ledger boards. \n Cross-Window Consistency : Ensuring that checkouts made in the Concierge immediately reflect in the merchant's Barista Queue or Appointment Log across separate browser tabs and embedded multi-views required implementing dual-channel sync ( BroadcastChannel with storage event fallbacks). \n \n\n \n\n What We Learned & The Future of the Open Web \n\n WebMCP represents a paradigm shift for web development. For the last 15 years, the web has been pressured into walled gardens and mobile app silos because machines couldn't reliably interact with standard HTML. \n\n By standardizing document.modelContext , the open web becomes the agentic web . A local family-owned bakery or indie bookstore can become fully AI-operable in an afternoon simply by exposing standard tools on their existing website. No platform monopolies, no 30% tolls, and no closed ecosystems—just humans, agents, and merchants collaborating over the open protocols of the web. \n\n \n\n \n Built With \n\n ai-agents api-free autonomous-agents broadcastchannel chrome-149 cross-tab-sync esm frontend human-in-the-loop javascript json-schema localstorage modelcontextprotocol modern-web multi-page-app open-web prompt-injection-defense react react19 security tailwindcss vite w3c web-standards webmcp \n \n\n \n Try it out \n\n \n \n \n GitHub Repo \n \n \n \n openai-webmcp-challenge.vercel.app \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n Built the Concierge hub (/src, root index.html): the get_errand_briefing and log_completed_step tools, and the live-updating shared trip log UI.\n Wrote the cross-origin orchestration flow that lets one agent discover and chain tools across the café, salon, and bookstore without a shared backend.\n Directed the demo script and recorded the submission video. \n \n\n \n \n \n \n \n \n\n \n David Kumar \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n \n Built Luxe Grooming Studio (/salon): check_availability and book_slot, adapting the café's confirm-before-commit pattern.\n Handled Vercel deployment config (vercel.json) for the multi-page app. \n \n\n \n \n \n \n \n \n\n \n Yuvraj Chaudhari \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n \n Built Paper & Ink Bookstore (/bookstore): search_catalog and reserve_book.\n Applied readOnlyHint and untrustedContentHint annotations across all tools, and wrote the test suite (npm test) verifying schema compliance and annotation correctness. \n \n\n \n \n \n \n \n \n\n \n Ritesh Amrutkar \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n \n Conceived the core architecture and led full-stack engineering for Open Web Concierge.
