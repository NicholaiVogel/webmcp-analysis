The WebMCP challenge made this even more interesting by allowing an AI agent to interact with the dataset directly through browser-based tools. \n\n What I Built \n\n DataLens is a CSV intelligence workspace with two agent-accessible WebMCP tools: \n\n \n get_dataset_summary returns the current dataset profile and preview. \n ask_dataset_question lets an agent ask questions about the uploaded data. \n \n\n The application automatically detects encodings, delimiters, metadata rows, numeric values, dates, missing values, and outliers. Users can then ask questions such as: \n\n \n What is the average sales by category? \n \n\n The answer is processed through a controlled set of validated data operations rather than executing arbitrary generated code. \n\n How I Built It \n\n The original data-analysis logic is written in Python using pandas. I added a FastAPI layer that exposes the analysis and question-answering functionality to a React frontend. \n\n The frontend was built with React, TypeScript, and Vite. WebMCP tools are registered using document.modelContext.registerTool() and include explicit JSON schemas and read-only annotations. \n\n The architecture is: \n\n \n User uploads a CSV in the React frontend. \n FastAPI sends the file through the existing robust loading and profiling pipeline. \n The frontend displays the profile and keeps the current dataset available to WebMCP callbacks. \n An agent can request the summary or ask a natural-language question. \n The backend validates the question and executes only approved pandas operations. \n \n\n What I Learned \n\n I learned that WebMCP is different from a traditional remote MCP server. The tools live in the web page and are registered in the browser, which makes the user interface and the agent share the same context. \n\n I also learned that tool descriptions and schemas are part of the security boundary. Tools should expose only the minimum information required, clearly identify read-only behavior, restrict input length, and treat dataset output as untrusted content. \n\n Challenges \n\n The biggest challenge was adapting a Streamlit application to a browser-native WebMCP architecture. Streamlit is excellent for quickly building data applications, but its server-rendered model does not provide a straightforward top-level JavaScript surface for WebMCP registration. \n\n To solve this, I created a React frontend and a small FastAPI bridge while preserving the existing Python analysis modules. Another challenge was preventing duplicate WebMCP registrations during React development, especially when React Strict Mode re-runs effects. I handled this with guarded one-time registration. \n\n WebMCP is still experimental, so browser support and agent behavior can vary. DataLens is designed to fail gracefully when document.modelContext is unavailable. \n\n \n\n \n Built With \n\n css csv data-analysis data-visualization fastapi gemini-api html model-context-protocol numpy pandas plotly postgresql python react streamlit typescript vite webmcp \n \n\n \n Try it out \n\n \n \n \n celadon-macaron-2e311a.netlify.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Nitesh Giri \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Nitesh Giri \n started this project\n \n —\n \n 2 days ago \n \n \n\n
