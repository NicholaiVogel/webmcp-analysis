A freelancer, tutor, consultant, or agency owner has to decide who to chase first, what tone to use, whether a payment link exists, whether a client promised to pay, and when to stop sending reminders. \n\n Most payment dashboards are built for humans clicking around tables. I wanted to explore what changes when the dashboard becomes agent-operable through WebMCP. \n\n What It Does \n\n Payment Recovery Agent turns overdue receivables into a structured recovery workflow. \n\n A human business owner stays in control of sensitive customer communication, while a browser agent can use WebMCP tools to: \n\n \n inspect the recovery snapshot \n list at-risk payments \n identify the highest-priority overdue invoice \n create a guarded recovery plan \n generate a payment handoff \n draft a WhatsApp-ready reminder \n mark promise-to-pay or recovered payments \n simulate verified payment success \n generate an audit trail \n \n\n The result is not just a reminder tool. It is a human-supervised recovery workflow where overdue money becomes prioritized, actionable, and auditable. \n\n Why WebMCP \n\n WebMCP is a strong fit because payment recovery depends on page-local state and safe sequencing. \n\n Without WebMCP, an agent would need to scrape visible tables, infer which invoice is selected, guess what buttons do, and risk taking the wrong action. With WebMCP, the site exposes explicit tools for each recovery step. \n\n The agent gets structured access to the workflow, and the human gets a clear interface for supervision. \n\n Human + Agent Experience \n\n The human decides what kind of follow-up is appropriate and remains responsible for customer-sensitive actions. \n\n The agent handles the repetitive work: \n\n \n ranking the recovery queue \n preparing next actions \n drafting messages \n attaching payment handoffs \n updating recovery state \n summarizing audit history \n \n\n This division of labor matters because payment recovery is not one action. It is a sequence of decisions where mistakes are costly: chasing the wrong person, over-messaging, sending a reminder after payment, or forgetting a promise-to-pay. \n\n How I Built It \n\n The app is a static web app built with HTML, CSS, and vanilla JavaScript. \n\n It registers 9 WebMCP tools using document.modelContext.registerTool() , with fallback support for navigator.modelContext : \n\n \n get_recovery_snapshot \n list_at_risk_payments \n draft_recovery_message \n create_recovery_plan \n mark_promise_to_pay \n mark_payment_recovered \n create_razorpay_link \n simulate_razorpay_paid \n generate_audit_trail \n \n\n Tool schemas use JSON Schema with additionalProperties: false . Read-only tools are marked with annotations.readOnlyHint: true , and state-changing tools are marked as write actions. \n\n The app uses synthetic demo data only and stores state in the browser for the demo. Every state-changing action writes to an audit trail. \n\n Challenges \n\n The main challenge was designing WebMCP tools that felt like a real agent workflow, not just buttons exposed to an agent. I had to decide which actions should be read-only, which actions change state, what guardrails belong in the outputs, and how to make the agent-human collaboration obvious in a short demo. \n\n Another challenge was keeping the project public and demo-safe while still making it feel realistic. The app uses synthetic receivables and simulated payment handoffs rather than private production data or real payment credentials. \n\n What I Learned \n\n I learned that WebMCP is most powerful when the website exposes meaningful workflow steps, not generic UI actions. The best tools are not "click this button" wrappers. They are bounded capabilities with clear inputs, structured outputs, and human-readable audit trails. \n\n What Is Next \n\n A production version would connect payment handoffs to a secure backend, create payment links server-side, verify payment success through webhooks or signatures, and sync with the user's real invoice/payment system. \n\n \n\n \n Built With \n\n chatgpt chrome css github html javascript webmcp \n \n\n \n Try it out \n\n \n \n \n anantg22.github.io \n \n \n \n GitHub Repo \n \n \n \n anantg22.github.io \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Anant Kumar Gupta \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Anant Kumar Gupta \n started this project\n \n —\n \n 4 days ago \n \n \n\n
