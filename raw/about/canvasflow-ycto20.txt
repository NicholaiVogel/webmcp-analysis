These workflows are highly interactive, but much of the existing web experience is still designed exclusively around human interaction. \n\n That led to CanvasFlow — an agent-native financial analysis workspace designed to make data exploration and visualization accessible to both humans and AI agents. \n\n What it does: \n\n CanvasFlow provides an interactive workspace for financial data analysis and visualization. \n\n Users can bring data into the canvas, explore it, analyze relationships within the dataset, and generate visual representations of their findings. \n\n The key difference is that CanvasFlow is not only designed around the traditional human UI. \n\n We exposed core application capabilities through WebMCP, allowing an AI agent to interact with CanvasFlow through structured tools rather than having to interpret the interface and figure out where to click. \n\n This creates two complementary interaction layers: \n\n Humans get the visual canvas.\nAgents get structured tools. \n\n Instead of an agent simply reading a financial dashboard, it can actually operate the application's capabilities to perform analysis and manipulate the workspace. \n\n The goal is to demonstrate what becomes possible when web applications are designed to be agent-operable, rather than merely agent-readable. \n\n How we built it: \n\n CanvasFlow was built as a WebMCP-enabled web application with the goal of keeping the architecture simple and focused on the core interaction between the application and an AI agent. \n\n We designed the application around a set of useful financial analysis and visualization capabilities and exposed those capabilities as WebMCP tools. \n\n This allows an agent to discover and invoke functionality directly through structured tool calls. \n\n The application was prototyped extremely quickly using Google Antigravity, allowing us to go from the initial idea to a functional WebMCP-enabled prototype in less than 20 minutes. \n\n Rather than spending the majority of the hackathon building a complex interface, we focused on validating the underlying idea: \n\n Can a web application expose meaningful functionality to an agent while remaining intuitive for a human? \n\n CanvasFlow is our answer to that question. \n\n Challenges we ran into: \n\n The biggest challenge was not getting an agent to interact with a webpage. \n\n It was deciding what the agent should actually be able to do. \n\n There is a significant difference between exposing UI actions as tools and exposing meaningful application capabilities. \n\n We had to think carefully about the right level of abstraction for each WebMCP tool: tools needed to be understandable to an agent while still mapping cleanly to useful actions inside the application. \n\n We also had to balance two different users. \n\n A financial analyst needs an intuitive visual workspace, while an AI agent needs structured, deterministic capabilities. \n\n Designing for both without allowing one interaction model to compromise the other became one of the most interesting parts of the project. \n\n Accomplishments that we're proud of: \n\n We're proud that CanvasFlow demonstrates a practical use case for WebMCP rather than treating it as a novelty. \n\n We built a working agent-native financial analysis environment in less than 20 minutes, while still demonstrating a meaningful interaction between an AI agent and a web application. \n\n We're particularly proud of the fact that the application doesn't require the agent to simply “look at the screen” and imitate a human. \n\n The agent can interact with actual application capabilities through structured WebMCP tools. \n\n More importantly, CanvasFlow gave us a practical way to explore what we believe is a much larger shift: \n\n The next generation of web applications may need two interfaces — one for humans and one for agents. \n\n What we learned: \n\n Our biggest lesson was that agent accessibility is fundamentally different from traditional web accessibility. \n\n Humans are exceptionally good at interpreting interfaces. We can look at a chart, understand what a button probably does, navigate unfamiliar layouts, and adapt when something isn't obvious. \n\n Agents need something different: clear capabilities, structured inputs, predictable outputs, and explicit actions. \n\n WebMCP provides an interesting bridge between those worlds. \n\n We also learned that building for agents changes how you think about application architecture. Instead of asking only: \n\n «“What should the user be able to click?”» \n\n you start asking: \n\n «“What should an agent be able to accomplish?”» \n\n That shift in perspective influenced almost every design decision we made in CanvasFlow. \n\n What's next for CanvasFlow: \n\n CanvasFlow is currently a prototype, but we see several directions for taking it much further. \n\n We want to expand its financial analysis capabilities, support more sophisticated datasets and visualizations, and make the agent capable of performing longer multi-step analytical workflows. \n\n We also want to explore collaboration between human analysts and agents — where an analyst can direct an agent to investigate a question, review its analysis, modify the direction of the investigation, and ultimately turn the results into a polished financial insight. \n\n Longer term, CanvasFlow is less about being another financial dashboard and more about exploring a broader idea: \n\n What happens when every useful capability inside a web application is designed to be accessible to both humans and agents? \n\n CanvasFlow is our first experiment in building toward that future. \n\n \n\n \n Built With \n\n css sql typescript \n \n\n \n Try it out \n\n \n \n \n GitHub Repo \n \n \n \n canvasflow-two.vercel.app \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Amezon Okolie \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n 1 \n \n \n\n\n \n 1 person likes this:\n \n\n \n \n \n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Amezon Okolie \n started this project\n \n —\n \n a day ago \n \n \n\n
