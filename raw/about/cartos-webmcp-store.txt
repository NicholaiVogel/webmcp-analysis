Agents Act. \n\n \n An agent-native e-commerce experience powered by WebMCP \n \n\n \n\n 💡 The Idea \n\n Shopping online is still fundamentally designed around humans . \n\n We search through products, open multiple pages, compare specifications, check reviews, evaluate prices, add items to our cart, enter delivery details, and finally complete the purchase. \n\n But as AI agents become increasingly capable, we asked a different question: \n\n \n What if an AI agent could actually use an e-commerce website instead of simply talking about it? \n \n\n That question inspired us to build CARTOS — an AI-native e-commerce experience powered by WebMCP . \n\n We built a complete shopping application backed by a real-world Amazon product dataset containing 123,133 products . \n\n Our goal wasn't to build another chatbot that recommends products. \n\n Our goal was to make the website itself usable by an AI agent. \n\n \n\n 🛒 What We Built \n\n CARTOS is a complete e-commerce experience with: \n\n \n 🔎 Product discovery \n 📦 Product details \n 🔥 Today's deals \n 🛒 Cart management \n 👤 User information \n 💳 Checkout \n 📋 Order history \n ⭐ Product reviews \n \n\n But underneath the interface, we built a WebMCP capability layer that exposes the application's functionality directly to AI agents. \n\n CARTOS currently exposes 15 WebMCP tools: \n\n 🔎 Product Discovery \n\n search_products(query, category?) \n\n Searches our 123,133-product catalog . \n\n get_product_details(asin) \n\n Retrieves product specifications, reviews, price, and ASIN metadata. \n\n get_todays_deals() \n\n Retrieves current promotions and highly-rated best sellers. \n\n recommend_product(productId, reason) \n\n Allows the agent to recommend a specific product with a reason without automatically adding it to the cart. \n\n \n\n 🛒 Cart Operations \n\n view_cart() \n\n Retrieves the current cart. \n\n add_to_cart(productId, quantity?) \n\n Adds a product to the cart. \n\n remove_from_cart(cartItemId) \n\n Removes an item from the cart. \n\n update_cart_quantity(productId, quantity) \n\n Updates the quantity of an item. \n\n clear_cart() \n\n Completely clears the cart. \n\n \n\n 👤 User & Checkout \n\n get_user_profile() \n\n Retrieves the user's name, email, saved addresses, and payment methods. \n\n add_saved_address(street, city, country) \n\n Adds a delivery address. \n\n add_payment_method(cardType, last4) \n\n Adds a payment-method reference. \n\n checkout_order(addressId, paymentMethodId) \n\n Creates an order draft for final human approval . \n\n \n\n 📦 Post-Purchase \n\n view_orders() \n\n Retrieves order history and statuses. \n\n leave_product_review(productId, stars, comment) \n\n Allows a product review to be submitted. \n\n \n\n 🤖 WebMCP in Action \n\n The most important part of our project isn't simply exposing these tools. \n\n It is what happens when an AI agent actually uses them. \n\n For our demonstration, we give the agent access to our live CARTOS storefront. \n\n Instead of manually explaining the application's capabilities, the agent can discover the WebMCP tools exposed directly by the website . \n\n The agent discovers CARTOS's capabilities and can then use them to perform a real shopping workflow. \n\n We give it a real shopping task: \n\n \n "Find me the best shoes with the best balance of price, rating, and quality. Search the catalog, compare the options, and recommend the best one." \n \n\n The agent can now use CARTOS's application capabilities to perform the research. \n\n It can: \n Search\n ↓\nInspect product details\n ↓\nEvaluate alternatives\n ↓\nRecommend the best option\n ↓\nAdd to cart\n\n---\n\n\n# 🤝 Human + Agent Collaboration\n\nThis is where we believe **WebMCP becomes especially powerful**.\n\nWe don't want an AI agent to completely replace the human.\n\nWe want the agent to **handle the complexity while the human retains control**.\n\n### 🤖 What the Agent Handles\n\n- Finding relevant products\n- Searching the catalog\n- Inspecting product information\n- Evaluating alternatives\n- Making recommendations\n- Managing the cart\n- Preparing the checkout\n\n### 👤 What the Human Handles\n\n- The final purchasing decision\n- Approval before the order is placed\n\nWhen the agent reaches checkout, our `checkout_order()` tool creates an **order draft for final human approval** rather than blindly completing the purchase.\n\nThis creates a clear boundary:\n\n> **The agent does the work. The human makes the final commitment.**\n\n---\n\n# 🌐 Why WebMCP?\n\nTraditional websites expose information primarily for **humans**.\n\nAI agents can potentially read that information, but **reading a webpage is very different from using an application**.\n\nWebMCP gives CARTOS a structured **capability layer**.\n\nInstead of an agent trying to figure out how to navigate buttons, pages, and UI elements, CARTOS exposes meaningful actions such as:\n\n```javascript\nsearch_products()\nget_product_details()\nadd_to_cart()\nview_cart()\ncheckout_order()\n\n# 🧠 What We Learned\n\nBuilding **CARTOS** changed how we think about web applications.\n\nWe initially thought of an e-commerce website as a collection of pages and UI components.\n\nThrough **WebMCP**, we started thinking about it differently:\n\n> **Every important capability of an application can become a capability that an agent can discover and use.**\n\nWe learned how important it is to design tools around **meaningful application actions**, rather than simply exposing backend functions.\n\nFor example, `search_products()` is useful to an agent because it represents an actual **user-level capability**.\n\nLikewise, `add_to_cart()` and `checkout_order()` allow the agent to progress through a **real shopping workflow**.\n\nThis helped us think about web development from two perspectives:\n\n### **Human UX + Agent UX**\n\n---\n\n# ⚙️ Challenges We Faced\n\nOne of our biggest challenges was deciding **what should actually become a WebMCP tool**.\n\nIt would have been easy to expose dozens of tiny functions simply to increase the tool count.\n\nInstead, we focused on capabilities that correspond to **meaningful shopping actions**.\n\nAnother challenge was designing the boundary between **agent autonomy and human control**.\n\nSearching and comparing products are low-risk actions that an agent can perform independently.\n\nPurchasing is different.\n\nThat's why our checkout flow deliberately stops at a **human approval point**.\n\nWe also had to connect the agent-facing tools to **real application state** so that actions such as adding an item to the cart weren't just simulated responses — they actually affected the shopping experience.\n\nThis made the WebMCP layer more than a collection of callable functions. It became a way for the agent to **participate in the application's actual workflow**.\n\n---\n\n# 🚀 What's Next?\n\nWe see this architecture extending far beyond shopping.\n\nToday, **CARTOS** demonstrates an agent operating an e-commerce application.\n\nTomorrow, the same model could allow agents to interact with:\n\n- ✈️ **Travel platforms**\n- 🏦 **Banking applications**\n- 📅 **Productivity tools**\n- 🏨 **Booking systems**\n- 💼 **Business applications**\n- 🛍️ **Marketplaces**\n- 🎧 **Customer-service platforms**\n\nThe underlying idea remains the same:\n\n> **Build applications that don't just display information to AI, but expose meaningful capabilities that AI agents can discover and use.**\n\nInstead of creating separate AI integrations for every possible workflow, websites can expose their own capabilities in a structured, agent-accessible way.\n\nThis opens the door to a web where agents can interact with applications **directly, reliably, and with clearly defined capabilities**.\n\n---\n\n# 🌟 Our Vision\n\nWe're not trying to build a smarter Amazon clone.\n\n**We're exploring what happens when websites become agent-accessible applications.**\n\nOur **123,133-product catalog** gives the agent a realistic environment to solve a genuine shopping problem.\n\nOur **15 WebMCP tools** give it the capabilities to interact with that environment.\n\nAnd our **human approval boundary** ensures that automation doesn't mean giving up control.\n\nToday, a user might ask an AI about a product, manually open an online store, repeat the search, compare options, manage the cart, and finally complete the purchase themselves.\n\nWith an agent-native storefront like **CARTOS**, the website can become an active participant in that workflow.\n\n> **The human sets the goal.**\n>\n> **The agent handles the complexity.**\n>\n> **The website provides the capabilities.**\n>\n> **The human remains in control.**\n\nThe future of the web may not be humans using websites alone.\n\nIt may be:\n\n# **Humans + AI Agents + Websites**\n\n**working together.**\n\nAnd **CARTOS is our step toward that future.**\n \n \n\n \n Built With \n\n
