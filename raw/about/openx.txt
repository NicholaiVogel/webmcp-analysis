\n\n \n \n \n \n \n \n \n \n\n \n \n \n \n \n \n \n \n\n \n \n \n \n \n \n \n \n\n \n \n \n \n 1 2 3 4 5 \n\n\n\n \n Inspiration \n\n AI agents can code, research, call tools, and pay for services, but they still operate like black boxes with fragmented memory and limited oversight. \n\n We built OpenX as a mission-control and self-improvement layer where humans, ChatGPT, Codex, and autonomous agents can observe, manage, and improve agent fleets through WebMCP . \n\n What it does \n\n \n 🌐 WebMCP-native control plane — exposes OpenX tools through document.modelContext , letting compatible AI clients inspect agents, lessons, skills, credits, and Dream Cycles directly from the browser. \n 🤖 Fleet Management — discovers kiro-cli , claude-code , Google ADK, and custom agents with real-time heartbeats and lifecycle tracking. \n 🧠 REM Dream Cycles — compress raw sessions into verified lessons and reusable Skills. \n 🛡️ 0G Compute Auditor — independently reviews lessons as keep, revise, or reject. \n 💾 0G Storage — anchors sanitized memory and audit proofs with verifiable Merkle receipts. \n 💸 x402 + RLUSD — lets agents autonomously pay for MCP tools and compute on XRPL. \n 💳 Tracks token and tool-call costs in real time. \n \n\n How we built it \n\n OpenX combines Next.js 14 + WebMCP , a Node/TypeScript Gateway, SQLite WAL, and Python Google ADK agents. \n\n Codex was part of our engineering workflow : we used it to explore the repository, understand modules, implement WebMCP and gateway features, debug integrations, review code, and validate behavior across TypeScript and Python. \n\n WebMCP turns the dashboard into an AI-operable application , so agents can call structured OpenX actions instead of relying on screenshots or DOM scraping. \n\n Challenges we ran into \n\n \n Reliable WebMCP tool schemas across different agent runtimes. \n Non-deterministic 0G Compute JSON and hallucinated citations. \n Preventing secrets and PII from reaching decentralized storage. \n SQLite contention from concurrent telemetry. \n Coordinating async Dream Cycles, MCP calls, and x402 payments without race conditions. \n \n\n Accomplishments that we're proud of \n\n \n Built a dashboard that AI agents can operate directly through WebMCP . \n Used Codex as an engineering collaborator , not just a code generator. \n Created an end-to-end pipeline from telemetry → audited lessons → reusable Skills. \n Combined decentralized memory, independent auditing, and autonomous micropayments in one system. \n \n\n What we learned \n\n WebMCP turns the frontend into an agent interface, not just a UI. \n\n Codex is most powerful with real repository context, tests, and runtime feedback. \n\n Agent memory also needs governance: compact, audited lessons are more valuable than replaying huge raw histories. \n\n What's next for OpenX \n\n \n Make Codex a first-class managed agent inside OpenX. \n Expand WebMCP controls for Dream Cycles, Skills, audits, and fleet operations. \n Build cross-agent collective memory on 0G. \n Add ZK-verifiable AI audits. \n Launch agent-to-agent Skill commerce using x402 + RLUSD. \n \n\n \n\n \n Built With \n\n codex llm
