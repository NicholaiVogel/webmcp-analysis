Buyability. \n \n 1 2 3 \n\n\n\n \n Inspiration \n\n AI agents are becoming a new way for people to interact with the web, but most small-business websites were built for humans and search engines — not for agents. \n\n A business may have products, services, prices, booking options or contact flows publicly available, yet an AI agent can still struggle to reliably understand what the business offers or how to take action. \n\n AgentReady started from a simple question: how can a small business know whether its website is actually ready for AI agents? \n\n What it does \n\n AgentReady audits a real website and evaluates its AI commerce readiness across three dimensions: \n\n Visibility → Understanding → Buyability \n\n It analyzes observable commercial information, evaluates what an AI agent can reliably understand, and produces evidence-based scores and prioritized recommendations. \n\n The goal is not simply to make websites more machine-readable. The goal is to help businesses move from being visible to AI agents to becoming genuinely understandable and actionable by them. \n\n AgentReady also exposes its audit capability directly to AI agents through WebMCP. \n\n The native WebMCP tool agentready.run_audit allows an agent to launch the same website audit available to a human through the AgentReady interface and receive structured results including readiness scores, observed evidence, recommended actions, rendering provenance and monitoring eligibility. \n\n This creates one capability for two users: \n\n Humans get a clear visual audit. AI agents get a structured, callable tool. \n\n How we built it \n\n AgentReady uses an evidence-first audit architecture designed to avoid inventing commercial facts. \n\n The challenge demo combines a browser interface with a bounded server-side audit function. For JavaScript-heavy websites where the initial HTML does not expose enough reliable evidence, AgentReady can use a controlled browser-rendering fallback and clearly reports that provenance. \n\n The WebMCP integration registers agentready.run_audit through: \n\n document.modelContext.registerTool(...) \n\n The tool calls the same AgentReady audit capability used by the human interface and returns structured content that an AI agent can consume directly. \n\n This means WebMCP is not a separate demonstration layer: humans and agents access the same underlying capability. \n\n AgentReady also includes monitoring of comparable audits over time, allowing businesses to identify improvements or degradation in their AI readiness while avoiding false comparisons when an acquisition is incomplete. \n\n Challenges \n\n The hardest problem has been factual reliability across very different types of websites. \n\n Real-world sites contain navigation elements, product cards, booking flows, duplicated prices, dynamic JavaScript content and commercial information distributed across different structures. \n\n AgentReady therefore follows a simple principle: \n\n Observed, not assumed. \n\n If reliable evidence cannot be observed, the system should report uncertainty rather than manufacture a confident answer. \n\n Another challenge was making dynamic website audits reproducible. The browser-rendering fallback and monitoring eligibility rules were designed to prevent incomplete page acquisition from creating misleading readiness changes. \n\n What's next \n\n The next step is expanding AgentReady from one callable audit capability into a broader AI commerce readiness layer where detected gaps can map to additional WebMCP actions. \n\n The longer-term loop is: \n\n Audit → Detect capability gap → Expose capability → Agent takes action \n\n The vision is to make AI commerce readiness accessible to small businesses that do not have dedicated technical teams — so they can participate in an increasingly agent-driven web without having to understand the underlying technology. \n\n \n\n \n Built With \n\n github html javascript netlify pytest python webmcp \n \n\n \n Try it out \n\n \n \n \n GitHub Repo \n \n \n \n agentready-ai.netlify.app \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n I designed and built AgentReady as a solo founder, from the product concept and AI commerce readiness framework to the audit architecture, WebMCP integration, browser-rendering fallback, monitoring logic, testing, deployment, and demo experience.
