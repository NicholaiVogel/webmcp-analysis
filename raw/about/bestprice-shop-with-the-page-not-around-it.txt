Like Comment Story Updates Live WebMCP on BestPrice.gr: the open shopping page exposes contextual tools so a person and their agent share the same screen. Why WebMCP This is browser-native WebMCP on the live BestPrice.gr page ( document.modelContext.registerTool ), not the remote MCP endpoint. The person and the agent share one open shopping page. Tools change with navigation, only act on what is currently visible, and never check out. Inspiration Shopping pages already contain the facts an agent needs, but the agent often has to infer them from layout. We wanted the page to describe its own visible state while the shopper stayed in control of the same screen. What it does BestPrice turns the shopping page a person already has open into a small, structured workspace for their agent. The homepage offers product search. A listing exposes the products, filters, and sorting choices currently visible. A product page exposes product facts, delivered-price comparison, specifications, and price history. The agent can open only a product whose exact ID and canonical BestPrice link are present in the visible listing. Every navigation remains visible. The tools do not check out, add to basket, sign in, return direct merchant URLs, or treat missing shipping as free. The shopper still chooses which shop to visit. How we built it The browser layer uses document.modelContext.registerTool and manages each tool as the page changes. Arguments are validated in executable code. URLs must be same-origin. Results come from visible page state, hidden and decoy elements are ignored, individual outputs are capped, partial registrations are rolled back, and telemetry failures cannot change tool results. The public source package includes 13 tool contracts, a local inspector, a deterministic evaluator, and automated tests under Apache License 2.0. Challenges we ran into BestPrice is a mature, dynamic commerce site, so the hard part was not defining a search tool. It was keeping tool state aligned with navigation, filters, sorting, product identity, and price data without teaching an agent to trust stale or hidden DOM. We also had to make failure states explicit, especially unknown shipping and incomplete page data. Accomplishments that we're proud of The WebMCP layer is live on BestPrice.gr and works across the homepage, search results, and product pages. It exposes useful shopping context without adding purchase authority. We also shipped a public inspector and evaluator so reviewers can see the registered tools and run repeatable checks. BestPrice and its remote MCP service existed before the challenge. This submission covers the new browser-native WebMCP layer built and shipped during the challenge window. What we learned WebMCP is most useful when page tools match what a person can actually see and do. Small, contextual tools with clear boundaries were more reliable than one broad shopping action. Keeping the human-visible page as the shared surface also made every agent action easier to understand. What's next We will measure real agent-assisted journeys, improve tool wording and output quality from that evidence, and keep testing against new browser and assistant implementations. Purchase decisions and checkout will remain with the shopper.
