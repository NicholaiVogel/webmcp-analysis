The answer became a curated catalog of 100 vetted AI tools for small and medium-sized businesses, with a KMU score, checked prices and honest caveats for every tool. When WebMCP (and the challenge) appeared, the next question was obvious. What if agents could use that catalog the same way people do? \n\n What it does \n\n Clever AI Tool Scout is a recommendation interface on top of the catalog. A person / human describes a business task, optionally adds a monthly budget in EUR, and gets up to three fitting tools with a reason, a caution and a link to the full review. An AI agent can do exactly the same through one WebMCP tool, find_ai_tools , with the same two inputs. People and agents share one recommendation engine. \n\n Live: cleverkitools.com/webmcp-challenge \n\n Why WebMCP is suited for this use case \n\n A tool catalog is a structured question with a structured answer. Without WebMCP an agent has to scrape a hundred German profile pages, guess prices and infer categories. With WebMCP the site says exactly what it can do: give me a task and a budget, I return ranked tools, prices in EUR, cautions and profile URLs. The agent gets a deterministic contract instead of a DOM to navigate, and the site owner keeps control over how recommendations are made.\nIn addition, I just wanted to try WebMCP 🙂 \n\n How it improves the user experience (or AGENT exprience?). \n\n \n For people: the same form, same results, nothing changes. No direct improvement. \n For agents: one straight call instead of dozens of page loads. No open API neccessary. No running MCP server neccessary. \n \n\n The Agent Flight Recorder shows every human and agent request of the session as a four-step trace (request received, intent matched, budget evaluated, result returned). Query text stays in the browser. I used it for debugging. \n\n What people and agents can accomplish together that was not possible before \n\n An agent can now answer "which AI tool should my small business use for X within Y euros" from a curated, price-checked source instead of from training data. It can hand the person a page that already shows the shortlist. The person can refine the task in the form, and the agent can pick that up again. \n\n On the other hand, to be honest, well, it's more a tech demo atm and not a super use case, I must admit. I'm sure better use cases will follow. \n\n How we built it (we = ChatGPT Codex and me) \n\n \n One tool, find_ai_tools , registered with document.modelContext.registerTool . Input schema: task (string, required) and max_monthly_budget (number, EUR, optional). \n The execute handler runs the same recommend() engine as the HTML form, renders the cards into the page and returns structured JSON. \n The handler respects the AbortSignal passed by the browser. \n Search core: 13 intents with German and English terms, category weights, tool boosts and a relevance floor. Prices are normalized to EUR from a known regular entry price (checked 21 Aug 2026). \n Catalog: 100 current tools, 15 new entries, 19 archived tools with replacements, loaded as static data. Everything runs in the browser, no server round-trip. \n Progressive by design: without document.modelContext the page is a normal form, and the status panel says so. \n Built with ChatGPT and Codex, deployed on cleverkitools.com. \n \n\n What the agent receives: \n {\n "request": { "task": "…", "max_monthly_budget": 30 },\n "visible_results_updated": true,\n "selection_status": "matched | fallback | archive_redirect | over_budget",\n "matched_intents": ["Video, audio & music"],\n "minimum_monthly_budget_eur": 12.9,\n "recommendations": [\n {\n "name": "OpusClip",\n "profile_url": "https://cleverkitools.com/ki-tools/opusclip/",\n "category": "Social Media & Ads",\n "why_fitting": "…",\n "caution": "…",\n "status": "current",\n "kmu_score": 86,\n "price": "Freemium · ab 15 USD/Monat (ca. 13,13 EUR/Monat)"\n }\n ],\n "archive_match": { "name": "Copy.ai", "status": "archived", "replacement": { "name": "Genspark" } }\n}\n \n Challenges we ran into \n\n WebMCP is only available in ChatGPT's in-app browser and in Chrome with the flag enabled, so the page had to work as a normal form everywhere else and report its WebMCP state without pretending. The second challenge was keeping one engine for both audiences: the agent needs structured fields, the person needs readable cards, and both had to come from the same call. \n\n What's next \n\n Not 100% sure yet.
