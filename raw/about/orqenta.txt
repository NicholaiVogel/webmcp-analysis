An agent may know 'what' a user wants but struggle with buttons, forms, page structure, and application-specific workflows. We were inspired by the idea behind "WebMCP": instead of forcing agents to interpret every interface visually, websites can expose their capabilities as structured tools that agents can understand and use. \n\n That became the foundation of "Orqenta", a human–agent collaboration layer for the open web. Our goal was to explore a future where "websites expose capabilities, agents execute them, and humans remain in control". \n\n What We Built \n\n Orqenta connects human intent with agent-accessible web capabilities through WebMCP. A user can describe what they want to accomplish, while an AI agent can discover available tools, understand their schemas, perform structured actions, and return meaningful results. \n\n Rather than treating an AI agent as an external chatbot, Orqenta treats it as a "participant in the web experience". \n\n The core interaction looks like: \n\n "Human intent → Agent discovers tools → Agent performs structured actions → Human reviews the result" \n\n This creates a more reliable interaction model than asking an agent to independently guess how a webpage works. \n\n How We Built It \n\n We designed Orqenta around a modular web architecture so that the product remains useful even when WebMCP is unavailable. \n\n At the application layer, we expose clearly defined capabilities through WebMCP tools using structured names, descriptions, input schemas, and executable functions. The frontend provides the human-facing interface, while the tool layer acts as the bridge between agent reasoning and application actions. \n\n We focused heavily on making every tool: \n\n \n "Discoverable" — agents can understand what the tool does. \n "Structured" — inputs and outputs follow predictable schemas. \n "Controllable" — humans can remain involved in consequential actions. \n "Composable" — multiple tools can be combined into larger workflows. \n "Progressively enhanced" — the application still works as a normal web application without WebMCP support. \n \n\n What We Learned \n\n The biggest lesson was that "agent-native web design is different from traditional UI design". \n\n A traditional interface is primarily designed for a human to visually interpret. An agent-facing interface needs something else: explicit capabilities, predictable inputs, clear outputs, validation, and well-defined boundaries. \n\n We learned to think about application features not only as UI components, but also as "machine-actionable capabilities". \n\n For example, instead of only building a "Search" interface, we ask: \n\n \n What exactly should an agent be able to do with search? \n \n\n That shift led us to define tools around intent and actions rather than around individual UI elements. \n\n We also learned that human oversight remains critical. Giving agents more capability does not mean removing people from the workflow. In many cases, the better experience is agent-assisted execution with human control at the right moments . \n\n Challenges We Faced \n\n One of our biggest challenges was working with an emerging technology and designing around capabilities that are still evolving. \n\n We had to make architectural decisions that would support WebMCP without making the entire application dependent on it. This led us to separate the core application logic from the agent interaction layer. \n\n Another challenge was determining the right level of tool abstraction. Exposing every UI interaction as a tool creates noise and makes agents harder to use. Exposing too few tools makes useful workflows impossible. We therefore focused on high-value, task-oriented capabilities instead of exposing raw interface actions. \n\n We also had to think carefully about security. An agent capable of taking actions on behalf of a user introduces questions around authorization, validation, sensitive operations, and human confirmation. We designed Orqenta so that agent capability does not automatically mean unrestricted authority. \n\n Why Orqenta Matters \n\n We believe the next evolution of the web will not be purely human-facing or purely agent-facing. \n\n It will be "collaborative". \n\n Humans bring goals, context, judgment, and creativity. Agents bring speed, automation, reasoning, and the ability to execute structured workflows. \n\n "Orqenta explores what happens when the web becomes a shared environment for both." \n\n Instead of AI merely reading the web, "Orqenta explores a web where agents can actually work with it—while people stay in control." \n\n \n\n \n Built With \n\n css4 eslint nanoid next.js playwright react tailwind typescript vercel vitest \n \n\n \n Try it out \n\n \n \n \n orqenta.vercel.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Muhammad Zeeshan \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Muhammad Zeeshan \n started this project\n \n —\n \n 3 days ago \n \n \n\n
