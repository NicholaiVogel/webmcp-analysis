It can be difficult for drivers to remember what was serviced and what maintenance is coming next. \n\n I wanted to explore how WebMCP could make a normal vehicle maintenance website more useful by allowing an AI agent to understand and interact with the application directly. \n\n What it does \n\n CarCare MCP is a vehicle maintenance dashboard that keeps track of a vehicle and its maintenance history. \n\n Users can view completed services, record new maintenance, and see when upcoming maintenance is due based on mileage. \n\n The application exposes its functionality to AI agents through WebMCP tools. These tools allow an agent to: \n\n \n Get vehicle information \n Read maintenance history \n Add maintenance records \n Calculate upcoming maintenance \n \n\n For example, instead of manually filling out a form, a user can tell an AI agent that an oil change was completed at a certain mileage, and the agent can use the WebMCP tool to add that information to the application. \n\n How I built it \n\n I built CarCare MCP as a lightweight web application using HTML, CSS, and JavaScript. \n\n Maintenance data is stored in the browser using localStorage. The application calculates upcoming maintenance based on the latest service mileage and predefined service intervals. \n\n I then integrated WebMCP using the Model Context API and registered tools with document.modelContext.registerTool() . Each tool includes a description, input schema, and an execute function that connects the AI agent to the same application logic used by the web interface. \n\n The application is deployed on Vercel, and the source code is available on GitHub. \n\n Challenges I ran into \n\n One of the main challenges was understanding how a traditional web application should expose its functionality to an AI agent. \n\n Instead of having an agent rely on clicking buttons or interpreting the visual interface, I needed to think about the application's actions as structured tools with clear descriptions and input schemas. \n\n I also had to test the experimental WebMCP implementation and verify that the browser correctly registered and exposed the tools. \n\n What I learned \n\n This project helped me understand the difference between building a website only for humans and building one that can also be understood and operated by AI agents. \n\n WebMCP allows the application itself to describe the actions an agent can perform. This can make agent interactions more structured and reliable than depending entirely on visual browser automation. \n\n What's next for CarCare MCP \n\n Future versions could support multiple vehicles, customizable maintenance schedules, cloud synchronization, service receipts, and more detailed maintenance recommendations. \n\n The same WebMCP approach could also allow an AI agent to manage a driver's complete maintenance workflow across multiple vehicles. \n\n \n\n \n Built With \n\n css3 html5 javascript vercel webmcp \n \n\n \n Try it out \n\n \n \n \n carcare-mcp.vercel.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Brian Wu \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Brian Wu \n started this project\n \n —\n \n a day ago \n \n \n\n
