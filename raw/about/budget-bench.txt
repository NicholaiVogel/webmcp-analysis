Handing an agent full write access to your money is wrong. Making it\nscrape and click a human UI is worse. WebMCP offers a third path: give the agent real tools\nand keep the human in the loop at the only moment that matters — approving the change. \n\n What it does \n\n Budget Bench is a household budget workbench where the browser agent and the human work on\nthe same live page: \n\n \n The agent reads the whole budget with get_budget_summary (income, category budgets,\nspend, what's over/tight, pending proposals). \n The agent acts through five proposing tools: find_savings (trims discretionary\ncategories and moves the difference to savings), set_category_budget ,\n add_category , record_spend , and propose_plan (full rebalance to hit a savings\ntarget, fixed costs untouched). \n Every mutation is a proposal. Tool calls never write to the budget. Each one lands in\nthe human-visible Proposal Tray with a plain-English summary and the agent's reason. \n The human approves or rejects each proposal (or the whole tray). Approvals apply\natomically; every proposal and every decision is written to the activity log. \n \n\n Why WebMCP is the strong fit \n\n \n Agent tools, not agent autonomy. Household money is exactly the case where an agent\nshould propose and a human should decide. WebMCP tools carry structured schemas, so the\nagent gets a reliable contract instead of DOM scraping; the tray guarantees the human veto. \n What people + agents can do together that was hard before: a two-minute conversation —\n"energy bill's up £35, find the money from discretionary" — becomes three reviewed,\nreversible, explained edits instead of a spreadsheet session. The same shared page also\nmeans the agent always sees the effect of its own proposals before the human decides. \n Shared context, not replicated state. The page state is the app: no backend, no\naccounts, no auth replication. That's only possible because WebMCP runs tools where the\nstate already lives — in the tab the human is looking at. \n \n\n How we built it \n\n One static page (vanilla HTML/CSS/JS, zero dependencies, zero build step) with a single\nstate object and one render function. Six tools registered via\n document.modelContext.registerTool({name, description, inputSchema, execute}) per the\nWebMCP draft. Proposals carry apply closures, so approval is atomic and the tray doubles\nas a transaction log. Tool logic is covered by an automated Playwright suite (27 checks:\nregistration, schema behaviour, proposal isolation, approve/reject application, error\npaths) which stubs only the browser side of modelContext — the app's tool code runs\nunchanged. Hosted on Surge. MIT licensed. \n\n Challenges we ran into \n\n Designing tools that are genuinely useful to an agent while guaranteeing the human veto:\nevery mutating tool needed to become a proposal generator rather than a writer, which\nreshaped the whole state model. Also pacing propose_plan so fixed costs stay untouchable\nand the plan lands as ONE reviewable decision instead of a barrage of edits. \n\n Accomplishments we're proud of \n\n The proposal tray pattern: six tools, one hard invariant — the agent proposes, the human\ndecides — and the activity log that proves it. \n\n What we learned \n\n That "agent-accessible" and "human-controlled" are not a trade-off if the tool layer is\ndesigned as a proposal system rather than a command API. \n\n What's next for Budget Bench \n\n CSV import of real bank data (local-only), per-category proposal bundles, and a\n"what-if" tool that compares two plans side by side in the tray. \n\n \n\n \n Built With \n\n ai-agents budget html javascript webmcp \n \n\n \n Try it out \n\n \n \n \n budget-bench.surge.sh \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n levellerhermes Adamou \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n levellerhermes Adamou \n started this project\n \n —\n \n 9 days ago \n \n \n\n
