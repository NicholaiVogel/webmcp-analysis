A WebMCP workspace where agents stay current and people retain authority. Like Comment Story Updates Inspiration Important shared decisions get stale as evidence changes. Commonplace turns that drift into a visible collaboration loop: people can see the decision, its evidence, the agent's reading, and the exact moment a person must decide. What it does Commonplace is a shared human-agent workspace built around a Freshness Protocol. A human records new evidence; the affected decision becomes paused; the agent re-grounds on the decision context and evidence objects; it proposes a new, cited decision; and a human alone confirms what becomes canonical. The shipped Project Aurora workspace gives judges a complete, fast demo path: Record the “Monday sensor reconciliation” update. Watch decision P-014 pause because its support is no longer fresh. Let the agent read structured decision/evidence context and create P-015. Confirm the human authority gate to make the revised date canonical. Why WebMCP A browser agent should not have to infer whether a decision is stale, which evidence supports it, or whether it may finalize a decision from visual UI. Commonplace exposes six browser-native WebMCP tools for those exact capabilities: get_decision_context get_evidence_changes get_evidence_objects get_decision_history propose_decision_update request_human_confirmation The agent receives structured, bounded context and must use a separate human-confirmation tool before any decision becomes canonical. This is not a generic chat layer: the agent has an explicit, inspectable role in the workspace’s state machine. Better together Humans contribute judgment and retain final authority. Agents handle the repetitive but high-risk reasoning work of grounding a proposal in current evidence, citing what changed, and keeping the activity trail legible. The result is a workspace where collaboration remains understandable after the moment has passed. Implementation Commonplace is a React + TypeScript + Vite web app deployed to Cloudflare Pages. It registers tools through document.modelContext.registerTool when the browser exposes WebMCP, validates every input, derives freshness and citations from workspace state, and refreshes the visible workspace after a tool action. It also provides a clear fallback mode in unsupported browsers.
