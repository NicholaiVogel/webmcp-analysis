The result is simple: people forget who they met, what they discussed, and who they should contact next. \n\n NeXaCard WebMCP — Relationship Copilot explores a different approach: make the relationship manager itself agent-native . \n\n What I Built \n\n NeXaCard is a lightweight relationship copilot that lets a person manage professional connections while an AI agent can interact directly with the web application through WebMCP . \n\n The app stores a small local relationship database containing contacts, relationship strength, interaction context, and follow-up state. \n\n Instead of requiring a user to navigate through the UI manually, an agent can understand natural-language requests and select the appropriate WebMCP tool. \n\n For example: \n\n \n "Who do I need to follow up with this week?" \n \n\n The agent discovers and invokes the identify_followup WebMCP tool, which returns the contacts needing attention. \n\n The current prototype exposes six WebMCP tools: \n\n \n search_contacts — search the local contact database \n get_contact_context — retrieve full relationship context \n get_interaction_history — retrieve past interactions \n identify_followup — identify contacts needing attention \n draft_followup — generate a follow-up draft \n create_followup — create a follow-up task \n \n\n This creates a simple agent workflow: \n\n Discover → Understand → Remember → Draft → Act \n\n Why WebMCP? \n\n The key idea behind this project is that a web application should not only be something humans click through. It can also expose meaningful capabilities directly to agents. \n\n With WebMCP, the application's functionality is described as structured tools that an agent can discover and invoke. \n\n In the demo, Gemini receives the natural-language request: \n\n \n "Who do I need to follow up with this week?" \n \n\n It selects the identify_followup tool, invokes it with the required arguments, receives the application's structured result, and uses that result to answer the user. \n\n The application therefore becomes an agent-accessible interface , rather than simply a visual dashboard. \n\n How I Built It \n\n The project intentionally uses a small, dependency-light architecture: \n\n \n Vanilla HTML \n CSS \n JavaScript \n WebMCP \n Gemini 3.6 Flash \n Browser-side local data \n LocalStorage \n Netlify for hosting \n \n\n The WebMCP tools are registered using the browser's document.modelContext API. \n\n No backend server or external database is required for the prototype. \n\n Challenges \n\n The biggest challenge was understanding the difference between a normal web page integration and a genuinely agent-accessible WebMCP application. \n\n I initially experimented with a custom JavaScript interface for exposing tools, but that was not the actual WebMCP API. I replaced that approach with the browser's WebMCP implementation using document.modelContext.registerTool() . \n\n I then verified the production deployment by inspecting the registered tools and executing them directly. \n\n The final test demonstrated the complete flow: \n\n Natural-language request → Gemini → WebMCP tool selection → tool execution → structured relationship data → agent response \n\n What I Learned \n\n This project changed how I think about web applications. \n\n Instead of designing only around: \n\n Human → UI → Application \n\n WebMCP enables another interaction model: \n\n Human → Agent → WebMCP Tool → Application \n\n The most interesting part is not simply adding AI to a website. It is giving an agent well-defined capabilities so that the agent can interact with the application's real functionality. \n\n Future Direction \n\n The prototype focuses on professional relationship management, but the same architecture could be applied to many agent-native web applications. \n\n Future versions could add richer relationship intelligence, calendar integration, email workflows, organization-level relationship graphs, and more sophisticated next-action recommendations. \n\n The goal is to make relationship management something an agent can actively help with rather than another dashboard a user has to maintain manually. \n\n \n\n \n Built With \n\n agentic-ai ai-agents css gemini html javascript localstorage netlify webmcp \n \n\n \n Try it out \n\n \n \n \n nexacard-webmcp.netlify.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n M Raghupathy \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n M Raghupathy \n started this project\n \n —\n \n 3 days ago \n \n \n\n
