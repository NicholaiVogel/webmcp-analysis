They were driving along a two-lane highway corridor—the kind of treacherous mountain pass defined by blind curves, sudden visibility drops, and heavy commercial freight trucks that turn everyday transit into deadly collision zones. \n\n On that road, a catastrophic crash occurred. I lost five of my closest family members in an instant. \n\n When the OpenAI WebMCP Challenge was announced, I knew I could not build a toy or another generic chatbot. I had to focus on a problem with real-world stakes: preventing this specific, devastating failure mode so no other family has to suffer that loss. \n\n Most browser AI agents today interact with applications through brittle screen-scraping, OCR, or simulated clicks. While that might suffice for casual e-commerce, life-safety operations cannot tolerate non-deterministic delays or scraping failures. When sudden fog drops visibility to near zero on blind S-bends, human drivers and dispatchers experience severe cognitive overload trying to calculate safe stopping sightlines and coordinate emergency interventions. \n\n I asked a fundamental question: \n\n \n What if high-risk transit corridors could be supervised directly inside the browser, where the application exposes deterministic, typed telematics tools to an AI agent? \n \n\n I built DispatchGuard WebMCP to pioneer what an agent-native safety cockpit looks like—merging autonomous collision risk evaluation with human supervisory dispatch into a synchronized, life-saving control loop. \n\n What it does \n\n DispatchGuard WebMCP is a real-time transit telemetry and collision mitigation command deck where human dispatchers and browser agents collaborate to secure hazardous, two-lane highway corridors. \n\n When the application loads in a WebMCP-capable browser, it exposes four typed tools directly to the agent layer via document.modelContext.registerTool : \n\n \n query_corridor_telemetry : Ingests real-time sector parameters—sightline distance (meters), weather state, commercial truck ratio, and blind curve counts. \n evaluate_overtake_risk : Runs kinematic collision modeling, evaluates hazard probability (0–100%), and escalates sector status to CRITICAL. \n broadcast_safety_alert : Pushes a geofenced advisory speed cap (e.g., 45 km/h) and overtake ban across active vehicle nodes and UI cards. \n export_incident_dossier : Bundles the entire incident timeline, telemetry data, and mitigation checklist into an audit-ready post-mortem modal with copyable JSON. \n \n\n The human operator retains visual control through an interactive SVG vector radar schematic, while the AI agent runs risk math in the background and executes safety protocols with zero screen-scraping delay. \n\n How I built it \n\n \n Frontend Stack : Built with Next.js 16 (Turbopack), React 19, and Tailwind CSS. The interface uses a dark, high-contrast command deck palette (deep slate #0A0B0E , warning amber, and critical red vectors) designed for high-stress situational awareness. \n WebMCP Registration : Implemented inside src/hooks/useWebMCP.ts . The tools are registered directly on document.modelContext with strict JSON Schema definitions for every input parameter. \n Fallback Simulation Harness : Because judges test across various environments (some with Chrome flags enabled, others in standard browsers), I built an on-page simulation bus. Clicking the harness tools runs the exact same client-side mutation logic as the native WebMCP calls, guaranteeing the demo works on every browser. \n Testing & Verification : Verified native tool discovery and execution using the official WebMCP browser extension and the ChatGPT in-app browser environment. \n \n\n Challenges I ran into \n\n \n Next.js SSR vs. Browser-Native WebMCP : In Next.js, document does not exist during server-side rendering. Furthermore, document.modelContext is injected dynamically by the browser or extension at runtime. I had to design a clean hydration guard and an asynchronous registration hook that polls safely for the context without throwing SSR errors or causing infinite re-renders. \n Input Validation for Autonomous Agent Calls : When an AI agent executes tool calls, it can occasionally pass unexpected string formats or out-of-range floats. I implemented runtime input sanitization to clamp numerical values (like speed caps and truck ratios) and normalize weather strings before passing them into the UI state machine. \n Real-Time Visual State Sync : Making the vector radar map dynamically pulse red, spike the risk gauge to 99%, and display active geofenced warning banners—all within milliseconds of an agent tool call—required keeping local UI state tightly coupled to the tool execution callbacks. \n \n\n Accomplishments that I'm proud of \n\n \n True In-Browser Agency : Proved that WebMCP can eliminate screen-scraping entirely. Tool execution happens sub-15ms directly in browser memory. \n Clean Fallback Architecture : Built a system that gracefully degrades: if native WebMCP is detected, it registers to the browser agent; if not, the interactive UI harness lets any user test the full lifecycle manually. \n Full Open-Source Compliance : Delivered a clean, production-built repository with complete TypeScript typing, strict zero-error builds, and an MIT license visible at the root. \n \n\n What I learned \n\n WebMCP represents a massive shift in how web applications should be architected. Instead of treating a web page as a purely visual surface meant only for human eyes, we can now design applications as shared state machines. The human sees an intuitive visual interface, while the AI agent interacts with typed, deterministic tools on the exact same page. \n\n What's next for DispatchGuard WebMCP \n\n A command deck in a browser is only the first step. To physically eliminate fatal head-on collisions on two-lane mountain corridors, the system must bridge the gap between software dispatch and real-time physical intervention on the asphalt: \n\n \n Sub-100ms Peer-to-Peer Overtake Clearance (Vehicle-to-Vehicle): \nDeveloping a decentralized WebMCP toolset that operates over local ad-hoc Wi-Fi / DSRC networks without cellular internet. When a driver signals an overtake behind a freight truck, the agent automatically interrogates the forward oncoming corridor and issues an immediate, non-negotiable "ABORT OVERTAKE" interlock if the time-to-collision window is under 6 seconds. \n Solar Edge Nodes for Mountain Blackspots: \nPartnering with roadside monitoring hardware (solar-powered radar/optical cameras on blind S-bends) to run local WebMCP micro-agents at the curve itself, beaming real-time corridor sightline obstructions directly to approaching vehicles and regional dispatch. \n Offline Edge PWA for Drivers and Remote Outposts: \nPackaging DispatchGuard into an ultra-lightweight, offline-first Progressive Web App (PWA) with client-side WebAssembly models, ensuring crash prediction algorithms function with zero latency in rural mountain valleys where cellular reception completely drops. \n Field Piloting on High-Risk African Transit Corridors: \nCollaborating with regional transport authorities, long-haul trucking cooperatives, and highway safety bureaus to pilot the early warning telemetry layer on notorious high-casualty mountain passes and freight corridors. \n \n\n \n\n \n Built With \n\n agents autonomous css javascript next.js openai react tailwind turbopack typescript vercel webmcp \n \n\n \n Try it out \n\n \n \n \n dispatch-guard-web-mcp.vercel.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n Solo architect and developer.
