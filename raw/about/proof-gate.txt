Proof Gate builds accountable intelligence. \n\n Proof Gate is a WebMCP-native evidence workspace where a human and a browsing agent build the same versioned case together. \n\n The contradiction is simple: web agents can often click and act, but they struggle to preserve shared state, provenance, uncertainty, and decision lineage across a real workflow. \n\n Why WebMCP \n\n Claim evaluation is stateful. A case contains a claim revision, decision context, evidence records, provenance, conflicts, a deterministic verdict, and an audit lineage. Without a structured application interface, a browsing model has to infer that state from DOM controls and maintain a separate copy. \n\n Proof Gate exposes six narrow tools through document.modelContext.registerTool(...) : \n\n \n read the current case \n set or revise the claim \n add evidence \n identify conflicts \n evaluate the current claim revision \n export the versioned record \n \n\n The human and the agent operate on the same application state. The agent does not maintain a hidden parallel case, and the human does not have to trust a black-box conclusion. \n\n Distillation Protocol: the governance boundary \n\n Proof Gate applies a two-way Distillation Protocol at the boundary between the web and the governed case. \n\n Inbound: raw user input, tool output, and external observations are converted into structured evidence with provenance, revision binding, uncertainty labels, and explicit source roles before they enter the case. \n\n Outbound: internal evaluations and proposed actions are converted into scoped, inspectable outputs. Evidence-derived content is marked as untrusted, and no raw external statement becomes authority merely because an API, tool, user, or model asserted it. \n\n This prevents four common failures: \n\n \n prompt or content injection becoming governance state \n API responses being mistaken for independently verified reality \n AI conclusions being silently promoted to facts \n stale or contradictory evidence being overwritten instead of preserved \n \n\n The anti-magic rule is: I do not know yet, and here is exactly what evidence would resolve it. \n\n Global Compass signature \n\n Proof Gate follows the Global Compass design philosophy: \n\n SEE REALITY → PRESERVE EVIDENCE → UNDERSTAND RELATIONSHIPS → SEPARATE CAPABILITY FROM AUTHORITY → VERIFY WHAT ACTUALLY HAPPENED → LEARN WITHOUT REWRITING HISTORY \n\n In this application that means: \n\n \n evidence is bound to explicit claim revisions \n duplicate source families do not manufacture independence \n context records do not inflate support or refutation confidence \n unknown dates remain unknown and future dates are rejected \n contradictory evidence stays visible instead of being silently overwritten \n only HTTP/HTTPS evidence URLs are accepted \n evidence-derived WebMCP outputs are marked as untrusted content \n conflicts are aggregated and the evidence ledger is bounded \n the evaluator does not claim to independently establish truth \n \n\n Better human + agent collaboration \n\n Before WebMCP, an agent interacting with a case workspace has to reverse-engineer controls and reconstruct application state from the page. With WebMCP, the application exposes the actual operations and schemas directly. \n\n The division of labor is explicit: \n\n Human: frames the claim, inspects evidence, corrects context, challenges conclusions, and retains authority over meaningful decisions. \n\n Agent: structures evidence, detects conflicts, evaluates the current revision, and prepares an export. \n\n Application: deterministically enforces revision boundaries, validates inputs, and preserves the lineage both sides can inspect. \n\n The agent can therefore be useful without becoming an unaccountable source of truth. \n\n Reality Triangle \n\n Proof Gate distinguishes three states instead of collapsing them: \n\n \n Intended: what the claim or decision asks us to establish \n Reported: what a source, tool, or provider says happened \n Observed: what the accumulated evidence actually supports \n \n\n Success is not established merely because a tool returned success or a model produced a confident answer. \n\n Implementation \n\n The WebMCP layer calls the same pure JavaScript evidence engine used by the visible human UI. Tool calls and UI actions mutate the same state. Where supported, the application also checks getTools() enumeration after registration. \n\n The evaluator is deliberately modest. Thresholds and source-family grouping are transparent demo heuristics rather than claims of calibrated universal truth. \n\n Scope \n\n Proof Gate is deliberately one focused web application, not an AI backend disguised as a hackathon entry. The demonstration is shared application state: explicit schemas for the agent, visible and revisable evidence for the human, deterministic evaluation, a governed boundary, and a versioned record they can inspect together. \n\n Accountable intelligence, not merely intelligent agents. \n\n \n\n \n Built With \n\n base44 chatgpt css github html javascript webmcp \n \n\n \n Try it out \n\n \n \n \n preview-sandbox--6a958777023cfbafb329bcee.base44.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Nathan Poinsette \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n Founder and independent AI builder creating evidence-first agent systems and WebMCP tools for transparent human-AI collaboration. \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Nathan Poinsette \n started this project\n \n —\n \n 2 days ago \n \n \n\n
