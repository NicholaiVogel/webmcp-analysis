Zero site setup. \n\n WebMCP lets agents use a site as tools instead of clicking through the UI. That only works if someone builds the tools. Every site is different — hand-writing and maintaining that for the whole web is the real bottleneck. We flipped it: the person who needs agent tools shouldn’t wait on every company to ship WebMCP. \n\n What it does \n\n Site2WebMCP is a Chrome extension (also available as an agent skill) that reads the forms and buttons already on a live page and exposes them as WebMCP tools. An agent can then run real workflows — search, add to cart, checkout, and so on — without browser control and without the site owner implementing anything. \n\n How we built it \n\n \n A simple webpage with two demo modes and WebMCP for auto-setup of demo 1 — a playground only. The product generates WebMCP for any external site. \n Chrome MV3 extension: discover forms and primary actions from the live DOM, plus registerTool where needed. \n An agent skill that does the same job as the extension — inject into the page, discover DOM actions, register them as WebMCP. \n \n\n Challenges \n\n Getting from “tools appear” to “an agent actually completes a workflow” was the hard part — especially validating the agent-side path, not just the discovery UI. The runtime still leans on e-commerce-shaped heuristics; proving this beyond that shape is the next fight. Hand-written WebMCP will always be sharper for a given site — this is WebMCP for sites that never shipped it, replaceable when they do. \n\n ChatGPT Desktop’s built-in browser is read-only: no extensions, no injected scripts. That blocks dynamically generated WebMCP there. \n\n Chrome Web Store review is slow, so the extension isn’t installable from the store yet. \n\n What’s next \n\n \n Use site JavaScript to find server requests and expose them as tools, with descriptions of what those functions do. \n Crawl support centres and docs for how to use the site, then turn that into tools and skills. \n Use llms.txt to extract tools or workflows (chains of tool calls). \n Use an external or browser-built-in LLM to identify workflows on a site and turn them into tools and skills. \n Measuring the speed and tokens savings compared to a vanila browser use that does clicks. \n \n\n \n\n \n Built With \n\n chrome grok-bot javascript \n \n\n \n Try it out \n\n \n \n \n GitHub Repo \n \n \n \n youtu.be \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Viacheslav Tradunsky \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n 1 \n \n \n\n\n \n 1 person likes this:\n \n\n \n \n \n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Viacheslav Tradunsky \n posted an update\n \n —\n \n 2 days ago \n \n \n\n Please watch with audio.
