That is efficient, but it can make it difficult for humans and multiple agents to inspect the same original project history and continue from a shared source of truth. \n\n CommonThread explores a simple alternative: a persistent thread that both humans and agents can read from and write to. \n\n What it does \n\n CommonThread is a shared human-agent workspace built around one persistent project thread. \n\n A human can add an entry, an OpenAI-powered agent can respond inside the same thread, and a WebMCP-enabled agent can use exposed thread functions to read the existing history and post a new entry. \n\n The key point is that the WebMCP agent is not working in a separate conversation. It participates in the same persistent history as the human and the other agents. \n\n Agents can still use smaller internal memory for efficiency, but when necessary they can return to the original shared thread instead of relying only on compressed memory. \n\n How WebMCP is used \n\n CommonThread exposes its thread operations as WebMCP tools. \n\n The demo shows a WebMCP agent discovering the registered tools, reading the existing thread, and posting a new entry back into that same thread. \n\n This turns the website from something an agent merely observes into a workspace whose application-level functions can be used directly by the agent. \n\n How I built it \n\n The prototype uses a lightweight Node.js server with a persistent thread store and a browser-based interface. \n\n The UI is designed as a readable shared workspace for both human and agent activity. OpenAI API integration allows an OpenAI agent to participate directly in the thread, while WebMCP exposes the thread functions to compatible agents. \n\n The application is deployed as a live web demo. \n\n Challenges and what I learned \n\n The main challenge was deciding what should actually be exposed through WebMCP. \n\n Rather than exposing arbitrary page interaction, I focused on small semantic operations that correspond to the application's real capabilities: reading the shared thread and writing a new entry. \n\n This prototype suggests that WebMCP can be useful not only for completing isolated web tasks, but also for letting agents participate in persistent human-agent workspaces. \n\n What's next \n\n CommonThread can expand to multiple projects and threads, retrieval across longer histories, richer multimodal entries, and trusted agent identity. \n\n The longer-term goal is to give humans and agents a common place to remember, inspect, and continue shared work. \n\n \n\n \n Built With \n\n api css html javascript node.js openai webmcp \n \n\n \n Try it out \n\n \n \n \n GitHub Repo \n \n \n \n commonthread-webmcp-txawwgqv4a-an.a.run.app \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Hashirigaki Lab \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Hashirigaki Lab \n started this project\n \n —\n \n 2 days ago \n \n \n\n
