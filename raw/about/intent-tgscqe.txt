But sometimes the hardest part is figuring out what we actually want to do in the first place. \n\n That became the idea behind INTENT — a workspace where the human and the AI can work on the intent itself before jumping into execution. \n\n How I Built It \n\n I built INTENT as a Next.js web app with a structured workspace for an evolving intent. Instead of keeping everything inside a chat, the application keeps track of things like intent nodes, decisions, actions, and open questions. \n\n The interesting part for this challenge was connecting that workspace to AI agents through WebMCP. \n\n I exposed six tools that let an agent work with the actual application state: \n\n \n "inspect_intent" \n "add_intent_node" \n "focus_attention" \n "surface_contradiction" \n "propose_intent_evolution" \n "fork_intent" \n \n\n These aren't just functions that return text. They are connected to the workspace, so when an agent uses them, the changes can be reflected in the UI. \n\n What I Learned \n\n The biggest thing I learned was that agent interaction feels different when the agent can actually interact with the application instead of only generating a response. \n\n Designing the tools also made me think carefully about what an agent should be allowed to do. I wanted the human to remain in control while still giving the agent enough access to be genuinely useful. \n\n I also learned a lot about the practical side of WebMCP — especially tool registration, connecting tools to application state, and testing the experience in the browser. \n\n Challenges \n\n The main challenge was getting the WebMCP integration working with the current API. My initial implementation used an older registration pattern, which caused the tools to fail during registration. \n\n I had to update the implementation to the current "ModelContext" API and make sure the tools were registered correctly without causing repeated registrations during React development and refreshes. \n\n Another challenge was making the tools useful enough to represent real actions in the workspace rather than just creating a collection of demo functions. \n\n What's Next \n\n INTENT is still an early version, but the direction I find interesting is giving agents more meaningful ways to participate in applications while keeping the human in control. \n\n For me, WebMCP makes that interaction feel much more direct: the agent doesn't just talk about the workspace — it can actually work with it. \n\n \n\n \n Built With \n\n agentic agents ai apis generative human-ai javascript next.js react typescript web webmcp \n \n\n \n Try it out \n\n \n \n \n intent-1xb6z1wf4-princex031.vercel.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Prince P. \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n Maverick \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Prince P. \n started this project\n \n —\n \n 2 days ago \n \n \n\n
