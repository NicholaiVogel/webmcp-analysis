engineering is becoming an important part of how people work with AI, but good prompts are often scattered across documents, chats, notes, and different AI tools. \n\n We wanted to build a place where prompts could be treated as reusable assets rather than disposable messages. \n\n That led to Prompt Lab — an agent-ready prompt library where humans can create, organise, improve, and reuse prompts, while AI agents can interact with the same library through WebMCP. \n\n What it does \n\n Prompt Lab helps users: \n\n \n Create and organise reusable prompts \n Group prompts into categories \n Build specialised AI agents \n Generate prompts through agent conversations \n Select and save useful prompts directly from the chat \n Search, update, and manage an existing prompt library \n \n\n With WebMCP, Prompt Lab also exposes structured actions to AI agents. \n\n Instead of an agent visually interpreting the interface and guessing which buttons to click, it can discover supported actions such as creating, searching, retrieving, or updating prompts and execute them directly through the website. \n\n This creates a shared workspace where both humans and agents can work with the same underlying prompt library. \n\n Why WebMCP \n\n Prompt Lab is a strong fit for WebMCP because the product contains many structured actions that are useful to both people and AI agents. \n\n Traditionally, an AI interacting with a website may need to rely on screenshots, DOM interpretation, or browser automation. \n\n WebMCP allows us to expose the capabilities of Prompt Lab explicitly. \n\n For example, an agent can understand that the application supports actions such as: \n\n \n search_prompts \n get_prompt \n create_prompt \n update_prompt \n delete_prompt \n create_agent \n get_agent_prompts \n \n\n This makes agent interactions more reliable, understandable, and efficient. \n\n It also creates a better user experience because a user can describe what they want naturally while the agent performs structured operations within Prompt Lab. \n\n How we built it \n\n Prompt Lab was built as a modern web application using React, TypeScript, Vite, and supporting backend/data services. \n\n We designed the product around two main experiences: \n\n \n A human-facing prompt management interface \n An agent-facing capability layer powered by WebMCP \n \n\n For the WebMCP implementation, we registered application capabilities using document.modelContext.registerTool(...) . \n\n Each tool includes a clear description, input schema, validation, execution logic, and structured output. \n\n Where possible, the WebMCP tools reuse the same underlying application logic as the normal user interface rather than creating a completely separate system. \n\n This means both humans and agents operate on the same prompt data and workflows. \n\n We also designed the agent chat so generated prompts can become interactive content directly inside the AI response. Users can select the prompts they want and save them into their library without switching to a separate workflow. \n\n Challenges we faced \n\n One of the biggest challenges was understanding how WebMCP should fit into an existing product architecture. \n\n It was tempting to treat WebMCP as a separate integration layer with duplicated application logic, but we learned that a better approach is to expose existing product capabilities through shared services. \n\n We also faced challenges around: \n\n \n Detecting whether WebMCP was available in the current browser environment \n Preventing duplicate tool registration during development \n Keeping the application functional in browsers without WebMCP support \n Designing tool schemas that were simple for agents to understand \n Making agent-generated prompts interactive without duplicating the same content elsewhere in the UI \n Maintaining a consistent experience between human-driven and agent-driven actions \n \n\n Another challenge was designing the demo itself. We wanted to demonstrate WebMCP as more than browser automation, so we focused on showing an agent interacting with Prompt Lab through clearly defined application capabilities. \n\n What we learned \n\n The project changed how we think about websites designed for AI agents. \n\n A website no longer has to expose functionality only through buttons, forms, and visual interfaces. \n\n With WebMCP, applications can expose their capabilities directly to agents while still maintaining a normal interface for humans. \n\n We learned that the strongest implementation is not about adding as many tools as possible. It is about exposing a small set of useful, well-defined actions that map directly to real product capabilities. \n\n We also learned that designing for humans and agents together creates new product possibilities. Instead of replacing the human interface, the agent becomes another way of interacting with the same application. \n\n What's next \n\n We would like to continue developing Prompt Lab into a broader collaborative prompt workspace. \n\n Future improvements could include: \n\n \n Prompt version history \n Shared team libraries \n Agent-created prompt collections \n Prompt performance and evaluation data \n More advanced search and filtering \n Additional WebMCP capabilities \n Cross-agent prompt sharing \n Collaborative workflows where humans review and approve agent-generated changes \n \n\n Our broader goal is to explore what software looks like when websites are designed from the beginning for both humans and AI agents . \n\n \n\n \n Built With \n\n chatgpt openai supabase typescript vite \n \n\n \n Try it out \n\n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n Ex: I worked on the development of the UX UI and the backend & Supabase.
