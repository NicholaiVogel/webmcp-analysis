Decisions didn't. \n\n I kept seeing the same mess: someone ships a little tool for fun, then hits auth or scraping and freezes on build vs buy. ChatGPT will write you a confident paragraph. Ask again and you get a longer paragraph. You're still doing the math in your head. \n\n I didn't know this domain well when I started. I just didn't want another essay. I wanted the page to move when the agent did something, and I wanted to see the call in a log so it couldn't just agree with me. \n\n What it does \n\n BuildVsBuy.ai is a decision canvas in the browser. You and the agent share one model. Nine WebMCP tools. Cards, weights, a future-stress banner, an override with a gap and a liability list. \n\n If it says Build dropped, the log has to show a rerank. If the log didn't change, it guessed. \n\n The demo walk: \n\n \n Auth. You admit you're shipping a prototype fast. Build usually falls last. \n Switch to scraping. "What if HIPAA and 50k users?" That's a simulation. Baseline cards stay put. \n You still want to own the crawler. It pins Build, shows how far that is from the math, and lists what you're taking on. \n \n\n Numbers on the axes are my estimates for the demo. Not vendor quotes. Not financial advice. \n\n How I built it \n\n Vite, vanilla JS, no backend. Vercel. \n\n Tools live in src/webmcp.js ( document.modelContext.registerTool ). Math lives in src/decision.js . The UI just redraws a snapshot. Human sliders and agent calls hit the same execute path, tagged human or agent so the log isn't lying about who did it. \n\n I also wrote two smoke scripts so I wasn't debugging this only through ChatGPT's mood that day. \n\n What I learned \n\n Soft instructions do not save a live agent. It will skip the rerank. It will invent cards. It will pin Buy because some flag wasn't set. \n\n The stuff that actually held on camera was refusing the bad call in the tool itself. Prompt text is decoration. \n\n Also: WebMCP is useful when the page is a real store, not when you ask the model to "look at the screenshot." \n\n Challenges \n\n Recording almost killed me. Same session, Prompt 2 did the right tool and nothing moved because the weight was already 10 so we skipped rerank. Prompt 4 looked like Buy won because override wouldn't pin Build unless core IP was already true. I fixed both in code. I was not going to sit there and whisper hints on camera. \n\n Keeping simulate as a projection (not rewriting live context) was another fight. Agents love to "just set HIPAA" and pretend the future already happened. \n\n I cut saved accounts, live pricing, and a third industry. Ten days. The loop had to work: ask, tool, visible state, honest disagreement. \n\n \n\n \n Built With \n\n chatgpt css html javascript vercel vite webmcp \n \n\n \n Try it out \n\n \n \n \n buildvsbuy-ai.vercel.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Param Mehta \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Param Mehta \n started this project\n \n —\n \n 2 days ago \n \n \n\n
