Agents already talk about housing well, but they usually fail when they have to click through a UI built for a mouse. WebMCP flips that: the site can expose the real actions (search, pin, compare, hold a viewing, draft and submit an offer) as structured tools on the same live page the person is looking at. \n\n Nest is that idea made concrete — a London rental board where you and your agent share one session, one map, and one shortlist. \n\n What it does \n\n Nest is an agent-native flat hunt: \n\n \n Browse seeded London listings on a live map \n Pin and compare homes side by side \n Propose and hold viewing slots (agent proposes; you confirm commits) \n Draft and submit an offer letter from the shortlist \n Inspect board state and registered WebMCP tools on an in-app Agent tools panel \n \n\n You steer in plain English in ChatGPT; Nest’s site tools update the UI in real time. Anything consequential (holding a viewing, submitting an offer) is a non-read-only tool so the browser can require confirmation. \n\n How we built it \n\n \n Vite + React + TypeScript for a fast, deployable SPA \n Zustand store shared by the human UI and every WebMCP execute handler (one source of truth) \n Leaflet map with OSM tiles for the spatial board \n WebMCP via document.modelContext.registerTool (with navigator.modelContext fallback), feature-detected, registered on the top-level page \n Seeded demo listings (no paid APIs) so judges can try the full path offline-friendly \n Built with Codex \n \n\n Core tools include search_listings , get_listing , pin_listing / unpin_listing , compare_shortlist , propose_viewings , hold_viewing , cancel_viewing , draft_offer , submit_offer , get_board_state , and set_preferences . \n\n Challenges \n\n \n Same-state collaboration — agent tools and UI clicks must never drift. We solved this by routing both through one store. \n Read vs commit — WebMCP’s value is trust. Marking search/compare read-only and viewings/offers as side-effecting was deliberate product design, not just annotations. \n Demo realism without backends — landlords, holds, and offers are simulated with structured JSON so the agent can reason, while the product still feels complete. \n Judges’ path — a clear happy path (search → pin → compare → hold viewings → draft → submit) plus a tools panel so WebMCP leverage is obvious in under three minutes. \n \n\n What we learned \n\n WebMCP isn’t “MCP in the browser” as a slogan — it’s best when the agent and the human must see the same thing : a map marker lighting up, a shortlist changing, an offer panel filling. Housing is a perfect stress test because the workflow is multi-step, spatial, and full of confirm-worthy actions. \n\n Try the demo path \n\n \n Open Nest in ChatGPT’s in-app browser (or Chrome with WebMCP testing enabled) \n Ask: “Find 2-beds under £2200 in Zone 2 that allow pets, pin the best three, compare them, hold two viewings, and draft an offer for my favorite.” \n Watch the board update; confirm when the browser asks on commits \n \n\n \n\n \n Built With \n\n codex \n \n\n \n Try it out \n\n \n \n \n omercelik.github.io \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Serdar Murat ÇELİK \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n\n \n Abdulhamit Mabocoglu \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n\n \n Mustafa Tunç \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n\n \n Omer Celik \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n 1 \n \n \n\n\n \n 1 person likes this:\n \n\n \n \n \n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Omer Celik \n started this project\n \n —\n \n 3 days ago \n \n \n\n
