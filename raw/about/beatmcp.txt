I wanted a more natural workflow where a person keeps creative control while an agent can contribute directly inside the same music workspace. \n\n The core question was: what if an agent could use a music-making web app through structured controls instead of guessing how to click through the interface? \n\n What it does \n\n BeatMCP is a four-bar, 64-step beat canvas where a person and an agent can build an instrumental together. \n\n The studio includes drums, bass, piano, guitar, bell, keys, pad, and lead lanes. Users can set tempo and key, program steps manually, and shape a beat in a shared timeline. \n\n Agents can use WebMCP tools to: \n\n \n read the current pattern and musical state \n set tempo, key, and scale \n write drum, bass, melody, and chord patterns \n create chords on Piano, Keys, and Pad lanes \n humanize timing and velocity \n reset a beat, start playback, and begin a live composition session \n list playable instruments and save/reuse patterns \n \n\n A key feature is live composition. When an agent writes a new layer, BeatMCP auditions the first new sound in sequence—such as kick, bass, chords, then melody—while the changed steps flash on the grid. This makes the agent's creative process visible and audible instead of hiding everything until the end. \n\n How we built it \n\n BeatMCP is built with Next.js, React, TypeScript, Zustand, Tone.js, and the @mcp-b WebMCP libraries. \n\n \n Next.js and React power the browser experience. \n Zustand keeps the beat, tracks, tempo, key, and pattern state synchronized. \n Tone.js synthesizes drums and instrument voices in the browser. \n WebMCP exposes structured tools directly from the page so agents can work with the same musical controls as users. \n The studio uses a 64-step master timeline so a beat can develop across four bars rather than being limited to one short loop. \n \n\n Challenges we ran into \n\n The hardest part was making the human-agent collaboration feel trustworthy in real time. \n\n Browser audio needs an initial user gesture, so we designed the flow around one Start click before an agent can begin live composition. We also had to prevent overlapping transport loops, keep WebMCP tool discovery fresh after page reloads, and make agent edits understandable through visual flashes and queued sound auditions. \n\n Another challenge was avoiding a traditional “AI generates everything” interaction. We wanted the agent to be musically useful without replacing the producer's judgment. \n\n What we learned \n\n We learned that WebMCP is most compelling when the agent has precise, meaningful controls and the person can immediately understand the consequences of each action. \n\n For music, that means an agent should not just return text or a finished file. It should be able to set a key, place a kick, write a chord, audition a sound, and respond to human feedback in the same live workspace. \n\n Why WebMCP \n\n BeatMCP becomes meaningfully better because agents can use the web app directly through structured tools. The agent reads the real state of the beat and changes the same instrument lanes the person sees and hears. \n\n That creates a collaborative workflow: the agent handles musical structure and repetitive programming, while the person decides what feels right. \n\n \n\n \n Built With \n\n agents ai api audio generative mcp-b music next.js react tech tone.js typescript vercel web webmcp zustand \n \n\n \n Try it out \n\n \n \n \n beatmcp.idoevergreen.me \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n ido evergreen \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n ido evergreen \n started this project\n \n —\n \n a day ago \n \n \n\n
