What it does MOHAE is a mobile-first Korea place discovery product. A traveler can swipe to save or pass places, inspect candidates on a Naver map, and ask a WebMCP Agent to search and render visible candidate scenes. For a shared trip, a host creates an expiring invite link. Travelers join from their own devices, make independent save/pass and map choices, tell their own Agent natural-language needs, and mark their selection complete. The host Agent then reads the accumulated evidence and proposes an approximate ordered plan. Demo flow Open MOHAE and explore Korea place cards by saving or passing. Inspect candidates on the map and save useful places. Create a shared trip and send the expiring invite link. Join from another device, make independent choices, and add a raw trip note through an Agent, such as ‘must-visit food’ or ‘less walking.’ Mark that traveler’s selection complete. Ask the host Agent to read the room context and present an ordered candidate scene. Switch to route mode to see the Agent-supplied order numbered with a guide line. Why WebMCP WebMCP lets an Agent read and change the currently visible shared product state while humans continue choosing in the UI. The browser page is not just a chat attachment: it exposes explicit tools for catalog search, scene rendering, preserving traveler language, and reading room evidence. Agent actions remain visible and inspectable in the same interface the group is using. MOHAE deploys four WebMCP tools with document.modelContext.registerTool : search_mohae_places : read-only catalog search. present_exploration : renders ordered deck/map scenes and can publish them to the shared room. add_group_trip_note : preserves a joined traveler’s raw natural-language note. get_group_trip_context : reads travelers’ save/pass/map choices, notes, readiness, anchors, and candidates. Provenance and scope Agent-researched external candidates stay provenance-tagged and separate from catalog admission. Route mode displays the Agent-supplied order and a guide line; it does not claim route optimization or travel-time calculation. MOHAE does not provide booking, live queue data, or full realtime presence. How we built it The product uses vanilla JavaScript, HTML, and CSS. WebMCP tools are registered with document.modelContext.registerTool . Supabase Postgres stores shared-trip data behind protected RPCs and row-level security, with append-only room events. The app is deployed on Vercel and uses the Naver Maps JavaScript SDK. Challenges and lessons The central design challenge was making Agent side effects visible, scoped, and auditable while several people continue using ordinary UI controls. We learned that coordination works better when the product preserves behavioral evidence and each traveler’s original words instead of compressing everyone into a single averaged profile.
