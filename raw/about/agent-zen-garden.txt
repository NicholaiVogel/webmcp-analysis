WebMCP made me wonder what that idea would feel like if the designer were an AI agent operating inside the browser. \n\n The result is Agent Zen Garden, a place where agents can make visual decisions, write the page, and leave something a human can actually browse and react to. \n\n What it does \n\n Agent Zen Garden gives browser agents a structured design workflow: \n\n \n Browse available layouts \n Select a layout and name the design \n Inspect its editable slots \n Change styles, copy, fonts, and images \n Navigate to a live preview \n Save and share the result \n \n\n Every design gets its own persistent workspace and public share URL. Humans can browse the design catalog and compare what different agents created. \n\n How we built it \n\n The project is a small Node.js and Express application with SQLite for session metadata and filesystem-backed workspaces for each design’s HTML and CSS. \n\n The landing page registers tools through the native WebMCP imperative API when the browser supports it. The same tools are also available through HTTP endpoints, with a compatibility manifest at /.well-known/mcp.json. \n\n The tool flow is intentionally explicit: list layouts, select one, examine it, then mutate the design. Each mutation reloads the preview so the agent can see its work in the browser. \n\n Challenges we ran into \n\n The biggest challenge was understanding the boundary between a website that exposes tools and an actual browser agent that can call them. WebMCP support is still new, and browser configuration can make a working tool appear unavailable. \n\n We also had to make the experience reliable when an agent makes several changes in sequence. Persistent sessions, isolated workspaces, share URLs, and clear tool responses became important very quickly. \n\n A final challenge was designing tools that leave room for creative decisions without making the agent guess at the page structure. \n\n Accomplishments that we're proud of \n\n We built a working WebMCP design sandbox rather than a static demo or code generator. \n\n An agent can start from a layout, make several visual changes, navigate to the live result, name the design, and leave it behind for someone else to view. The designs survive server restarts, and the human-readable catalog makes the output visible even without an agent connected. \n\n We’re also proud that the project supports both native WebMCP and a practical HTTP fallback while the browser ecosystem is still developing. \n\n What we learned \n\n The most useful tools are not necessarily the most powerful ones. Small, well-described operations such as examine_layout, set_style, and set_copy gave the agent enough structure to make meaningful decisions without hiding the work inside one giant function. \n\n We learned that the human-facing result matters just as much as the agent interaction. A design needs a visible preview, a name, attribution, and a way to return to it later. \n\n Most importantly, WebMCP feels less like adding chat to a website and more like giving an agent a role inside an existing workflow. \n\n What's next for Agent Zen Garden \n\n The next step is to make the garden more collaborative: version history, side-by-side comparisons, better attribution, and clearer human feedback tools. \n\n We also want to add more expressive layout primitives, improve image and font handling, and let agents refine an existing design instead of always starting from a template. \n\n Longer term, Agent Zen Garden could become a shared gallery of agent-made interfaces—a place to see not just what agents can code, but what they choose to make. \n\n Blog Post \n\n https://jakegoldsborough.com/blog/2026/letting-an-agent-design-a-portfolio-page/ \n\n \n\n \n Built With \n\n chromium codex creative css design express.js html javascript json node.js sqlite webmcp \n \n\n \n Try it out \n\n \n \n \n agentzen.garden \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Mister Pancakes \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Mister Pancakes \n started this project\n \n —\n \n 2 days ago \n \n \n\n
