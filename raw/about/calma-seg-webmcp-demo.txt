I wanted to explore how people and browser agents could work together to make safe, prewritten information easier to discover while maintaining clear clinical, privacy, and emergency boundaries. \n\n What it does \n\n CALMA-SEG is a bilingual English-Spanish WebMCP demonstration. People can use its ordinary interface to: \n\n \n Filter short psychoeducational exercises by category and duration. \n View complete exercise instructions and safety notes. \n Find general human-support options based on a self-selected urgency level. \n Read the demo’s safety and privacy limitations. \n \n\n A compatible browser agent can discover and invoke the same capabilities through four WebMCP tools: \n\n \n list_wellbeing_exercises \n show_wellbeing_exercise \n find_human_support_options \n explain_safety_limits \n \n\n Every successful agent call produces a visible change in the human interface. The page updates its filters, displayed content, language, or Agent Activity panel so that the person can see what the agent did. \n\n How I built it \n\n I built CALMA-SEG as a static Vite application using semantic HTML, responsive CSS, and vanilla JavaScript. \n\n The tools are registered with the WebMCP imperative API through document.modelContext.registerTool . Each tool has a name, description, JSON input schema, validated parameters, and a predictable text result. \n\n All educational content is fixed, synthetic, and stored locally in the application. The project has no backend, database, authentication, analytics, cookies, local storage, or external AI API. It is deployed through Netlify from a public GitHub repository. \n\n Why WebMCP \n\n Without WebMCP, a browser agent would need to interpret headings, dropdowns, cards, and buttons from the DOM and infer their meaning. With WebMCP, the website declares its capabilities directly. \n\n For example, an agent can request a Spanish exercise with a maximum duration of three minutes through validated parameters. The website then returns a structured result and synchronizes the visible human interface with that request. \n\n This creates a more predictable and transparent collaboration between the person, the browser agent, and the website. \n\n Challenges \n\n The main challenge was designing tools that were useful without crossing clinical or privacy boundaries. CALMA-SEG does not diagnose, provide therapy, recommend medication, infer a person’s mental state, or function as an emergency service. \n\n Another challenge was ensuring that agent actions were never silent. The exercise-listing tool originally returned information only to the agent. I revised it so that it also updates the visible filters, exercise list, language, and Agent Activity panel. \n\n I also had to account for WebMCP’s experimental browser availability. When WebMCP is unavailable, the page reports this honestly while keeping the complete manual interface functional. \n\n What I learned \n\n I learned how WebMCP can turn an ordinary website into an explicit set of safe, typed capabilities for browser agents. I also learned that agent-friendly design requires more than returning data: actions should remain understandable and visible to the person using the page. \n\n The project reinforced the importance of input validation, progressive enhancement, bilingual consistency, privacy by design, and careful safety language. \n\n What’s next \n\n Future work could include accessibility and usability testing, additional reviewed educational content, and evaluation of how clearly people understand agent actions and safety boundaries. \n\n Any research or institutional pilot would require separate authorization, ethical and legal review, data-protection safeguards, informed consent, and professional supervision. This hackathon submission is an independent technical demonstration, not a clinical service or institutional implementation. \n\n \n\n \n Built With \n\n accessibility bilingual css3 github html5 javascript json netlify vite webmcp \n \n\n \n Try it out \n\n \n \n \n lively-pika-916d97.netlify.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Lidia Maya \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Lidia Maya \n started this project\n \n —\n \n 4 days ago \n \n \n\n
