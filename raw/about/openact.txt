A confirmation-first WebMCP agent for screen reader users. The screen reader stays the interface; WebMCP is the actuator. Like Comment Story Updates Inspiration WebMCP can expose higher-level page actions, but putting agent-oriented tools into the accessibility tree would make them appear as page content to screen readers. OpenAct explores the indirect model instead: an agent can reason about available actions while the screen reader remains the user's interface. What it does An NVDA user describes an action in natural language. OpenAct discovers native WebMCP tools, or conservatively infers tools when native tools are unavailable. It proposes exactly one call, presents an accessible and editable confirmation dialog, executes only after explicit confirmation, and speaks the result. The demo is a fictional Northstar City permit workflow with two equivalent routes: /baseline : a keyboard and screen-reader-operable form without WebMCP. /instrumented : the same form with four native tools registered through document.modelContext . The tools are save_property_details , save_project_details , review_application , and submit_application . Why WebMCP OpenAct uses WebMCP as an action layer rather than another interface a screen reader must navigate. Native tools give an agent structured actions and schemas while the user keeps the familiar NVDA interaction model. This makes higher-level assistance possible without placing agent-only content or metadata in the accessibility tree. How it works One shared action definition generates both the accessible HTML form and each WebMCP tool. A parity test fails the build if their labels, required fields, enums, or schemas drift. The Chrome MV3 extension discovers page tools and enforces authorization. The NVDA add-on owns the reasoning layer, confirmation dialog, settings, speech, and a standard-library localhost relay. The relay binds to 127.0.0.1 and pairs through a one-time code. At runtime, the NVDA add-on uses the OpenAI Responses API with a configurable model that defaults to gpt-5.4-mini . It sends bounded context with store: false and requires a strict call , clarify , or refuse decision. The model can propose an action, but it cannot authorize or execute one. Safety and accessibility Every call requires confirmation. Unknown reversibility is treated as irreversible. HMAC covers the call ID, tool name, timestamp, and canonical arguments. Expired, replayed, invalid, or retargeted confirmations are rejected. A kill switch blocks new requests and clears queued work. The autobridge fails closed on ambiguous, stale, unnamed, or unsupported controls. Telemetry is metadata-only and excludes utterances, arguments, form values, API keys, and unrestricted URLs. No agent-oriented text or metadata is added to the accessibility tree. The visible form remains fully usable without OpenAct. Verification The repository includes unit, property, cross-language, browser, accessibility, native Chrome, coverage, and mutation checks. Native verification drives all four tools in installed Chrome 151 with WebMCP enabled and no injected modelContext . Axe reports zero automated violations on the tested routes and states. Honest limits WebMCP does not make an inaccessible website accessible. It exposes actions, not missing labels, keyboard support, structure, or comprehension. This prototype has not been validated with disabled participants and makes no measured task-completion claim. Northstar City and all demo data are fictional. The native page round trip is verified in Chrome. ChatGPT's in-app browser and the complete packed extension, relay, and installed NVDA path remain pending manual verification.
