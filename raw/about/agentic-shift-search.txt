We achieve this by structuring our content and data, implementing relevant schema markup, and actively exploring Model Context Protocol (MCP) integrations. WebMCP felt like a perfect enabler for making interactions with AI agents quicker, smoother, and completely frictionless. We couldn't wait to try it. \n\n What it does \n\n It allows agents to interact with the API endpoint including available clinician shifts on nursa.com. Instead of searching the shifts manually with the UI, we allow agents to use all our filters inside of WebMCP tools: \n\n search_shifts - searches by license, state, specialty, minimum hourly pay, date range, and free text; returns up to 10 compact results. Data only - it never touches the list on screen. \n\n apply_filters - takes the same filter inputs and writes into the shared filter store, so the visible list re-renders with the agent's choice. This is the human+agent moment the project is built around. \n\n How we built it \n\n We created a simple page displaying shifts available on our website and allowing for a filter selection. We added a script that registers WebMCP tools and references our endpoint. We tested it with WebMCP Model Context Tool Inspector \n\n Challenges we ran into \n\n 1) WebMCP is really new. Right now it only works in ChatGPT's desktop app, and it doesn't behave the same way twice. The same prompt might work on one try and fail on the next. We spent a surprising amount of time just rewording tool descriptions until the model used them the way we wanted.\n2) Dates gave us the most trouble. First a timezone bug: someone asked for shifts "from Sep 7th" and the filter got set to Sep 6th. Then ChatGPT told a user that shifts were "in 2027", because our responses only said "Sep 5" with no year and it guessed. We ended up sending full timestamps with the year and timezone, and kept the pretty labels just for display.\n3) The AI would answer with stale results. Asking "RN shifts" and then "RN shifts in California" sometimes returned the first answer again, because the second search didn't properly reset the state from the first one. \n\n Accomplishments that we're proud of \n\n Quick implementation of a powerful feature we can later roll out throughout our platform. \n\n What we learned \n\n We weren't familiar with WebMCP before. Building this app gave us hands-on experience with its architecture, tool registration, and local testing workflows, giving us a clear view of both its massive potential for agentic search and its current limitations. \n\n What's next for Agentic Shift Search \n\n Further improvements to existing tools like expanding them with shift details, adding new tools and potential rollout to our main search pages, e.g. https://nursa.com/jobs/shifts \n\n \n\n \n Built With \n\n json typescript webflow webmcp \n \n\n \n Try it out \n\n \n \n \n nursa.com \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Adam Sidorczuk \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n\n \n Tiago Satur \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Adam Sidorczuk \n started this project\n \n —\n \n 3 days ago \n \n \n\n
