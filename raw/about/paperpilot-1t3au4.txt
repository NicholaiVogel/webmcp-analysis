The result? The LLM hallucinates methodologies, loses track of citations, and breaks LaTeX math formatting. \n\n \n I realized that LLMs don't need better prompts—they need ==Agent-Native infrastructure==. \n \n\n Why this is a perfect fit for WebMCP \n\n Before WebMCP, LLMs were blind to the user's UI. By implementing WebMCP, I exposed 13 strictly typed tools directly to the agent. This creates a massive UX paradigm shift: \n\n \n [x] Zero Copy-Pasting: The agent fetches full-text HTML directly via extract_findings . \n [x] No More Hallucinations: The compare_papers tool forces the agent to read structured matrix data. \n [x] Synchronous Collaboration: When the agent calls draft_section , the manuscript in my React UI updates instantaneously. \n \n\n How I Built It: The Core Mechanisms \n\n I built PaperPilot using Next.js 14, React 18, and TypeScript, deployed seamlessly on Vercel. To make this production-ready, I engineered three core mechanisms: \n\n 1. The Zero-Backend Event Bus \n\n To achieve real-time UI synchronization without the latency of WebSockets, I implemented a decoupled event architecture. When ChatGPT executes a mutation tool:\n document.modelContext.registerTool({ name: "draft_section" }) \nIt triggers a pure async Next.js Server Action. This action mutates the local data store and emits a native DOM CustomEvent (e.g., paperpilot:outlines-changed ). The React UI listens to this bus and re-renders instantaneously. \n\n 2. Heuristic Extraction & Grammar-Aware Parsing \n\n Academic HTML is notoriously messy. To prevent context window pollution, I engineered an extraction algorithm that isolates methodology while discarding boilerplate (Appendices, References). The extraction logic E for a document D composed of sentences s i is defined as: \n\n E ( D ) = ⋃ i = 1 N s i subject to class ( s i ) ≠ "ltx_bibliography" \n\n Furthermore, naive sentence splitting ruins context by breaking on abbreviations like "e.g." or "et al." I parse sentences using a strict, grammar-aware Regex formula to guarantee abbreviation bypass:\n (?<=[a-z]{3,}[.!?])\\s+(?=[A-Z0-9]) \n\n 3. Math-Safe LaTeX Compilation \n\n ChatGPT frequently generates inline mathematical formulas, such as O ( log ⁡ d ) . If I blindly escaped reserved LaTeX characters (like _ or % ), it would break the math mode syntax. I engineered a custom AST-like parser that isolates $ and $ $ blocks, safely escapes rogue characters only in standard text strings, and then restores the math blocks. \n\n The agent also autonomously injects \\cite{} markers linked to a dynamically generated \\bibitem matrix, guaranteeing ==100% compilable Overleaf code==. \n\n The Proof: My 20-Paper Stress Test \n\n To prove PaperPilot isn't just a brittle hackathon demo, I built an automated stress test against 20 seminal AI papers (including Attention Is All You Need and Mistral 7B ). \n\n \n \n Metric \n Success Rate \n Truncation Errors \n \n \n \n Methodology Extracted \n 20 / 20 \n 0 \n \n \n Key Claims Extracted \n 20 / 20 \n 0 \n \n \n Limitations Extracted \n 20 / 20 \n 0 \n \n \n Conclusion Extracted \n 20 / 20 \n 0 \n \n \n\n What I learned & What's next \n\n I learned that strict typing in WebMCP inputSchemas is the absolute key to preventing agent hallucinations.
