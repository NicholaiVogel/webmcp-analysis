When a conversation ends, the next person or agent often has to reconstruct what happened, what decisions were made, and what work should happen next. \n\n Handoff explores a different model: a shared web workspace where humans and AI agents operate on the same project state. \n\n What it does \n\n Handoff gives a project a persistent shared state built around: \n\n \n goals \n open work \n evidence \n decisions \n activity \n the next handoff \n \n\n Humans interact with that state through the web interface. AI agents interact with the same underlying capabilities through WebMCP tools. \n\n An agent can inspect the current project, understand unfinished work, search existing evidence, contribute findings, propose results, record agreed decisions, complete work, and determine the next handoff. \n\n The key idea is simple: \n\n The conversation can end. The work doesn't. \n\n Why WebMCP \n\n Without WebMCP, an agent would need to infer how to use the interface by reading the page and manipulating UI elements. \n\n With WebMCP, Handoff exposes the application's meaningful actions directly as structured tools. \n\n The human UI and the agent tools operate on the same domain actions and shared state. WebMCP is therefore not an add-on to Handoff; it is what allows the application to become a genuine human-agent workspace. \n\n Human + agent collaboration \n\n A human can define a goal, add context, review evidence, and make important decisions. \n\n An agent can then pick up the project, determine what remains unfinished, inspect existing evidence, contribute work, and leave the project in a clean state for whoever comes next. \n\n The next worker can be the same person, another person, or another AI agent. \n\n Built for the WebMCP Challenge \n\n Handoff was created for the 2026 WebMCP Challenge as an experiment in agent-native web applications. \n\n The goal is to demonstrate that websites do not only need to be readable by agents — they can explicitly expose the actions and state that agents need to collaborate safely and effectively with humans. \n\n \n\n \n Built With \n\n ai-agents codex human-in-the-loop javascript next.js opencode react tailwind typescript webmcp \n \n\n \n Try it out \n\n \n \n \n handoff-ai-webmcp.netlify.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n Built the product concept, architecture, WebMCP integration, human-in-the-loop workflow, real OpenCode/Codex runtime orchestration, testing, and final submission. \n \n\n \n \n \n \n \n \n\n \n Julián Sánchez \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Julián Sánchez \n started this project\n \n —\n \n 2 days ago \n \n \n\n
