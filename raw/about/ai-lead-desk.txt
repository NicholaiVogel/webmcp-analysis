Browser agents that rely on guessing which visual control to click can be brittle, while sensitive final actions still require human judgment. \n\n AI Lead Desk was built to show a different model: give an AI agent a small set of structured WebMCP actions, keep every transition visible in the interface, and preserve a real human approval boundary. \n\n What it does \n\n AI Lead Desk turns one sales objective into a visible five-stage workflow: \n\n Find → Research → Qualify → Prepare Outreach → Human Approval → Pipeline \n\n ChatGPT can: \n\n \n find five matching companies, \n research the strongest candidate, \n qualify the lead against a defined target profile, \n prepare a personalized outreach draft, \n and move the lead into Pipeline only after explicit human approval. \n \n\n The outreach remains Draft / Not sent . The challenge version does not send email or WhatsApp messages. \n\n The current demo uses synthetic logistics and freight-forwarding companies in Dubai. They are demonstration data, not verified real prospects. \n\n How we built it \n\n AI Lead Desk is built with Next.js, React, and TypeScript. \n\n The application registers exactly five native WebMCP tools through document.modelContext.registerTool : \n\n \n search_leads \n research_company \n qualify_lead \n prepare_outreach \n add_to_pipeline \n \n\n The WebMCP tools and the visible UI use the same validated domain actions and application state. That means tool execution, lead stages, qualification results, approval state, and the Activity Log remain synchronized. \n\n For live execution, the application sends validated tool requests to a server-side Next.js endpoint. A secure n8n router handles the five known actions. The webhook URL and credential remain server-side and never enter the browser bundle. \n\n A deterministic DEMO_MODE fallback is also available for network-independent testing. \n\n Human + agent collaboration \n\n The agent handles the repetitive work: lead discovery, company research, qualification, and draft preparation. \n\n The human retains control where judgment and accountability matter. \n\n add_to_pipeline cannot be authorized by the agent itself. Approval must first be recorded through the visible Approve for pipeline interaction in the application. \n\n Clicking approval does not send outreach. It only authorizes the final Pipeline transition. \n\n Challenges \n\n The main challenges were: \n\n \n verifying native WebMCP discovery and execution in a real supported browser client, \n keeping agent actions and visible UI state on one shared workflow, \n enforcing a genuine human-controlled approval boundary, \n normalizing five typed actions through one secure n8n router, \n and making the draft-only outreach behavior unmistakable. \n \n\n Accomplishments \n\n \n Exactly five native WebMCP tools are exposed. \n A complete production workflow works from lead search through approved Pipeline transition. \n Atlas Freight Network scores 91/100, Grade A in the canonical demo. \n Human approval is enforced before the final transition. \n Outreach remains Draft / Not sent . \n Live n8n routing works in production. \n 42 automated tests across 10 files pass. \n Lint, TypeScript validation, and production build all pass. \n The full production E2E flow was verified successfully. \n \n\n What we learned \n\n Structured browser tools are more useful when they do more than expose actions. They also need strict contracts, shared application state, lifecycle cleanup, visible feedback, safe error handling, and clear authority boundaries. \n\n WebMCP lets the agent perform predictable actions without guessing how the interface works, while the human can still see and control the workflow. \n\n What's next \n\n The commercial direction is to connect verified company-data providers, customer-specific qualification criteria, and integrations with existing CRM or sales systems. \n\n Any future outreach-sending capability would require its own explicit review and authorization design. \n\n The challenge version intentionally remains focused on lead research, qualification, draft preparation, and human-controlled pipeline management. \n\n Data disclosure \n\n All company records and evidence shown in the current challenge demo are synthetic test data. No claim is made that the demo generated verified real leads or sent real outreach. \n\n \n\n \n Built With \n\n chatgpt n8n next.js node.js react typescript vercel webmcp \n \n\n \n Try it out \n\n \n \n \n ai-lead-desk-webmcp.vercel.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n Solo builder.
