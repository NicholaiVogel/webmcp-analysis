Before you shoot it. \n\n Inspiration \n\n I come from the world of film production in Morocco — a country that hosts\ndozens of international shoots every year with a vibrant local industry.\nYet I watched producers coordinate 10+ departments through spreadsheets,\nphone calls, and paper call sheets. A single weather change could trigger\nhours of re-planning calls. \n\n I asked: what if the producer's AI agent could do this coordination\ndirectly — deterministically, instantly, reliably? That question is\nexactly what WebMCP enables. ROYA (رؤية = "vision" in Arabic) gives every\nfilmmaker the vision of their entire production — from script to screen —\nbefore the camera rolls. \n\n What it does \n\n \n Script Analysis — paste a screenplay (Arabic/English/French); the\nagent calls analyze_script to extract scenes, cast, props, locations,\nand per-department notes. \n Weather-aware scheduling — get_weather_forecast +\n generate_schedule build a calendar that auto-moves outdoor scenes\nindoors when rain probability is high. \n Department task board — assign_task distributes work to 8 departments. \n Live status dashboard — get_production_status returns completion\nrates and weather alerts. \n Call sheet export — export_call_sheet produces the daily briefing. \n Scene control — get_scene_breakdown + reschedule_scene . \n \n\n Why WebMCP \n\n Film logistics is the perfect agent-native problem: structured actions\n(schedule, assign, reschedule, export) that must execute deterministically\ninstead of being guessed through a UI. Any agent — ChatGPT's in-app browser,\na producer's assistant bot, or another production tool — can operate ROYA\ndirectly through its 8 registered tools. \n\n Human + agent workflow \n\n 👤 Producer pastes a raw screenplay\n🤖 Agent → analyze_script (12 scenes, 6 cast, 5 locations)\n🤖 Agent → get_weather_forecast ×3 shooting days\n🤖 Agent → generate_schedule (priority: weather)\n🤖 Agent → assign_task ×8 departments\n👤 Producer approves one change\n🤖 Agent → reschedule_scene + export_call_sheet \n👤 Crew receives the briefing instantly \n\n 6–8 hours of manual coordination → under 5 minutes. \n\n How I built it \n\n \n Frontend: Next.js 14 App Router, React, TypeScript, Tailwind CSS\n(charcoal #0a0a0f + amber-gold identity, Arabic/English) \n AI: OpenAI GPT-4o-mini, JSON mode for screenplay extraction \n Weather: OpenWeatherMap with graceful mock fallback (zero-key demo) \n WebMCP: 8 tools via document.modelContext.registerTool() with\n navigator.modelContext fallback \n State: client-side React context + localStorage; server routes stateless \n Hosting: Vercel auto-deploy on every push; MIT license \n Verification: Puppeteer E2E launching Chrome 152 with\n --enable-features=WebMCP,WebMCPAPI,WebModelContext , asserting 8/8 tools\nregister and executing two against the live URL (report: e2e/results.json ) \n \n\n Challenges & what I learned \n\n \n WebMCP availability: stable Chrome didn't expose modelContext ; I\nfeature-detected both surfaces and built an E2E harness with cached\nChrome 152 + flags to prove registration AND execution. \n React #418 hydration: reading localStorage during render broke SSR\nparity; fixed by seeding identical demo state and hydrating in useEffect . \n Shared-state leak: an early server singleton mixed visitors' data;\nper-session client state + Reset button + "Demo data / Your analysis"\nbadges now keep every judge's session pristine. \n \n\n The opportunity \n\n Production-management software is a $6.66B market (2026, +9%/yr), yet no\nArabic-first, weather-aware, agent-native tool exists. MENA produces 200+\nfilms/year with almost no tailored tooling. ROYA is the first. \n\n Try it \n\n \n Live: https://roya-seven.vercel.app — no signup; Reset button included \n Verify locally: node e2e/webmcp.test.mjs \n \n\n Built for the OpenAI WebMCP Challenge 2026 — Arabian Company for Production\n& Digital Services. \n\n \n\n \n Built With \n\n css gpt-4o next.js node.js openai puppeteer react tailwind typescript vercel webmcp \n \n\n \n Try it out \n\n \n \n \n roya-seven.vercel.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n Solo founder: originated the concept from real film-production experience\n in Morocco, defined the product and the 8-tool WebMCP architecture,\n orchestrated AI coding agents for implementation, and personally verified\n the integration end-to-end with a Puppeteer + Chrome 152 WebMCP E2E harness. \n \n\n \n \n \n \n \n \n\n \n حمدي أبو العلى أشتوك \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n حمدي أبو العلى أشتوك \n started this project\n \n —\n \n a day ago \n \n \n\n
