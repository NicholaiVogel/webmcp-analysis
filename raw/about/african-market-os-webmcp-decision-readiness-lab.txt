A browser-agent lab that turns high-context market decisions into evidence gaps, safe next steps, and human-controlled activation. Like Comment Story Updates Live WebMCP first-call returns a bounded, gap-first response and maximum-safe next action. The agent converts missing evidence into observable requests before any consequential decision. Exactly five page-defined WebMCP tools are discoverable in the browser agent. Inspiration High-context market decisions often fail before execution because founders, investors, and advisers mistake a persuasive narrative for sufficient evidence. A browser agent can read a conventional page, but it still has to infer which fields matter, what sequence to follow, and when to stop. In market-entry, partnership, investment, and scale decisions, that guesswork can turn thin evidence into false confidence. We built the African Market OS WebMCP Decision Readiness Lab to explore a better interaction: the human supplies context and intent, the website supplies authoritative tools and boundaries, and the browser agent helps turn uncertainty into a practical evidence plan. What it does The live page supports both people and WebMCP-capable browser agents. A user scopes a non-confidential decision with an entity, country, local market or corridor, sector, decision type, timeframe, and evidence note. The page registers exactly five WebMCP tools: amos_scope_market_decision strictly validates and structures the decision context. amos_run_public_first_call calls African Market OS's live, keyless MVR first-call preflight for the active scope. amos_extract_evidence_gap_plan turns returned evidence gaps into observable requests only after a bound preflight exists. amos_prepare_human_next_step validates and prepares a bounded route for a human to choose. amos_get_webmcp_demo_script provides a repeatable state-aware reviewer sequence. The result is deliberately not an approval or readiness verdict. It identifies what is known, what evidence is absent, what must not be claimed, and the maximum-safe action available now. Why WebMCP is a strong fit Without WebMCP, an agent must scrape labels, guess UI state, and improvise the workflow. With WebMCP, the page exposes named tools, descriptions, JSON input schemas, execution logic, and explicit authority boundaries in the same context the person is viewing. The agent can invoke the intended operation and receive a structured response consistent with the human-facing experience. This creates a better experience through shared context, lower ambiguity, and safer activation. The workflow distinguishes evidence support from commercial, legal, credit, investment, procurement, or regulatory authorization. What people and agents can do together A person decides which real-world decision to examine and controls every consequential or commercial next step. The browser agent can structure the input, call the live preflight, summarize the evidence gaps, and prepare a focused plan. The visible buttons call the same functions, so browsers without WebMCP retain the full human workflow. How we built it The demo is a self-contained HTML, CSS, and JavaScript application deployed on African Market OS through Cloudflare. It uses the imperative WebMCP API, document.modelContext.registerTool() , to register five page-specific tools. Schemas describe the contract, but every handler also validates independently. Required fields, allowed values, lengths, unexpected properties, and sensitive-data indicators are rejected rather than silently repaired. A deterministic scope_id binds the visible decision to the first call, and the returned preflight_id binds every downstream action. Changing the scope invalidates the old preflight. Same-key retries reuse the active workflow unless an agent explicitly requests a new one. The default agent_compact profile returns one canonical page-level next action. An opt-in debug_full profile preserves deeper inspection without burdening normal agent context. If the upstream MVR response recommends a capability that is not one of the page's five tools, the response labels it as a separate remote-MCP continuation instead of pretending it is locally callable. Protected MVR scoring and private calibration assets are never exposed. The public result states when live scoring did not run and carries a clear not_a_verdict boundary. Challenges The hardest part was not registering a browser tool. It was making schema declarations, handler behavior, visible page state, retries, and downstream handoffs tell the same truth. We had to prevent sample fallbacks from masking invalid agent input, stop stale preflights from surviving a changed form, make retries idempotent, and keep remote MCP capabilities distinct from page-defined tools. Accomplishments Exactly five page-defined WebMCP tools are discoverable. Empty, malformed, over-limit, unexpected, and stale-state inputs fail explicitly. A valid first call returns HTTP 200, a compact gap-first response, and one bound next action. Same-key retries reuse the exact preflight rather than creating duplicate workflows. Human and agent paths share one implementation, while payment and consequential action remain human-controlled. A post-build adversarial review was converted into regression coverage: the production Worker suite passes 153 of 153 tests, the public repository includes a passing dependency-free contract test, and a 30-case Agent Experience regression records the post-fix evidence and caveats. The production /mcp/ and canonical /mcp/preflight surfaces remain separate and unchanged. What we learned WebMCP is most valuable when it carries semantics, not just clicks. Schema declaration alone is not enough; handlers must defend the same contract. Every multi-tool handoff needs explicit state identity. For evidence-sensitive decisions, a well-designed stop condition is a feature: helping an agent say collect this proof next can be more useful than producing another confident answer. What's next We plan to test the workflow with founders, programme operators, investors, and advisers; measure where agents stop in the handoff sequence; improve accessibility of structured results; and evaluate how evidence plans change real decisions over time. Consequential judgments, credentials, contracting, and payment will remain human-controlled.
