Rather than requiring a user to manually navigate a directory, an AI agent can interact directly with AskJosh's structured service data and help turn a real-world maintenance problem into an actionable plan. \n\n This challenge edition is focused on La Brea, Trinidad and Tobago, and uses a deliberately small illustrative demo catalogue. The goal is to demonstrate an architecture that could later expand to verified providers, additional communities and more service categories. \n\n What it does \n\n AskJosh is an agent-ready local maintenance concierge. \n\n Through WebMCP, the challenge edition exposes three read-only tools: \n\n \n find_maintenance_services — finds relevant maintenance services from the AskJosh demo catalogue. \n get_maintenance_service_details — retrieves grounded information about a specific service using its exact service ID. \n build_property_maintenance_plan — combines selected services into a structured draft maintenance plan with deterministic sequencing and illustrative cost ranges. \n \n\n For example, a user can ask for help preparing a community centre that needs AC servicing, electrical checks, pressure washing and lawn care. \n\n The agent can discover the relevant AskJosh services, work with their exact service IDs and create a combined maintenance plan without inventing providers, prices or availability. \n\n AskJosh also works as a normal website, allowing people to search the same demo catalogue without using an AI agent. \n\n How I built it \n\n AskJosh is built with Next.js, React and TypeScript and deployed on Vercel. \n\n For the challenge edition, I created a deliberately small deterministic catalogue containing illustrative maintenance services for La Brea, Trinidad and Tobago. \n\n The underlying service logic is shared by both the normal website experience and the WebMCP tools. \n\n The WebMCP integration uses the browser's Site Tools / WebMCP interface to register structured tools directly from the AskJosh web application. \n\n The architecture is intentionally simple: \n\n AskJosh illustrative demo catalogue \n→ deterministic shared service logic \n→ WebMCP tools \n→ AI agent \n→ structured grounded response \n\n The WebMCP tools are read-only. They do not submit bookings, contact providers, send emails, write personal information to a database or expose private administrative functionality. \n\n AskJosh also detects whether WebMCP is available so the normal website remains usable in unsupported environments. \n\n Challenges I ran into \n\n One of the biggest challenges was making the agent experience useful without allowing the system to invent local service information. \n\n Rather than asking an AI model inside AskJosh to generate providers, prices or service information, I designed the WebMCP tools around deterministic catalogue data and stable service IDs. \n\n I also separated discovery and planning from consequential actions. The current WebMCP implementation can search, retrieve details and prepare maintenance plans, but it cannot silently contact providers or submit requests on a user's behalf. \n\n Another challenge was maintaining a normal human-facing website while introducing an agent-facing WebMCP capability. WebMCP support is feature-detected so unsupported browsers continue to receive the conventional AskJosh experience. \n\n Accomplishments that I'm proud of \n\n \n Three working read-only WebMCP tools that can be discovered and called by an agent. \n A multi-tool workflow from service discovery to detailed retrieval to maintenance planning. \n Exact service-ID grounding to reduce hallucination and incorrect matches. \n Deterministic illustrative cost aggregation using catalogue values rather than AI-generated estimates. \n Safe handling of unsupported locations and invalid service IDs. \n A read-only architecture with no hidden consequential actions. \n A normal website experience that continues to work independently of WebMCP. \n Automated tests covering the WebMCP service-search, detail and planning functionality. \n A separate sanitized public challenge edition that demonstrates the WebMCP architecture without exposing the broader AskJosh project. \n \n\n What I learned \n\n WebMCP changes the role of a website. \n\n Instead of an AI assistant only reading visible page content, a site can expose carefully designed capabilities that allow an agent to interact with the product in a structured way. \n\n I also learned that more tools are not necessarily better. A small set of well-scoped, grounded tools can create a useful agent workflow while remaining predictable, deterministic and safe. \n\n What's next for AskJosh \n\n The challenge edition intentionally uses a small illustrative maintenance catalogue. \n\n The longer-term opportunity is to expand AskJosh to verified local providers, additional service categories and more communities while preserving the same agent-access architecture. \n\n Future possibilities include broader geographic coverage, provider onboarding and verification, richer service discovery, and carefully reviewed user-authorized request workflows. \n\n The goal is to evolve AskJosh from a focused maintenance concierge into a practical AI-accessible community services platform. \n\n \n\n \n Built With \n\n codex css github javascript next.js react tailwind typescript vercel webmcp \n \n\n \n Try it out \n\n \n \n \n askjosh-webmcp-demo.vercel.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n ChrisDC82 Din Chong \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n ChrisDC82 Din Chong \n started this project\n \n —\n \n 3 days ago \n \n \n\n
