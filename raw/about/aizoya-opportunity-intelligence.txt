Key information is often scattered across dashboards, websites, documents, and portals. Traditional browser agents must interpret visual interfaces and guess which controls to use, resulting in slow and unreliable performance. \n\n AIZOYA Opportunity Intelligence introduces a new approach: a website designed for both people and AI agents. WebMCP enables the site to present clear, structured capabilities while maintaining the visual experience and user control. \n\n What it does \n\n AIZOYA Opportunity Intelligence serves as a WebMCP-enabled opportunity command center. Users can instruct an AI agent to: \n\n \n List the opportunities available on the page \n Compare two opportunities using their scores, strategic fit, deadlines, and other decision factors \n Add a selected opportunity to the shortlist \n \n\n The agent uses registered website tools rather than guessing through the interface. Because the page and agent share the same context, results appear directly in the user interface. \n\n The prototype shows how WebMCP can support business research, innovation portfolios, grant discovery, accelerator applications, procurement opportunities, and other decision-intensive workflows. \n\n How we built it \n\n We developed a responsive web application with Next.js, React, and TypeScript, and deployed it on Vercel. The application registers structured WebMCP tools with defined names, descriptions, inputs, and outputs. \n\n The core tools support three stages of the decision workflow: \n\n \n Opportunity discovery \n Side-by-side comparison \n User-directed shortlisting \n \n\n The interface displays structured opportunity records, and the WebMCP layer provides agents with reliable access to these capabilities. We tested the deployed application using ChatGPT’s in-app browser by issuing natural-language requests and confirming the correct tools were identified and executed. \n\n Challenges we ran into \n\n Our main challenge was designing tools that were useful to agents without being too broad or ambiguous. Tool descriptions, parameter schemas, opportunity identifiers, and results needed to be predictable. \n\n We also needed to make agent interactions visible and understandable to users. Because shortlisting changes application state, the workflow required clear intent and observable feedback instead of hidden automation. \n\n Testing an emerging browser standard required validating both the traditional user interface and the agent-driven experience. \n\n Accomplishments that we’re proud of \n\n \n Built and deployed a working WebMCP-enabled application \n Registered multiple focused tools instead of one unrestricted tool \n Demonstrated an end-to-end agent workflow \n Enabled structured comparison between opportunities \n Connected an agent action to visible shortlist state \n Preserved a useful interface for people who interact with the site manually \n \n\n What we learned \n\n WebMCP changes how websites communicate their capabilities. Visual design remains important for users, while structured tools give agents clearer instructions and more reliable actions. \n\n We also learned that the most effective agent tools are focused, well-described, and based on visible application state. Human control and transparency become increasingly important as agent capabilities grow. \n\n What’s next \n\n Next, we plan to expand the prototype into a comprehensive AIZOYA portfolio command center with authenticated workspaces, live opportunity sources, evidence-backed scoring, deadlines, reminders, bilingual support, audit history, and approval controls for key actions. \n\n Our long-term vision is a human-centered intelligence system that enables organizations and their AI agents to discover opportunities, evaluate them consistently, and act more quickly and with greater accountability. \n\n \n\n \n Built With \n\n ai and-javascript-and-deployed-it-on-vercel.-the-application-uses-the-imperative-webmcp-api-through-document.modelcontext.registertool(.)-to-register-six-structured-tools-with-defined-descriptions annotations chatgpt codex css css3 github html5 input-schemas javascript validation vercel webmcp \n \n\n \n Try it out \n\n \n \n \n aizoya-intelligence-webmcp.vercel.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n As the sole founder, product lead, and builder for AIZOYA Opportunity Intelligence, I defined the problem, designed the human-agent workflow, structured opportunity data, specified six WebMCP tools, directed implementation, tested the application in ChatGPT’s in-app browser, refined the user experience, validated public deployment, prepared documentation, and produced the demonstration video. \n\n I used OpenAI Codex and ChatGPT for implementation support, debugging, testing, documentation, and quality review.
