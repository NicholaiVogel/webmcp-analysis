This project instead registers five narrow tools with document.modelContext.registerTool(...) : \n\n \n get_synthetic_pika_profile \n list_synthetic_pika_events \n get_synthetic_pika_today \n preview_synthetic_pika_check_in \n commit_synthetic_pika_check_in \n \n\n Preview validates without writing and returns a payload-bound confirmation token. Commit fails closed unless it receives the unchanged payload and matching token. A changed or unpreviewed payload is rejected. \n\n Human + agent collaboration \n\n The agent reduces repetitive interaction while the person sees the proposal, controls confirmation, and verifies the outcome. Both then see the same browser-only state. \n\n What I learned \n\n The most useful lesson was that exposing a tool is only half of the work. The human page and the agent must stay consistent around the same proposed action. \n\n During testing, we found a real UI bug: after preview, a re-render could reset the visible form to its defaults while the pending payload still held the earlier values. That could make the confirmation screen misleading even though the underlying token guard still worked. \n\n We fixed it by preserving the exact previewed values in the UI and invalidating confirmation whenever the form changes. This reinforced the main product principle behind the demo: WebMCP can give an agent useful capabilities, but consequential actions still need deterministic guards and visible human review. \n\n Safety and hackathon boundary \n\n All data is fictional and marked synthetic_hackathon_only . Mutable state stays in namespaced browser localStorage . The demo has no production CAIOS API, database, customer record, real pet record, private prompt, proprietary memory engine, nutrition reasoning, or clinical logic. It does not diagnose, prescribe, or replace veterinary or emergency care. \n\n CAIOS existed before the submission period as a broader pet-care product vision. During the submission period, we created this standalone WebMCP Gateway, five tools, synthetic dataset, confirmation guards, seven deterministic tests, CI, documentation, public repository, and independent deployment. \n\n Implementation and verification \n\n Built with TypeScript, Vite, the WebMCP browser API, and deterministic browser storage. Seven tests cover the tool boundary and guarded writes. Type checking and production builds pass. \n\n The live workflow was verified end-to-end in an OpenAI cloud Chrome CDP environment: five tools were discovered; a direct commit failed closed; preview returned a payload-bound token; the exact payload committed; and a final read returned the same visible browser-only state. \n\n Try it \n\n Live demo: https://caios-webmcp-challenge.vercel.app \n\n Public repository: https://github.com/corwinlim/caios-webmcp-challenge \n\n Demo video: https://youtu.be/FDoAIoCU3i0 \n\n No account or credentials are required.
