One script line turns any site's existing frontend into WebMCP tools you can speak to and point at — voice and hand gestures, no LLM in the loop. Like Comment Story Updates What it is Handsfree gives any website you can edit voice commands and hand-gesture control on top of WebMCP, with one command to your Claude Code and one <script> line in the page. WebMCP (the W3C Web Machine Learning draft, document.modelContext ) lets a page expose what it can do as tools : named functions with a description and a JSON schema. That is the half meant for agents. Handsfree is the other half, for people: a runtime that reads the same tools and drives them from speech and from a camera, with no LLM in the loop. Inspiration Every "agentic web" demo we saw ended with a chat box. But if a page has already declared its capabilities as tools, the input layer is free to be anything: a microphone, a hand, a floating sentence. We wanted to prove that the tool layer is the real product and the modality is a one-line add-on, and that the honest promise is "one command plus one line", not "one line". How we built it The tool layer. A demo shop ( webmcp-shop-demo.vercel.app ) where every capability is a WebMCP tool: ask , search_products , open_landing_page , focus_product , open_product , buy_now , scroll_page , refine_results , show_brands , browse_all , describe_focused , close_panel , help . The floating input box, the voice layer and the gesture layer are three clients of the same tools; a trace panel shows every call. Data comes from a public MCP catalog server ( search_global_catalog ) through a millisecond local index that the live catalog keeps growing. The Claude Code plugin. A skill that audits a codebase's existing frontend, wires the real actions to registerTool (never synthetic clicks when an API exists), marks one tool as the text-sink , one as scroll , gates money-moving tools with confirm , injects the runtime and verifies in the browser. Plus an idempotent injector CLI and a tool-authoring reference that quotes the draft precisely ( registerTool(tool, {signal, exposedTo}) , getTools , executeTool , toolchange ). The runtime ( handsfree.js , ~50 KB, zero dependencies). Discovers tools through the page's registry, by wrapping registerTool , or via a polyfill. Voice uses the Web Speech API and a rule router: built-in intents, tool phrases, tool names as words, then the text-sink. Gestures use MediaPipe HandLandmarker on-device: the index fingertip is a projected cursor, an air-tap clicks, the outer left/right bands scroll (faster towards the edge), an open-hand wave goes back or forward. Everything is drawn on a dot field that bulges under the cursor; a walkthrough tutorial starts the camera only at its last step. What we learned The current draft has no unregisterTool ; you abort the AbortSignal you registered with. execute gets (input, {signal}) and may return any JSON value. Only readOnlyHint and untrustedContentHint are spec annotations, so our handsfree.* hints stay on the page-side registry and are stripped before forwarding to a native implementation. Rules beat models here. With good tool descriptions and phrases, 100% of our test utterances route correctly with zero model calls and zero latency; what a model would add is ambiguity handling, not the happy path. Gesture UX is about resting positions, not gestures: mapping the lower-left / lower-right of the camera frame to the whole screen so the arm can rest low mattered more than any recognizer tuning. Challenges Popups. A gesture or voice action carries no user activation, so window.open is blocked. The runtime navigates the current tab for synthetic clicks and asks the site for an in-page panel; "back" closes it first. Speech engines rewrite you. "landing page for cozy gifts under fifty dollars" arrives as "Landing page 4 cozy gifts under fifty dollars." We undo the common rewrites before matching and strip price phrases into max_price . Embedded browsers report a 0-height viewport , which put our fixed input box off screen; the page now measures the visual viewport and falls back to normal flow. A 12–70 s upstream search cannot sit on the render path, so every view paints from a local index in milliseconds and the live catalog tops it up in the background. Smooth scrolling never progresses in background tabs , which silently broke per-frame gesture scrolling until we forced instant steps. What's next Native document.modelContext on Chrome's origin trial, a real LLM fallback for the long tail of utterances, and a Shopify-theme recipe so the skill can instrument a store in one run.
