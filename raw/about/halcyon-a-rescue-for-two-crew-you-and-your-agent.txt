You're the last awake crew member. Your agent is the ship computer. A WebMCP co-op puzzle game that neither human nor agent can finish alone. Like 1 Comment Story Updates landing page first step Inspiration Every famous ship computer is a villain. HAL locks the pod bay doors. We wanted the opposite: a ship computer you trust with your life — because it's your own agent. When OpenAI framed the WebMCP Challenge as "an app that becomes meaningfully better when people and their agents can use it together," we took it literally: HALCYON is a game that is not merely better together — it is impossible alone . What it does You are the last awake crew member of the ISV Halcyon , drifting after a micrometeorite storm. Your agent — ChatGPT or Codex in a WebMCP browser — becomes the ship computer through tools the page registers with document.modelContext . Six chapters take the ship from dark hull to jump-home, and each one is built on a different WebMCP capability: Contact — tool discovery: you throw the breaker, the agent must catch the boot handshake inside the surge window. Manifest — read-only tools: the agent knows what broke; only you can see which hatches still open. Power — JSON-schema inputs + structured errors: the agent routes amps against hidden minimums, self-correcting from machine-readable brownout errors, while you re-seat the physical fuses. Antenna — dynamic registration: you align the dish by ear ; lock-on registers new comms tools into the live page. Two-Man Rule — human confirmation as a mechanic: the agent times the arm from telemetry; you hold both vent handles at once. WebMCP's sensitive-action philosophy, playable. Burn — orchestration: an interleaved launch checklist, then a flight-recorder replay of everything your crew did together. How we built it The game about a human-agent crew was built by a human-agent crew . Claude helped create the original design spec and implementation plan. Keelen's autonomous development loop, powered by OpenAI Codex, implemented much of that plan through CI-gated pull requests on self-hosted runners. We then used Codex and ChatGPT directly to finish the remaining work, diagnose live-play issues, and complete the recorded Chrome/WebMCP playthrough. The final app uses no frontend framework or backend and has zero runtime dependencies: TypeScript + Vite, SVG scenes, synthesized WebAudio, and a typed WebMCP registry with validation, rate limits, and coaching errors. Challenges The hard problem is asymmetry integrity : an agent can read the DOM, so "human-only" information cannot be text. We split the channels — audio pitch and motion for the human, tool-returned data (never rendered) for the agent — and gated hard state changes inside tool execute functions with no UI equivalent. What we learned Tool design is level design. A good inputSchema is a puzzle boundary; a good structured error is a hint system; readOnlyHint is dramatic irony. And an error message written for an agent ("give life_support at least 18A and route again") is the best tutorial text we have ever shipped. What's next A shared starmap: every crew that completes the rescue lights a beacon all players can see. More ships, more capability chapters as WebMCP grows.
