When an incident occurs, security teams need to understand the evidence, replay the risky behavior, evaluate a possible fix, and preserve a clear audit trail. We wanted to explore how agents could help with this workflow without giving them unrestricted authority to change runtime policies. \n\n That idea became Sentinel Desk : an open-source, standalone AI incident response desk powered by WebMCP. \n\n Sentinel Desk lets an agent search incidents, inspect model traces, identify policy violations, simulate a proposed runtime guard, and request human approval. The final policy-changing action remains explicitly gated by the human operator. After approval, the guard is activated and the action appears in the provenance timeline. \n\n The WebMCP layer exposes six tools: \n\n \n search_incidents \n inspect_trace \n simulate_guard \n request_guard_approval \n apply_guard \n get_audit_report \n \n\n These tools are registered through the WebMCP Imperative API using document.modelContext.registerTool . The application also works as a normal web interface, so people can manually explore the workflow even when WebMCP is not available. \n\n The most important thing we learned is that WebMCP is not simply a replacement for clicking buttons. A well-designed tool gives an agent a precise capability, a clear input schema, and an explicit trust boundary. This is especially important for security workflows: reading evidence and proposing a remediation are different actions from activating a policy change. \n\n One of our main challenges was working with an emerging browser API while preserving a reliable human experience. We had to handle WebMCP availability, tool registration, cancellation and permission boundaries, while keeping the application usable in a regular browser. We also needed to make a synthetic runtime feel realistic without implying that it was connected to production data. \n\n Sentinel Desk demonstrates a possible future for AI governance: agents can help investigate complex incidents and prepare remediation, while people retain authority over consequential runtime changes. \n\n \n\n \n Built With \n\n tailwind typescript vite \n \n\n \n Try it out \n\n \n \n \n sentinel-desk-webmcp.hakan-damar.workers.dev \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n This was my first time using WebMCP, and it helped me understand the concept more clearly. \n \n\n \n \n \n \n \n \n\n \n Hakan Damar \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n 1 \n \n \n\n\n \n 1 person likes this:\n \n\n \n \n \n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Hakan Damar \n started this project\n \n —\n \n 3 days ago \n \n \n\n
