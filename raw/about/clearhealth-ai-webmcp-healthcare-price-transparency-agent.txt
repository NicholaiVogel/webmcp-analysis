I wanted to explore how WebMCP could make an existing healthcare application more useful to AI agents without removing the human experience. \n\n The project originally started as a healthcare claims and Machine-Readable File (MRF) coding challenge. I extended it for the WebMCP Challenge so that both humans and AI agents can interact with the same underlying healthcare claims data. \n\n Why WebMCP is a Strong Fit \n\n Healthcare price transparency is a strong fit for WebMCP because users often need to search, compare, and summarize structured pricing information rather than simply browse a webpage. Traditional web interfaces are designed primarily for humans, requiring an AI agent to understand the interface and determine how to perform these tasks. \n\n This project exposes three meaningful healthcare capabilities through WebMCP: searching claims, comparing procedure prices, and summarizing provider claims. These operations have clearly defined inputs and structured outputs, making them natural capabilities for an AI agent to invoke. \n\n For example, instead of an agent navigating the application to compare prices for a procedure, it can call compare_healthcare_prices with a procedure code and receive the relevant billed, allowed, and paid statistics. Similarly, an agent can search claims or obtain a provider summary without relying on UI navigation or screen scraping. \n\n This creates a human-and-agent experience in which people can continue using the visual healthcare application, while agents can directly access its core capabilities. WebMCP therefore transforms the website from a human-only interface into one that can be used by both humans and AI agents. \n\n What it does \n\n ClearHealth AI is a healthcare price-transparency application enhanced with WebMCP. \n\n A human can use the web application to explore healthcare claims and pricing information. An AI agent can access the same data through three read-only WebMCP tools: \n\n \n search_healthcare_claims — searches claims using structured filters such as provider name, procedure code, and place of service. \n compare_healthcare_prices — calculates billed, allowed, and paid price statistics for a procedure, including averages, minimums, maximums, totals, and amount differences. \n summarize_provider_claims — provides an aggregate summary of a provider's claims, including claim count, billed, allowed, and paid amounts, average allowed amount, and associated procedures. \n \n\n For example, an agent can search for claims associated with Michael Poole, compare prices for procedure s5301 , and then summarize Michael Poole's claims without having to navigate the application's user interface. \n\n How I built it \n\n The application is built with React and TypeScript and uses a healthcare claims data layer to provide structured data to the WebMCP tools. \n\n The WebMCP implementation is located in: \n\n frontend/src/webmcp/tools.ts \n\n I check whether WebMCP is available and register the tools through: \n\n document.modelContext.registerTool(...) \n\n Each tool provides a unique name, human-readable title, description, structured input schema, read-only annotation, and asynchronous execution function. \n\n The tools are read-only and reuse the application's healthcare claims data without modifying the underlying dataset. \n\n I also use Mantine for UI components, Tailwind CSS for styling, PapaParse for CSV parsing, AG Grid for data presentation, Zod for schema validation, MobX for state management, and React Router for navigation. \n\n Challenges I ran into \n\n The main challenge was deciding which application capabilities would provide real value to AI agents. \n\n Instead of exposing simple UI actions, I focused on meaningful healthcare operations with clearly defined inputs and structured outputs. I also needed to make the WebMCP layer work alongside the existing human-facing application rather than replacing it. \n\n Another challenge was designing the tool outputs so that an agent receives useful structured information that can be directly interpreted and communicated to a user. \n\n Accomplishments that I'm proud of \n\n I successfully extended an existing healthcare claims application with an agent-facing WebMCP layer. \n\n The application now provides three distinct healthcare capabilities that an AI agent can discover and invoke: \n\n \n Search healthcare claims \n Compare healthcare prices \n Summarize provider claims \n \n\n I'm especially proud that the same underlying healthcare data can support both a traditional human interface and direct agent interaction. \n\n I also kept the WebMCP tools read-only so that agent interactions do not modify the underlying claims data. \n\n What I learned \n\n This project helped me understand how WebMCP can provide a structured interface between a web application and AI agents. \n\n I learned that an effective agent-facing interface is not simply about exposing more functionality. The capabilities need to represent meaningful user tasks, have clear inputs and outputs, and be easy for an agent to invoke. \n\n I also learned that WebMCP can complement a human-first interface: people can continue using the application visually while agents can directly access the application's capabilities. \n\n What's next for ClearHealth AI: Healthcare Price Transparency Agent | WebMCP \n\n My next step is to expand the agent capabilities while maintaining clear, read-only boundaries around healthcare data. \n\n Future improvements could include additional healthcare analytics tools, richer natural-language interactions, stronger validation and error handling, and additional ways for humans and AI agents to collaborate when exploring healthcare price-transparency information. \n\n My goal is to continue evolving ClearHealth AI into an application where healthcare data is accessible through both intuitive human experiences and well-defined agent capabilities. \n\n \n\n \n Built With \n\n ag agents ai css grid healthcare mantine mobx papaparse price react router tailwind transparency typescript vercel webmcp zod \n \n\n \n Try it out \n\n \n \n \n frontend-challenge-1-delta.vercel.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Chitipolu Sri Sudheera \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Chitipolu Sri Sudheera \n started this project\n \n —\n \n 5 days ago \n \n \n\n
