Choosing cameras, LiDAR, compute, sensors, and power systems involves a lot of searching, comparing, budgeting, and repetitive decision-making. \n\n Our idea was simple: let the AI handle the research and recommendations, while keeping the human in control of the final decision. \n\n That became Human-Agent Robotics Procurement \n\n What it does \n\n Human-Agent Robotics Procurement lets an AI agent work directly with a robotics procurement workspace through WebMCP. \n\n The agent can search equipment, compare products, calculate budgets, and generate complete configurations. Instead of simply returning a list of products, it can reason about the project and propose different configurations based on priorities such as cost or performance. \n\n The human remains in control. Recommendations are presented for review, and consequential project changes require explicit human approval. \n\n The agent proposes. The human decides. \n\n How we built it \n\n We built the application with React Native, Expo, TypeScript, and Zustand, with WebMCP providing the agent-facing interface. \n\n We exposed six structured tools through document.modelContext for product search, comparison, budgeting, project updates, optimization, and human approval. \n\n The application maintains shared project, activity, and approval state, allowing the human UI and AI agent to work with the same underlying workspace. \n\n A key part of the implementation was separating recommendation from mutation. The optimization agent can generate configurations without changing the project. Only an explicit human approval can turn a recommendation into an actual project change \n\n Challenges we ran into \n\n The biggest challenge was figuring out how to integrate WebMCP into an existing Expo application while keeping browser-specific functionality separate from the native application. \n\n We also had to carefully design the boundary between agent autonomy and human control. \n\n It was tempting to let the agent automatically apply its recommendations, but that would remove an important part of the procurement decision. We instead designed a workflow where the agent can do the time-consuming work independently, while the human remains the final authority. \n\n Making the agent's actions visible was another challenge, so we added activity tracking to show users what the agent is doing and when human input is required \n\n Accomplishments that we're proud of \n\n We're proud that we transformed a normal procurement interface into an agent-ready web application. \n\n The agent can discover and use structured capabilities directly from the page instead of trying to understand the application by interpreting the UI. \n\n We successfully implemented six WebMCP tools and connected them to the same application state used by the human interface. \n\n We're especially proud of the approval workflow. The agent can search, analyze, optimize, and recommend independently, but it cannot silently make consequential changes. \n\n That creates a practical model for human-agent collaboration: \n\n AI handles the work. Humans retain the authority \n\n What we learned \n\n We learned that building for AI agents requires thinking beyond traditional UI design. \n\n A human sees buttons, screens, and menus. An agent needs clearly defined capabilities, inputs, outputs, and consequences. \n\n WebMCP gave us a way to expose those capabilities directly to the agent. \n\n We also learned that meaningful agent autonomy doesn't require removing humans from the process. In many real-world workflows, the best experience may be an agent that can do most of the research and reasoning while keeping humans responsible for important decisions \n\n What's next for human-agent-collab \n\n We're excited to take the project from a prototype into a more complete autonomous procurement system. \n\n Next, we want to connect the workspace to real supplier catalogs, live pricing, inventory, quotations, and delivery information. We also want to introduce multiple specialized agents that can handle supplier discovery, technical compatibility, cost optimization, and negotiation. \n\n The long-term vision is a procurement workspace where AI agents can take on increasingly complex work across the entire purchasing process, while humans remain in control of approvals and high-impact decisions. \n\n Human-Agent-Collab is our exploration of what procurement could look like when humans and AI agents work in the same workspace not as separate systems, but as collaborators \n\n \n\n \n Built With \n\n ai expo.io react robotics router \n \n\n \n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n joshua munyao \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n joshua munyao \n started this project\n \n —\n \n 2 days ago \n \n \n\n
