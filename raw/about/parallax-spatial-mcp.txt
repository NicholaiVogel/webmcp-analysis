If an agent moves, rotates, or modifies something in a 3D world, we need a way to know what it was allowed to do, what actually changed, and whether the result matched the objective. \n\n That led to the core loop: \n\n Observe → Act → See Again → Verify → Receipt \n\n The goal was to make spatial agency more accountable instead of treating a tool call as proof that a task succeeded. \n\n What it does \n\n PARALLAX is a Spatial MCP for autonomous agents. It turns 3D environments into governed workspaces where an agent can: \n\n \n inspect a scene \n discover bounded capabilities \n request authorized spatial actions \n execute allowed changes \n re-observe the resulting state \n verify the outcome \n produce an execution receipt \n \n\n Restricted actions can be denied without changing the protected scene state. \n\n Our WebMCP demo uses a virtual production studio. The agent is given the objective of preparing the studio for an interview while operating inside defined permissions. \n\n How we built it \n\n PARALLAX was built with WebMCP, TypeScript, React, Three.js, React Three Fiber, Vite, GLTF assets, and OpenAI Codex , with ChatGPT and Hermes assisting with development, verification, documentation, and submission preparation. \n\n The application separates the visual 3D scene from the authoritative logical state. Scene objects expose spatial capabilities, actions pass through governance checks, the environment is re-observed after execution, and verification determines whether the objective was satisfied before a receipt is shown. \n\n We also built explicit denial behavior so a restricted mutation can fail closed rather than silently modifying the scene. \n\n Challenges we faced \n\n The hardest challenge was making the execution loop understandable visually, not just technically correct. \n\n Early versions used proxy geometry that made real scene changes difficult to recognize. We had to improve object presentation, before/after comparison, labels, camera framing, video backgrounds, and the relationship between the 3D environment and the governance system. \n\n Deployment parity was another major challenge. A local build could look correct while a production deployment could lose assets, motion, layout, or visual hierarchy. That pushed us to add stronger design and production-parity checks. \n\n We also had to be disciplined about claims. A generated visualization is not the same thing as a verified result, so throughout the project we used the rule: \n\n Generated! = Verified \n\n What we learned \n\n We learned that agentic spatial systems need more than tool access. They need an execution contract. \n\n The important part is not simply whether an agent can manipulate a 3D environment. It is whether the system can clearly answer: \n\n What did the agent observe? \nWhat was it authorized to do? \nWhat changed? \nDid the change satisfy the objective? \nWhat evidence remains afterward? \n\n PARALLAX is our attempt to make those questions first-class parts of spatial agent infrastructure. \n\n \n\n \n Built With \n\n ai-agents codex css3 gltf html5 javascript openai three.js typescript vite webmcp \n \n\n \n Try it out \n\n \n \n \n GitHub Repo \n \n \n \n GitHub Repo \n \n \n \n agentropolis-city-of-agents.github.io \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n I conceived and built PARALLAX as a solo founder, defining the Spatial MCP architecture, governed execution loop, 3D interaction model, authorization and denial system, verification workflow, receipt system, product design, and overall user experience.
