We wanted to explore what happens when a procurement dashboard is designed for both people and AI agents from the beginning. \n\n What it does \n\n BidLens helps suppliers discover and evaluate procurement opportunities through a unified intelligence workspace. \n\n Users can: \n\n \n Search and filter procurement opportunities \n Review supplier fit scores and eligibility requirements \n Identify risks and missing documents \n Compare two or three opportunities \n Prepare bid workspaces with checklists and notes \n Track preparation status and bid readiness \n Browse opportunities and records through paginated interfaces \n \n\n BidLens also exposes WebMCP tools that allow an AI agent to work with the application: \n\n \n find_opportunities \n investigate_opportunity \n compare_opportunities \n prepare_bid_workspace \n update_bid_workspace \n \n\n Read-only tools can be used directly by an agent. Actions that change application state require explicit human confirmation. \n\n How we built it \n\n BidLens was built as a React and TypeScript single-page application using Vite, TanStack Router, and Tailwind CSS. The application uses realistic demonstration data modelled on Zimbabwean e-GP procurement structures. \n\n The WebMCP integration is implemented through document.modelContext.registerTool() . Each tool has a clear description, structured JSON input schema, and an execution function connected to the application state. \n\n The application is deployed on Cloudflare Pages, with SPA fallback routing configured so that nested pages remain accessible when loaded directly. \n\n We tested the live application using ChatGPT's desktop in-app browser and Google Chrome with WebMCP testing enabled. \n\n Challenges we ran into \n\n One challenge was translating a complex procurement workflow into a clear experience that would be useful to both experienced suppliers and new users. \n\n We also had to connect agent tool execution to React application state while keeping the interface predictable. Browser implementations may provide tool input as either an object or a serialized JSON string, so the tool layer was designed to handle both formats. \n\n Another important challenge was deciding which actions should be automatic and which should require human approval. We chose to keep discovery and analysis read-only, while requiring confirmation before creating or updating bid workspaces. \n\n Finally, we converted the application into a reliable static deployment while preserving nested routes, responsive layouts, pagination, and WebMCP registration. \n\n Accomplishments that we're proud of \n\n \n Built a complete procurement intelligence experience rather than a standalone technical demo \n Implemented five functional WebMCP tools \n Connected WebMCP tools to live application state \n Added human confirmation for state-changing actions \n Deployed a working public application on Cloudflare Pages \n Verified tool discovery and read-only tool execution in ChatGPT's desktop in-app browser \n Added responsive layouts and pagination across the application's data-heavy views \n Published the source code with an open-source license \n Created a practical use case focused on suppliers and public procurement in Zimbabwe \n \n\n What we learned \n\n We learned that WebMCP works best when applications expose meaningful, task-oriented tools instead of forcing agents to reproduce every individual user-interface interaction. \n\n Structured schemas make agent interactions more reliable, while clear tool descriptions help agents understand when each capability should be used. \n\n We also learned that state-changing tools need strong human-in-the-loop safeguards. Agents can help users investigate and prepare decisions, but important procurement actions should remain transparent and explicitly approved. \n\n Most importantly, WebMCP allows a website to become an active workspace where humans and agents can collaborate rather than treating AI as a separate chatbot layered on top of the product. \n\n What's next for BidLens \n\n The next stage is to connect BidLens to authorized live procurement feeds and persistent backend storage. \n\n Future improvements include: \n\n \n Supplier accounts and team collaboration \n Real-time procurement notifications \n Document extraction and compliance checking \n More advanced tender and supplier matching \n Audit logs for agent activity and human approvals \n Persistent bid workspaces \n \n\n \n\n \n Built
