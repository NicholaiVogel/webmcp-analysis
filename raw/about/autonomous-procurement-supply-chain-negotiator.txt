When a port closes or commodity prices spike, procurement teams scramble across 5+ separate systems—checking inventory, calling freight forwarders, reviewing supplier health, and manually calculating landed costs in Excel. By the time they respond, they've lost hours and thousands of dollars. \n\n We built The Autonomous Procurement & Supply Chain Negotiator to solve this. We wanted to show that WebMCP isn't just for chatbots—it's for serious enterprise tools where humans and AI work together safely . \n\n The "aha" moment came when we realized WebMCP lets an AI agent orchestrate data from multiple sources in parallel , triggered by a single human gesture—something that was impossible before. \n\n \n\n What It Does \n\n The Autonomous Procurement & Supply Chain Negotiator is a real-time dashboard where: \n\n \n A global heatmap shows port congestion, supplier health, and active shipping lanes \n A priority slider lets the human express "Cost vs Speed" preferences \n A WebMCP agent fires 8 tools in parallel to analyze commodities, inventory, shipping routes, supplier health, and bulk discounts \n 3 alternative sourcing routes appear as clickable cards \n A PO draft is generated and placed in an approval queue \n Human approval (with cryptographic token verification) executes the final purchase order \n \n\n The agent does 99% of the work —data aggregation, scenario modeling, and drafting. The human does the 1% that matters —deciding to spend money. \n\n \n\n How We Built It \n\n Tech Stack \n\n \n Frontend: Next.js 15 + React Server Components + Tailwind CSS + shadcn/ui \n State Management: Zustand + React Query \n Charts & Maps: Recharts + Mapbox GL \n Deployment: Vercel (with Cloudflare edge caching) \n WebMCP: 8 tools registered via document.modelContext.registerTool() \n \n\n The 8 WebMCP Tools \n\n We registered strict input schemas for every tool: \n document . modelContext . registerTool ( { \n name : "fetch_commodity_prices" , \n description : "Fetches real-time spot prices for copper, lithium, crude oil, gold, and silver." , \n inputSchema : { \n type : "object" , \n properties : { \n commodities : { \n type : "array" , \n items : { type : "string" , enum : [ "copper" , "lithium" , "crude_oil" , "natural_gas" , "gold" , "silver" ] } \n } , \n currency : { type : "string" , enum : [ "USD" , "EUR" , "GBP" ] , default : "USD" } \n } , \n required : [ "commodities" ] \n } , \n execute : async ( { commodities , currency } ) = > { \n // Parallel fetch from CommodityPriceAPI + Live-Rates.com\n // Return { commodity: { price, change_24h, change_7d, volume } }\n } , \n annotations : { readOnlyHint : true } \n } ) ; \n\n // Plus 7 more tools:\n // - calculate_landed_cost\n // - analyze_supplier_health\n // - simulate_bulk_discount\n // - get_inventory_status\n // - assess_port_risk\n // - generate_po_draft (requires human approval)\n // - execute_approved_po (human-only)\n Critical Safety Pattern : Human - in - the - Loop ( HITL ) \nThe agent cannot execute purchase orders . WebMCP Flag Only in Chrome Canary\nEarly development was tricky because WebMCP requires Chrome 146 + with the #enable - webmcp - testing flag . We worked around this by building a graceful fallback— if WebMCP isn't available , the app runs in simulation mode with mocked tool calls so the UI still works for local development . \n\n 2 . Balancing AI Autonomy vs . Safety\nWe debated how much autonomy the agent should have . Too little → useless . Too much → dangerous . The two - tool split ( generate_po_draft + execute_approved_po ) was the perfect compromise—the agent does all the work but cannot spend money without human approval . \n\n 3 . Real - Time Data Integration\nCommodity APIs have rate limits and some require paid keys . We built a 5 - minute Cloudflare KV cache and used Promise . allSettled ( ) so one failing API doesn't break the entire orchestration . \n\n 4 . State Management\nCoordinating UI state ( slider value , selected route , tool outputs ) across React components required a robust Zustand store with distinct slices for UI , tool results , and agent reasoning logs . \n\nAccomplishments We're Proud Of\n✅ Sub - 800ms orchestration — 6 parallel tool calls , UI updates in under a second\n✅ Unforgeable approval system — Agents cannot bypass human approval\n✅ Full Next . js production app — Not a prototype , deployed on Vercel\n✅ Agent reasoning sidebar — Builds transparency and trust\n✅ Global heatmap — Real - time port congestion and supplier health visualization\n✅ 9 hours to deadline — Submitted on time ! \n\nWhat We Learned\nWebMCP is a Game - Changer\nBefore WebMCP , building this would have required a complex backend orchestrator , custom API routes , and WebSocket connections . WebMCP lets the browser handle orchestration natively , eliminating hundreds of lines of backend code . \n\nThe Browser is the New Orchestrator \nWith WebMCP , the browser isn 't just rendering UI—it' s coordinating data fetching , tool execution , and state updates . This shifts the architecture dramatically toward thin servers and intelligent clients . \n\nHuman - in - the - Loop is Essential\nEnterprise AI isn 't about replacing humans—it' s about augmenting them . The two - tool split with cryptographic approval tokens is a pattern we'll use in future WebMCP projects . \n\nWhat's Next\n🔹 Real API Integration — Replace mock data with CommodityPriceAPI , CerebroChain , and D & B APIs\n🔹 Multi - User Teams — Add team workspaces with role - based permissions\n🔹 Slack / Teams Integration — Notify procurement teams when critical alerts fire\n🔹 Predictive Analytics — Use historical data to forecast future disruptions\n🔹 Mobile App — Build a React Native companion for on - the - go approvals\n\nWhy This Wins the WebMCP Challenge\nCriterion How We Score\nWebMCP Leverage 8 tools with strict schemas , parallel orchestration , secure HITL pattern , AbortSignal cleanup\nExecution Full Next . js production app with real - time UI , deployed on Vercel , working live demo\nPotential Impact Solves a billion - dollar problem — supply chain disruptions cost 15 - 20 % of EBITDA\nCreativity & Ambition Slider - driven agent orchestration + global heatmap + unforgeable approval tokens\n \n \n\n \n Built With \n\n 15 api cerebrochain cloudflare commoditypriceapi gl mapbox next.js vercel webmcp \n \n\n \n Try it out \n\n \n \n \n autonomous-pied.vercel.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Samra Safdar \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n I try things \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Samra Safdar \n started this project\n \n —\n \n 2 days ago \n \n \n\n
