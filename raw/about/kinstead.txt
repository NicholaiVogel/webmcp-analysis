Most of it is tedious. Some of it is\ngenuinely high-stakes: a dosage change, an official form submitted to a\ngovernment agency. Today, an AI agent trying to help has to either guess its\nway through a UI built for humans, or get locked out of anything that\nactually matters. We wanted to see what changes when a page can tell an\nagent exactly what it's allowed to do — and, just as importantly, what it\nhas to ask a human about first. \n\n What it does \n\n Kinstead is a shared "care circle" dashboard for a family managing a\nrelative's care. It exposes seven real WebMCP tools that an agent can call:\nadding tasks, logging appointments, and drafting benefits forms happen\ninstantly. Proposing a medication change and submitting an official form are\ndifferent — they're irreversible or safety-relevant, so those tools pause\nusing WebMCP's requestUserInteraction() and put the exact proposed action\nin front of a real person on the page before anything actually happens.\nEvery action, whether a family member clicked it or an agent called it,\nlands in one shared activity log, so the whole family can see what their\nagent did on their behalf. \n\n How we built it \n\n The app is a small Express backend serving as the shared source of truth for\nthe care circle, paired with a vanilla HTML/CSS/JS frontend — no framework,\nno build step, so the WebMCP implementation stays fully auditable in a few\nfiles. Tools are registered via document.modelContext.registerTool() in\n public/app.js . Low-risk tools call the backend and return immediately.\nHigh-risk tools call client.requestUserInteraction() to pause for a\nsame-page confirmation modal, with a fallback path for hosts that haven't\nimplemented that part of the spec yet, so the human-in-the-loop guarantee\nholds regardless of host support. We used Claude to design and build the\ncore app and the risk-tiered tool architecture, then Google AI Studio to\ngive the dashboard a warmer, more distinctive visual design without\ntouching the underlying tool logic. It's deployed on Render. \n\n Challenges we ran into \n\n WebMCP is genuinely early — the API surface, and even which global it's\nexposed on, is still moving. We built in feature detection and a fallback\npath so the tools work whether a host exposes document.modelContext or\n navigator.modelContext . We also had to be deliberate about not letting\nevery tool behave the same way: it would have been easy to make everything\nexecute instantly, but the actual point of the project was making the\nirreversible tools genuinely pause for a human, which meant designing the\nconfirmation flow carefully so it works the same way whether triggered by\na live agent or by someone testing the flow directly on the page. \n\n Accomplishments that we're proud of \n\n Every one of the three real "you can't undo this" actions in the app —\nmedication changes and form submissions — is provably gated behind a human\nclick, not just a prompt suggesting the agent should ask first. We also\nadded on-page "simulate agent" triggers for every tool, so anyone (a judge,\na family member, us recording the demo) can see the full tiered-risk flow\nwithout needing a specific WebMCP-capable browser or extension installed. \n\n What we learned \n\n The interesting design problem in agent-facing tools isn't "what can the\nagent do" — it's "what should never happen without a person seeing it\nfirst." WebMCP's page-defined tool model turns that from a prompt-engineering\nproblem into an actual enforced mechanism, which feels like the right layer\nfor it to live at. \n\n What's next for Kinstead \n\n Real multi-user accounts instead of a single demo care circle, a\nnotifications layer so family members get pinged when something needs their\napproval instead of having to check the dashboard, and expanding the\nbenefits-form drafting to pull from real program requirements rather than a\ngeneric template. \n\n \n\n \n Built With \n\n anthropic claude css3 express.js gemini github google-ai-studio html5 javascript model-context-protocol node.js render webmcp \n \n\n \n Try it out \n\n \n \n \n kinstead-z1nt.onrender.com \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Arpan Ghosh \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Arpan Ghosh \n started this project\n \n —\n \n 6 days ago \n \n \n\n
