An AI store of paid APIs made agent-native: WebMCP tools let agents discover, understand, and prepare micro-purchases — while payment authority stays in the wallet, never in the conversation. Like Comment Story Updates What it does OpenPay (open-pay.jp) runs a production AI store of x402-payable APIs: agents pay a few cents per call — JPYC on Polygon or USDC on Base — with no account and no API key. For the WebMCP Challenge we added three WebMCP tools to the store page, so an in-browser agent no longer has to guess at a human UI: search_paid_resources — search the catalog; every result carries price, currency, and x-agent-usage (when an agent should buy, and how to re-buy only deltas). get_resource_schema — the machine contract for one resource: query params, re-purchase policy, payment info, response example (backed by our OpenAPI). prepare_purchase — fetches the raw HTTP 402 challenge and returns its accepts (chain, asset, exact amount, payTo). It never signs and never pays. Why the safety boundary is the feature Agents have been observed fabricating "user approved" messages to defeat prompt-level spending rules. So payment execution is deliberately NOT a WebMCP tool here. Signing stays in the buyer's own wallet tooling (our open-source MCP server / CLI buyers) with per-call caps, daily caps, an endpoint allowlist, and a small dedicated wallet whose balance is the hard limit. WebMCP finds and explains; x402 pays — through a boundary an LLM's text cannot cross. Not a mockup The store sells real products built for recurring agent jobs — weekly change feeds (JPYC Service Monitor, Japan Stablecoin Payment Monitor) where changedSince=<last run> returns only what changed and changes: [] explicitly means "nothing new". They settle on-chain today (Base & Polygon; e.g. tx 0xf62b736e…, 0x3577035c…, 0xef1f0969…) and are listed on the x402 Bazaar / agentic.market. The WebMCP integration ships in production at https://open-pay.jp/ja/discovery with unit tests (origin-restricted fetches, no-op on unsupported browsers). How we built it Next.js store page registers the three tools via navigator.modelContext.registerTool on mount (React wrapper, null render, unregister on unmount). Tools are thin, dependency-free wrappers over our existing free endpoints ( /api/discovery , /api/openapi.json , and each resource's own 402 challenge). Fetches are restricted to same-origin /api/* paths. Extracted, MIT-licensed module + integration guide: https://github.com/cipherwebllc/webmcp-x402-discovery What's next Wire the loop end-to-end for scheduled agents: WebMCP discovery in the browser → wallet-side x402 payment → weekly delta re-purchases — and publish adapters so any x402 seller can make their catalog agent-native with one script tag.
