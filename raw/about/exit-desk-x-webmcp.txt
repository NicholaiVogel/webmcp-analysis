Its free assessment asks eight questions and evaluates a company across revenue quality, founder dependence, financial health, competitive position, and timing alignment. \n\n The WebMCP Challenge gave us a simple question: \n\n What if ChatGPT did not have to operate Exit Desk by guessing how its interface works? What if Exit Desk could expose its actual capability directly to the agent? \n\n That became Exit Desk × WebMCP. \n\n What it does \n\n A business owner can describe their company to ChatGPT in ordinary language: \n\n \n “We do about $5M in revenue. Customers repeat but aren't contracted. I still own key client relationships. Our largest customer is about 15% of revenue. The team handles daily operations, margins are stable, our moat is reputation, and I'm exploring a sale.” \n \n\n Instead of clicking through Exit Desk's eight-question interface, ChatGPT discovers a WebMCP tool exposed by the site: \n\n run_exit_readiness_assessment \n\n ChatGPT translates the owner's natural-language description into the structured inputs required by Exit Desk and invokes the tool. \n\n Exit Desk then runs its existing deterministic assessment engine and returns the same score, dimension scores, weakest dimension, findings, and next-step information that the human-facing application produces. \n\n The human and the agent therefore work from the same authoritative result. \n\n Why WebMCP matters \n\n The important architectural distinction is that ChatGPT does not recreate Exit Desk's M&A logic. \n\n ChatGPT handles conversation, intent, and translation. \n\n Exit Desk remains the authoritative application performing the assessment. \n\n Without WebMCP, an agent has to infer the interface and manipulate eight separate questions. With WebMCP, the website declares what it can do and the structured inputs it requires. \n\n The interaction becomes: \n\n Natural language → ChatGPT → WebMCP tool → Exit Desk assessment → structured result \n\n This turns Exit Desk from a website an AI can read or click through into a capability an AI can reliably operate. \n\n How we built it \n\n The production Exit Desk assessment runs at mikeye.com/exit/score . \n\n For the challenge, we added a WebMCP integration using the imperative document.modelContext.registerTool() API. \n\n The tool defines a structured input schema for the eight assessment dimensions and maps those inputs into Exit Desk's existing assessment application. It invokes the same scoring and results logic used by the human interface, then returns structured output to the agent. \n\n The WebMCP source lives in the public GitHub repository and is deployed through Vercel. The production Webflow page loads that repository-backed implementation. \n\n We tested the integration using ChatGPT's in-app browser. ChatGPT successfully discovered run_exit_readiness_assessment , invoked it, and received Exit Desk's resulting score and dimension analysis. \n\n What we built during the challenge \n\n Exit Desk itself predates the WebMCP Challenge. \n\n The WebMCP capability does not. \n\n During the challenge period we: \n\n \n Designed the agent-facing assessment interface. \n Implemented run_exit_readiness_assessment . \n Defined the structured input schema and mappings. \n Connected WebMCP to Exit Desk's existing scoring engine and human-facing results. \n Deployed the integration to the production Exit Desk website. \n Tested the complete flow using ChatGPT's in-app browser. \n Added public implementation documentation and challenge-period source history. \n \n\n The GitHub commit history documents these additions separately from the pre-existing application. \n\n What we learned \n\n The most interesting lesson was that WebMCP is not primarily about making agents better at clicking websites. \n\n It can remove the need to click them. \n\n A website can retain ownership of its domain logic while allowing an AI agent to provide a much more natural interface to that capability. \n\n For Exit Desk, that means the AI does not become the M&A assessment engine. It becomes the conversational layer through which a founder can access that engine. \n\n What's next \n\n The same architecture can extend beyond the initial assessment. \n\n Future Exit Desk tools could help owners prepare diligence materials, identify buyer-readiness gaps, evaluate founder dependence, compare buyer types, and prepare for acquisition conversations. \n\n The broader idea is simple: \n\n The web is moving from machine-readable to machine-operable. \n\n \n\n \n Built With \n\n chatgpt javascript next.js openai typescript vercel webflow webmcp \n \n\n \n Try it out \n\n \n \n \n www.mikeye.com \n \n \n \n GitHub Repo \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n I built the WebMCP integration for my existing Exit Desk application, including the tool schema, connection to the live assessment engine, production deployment, and testing in ChatGPT's in-app browser.
