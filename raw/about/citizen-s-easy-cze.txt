Even in modern digital states like Thailand—where identity infrastructure such as ThaID has made remarkable progress in digital authentication—citizens still find themselves trapped in "form purgatory."\nLogging in is no longer the hardest step; what comes after authentication is the bottleneck. A citizen wanting to update a mailing address or register for a local municipal permit still has to manually navigate complex service directories, decipher bureaucratic jargon, and re-type 15 to 30 redundant fields (name, national identification number, sub-district, district, postal code, and contact information) over and over again for every different agency.\nWhen we discovered the WebMCP standard, a realization hit us: the web does not need another government portal or chatbot widget; the web needs to become machine-actionable. We asked ourselves:\n"What if citizens never had to fill out another public form? What if they could simply state their goal, and an AI agent collaborated with the browser to do the tedious mechanical work—while keeping the human fully in control and preserving strict data privacy?"\nThat question gave birth to Citizen's Easy (CZE). \n\n What it does \n\n CZE shifts the citizen-web interaction paradigm from "Form-First" (human as manual typist) to "Intent-First" (human as supervisor and decision-maker).\nNatural Intent Expression: Instead of navigating complex drop-downs, the citizen states what they need in conversational language (e.g., "I just moved to Ideo Sukhumvit 40, Room 502/14. Please update my contact address for public correspondence.").\nGranular, Privacy-Preserving Consent: CZE does not dump personal data into an opaque LLM context. Through WebMCP tools, the agent analyzes the intent and prompts the user with a Least-Privilege Consent Dialog, requesting only the specific data fields required (e.g., verified_name and registered_address, strictly omitting tax IDs, biometric tokens, or family trees).\nBidirectional WebMCP Orchestration: Once the human grants permission, the agent invokes client-side WebMCP tools:\nIt retrieves the verified credentials from a ThaID-compatible sandbox identity provider.\nIt parses the natural address into standard administrative hierarchy (Subdistrict, District, Province, Postal Code).\nIt dynamically populates the living form in the DOM and visibly highlights modified sections with gold focal indicators so the citizen can track changes in real time.\nValidation & Human-in-the-Loop Submission: The agent runs client-side integrity checks (\\text{Field Validation} = 100\\%) and prepares the application summary. The final submission is locked until the human performs an explicit visual verification and clicks "Approve & Submit". \n\n How we built it \n\n We designed CZE to run natively within modern WebMCP-enabled environments (such as Google Chrome with WebMCP flags and the ChatGPT in-app browser).\n┌─────────────────────────────────────────────────────────────┐\n│ Citizen (Human User) │\n│ Expresses Intent & Grants Consent │\n└──────────────┬───────────────────────────────▲──────────────┘\n │ │ Visual Feedback\n ▼ │ & Verification\n┌──────────────────────────────────────────────┴──────────────┐\n│ WebMCP Tool Registry Layer │\n│ (document.modelContext.registerTool API) │\n│ │\n│ ├── request_citizen_consent() │\n│ ├── get_verified_identity() │\n│ ├── get_registered_address() │\n│ ├── autofill_service_application() │\n│ ├── validate_application_rules() │\n│ └── submit_application() │\n└──────────────┬───────────────────────────────▲──────────────┘\n │ Execute Mutation │ Query State\n┌──────────────▼───────────────────────────────┴──────────────┐\n│ CZE Client Interface │\n│ - Feeding raw citizen records into an LLM context window violates fundamental data minimization standards (\\text{GDPR / PDPA}). We solved this by designing an intermediate Consent Handshake: the agent never queries the identity provider directly; it calls request_citizen_consent(), which renders a browser-native modal. The token is only released to the DOM once the human approves.\nBidirectional State Sync without Jitter:\nEnsuring that tool execution results from the WebMCP runtime synced seamlessly with React's internal state without causing race conditions or layout flickers required crafting deterministic action reducers for the form manager.\nDeterministic Address Resolution:\nThai administrative addresses consist of nested layers (Tambon, Amphoe, Changwat, Zipcode). When a user provides messy conversational text, mapping it accurately to official administrative data required a robust validation tool (validate_application_rules) that gives structured feedback back to both the agent and the human reviewer. \n\n Accomplishments that we're proud of \n\n True Human-Agent Co-Creation: We avoided the cliché of a standalone chat bubble. In CZE, the agent and the human share the same canvas—the agent fills, the human inspects, and the browser visually indicates every action.\nMeasurable Efficiency Gain: We reduced the time required to complete a complex municipal change-of-address form from an average of T_{\\text{manual}} \\approx 12\\text{ minutes} down to T_{\\text{CZE}} \\approx 35\\text{ seconds}, representing a speedup efficiency factor of:\nwhile reducing manual keystroke errors to essentially zero.\nFull WebMCP Standard Adherence: Every single action on the page is exposed via clear, discoverable, and well-typed schemas using the native WebMCP browser specification. \n\n What we learned \n\n WebMCP is the missing bridge between APIs and User Interfaces: Traditional APIs connect servers to servers; UI connects servers to humans. WebMCP connects agents to interactive user interfaces, allowing the agent to operate within the exact security and permission context granted by the human in the browser.\nAgent UX requires "Visual Legibility": When an agent executes tools, users feel uneasy if changes occur invisibly in the background. Adding visible highlight rings, smooth scrolling to active fields, and progressive disclosure cards dramatically increased user trust and satisfaction \n\n What's next for Citizen's Easy (CZE) \n\n Expanding Beyond Address Changes: Integrating additional high-friction citizen workflows, such as business license renewals, child allowance subsidies, and elderly healthcare registrations.\nOfficial Digital ID Gateway Integration: Collaborating with standard digital identity sandboxes (such as Thailand's Department of Provincial Administration guidelines for ThaID Relying Parties) to establish an open-source standard for citizen-agent interaction.\nMulti-lingual & Voice Accessibility: Leveraging web speech recognition to enable elderly or visually impaired citizens to access public services entirely through spoken dialect, making public governance accessible to every single citizen regardless of tech literacy. \n\n \n\n \n Built With \n\n agentic-web civic-tech css3 digital-id government-tech html5 human-in-the-loop javascript json-schema openai react tailwindcss thaid typescript vercel webmcp \n \n\n \n Try it out \n\n \n \n \n GitHub Repo \n \n \n \n cze-webapp-mcp-demo.netlify.app \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n novaonereport-rgb Thongchai \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n novaonereport-rgb Thongchai \n started this project\n \n —\n \n 2 days ago \n \n \n\n
