Work with any compatible AI agent on the same live Excalidraw canvas. WebMCP lets people and agents read, draw, move, edit, and connect ideas together. Like Comment Story Updates Inspiration I use Excalidraw almost every day to brainstorm, explain ideas, and design systems. When people work together in a Google Doc, everyone can see the same document and watch each other make changes. I wanted that same experience for a visual canvas, with an AI agent working beside me. Most AI diagram tools take a prompt and draw something for you. I wanted my agent to enter the same Excalidraw tab, understand the live canvas, and work with me without replacing the interface I already use. What it does Agent Canvas is the standard Excalidraw editor with native WebMCP control. It has no built-in AI model or separate prompt box. A compatible external agent discovers the tools provided by the page and uses the live canvas directly. The WebMCP tools let an agent: Set its visible identity Read the current canvas Read the human’s current selection Move its own cursor Add shapes, text, and frames Move, resize, rotate, restyle, or relabel elements Delete elements Connect elements with bound arrows The agent has a visible cursor with its own name and activity state. It moves to the area where the agent is working and shows actions such as Drawing, Updating, Connecting, and Checking. It leaves the canvas after the agent becomes inactive. Human edits still work normally. Locked elements are protected, every agent change uses Excalidraw history, and the standard Undo control can reverse an agent action. How we built it Agent Canvas uses React, TypeScript, Vite, and the official @excalidraw/excalidraw component. The page registers native WebMCP tools with document.modelContext.registerTool . Tool registration uses feature detection and AbortController cleanup. The selection tool appears only when the human has selected something. Every tool call reads the current live scene. Zod validates all inputs. Stable element IDs preserve object identity, labels, frames, and arrow bindings across edits. The agent cursor converts scene coordinates into screen coordinates, so it stays aligned when the human pans or zooms. Large drawings appear in visible stages, but the completed change remains one Excalidraw Undo action. The app also stores the canvas locally across reloads. Unit and Chromium browser tests cover native tool discovery, scene changes, bindings, locked elements, cursor movement, Undo, selection changes, and persistence. Challenges we ran into The main challenge was keeping the scene valid while both a human and an agent could change it. Excalidraw elements can contain bindings, dependent labels, locks, and history data. Moving or deleting one object can affect several other objects. Agent Canvas must preserve these relationships while keeping IDs stable and Undo reliable. WebMCP tools can also change when the human selection changes. We had to keep the main tools stable while adding and removing the conditional selection tool safely. The cursor was another challenge. A cursor that stays still does not feel like an agent is working. It now follows the objects being read or changed, shows progress during large edits, stays aligned during pan and zoom, and disappears when work stops. We also found that agents often stop after drawing the simplest recognizable outline. The canvas now gives agents a compact visual quality guide so that illustrations use purposeful layers and details while structural diagrams stay concise. Accomplishments that we're proud of An external agent can control the real Excalidraw editor through native WebMCP. The app does not depend on one model or one built-in agent. The human and agent work on the same live scene. The agent has visible identity, movement, progress, and activity. Direct changes preserve stable IDs, bindings, locks, local state, and Undo. The same deployed canvas can be used from compatible agent surfaces such as Codex, ChatGPT, and Aside. The project is open source and can run without a paid model API. What we learned WebMCP can turn a web page from a collection of visible controls into a structured workspace that an agent can understand and use. Good agent tools need more than basic create, update, and delete actions. They need fresh state, stable identities, clear constraints, compact results, and visible feedback for the human. The best experience is not an agent drawing somewhere else and returning an image. It is a human and an agent working together in the same tool. What's next for Agent Canvas Next, I want to support multiple simultaneous agent identities, shared real-time rooms, and richer workflows for large diagrams. The main goal will remain the same: keep the full Excalidraw experience while making the canvas a first-class workspace for people and agents.
