For example, ChatGPT can change the cough intensity, adjust the encounter distance, modify other parameters, and generate the coughing fit. \n\n The important part is that the human interface and the AI tools are not separate experiences. They operate on the same application state. \n\n A human can change a slider, then an AI can change it again, and the interface immediately reflects the result. \n\n The Audio \n\n All original cough sounds used in this project were recorded by me. \n\n No elderly men were recorded for this project. \n\n Instead of using stock audio or third-party cough samples, I performed and recorded the coughing sounds myself. The recordings are then dynamically processed by JavaScript to create variations in the final coughing fits. \n\n The application uses browser audio processing to alter characteristics of the recordings and combine them into different sequences depending on the current settings. \n\n In other words: \n\n The creator provided the cough.\nJavaScript provided the old man. \n\n WebMCP \n\n The application exposes its controls as WebMCP tools using document.modelContext.registerTool . \n\n This allows an AI agent such as ChatGPT to understand the actions available on the website without having to guess how to interact with the visual interface. \n\n The WebMCP tools connect directly to the same underlying state and functions used by the human-facing controls. \n\n For example, an agent can receive an instruction such as: \n\n “Set the cough intensity to 10, set the major blood vessel danger to 95, set the encounter distance to 1 meter, and generate the coughing fit.” \n\n The application then updates the corresponding controls and generates the result. \n\n This creates a simple demonstration of human-agent collaboration in which both sides can operate the same web application. \n\n How It Was Built \n\n The project was built with: \n\n \n JavaScript \n Vite \n Web Audio API \n WebMCP \n HTML and CSS \n Vercel \n \n\n The coughing audio is based on creator-recorded samples and is processed dynamically in the browser. \n\n The project does not require an external AI API for the website itself. Instead, it exposes capabilities through WebMCP so compatible AI agents can interact with the application. \n\n Why This Project? \n\n I wanted to build something that demonstrated WebMCP clearly without hiding the interaction behind a complicated application. \n\n The interface intentionally makes it obvious when a human changes a value and when an AI agent changes the same value. \n\n The absurd premise also makes the demonstration easy to remember. \n\n Many agent demos focus on productivity. \n\n This one focuses on a fictional phlegm-spitting old man coughing on the way home from school. \n\n Someone had to. \n\n Development \n\n This project was built under a tight hackathon deadline, so I intentionally kept the interface focused and relatively minimal in order to prioritize WebMCP interaction, reliability, and a working public demonstration. \n\n The final application is deployed publicly and can be controlled manually or through WebMCP in a compatible browser environment. \n\n What began as an extremely unnecessary coughing simulator became an experiment in giving humans and AI agents equal access to the same interactive web application. \n\n \n\n \n Built
