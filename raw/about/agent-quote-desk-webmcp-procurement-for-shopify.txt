Why I built this At Packrift, customers do not buy packaging by keyword. They buy by dimensions, material strength, pack counts, and landed cost. Freight alone can be 30–100% of the product cost. A buyer may have a supplier quote with inconsistent product names and simply want to know: do these alternatives fit, and what will I actually save? Answering that usually means spreadsheets, product tabs, freight math, and email. I built Agent Quote Desk so the buyer and agent can do that work in one shared, visible workspace. What the agent can actually do Paste a competitor quote from Uline, Amazon, or another supplier in any format. The agent reads the worksheet, matches each line to Packrift's catalog, adds the comparison rows on screen, calculates live freight, and totals the savings. Ask a product-page question such as "Will an 11 × 8 × 3.5 inch stack fit in this box?" The check_fit_in_this_product tool answers from live page context with no network request. For parcel-size orders, use Shopify's built-in update_cart and proceed_to_checkout tools in the same tab. For freight-class orders, use file_pay_ready_quote_from_worksheet . It requires explicit buyer consent and sends the result to Packrift's human-verified quote workflow. Nothing is auto-charged. The buyer sees every tool call mirrored in the Agent Desk panel. The agent is not working behind a curtain. Why this is a WebMCP use case Shopify's built-in tools are useful, but they are the same on every store. They do not know Packrift's box specs, freight rules, quote workflow, or what makes one product a safe substitute for another. WebMCP lets the merchant give an agent that missing domain knowledge inside the page where the buyer is already working. The result is not just easier navigation. It is a procurement workflow that ordinary browser clicking cannot reliably complete. webmcp.json: the giveaway inside the giveaway I also built and deployed webmcp.json , a declarative manifest for agent tools. The idea is simple: what robots.txt did for crawlers, webmcp.json can do for agent capabilities. A merchant lists tools in one JSON file, including static answers, MCP bridges, or HTTPS APIs with page-level scoping. The kit compiles them into live WebMCP tools at page load and refuses unsafe endpoints at compile time. Packrift's get_agent_guide tool ships this way, so an arriving agent can learn the store's workflows before it acts. Anonymous aggregate telemetry records only the tool and page type, never PII, and is public at https://packrift-webmcp-telemetry.packrift-co.workers.dev/stats . How I built it webmcp-merchant-kit is an open-source, zero-dependency layer that registers merchant tools alongside platform tools. It waits for document.modelContext , detects name collisions, scopes tools to pages, validates required input, shapes outputs for agents, and emits register/call/result/error events for the visible UI. The project provides 15 merchant tools across three scopes: six global tools, two product-page tools, and six desk-page tools, plus one tool compiled from webmcp.json . The same production registry serves three transports: in-page WebMCP, remote MCP over Streamable HTTP at https://mcp.packrift.com , and Shopify UCP at https://packrift.com/.well-known/ucp . The live theme integration is about 40 lines of Liquid and one 17 KB script. A bundled polyfill harness makes the complete flow reproducible in any browser. The hard parts and what I learned The first challenge was coexistence. A merchant kit cannot break Shopify's built-in tools or quietly shadow their names, so registration fails safely on collisions and page-scoped tools unregister cleanly. The native API also exposed two details that changed the implementation. executeTool expects the RegisteredTool object rather than a name, and the browser does not enforce inputSchema for the tool. The kit now handles both correctly and validates required fields itself. The final challenge was trust. Maximum autonomy is not always the right goal. A small parcel can go to checkout, but a freight quote should pause for buyer consent and human verification. The workflow makes that boundary explicit. The repository includes 10 automated tests plus a browser demo verifier. Real stakes Packrift is a working packaging distributor with 13,000 SKUs, five US warehouses, live freight rates, and real customers. This is not a mock storefront. Agent Quote Desk writes into the same human-verified pipeline that produces pay-ready quotes today. The project is a working demonstration of a bigger idea: merchants should be able to teach agents how their business actually works, while buyers remain in control and can see every step.
