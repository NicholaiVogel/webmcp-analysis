That becomes a serious problem when working with real-world data, especially economic data. \n\n While investigating whether construction activity changed Kenya's economic growth, I realized that observing two variables moving together does not mean that one caused the other. \n\n If construction changes by (\\Delta C) and GDP changes by (\\Delta GDP), we might observe: \n\n Δ C > 0 , Δ G D P > 0 \n\n But that does not automatically establish: \n\n C → G D P \n\n The first statement is an observation. The second is a causal claim. \n\n That distinction inspired EVIDENCE. \n\n I wanted to experiment with an AI research environment where the agent has to interact with evidence, distinguish observations from inferences, recognize uncertainty, and avoid turning weak evidence into strong conclusions. \n\n \n\n What it does \n\n EVIDENCE is an agent-native research laboratory. \n\n Instead of treating research as: \n\n Question → Answer \n\n EVIDENCE treats it as a process: \n\n Q → E → O → I → U → C \n\n where: \n\n \n (Q) = research question \n (E) = evidence \n (O) = observation \n (I) = inference \n (U) = uncertainty \n (C) = conclusion \n \n\n The agent can interact with structured evidence tools and update its understanding of the investigation as new information becomes available. \n\n I think of the research process as a changing state: \n\n S t + 1 = f ( S t , A t , E t ) \n\n where (S_t) is the current research state, (A_t) is the agent's action, and (E_t) is the evidence returned by the environment. \n\n This means the agent is not simply generating an answer. It is navigating a research state. \n\n Most importantly, EVIDENCE allows insufficient evidence to remain a valid outcome . \n\n \n\n How we built it \n\n I built EVIDENCE as a web application using React, Vite, JavaScript, and WebMCP . \n\n I started with the research interface and gradually built the agent interaction around structured tools. \n\n The main idea was to expose capabilities that allow an agent to inspect evidence instead of simply giving the agent a large block of information and asking it to summarize everything. \n\n The workflow became roughly: \n\n Research Question → Tool Action → Evidence → Updated State \n\n I also used real economic data while developing the concept, which helped me test the difference between what the data directly shows and what an AI might be tempted to conclude from it. \n\n For example, correlation can be expressed as: \n\n r = Cov ( X , Y ) σ X σ Y \n\n A strong correlation can tell us that two variables move together, but it does not by itself prove: \n\n X → Y \n\n That principle influenced both the research methodology and the architecture of EVIDENCE. \n\n \n\n Challenges we ran into \n\n The hardest challenge was not building the interface. It was deciding how an AI should reason about evidence . \n\n It is easy to make a system that produces a convincing paragraph. It is much harder to make one that recognizes when the evidence is insufficient. \n\n I also encountered several technical challenges during development: \n\n \n Vite development-server and Hot Module Replacement issues \n Port conflicts \n Import and configuration errors \n API authentication problems \n Environment-variable issues \n Iterating on the research interface \n Understanding how WebMCP should fit into the application \n Designing tools that are useful to both humans and AI agents \n \n\n One thing that helped me was applying the same state-based thinking to debugging. \n\n Instead of asking only: \n\n \n "What is broken?" \n \n\n I started asking: \n\n What state is the system in? \n\n What changed? \n\n What caused the transition? \n\n That changed the way I debugged the application. \n\n \n\n Accomplishments that we're proud of \n\n I'm proud that EVIDENCE became more than an AI interface. \n\n I managed to turn an idea about evidence-based reasoning into a working agent-oriented research environment. \n\n I'm especially proud of three things. \n\n First, the research model. \n\n The system explicitly separates observations, evidence, inference, uncertainty, and conclusions. \n\n Second, the agent interaction. \n\n I experimented with WebMCP to move beyond the traditional chatbot model and make the web application an environment that an AI agent can interact with. \n\n Third, the philosophy behind the project. \n\n I deliberately designed the system around the possibility that the correct answer can be: \n\n \n The available evidence is not sufficient to establish the claim. \n \n\n For me, that is more valuable than producing an impressive answer that the evidence cannot support. \n\n \n\n What we learned \n\n The biggest lesson I learned is that answer generation and research are different problems . \n\n An AI can be extremely good at producing plausible explanations while still making unsupported jumps between evidence and conclusions. \n\n Building EVIDENCE made me think about research as a dynamic process. \n\n If the current research state is (S_t), then new evidence can change it: \n\n S t + 1 = f ( S t , E t ) \n\n Sometimes the new evidence increases confidence: \n\n K t + 1 > K t \n\n Sometimes it should decrease confidence: \n\n K t + 1 < K t \n\n A good research agent therefore shouldn't always become more confident. \n\n It should become better calibrated to the evidence . \n\n I also learned that WebMCP changes how I think about web applications. A website can become more than something an AI reads. It can become an environment containing tools that an agent can discover and use. \n\n \n\n What's next for EVIDENCE \n\n The current version is a foundation. \n\n Next, I want to make the research process more rigorous and more auditable. \n\n Some of the things I want to build include: \n\n \n Statistical analysis tools \n Time-series analysis \n Causal inference tools \n Automatic contradiction detection \n Source and evidence provenance \n Hypothesis testing \n Reproducible research traces \n Research-state visualization \n Stronger agent evaluation \n More WebMCP-native capabilities \n \n\n I would also like to represent the investigation as an evidence graph: \n\n G = ( V , E ) \n\n where (V) contains observations, datasets, hypotheses, assumptions, and conclusions, while (E) represents relationships such as support, contradiction, and dependency. \n\n The long-term goal is to make it possible to look at an AI's research process and ask: \n\n What did it observe? \n\n What did it infer? \n\n What evidence changed its mind? \n\n Which assumptions did it make? \n\n And how strong is the final claim? \n\n That is the direction I want to take EVIDENCE: from an AI that simply answers questions toward an AI that can show the path from evidence to knowledge . \n\n \n\n \n Built With \n\n ai-agents javascript react vite webmcp \n \n\n \n Try it out \n\n \n \n \n evidence-gray-two.vercel.app \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n I designed and built EVIDENCE from the ground up.
