Those facts are already structured (name, version line, date, successor, source). A human needs a scannable board; an agent needs typed actions — not a screenshot of a table and not a private MCP server the human cannot see. \n\n Why WebMCP \n\n The page is the product and the tool host. On load we register list_upcoming_eols , get_eol_detail , and suggest_upgrade_path via document.modelContext.registerTool . ChatGPT's in-app browser or Chrome with WebMCP enabled discovers the same dataset the UI renders. No login wall, no second API for agents. \n\n Better user experience \n\n Without WebMCP, a maintainer either hunts vendor blogs and changelogs by hand, or lets an agent scrape HTML and hope the date is still in the DOM. Both drift. EOL Desk is one board for humans and agents: scan upcoming cutoffs, open a row, or call typed tools for JSON. One source of truth. \n\n People and agents together \n\n Before, asking what dies in 90 days meant the model guessed from training data or scraped pages. Now a person keeps the board honest while ChatGPT or Chrome WebMCP calls list_upcoming_eols , get_eol_detail , and suggest_upgrade_path on the same page. Shared structured facts, no scrape. \n\n How we built it \n\n Greenfield public page on Cloudflare Pages/Workers. On load we feature-detect document.modelContext (fallback navigator.modelContext ) and register three tools with the Imperative API against the same dataset as the table: list_upcoming_eols , get_eol_detail , suggest_upgrade_path . Tested with the ChatGPT in-app browser and Chrome 149+ chrome://flags/#enable-webmcp-testing . \n\n Judge access: none needed, public page. \n\n Challenges I ran into \n\n A 48-hour build window. Getting a public GitHub repo up under an existing RonnyKane account. Sorting out the difference between a Devpost portfolio project and actually attaching it to the hackathon. And the fact that WebMCP only works for judges in the ChatGPT in-app browser or Chrome 149+ with the testing flag enabled. \n\n Accomplishments that I'm proud of \n\n Shipped a public live URL, an MIT-licensed repo, and a sub-3-minute demo with all three tools registered on the page. \n\n What I learned \n\n The product is the page as the tool host. Humans and agents need one source of truth, not a scrape. \n\n What's next for EOL Desk \n\n Keep the calendar current and the tools stable through judging (Sep 4-21). \n\n \n\n \n Built With \n\n cloudflare cloudflare-pages javascript webmcp workers \n \n\n \n Try it out \n\n \n \n \n eol-desk.pages.dev \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n byron oldham \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n byron oldham \n started this project\n \n —\n \n 4 days ago \n \n \n\n
