We wanted to explore a different model: what if an AI agent could become a first-class user of a web application? \n\n That idea led to AG-Slide, a presentation editor built around WebMCP. The goal is not simply to generate slides with AI but to let a human and an AI agent collaboratively work on the same live presentation. \n\n What it does \n\n AG-Slide provides a real-time presentation canvas where users can create, edit, and organize slides while an agent can directly operate the application through structured tools. \n\n The application exposes four core tools: \n\n \n ``— create a new presentation slide \n ``— modify slide content \n ``— change the presentation theme \n ``— add data-driven metric cards \n \n\n Instead of an agent trying to understand buttons, DOM elements, or screen coordinates, it can use structured capabilities exposed by the application. \n\n For example, a user can ask: \n\n \n "Create a slide about market opportunity with three metrics." \n \n\n The agent translates that intent into structured tool calls, executes them, and the presentation updates immediately on the same canvas. \n\n Human + Agent Collaboration \n\n The most important part of AG-Slide is the shared application state. \n\n Humans can edit slides manually while the agent can modify the same presentation through tools. Every agent action is visible in the Agent Inspector, including the tool name, arguments, execution status, and result. \n\n This makes the interaction transparent instead of treating AI as a black box. \n\n How we built it \n\n Ag-Slide is built with Next.js, React, TypeScript, Tailwind CSS, Zustand, and Lucide React . \n\n The core architecture follows: \n\n User / Agent → Tool Call → Validation → Tool Executor → Zustand → Live Canvas \n\n We also built an agent simulator with a deterministic fallback so the core experience works without requiring an external AI API. This allowed us to focus on demonstrating the WebMCP interaction model reliably. \n\n Challenges \n\n The biggest challenge was designing the boundary between the agent and the application state. We wanted agent actions to be real application operations rather than simulated UI interactions. \n\n We also had to make tool execution observable and reliable while keeping the interface simple enough for a human to understand what the agent was doing in real time. \n\n What we learned \n\n Building Ag-Slide changed our perspective on agentic applications. The interesting question is not only "How can AI generate content?" but also "How can applications expose meaningful capabilities that agents can use?"\nWebMCP provides a compelling direction for this: instead of building AI around a UI, applications can make their functionality directly understandable and usable by agents. \n\n AG-Slide is our exploration of what that future could look like for creative software. \n\n \n\n \n Built With \n\n ai context css html javascript lucide model next.js protocol react tailwind typescript webmcp zustand \n \n\n \n Try it out \n\n \n \n \n GitHub Repo \n \n \n \n agslide.vercel.app \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n I independently designed and built Ag-Slide, including the application architecture, presentation editor, WebMCP tool integration, shared state management, Agent Inspector, tool execution system, and live human-agent collaboration workflow.
