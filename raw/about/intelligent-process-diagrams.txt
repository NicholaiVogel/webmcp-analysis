It may look like an ordinary diagramming tool, but under the hood it's a markdown-driven agent friendly security, governance, and process improvement machine powered by WebMCP! Like Comment Story Updates 1 Inspiration I've found that giving agents structure and tools greatly enhances how they operate. A process diagram can look complete while hiding the complexity in simple steps. I wanted to make diagrams something people and AI agents can inspect, test, and improve together. What it does This project turns a process map into an interactive workspace for human-agent collaboration with a massive amount of context behind each input, action, output, and relationship by adding markdown to each point in the process. An agent can read all of this structure context to draft a new process, inspect steps and connections, and test scenarios by simulating outcomes that expose possible gaps. Proposed repairs appear as suggested change that a person can review before approval, adding to the collaborative feel between you and the agent. The included demo explores an AI evaluation process: what happens if a sandboxed agent decides it wants to escape? Our agent can identify a missing review step and propose a repair before the infrastructure is ever built. Also took me forever to realize I couldn't use Luna with webMCP I'm happy to share more specifics if you'd like added feedback. Codex summarized our struggles below: WebMCP tools registered on the page but were not visible in every browser session. Native WebMCP testing required browser support, enabled settings, and correct host headers. Tool registration needed reliable retry, cleanup, and discovery checks. Tool inputs and outputs needed strict validation and clear safety annotations. Repair proposals needed exact graph and evidence references to reject stale requests. Agent-proposed drafts and repairs had to remain pending until human approval. Accomplishments that we're proud of Just finishing the challenge - everything feels SO busy lately. I believe the first safety net of agentic alignment is to remove ambiguity from instructions. If an agent is given an INTENT.md contract then agents can act with more clarity around vulnerable or critical systems where more deterministic outcomes are required. In this project, each node, port (node input and output point), and relationship have theirs own markdown and metadata. The result is a structured graph where every part can explain what should happen, why it should happen, what evidence is required, and where authority stops. This opens up a possible use case as an agent-readable intent contract - INTENT.md During the diagram buildout, a model could inspect the complete process to find ambiguous or missing rules, conflicting conditions, unsafe capability paths, and downstream consequences. The current export already provides stable IDs, explicit relationships, decision paths, and human-review boundaries. The next step would be to add typed permissions, prohibitions, invariants, data contracts, and authoritative branch conditions. This goes beyond instructions or skills by outlining a process end-to-end so an agent understands what's in scope and how to get from point A to point B in a safe and repeatable pattern.
