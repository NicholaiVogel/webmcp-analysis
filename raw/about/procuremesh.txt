AI agents can use these interfaces, but they often have to interpret the DOM, locate the correct controls and simulate human interaction. \n\n ProcureMesh explores a different model for the open web: websites exposing structured, trustworthy capabilities directly to agents while humans remain informed and in control. \n\n Procurement is a strong example because buying decisions involve structured requirements, supplier qualification, commercial comparison, compliance rules and actions that should not happen without appropriate human oversight. \n\n What it does \n\n ProcureMesh is an agent-native procurement marketplace built around WebMCP. \n\n A buyer defines a procurement mission such as: \n\n \n required service \n maximum budget \n delivery deadline \n minimum technical score \n minimum HSE score \n local-content requirements \n desired shortlist size \n \n\n Instead of forcing an AI agent to navigate the website by interpreting buttons and supplier cards, ProcureMesh exposes structured WebMCP tools that the agent can discover and use directly. \n\n The application supports capabilities including: \n\n \n search_suppliers — find and qualify suppliers against the buying mission \n inspect_supplier — inspect a supplier's commercial, technical and compliance information \n compare_suppliers — compare qualified suppliers using deterministic procurement rules \n create_shortlist — create a supplier shortlist \n draft_rfq — prepare a structured request for quotation \n submit_rfq — request simulated RFQ issuance with human approval \n get_audit_log — inspect the human and agent action history \n \n\n The same application state is visible to both the human and the agent, so users can see what the agent is doing rather than treating automation as a black box. \n\n Why WebMCP \n\n WebMCP is not an add-on to ProcureMesh; it is the core interaction model. \n\n A conventional browser agent may need to: \n\n \n understand the layout of a marketplace \n locate filters \n click supplier cards \n interpret tables \n fill forms \n track changing page state \n \n\n ProcureMesh instead exposes explicit capabilities with structured inputs and outputs. \n\n The interaction becomes: \n\n Human defines intent → Agent discovers WebMCP tools → Application validates business rules → UI reflects the action → Human approves consequential actions \n\n This creates a more reliable and transparent interface between websites and AI agents. \n\n Human + Agent Collaboration \n\n ProcureMesh demonstrates a division of work where each participant does what they are best suited to do. \n\n The human defines the procurement strategy, mandatory constraints and approval boundaries. \n\n The agent can rapidly search, inspect, compare and prepare actions. \n\n The application independently validates mandatory procurement rules. \n\n For example, a supplier cannot become acceptable simply because it has a strong overall score if it fails a mandatory HSE, budget, delivery or local-content requirement. \n\n For consequential actions such as issuing an RFQ, human approval remains part of the workflow. \n\n Our design principle is: \n\n The model proposes. Business rules validate. Humans approve consequential actions. \n\n How we built it \n\n ProcureMesh is implemented as a lightweight web application using React and TypeScript. \n\n The WebMCP integration uses the browser's document.modelContext.registerTool() interface to expose procurement capabilities with defined names, descriptions, input schemas and execution handlers. \n\n Both the normal human interface and WebMCP tools use the same underlying procurement business logic. This avoids maintaining separate rules for humans and agents. \n\n Supplier qualification is deterministic rather than generated by an LLM. \n\n Mandatory criteria include: \n\n \n budget \n delivery \n technical threshold \n HSE threshold \n local-content requirements \n \n\n Eligible suppliers can then be ranked using commercial, technical, HSE and delivery criteria. \n\n The demonstration uses fictional supplier data so that the complete workflow can be tested safely and consistently without exposing real supplier information. \n\n Agent Action Ledger \n\n One of the key features is the Agent Action Ledger. \n\n When an agent searches suppliers, inspects a company, performs a comparison, creates a shortlist or prepares an RFQ, the activity becomes visible in the application. \n\n This creates an auditable human-agent workspace instead of invisible browser automation. \n\n The ledger distinguishes between human and agent activity and records important workflow events such as approval requests, rejections and simulated RFQ issuance. \n\n Safety and Trust \n\n ProcureMesh follows a human-in-the-loop approach. \n\n Read-only research actions are separated from actions that change procurement state. \n\n Supplier-provided content is treated as untrusted data rather than executable instructions. \n\n Tool inputs are validated against explicit schemas and procurement rules. \n\n Consequential operations require additional controls rather than allowing an agent to perform them silently. \n\n All supplier names, pricing, scores, certifications and qualification information in the demonstration are fictional. \n\n Challenges \n\n One of the main design challenges was deciding what an agent should be allowed to do autonomously and what should remain under explicit human control. \n\n Another challenge was making WebMCP fundamental to the application instead of simply adding one demonstration tool to an otherwise traditional web app. \n\n We addressed this by designing the entire procurement workflow around reusable business capabilities that can be invoked by either the human interface or WebMCP. \n\n What we learned \n\n Building ProcureMesh changed the way we think about web interfaces. \n\n The future agent-accessible web may not be about teaching increasingly sophisticated models how to click every possible interface. \n\n A complementary approach is for websites themselves to expose useful, well-described and safely constrained capabilities. \n\n WebMCP creates an opportunity to make websites understandable to both humans and agents without removing human oversight. \n\n What's next \n\n ProcureMesh currently focuses on a controlled procurement demonstration. \n\n The broader vision is an open procurement ecosystem where supplier websites, marketplaces and enterprise platforms can expose standardized agent-accessible capabilities for: \n\n \n supplier discovery \n qualification \n RFQs \n commercial clarification \n catalogue queries \n availability \n compliance evidence \n tender participation \n order status \n \n\n ProcureMesh is an experiment in what procurement could look like when the open web becomes natively usable by both people and their agents. \n\n \n\n \n Built With \n\n css3 github html5 javascript localstorage react typescript verceltailwind vite vitest webmcp \n \n\n \n Try it
