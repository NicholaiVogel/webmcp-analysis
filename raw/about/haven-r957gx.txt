You either manually enter every transaction by hand, or you hand over your secure banking credentials to a third-party server via aggregators like Plaid. We believe AI can solve this friction, but sending sensitive bank statements to an external AI backend is a massive privacy risk. Most people simply refuse to do it. \n\n We built Haven to solve this using a zero-backend architecture powered by the WebMCP protocol. We were inspired by the idea that the frontend browser itself is powerful enough to be the entire application. \n\n ⚙️ What it does \n\n Haven is a completely client-side, React-based financial dashboard. There is no database. All state is securely persisted right in the browser's local storage. By opening Haven inside a WebMCP-enabled environment (like the ChatGPT desktop app), the frontend instantly registers custom WebMCP tools ( add_transaction , set_net_worth ) directly to window.modelContext . \n\n Users simply paste their raw, messy bank statements into the chat. The AI extracts the entities and executes our client-side WebMCP tools, instantly updating the React context state. Transactions appear, monthly spend calculates, and net worth dynamically updates—all without a single byte of financial data ever hitting a backend server. \n\n 🛠️ How we built it \n\n We built Haven using a modern stack focused entirely on the client side: \n\n \n Frontend: React (Vite) + TypeScript for type-safe components. \n Styling: TailwindCSS and Lucide Icons for a senior-grade, premium aesthetic that avoids the generic "AI dashboard" cliches. \n State Management: React Context API paired with custom useLocalStorage hooks to ensure data persistence across sessions. \n WebMCP Integration: We built a custom useWebMCP hook that intelligently polls for window.modelContext and registers strict, JSON-schema-typed tools ( add_transaction , set_net_worth ). When the agent triggers these tools, they directly manipulate the React Context state, bypassing the need for any API routes. \n Deployment: Vercel (configured with vercel.json for SPA routing, ensuring deep links work perfectly inside the ChatGPT in-app browser). \n \n\n ⚠️ Challenges we ran into \n\n The biggest challenge was bridging the gap between an external AI environment and our React application state. \nInitially, we explored building a Chrome Extension to inject the tools, but modern browser security policies (and a desire for a frictionless user experience) pushed us to rely on native WebMCP support. \n\n We also had to solve a race condition where the React app would load faster than the host environment could inject window.modelContext . We solved this by writing a resilient polling mechanism that waits for the context to become available before registering the schemas. Lastly, configuring Vercel to correctly route SPA traffic inside the ChatGPT embedded browser required some deep-dive debugging into routing rules. \n\n 🏆 Accomplishments that we're proud of \n\n \n True Zero-Backend Architecture: We proved that you do not need a heavy server-side MCP protocol to build highly ambitious, agent-native applications. \n Absolute Privacy: We created a powerful AI financial advisor with zero privacy risk. \n Execution & Polish: We strictly adhered to the hackathon judging criteria, delivering a premium UX that feels like a production-ready product. \n \n\n 📚 What we learned \n\n We learned the immense power of Client-Side MCP . Before this project, we assumed LLM integration required API keys, cloud functions, and backend tool execution. WebMCP flipped our mental model upside down. Learning to trust the client environment and exposing typed JSON schemas directly to the browser DOM opened our eyes to a whole new paradigm of privacy-first AI apps. \n\n 🚀 What's next for Haven \n\n Our next steps are to expand the WebMCP tool registry to include: \n\n \n analyze_spending_trends : Allowing the AI to read the local historical data arrays and output insights. \n CSV Parsing Tools: Enabling the agent to natively ingest full CSV exports from major banks entirely client-side. \n Cross-Device Sync: Exploring encrypted peer-to-peer sync (like WebRTC) so users can share their local dashboard across devices without a central database. \n \n\n \n\n \n Built With \n\n localstorage react typescript webmcp \n \n\n \n Try it out \n\n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Samuel Rex \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Samuel Rex \n started this project\n \n —\n \n 2 days ago \n \n \n\n
