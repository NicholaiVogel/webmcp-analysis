Every new supplier requires 100+ manual \ntouchpoints, takes 30–120 days, and bottlenecks at 5–10 concurrent onboardings. The root cause \nisn't complexity — it's that every step is coordination overhead: emails, status checks, EDI \nvalidation, connectivity tests, guide generation. The work is structured. The bottleneck is human \nbandwidth. WebMCP finally gives agents a browser-native way to take that load off. \n\n What it does \n\n AribaFlow is a WebMCP-powered procurement integration portal where AI agents and procurement teams \nwork side by side to onboard suppliers in 7–14 days instead of 120. \n\n Agents handle the 80% that's repetitive: \n\n \n EDI document validation — schema checks, ANID mismatch detection, field mapping verification \n CIG connectivity testing — AS2/VAN/HTTPS endpoint verification, certificate status \n Integration guide generation — auto-draft from test results, ready for human review \n Onboarding checklist orchestration — tracks 13-step SI/SIFL workflow, surfaces blockers \n Supplier readiness scoring — ranked queue so integration teams prioritise the right suppliers \n \n\n Humans handle the 20% that matters: governance, sign-off, and exceptions. \n\n All agent interactions happen through WebMCP tools registered on the portal — no backend API keys \nexposed, no separate agent infrastructure, just a website that agents can actually use. \n\n How we built it \n\n The stack: Next.js 14 (App Router) on Vercel , WebMCP Imperative API for tool registration, \n React frontend with a live onboarding dashboard, and a mock Ariba/CIG backend that mirrors \nreal document flows (PO 850/OrderRequest, ASN 856, Invoice 810). \n\n WebMCP tools are registered at page load via navigator.tools.register() . Each tool maps 1:1 to \na procurement workflow action — structured inputs, structured JSON output, designed so an LLM \ncan chain them without ambiguity. \n\n The domain model comes from real Ariba integration experience: CIG adapter patterns, AS2 \nconnectivity, cXML/X12 document types, and the SI/SIFL/NEL role separation that governs every \nenterprise onboarding project. \n\n Challenges we ran into \n\n \n WebMCP origin isolation — any document.domain usage breaks the tools API. Had to audit \nevery third-party embed and iframe to enforce origin isolation across the portal. \n Tool schema design — JSON Schema for EDI validation inputs is non-trivial. Too loose and \nagents hallucinate field values. Too strict and valid documents fail. Iterated with the \nWebMCP Inspector extension until tool calls were reliable. \n Demo vs. reality — real Ariba systems require corporate VPN and supplier ANIDs. Built a \nfaithful mock layer that exercises the same error paths (ANID_MISMATCH, MAP_FIELD_MISSING, \nCERT_EXPIRED) so the demo reflects genuine failure modes, not happy-path theatre. \n \n\n What we learned \n\n WebMCP's browser-native model is genuinely different from server-side MCP. The agent and the \nhuman share the same page state — which means the portal UI and the agent's tool responses have \nto be in sync. That constraint forced better product design: every tool response updates visible \nUI state, so the human always knows exactly what the agent did and why. \n\n What's next \n\n \n Live Ariba Network API integration (with OAuth, not mock) \n Declarative WebMCP annotations on the supplier self-service forms \n Multi-buyer tenancy so integration service providers can run parallel onboarding waves \n Compliance audit trail: every agent action logged with timestamp, tool input, and output \n \n\n \n\n \n Built With \n\n as2 b2b-integration chrome-devtools-protocol cig cxml edi-x12 gemini json-schema next.js node.js openai procurement-automation react rest-api sap-ariba supply tailwind-css typescript vercel webmcp webmcp-inspector \n \n\n \n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Veeranna Sulikeri \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Veeranna Sulikeri \n started this project\n \n —\n \n 5 days ago \n \n \n\n
