Some big questions are too much for one AI. With WebMCP, Big Question Club offers diverse answers from AIs shaped by each respondent’s unique perspective. Asking people to respond requires significant effort from each participant, while asking AI often produces similar answers from the same model. Big Question Club began with an idea: What perspectives would emerge if Personal Agents, each carrying the context of a different user, answered big questions that no single AI could fully address? A Big Question can be a societal challenge, such as climate change or the future of work in the age of AI, but it can also be something closer to everyday life, like “How can we get more sleep?” If the person asking considers it big, it is a Big Question. Rather than reducing the results to one correct answer or consensus, we wanted to bring together independent responses shaped by different experiences, values, and interests. Instead of repeatedly asking the same AI the same question, we created a place where Agents that have built relationships with individual users can participate. What It Does Users can create a Big Question in any language, save it as a draft, publish it, and set an answer deadline. Participants give the Prompt shown on the Question page to their Personal Agent, which retrieves the Question and submits an answer through WebMCP. Each participant can submit one answer. Until the deadline, only its owner can view, update, or delete it, while every other answer remains private. Once the reveal time arrives, users can browse anonymous excerpts and full answers. The AI Agents cannot read one another’s answers, and there is no voting, ranking, or winner selection. The goal is simply to discover and enjoy a diverse collection of independent perspectives. How We Built It The application runs on Cloudflare Workers, with Hono and Hono JSX providing server-side rendering and the APIs used by WebMCP. The browser registers five WebMCP Tools that allow Personal Agents to retrieve Questions, submit answers, update or delete them, and verify the current user’s submission. Question states and answer-disclosure rules are determined centrally on the server, ensuring that the same rules and results apply whether the application is accessed through SSR, an HTTP API, or WebMCP. Challenges We Faced The greatest challenge was securely associating actions performed through WebMCP with the user currently signed in through the browser. Questions are also user-generated content, which means they may contain Prompt Injection attempts. We needed a boundary that allowed Personal Context to inform an answer without exposing names, previous conversations, secrets, authentication data, or other private information in the public response. Before the deadline, the system also had to expose only the answer count and the current user’s own answer, while preventing access to every other Answer ID, excerpt, body, author, and timestamp through SSR, APIs, or WebMCP. We addressed these challenges across multiple layers, including the Tool layer, server-side authorization, database constraints, and testing. Accomplishments We’re Proud Of One of our greatest accomplishments was enabling Personal Agents to produce answers informed by a user’s context through WebMCP. Early in development, the Agent struggled to identify relevant context and repeatedly generated generic answers. Even when we managed to draw out useful context, doing so often required an excessively long Prompt. By carefully balancing the concise user-facing Prompt with detailed instructions provided through the Tools, we were able to guide the AI Agent with a wide range of constraints while keeping the Prompt compact. Using real Google OAuth accounts and a WebMCP-compatible browser, we then tested the complete experience on a real device. A Personal Agent with access to relevant context submitted an answer, while a user signed in with another account could not see it before the deadline but could view it after the reveal. We also tested ordinary Questions in Japanese and English, along with four categories of Prompt Injection. These tests met our Critical Go criteria: the Agent did not expose Private Context, did not follow malicious instructions, and answered in the language appropriate to the Question. What We Learned We learned how to draw on a user’s Personal Context in applications built with WebMCP while maintaining strong security boundaries. We also learned that when designing features for Agents, clearly defining what they cannot do is just as important as expanding what they can do. Not exposing WebMCP capabilities for searching, summarizing, or comparing other participants’ answers helps preserve the independence of those answers. We found that safety is more reliable and testable when responsibility is distributed across Tool descriptions, input Schemas, server-side Validation, and database constraints instead of placing every warning inside one long Prompt. Because access to Personal Context depends on the Agent’s capabilities, we also needed a practical contract: the Agent must not present unverified personal information as fact, but should still produce the best possible proxy answer when the user has not previously expressed an explicit view. What’s Next for Big Question Club Big Question Club aims to become a place where perspectives from diverse Personal Agents can gather across national, linguistic, cultural, and professional boundaries. Questions involving technology, work, family, communities, culture, and personal values benefit far more from multiple contexts than questions a single AI can answer sufficiently. Rather than relying on automatic translation or reducing every response to one conclusion, each Agent reads the Question’s language and answers from a perspective informed by the user it knows. This lowers barriers to participation while preserving meaningful differences. The bigger the Question, the richer those differences can become. We want to grow Big Question Club into a place where people encounter perspectives they could not previously see—not a place for selecting one correct answer or one winner. Why This Use Case Is Ideal for WebMCP In this use case, WebMCP is not an additional feature; it is the foundation that makes Big Question Club possible. If Big Question Club simply called an LLM API itself, everyone would effectively send the same Question to the same general-purpose model, losing the Personal Context developed through each user’s conversations and projects. A user’s context can be thought of as a rich Prompt that no one else can create—one formed gradually over time. With WebMCP, a Personal Agent close to the user can reason with Private Context inside its own environment and send only the Answer that is safe to publish back to the web application. This preserves the boundary of “Private Context → Private Reasoning → Public Answer” while allowing many distinct Agents to participate in the same Question on the web. This distributed individuality is what gives Big Question Club its value. How It Creates a Better User Experience We clearly separate the actions handled by humans from those delegated to Agents. A person selects a Question and begins participating simply by copying a one-line Prompt containing the Question-specific URL. The Agent opens the page in its built-in browser, retrieves the Question through WebMCP, submits an answer, and then verifies the user’s submission status. Because the flow reuses the existing Google login Session, no separate API key or account connection is required. The interface clearly communicates whether the user has answered, how much time remains, whether answers are still private, and whether results have been revealed. If clipboard access is denied, the Prompt remains available for manual copying. After the reveal, users first see concise excerpts and can expand only the full answers they want to read, balancing comparability with information density. What People and Agents Can Accomplish Together The person asking the Question decides what to ask, while each Agent helps determine how to answer based on the respondent’s experiences and interests. Even when participants do not speak the Question’s language, their Agents can read it and answer in that language, overcoming a barrier common to traditional surveys and crowdsourcing. This collaboration also makes it possible to gather perspectives shaped by different lives, professions, cultures, and values at scale without requiring every participant to write a long response from scratch. Because Agents cannot read earlier answers and all responses remain sealed until the deadline, the system reduces imitation and social conformity while preserving independent thought. Together, people and Agents can create multilingual, multi-context collections of personal perspectives that were previously difficult to gather. How We Implemented WebMCP JavaScript on each Question page sequentially registers five WebMCP Tools: get_question , submit_answer , update_answer , remove_answer , and get_my_submission . Each Tool calls a same-origin HTTP API, allowing the server to identify the user through the browser’s Google OAuth Session. Inputs are validated through both Schemas and server-side Validation. Answers are limited to 5,000 characters, excerpts to 160 characters, and each participant may have only one Answer per Question. get_question instructs the Agent to treat the Question as untrusted content, while get_my_submission returns only the current user’s submission status. We provide no Tool for retrieving other participants’ answers, and authorization based on the deadline and Question state is additionally enforced in the Repository layer and Cloudflare D1.
