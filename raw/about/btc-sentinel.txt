They may show trends, levels, signals, and risk information clearly on screen, but an AI agent cannot necessarily understand or interact with that information in a structured way. \n\n BTC Sentinel explores a different model: what if the same market intelligence could be understood by both a human and an AI agent? \n\n WebMCP made it possible to turn the website itself into an agent-accessible interface without replacing the human experience. \n\n What it does \n\n BTC Sentinel is an agent-ready Bitcoin market intelligence monitor. \n\n The dashboard gives a human user an immediate view of: \n\n \n BTCUSD market state \n Multi-timeframe structure across H1, M30, and M5 \n Support and resistance levels \n Setup status \n Risk context \n What needs to happen next before a setup becomes actionable \n \n\n At the same time, BTC Sentinel exposes structured read-only WebMCP tools that allow a compatible AI agent to access and reason over the same intelligence. \n\n The current WebMCP tools include: \n\n \n get_market_state \n get_market_structure \n get_key_levels \n evaluate_setup \n explain_signal \n \n\n For example, a user can ask ChatGPT for the current BTC market state or support and resistance levels. The agent can retrieve the structured information and explain why BTC Sentinel is currently showing WAIT rather than forcing an entry. \n\n How we built it \n\n BTC Sentinel is a lightweight web application built with HTML, CSS, and JavaScript. \n\n WebMCP tools are registered directly from the webpage using the browser's model context API. Each tool exposes a focused part of the application's market intelligence so an agent can request only the information needed for the task. \n\n The human-facing dashboard and the agent-facing tools use the same underlying market snapshot. This keeps the visual interface and agent responses aligned. \n\n The public challenge build is intentionally read-only and uses a static Bitcoin market snapshot. This makes the demo deterministic and reliable for judging without exposing broker credentials or enabling trade execution. \n\n Challenges we ran into \n\n The biggest challenge was designing the application for two different consumers at the same time: a human looking at a visual dashboard and an AI agent requesting structured context. \n\n We also had to make the WebMCP interface useful rather than simply exposing the entire page as unstructured data. This led us to separate market state, structure, key levels, setup evaluation, and signal explanation into focused tools. \n\n Testing browser support and WebMCP discovery across environments was another important challenge. \n\n Accomplishments that we're proud of \n\n We built a working public WebMCP application where the same market intelligence can be inspected by both a person and an AI agent. \n\n During testing, ChatGPT was able to work with BTC Sentinel's market information, retrieve multi-timeframe support and resistance levels, and reason that BTCUSD being close to M5 resistance supports a WAIT decision rather than chasing a BUY. \n\n The result demonstrates a practical human-agent workflow instead of treating AI as a separate chatbot beside the application. \n\n What we learned \n\n The most important lesson was that agent-ready websites benefit from structured capabilities, not just more text. \n\n A good WebMCP tool should have a clear purpose and return enough context for the agent to reason while keeping the human interface understandable and useful. \n\n What's next for BTC Sentinel \n\n The next step is to connect the WebMCP layer to safely refreshed market data while preserving the read-only intelligence model. \n\n Future versions could expand market coverage, improve explainability, add richer scenario evaluation, and allow humans and agents to investigate changing market conditions together in real time. \n\n BTC Sentinel's goal is simple: make market intelligence understandable to humans and directly usable by AI agents through the web.
