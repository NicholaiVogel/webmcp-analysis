An agent can discover the page's structured remember_note WebMCP tool and pin the same kind of note directly. \n\n Both paths update the same visible card, and agent-made changes are clearly labeled Pinned by Agent . \n\n The result is deliberately simple: the agent acts through a capability the page explicitly declares, while the person sees exactly what changed and retains normal control. \n\n How I built it \n\n The project is a dependency-free static site built with HTML, CSS, and JavaScript. \n\n It registers one WebMCP tool with: \n\n document.modelContext.registerTool(...) \n\n The tool is: \n\n \n remember_note \n one required string input \n limited to 180 characters \n executed through the same application function used by the human form \n reflected immediately in the visible UI \n \n\n There is no backend, account, database, analytics, cookie, upload, or private system connection. \n\n The project is deployed publicly with GitHub Pages and the repository includes an MIT license. \n\n Challenges I ran into \n\n The biggest challenge was proving the real agent path rather than stopping at code that merely looked correct, buy trial and error. \n\n Ordinary Chrome on my development machine did not expose the WebMCP capability I needed for the final proof. The working validation therefore had to happen against the public HTTPS deployment through ChatGPT's WebMCP-capable in-app browser. \n\n That final test proved the important part: ChatGPT discovered remember_note , invoked it, and the live page visibly changed to show the result as Pinned by Agent . \n\n Accomplishments that I'm proud of \n\n This project now has a complete end-to-end proof: \n\n \n a public HTTPS application \n a public repository \n an MIT license \n a WebMCP tool that can be discovered by an agent \n successful live agent invocation \n a visible result a human can immediately verify \n a normal human interaction path that remains available alongside the agent path \n \n\n What I learned \n\n The smallest credible WebMCP experience does not need to be a large agent platform. \n\n A useful pattern can be much smaller: \n\n Declare one useful capability, let an agent invoke it directly, make the result visible to the human, and preserve ordinary human control. \n\n That creates a cleaner relationship between webpages and agents than forcing the agent to infer controls or imitate a person. \n\n What's next for Eyelet WebMCP Probe \n\n The probe is intentionally small, but the pattern can expand to other bounded webpage actions where explicit, typed capabilities are safer and clearer than UI guessing. \n\n For this Challenge, though, the focus is the proof itself: one declared capability, one successful agent invocation, and one visible human-verifiable result. \n\n \n\n \n Built With \n\n chatgpt css github html javascript pages webmcp \n
