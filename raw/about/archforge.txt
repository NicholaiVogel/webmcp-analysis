WebMCP lets an agent safely\ncreate, change, validate, and export the same living architecture model a\nperson sees, instead of returning disconnected chat output. \n\n How does it create a better user experience? \n\n People and agents work on one inspectable architecture. The human provides\ncontext and makes final choices; the agent makes structured changes and\nanalysis. Recommendations explain rationale and tradeoffs, while Signals shows\nevery agent action and result. \n\n What can people and agents do together that was difficult or impossible before? \n\n Together, they can turn requirements and constraints into a provider-neutral\narchitecture, evaluate AWS or Azure options, identify risks, and export a\nvalidated design—all while keeping decisions visible, editable, and reversible. \n\n How did you implement WebMCP? \n\n ArchForge detects document.modelContext and registers typed, runtime-validated\nWebMCP tools over its application services. UI and agent actions share the same\ncommand path; tools return structured results, mutation details, and safe\nerrors. The design_system workflow validates requests before making changes\nand reports each step. \n\n \n\n \n Built With \n\n next vercel webmcp \n \n\n \n Try it out \n\n \n \n \n archforge-tau.vercel.app \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Amit Sharma \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Amit Sharma \n started this project\n \n —\n \n 2 days ago \n \n \n\n
