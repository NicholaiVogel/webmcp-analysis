The useful question is often simple: “What needs my attention, and what should I do next?” IWB Home Base explores how an owner and an AI agent can answer that question together inside one shared workspace. \n\n What it does \n\n The demo brings active projects, prioritized attention items, business opportunities, and follow-up drafts into one command center. The agent can inspect the business, investigate a specific project, and prepare a follow-up when the human asks. The resulting draft appears immediately in the same interface the owner is viewing. \n\n For example, the agent can identify an unanswered estimate for Cedar House Bar, retrieve its project context, and prepare a follow-up for human review. Every draft is marked as requiring human approval. The demo has no sending capability. \n\n Why WebMCP matters \n\n Five structured browser tools turn the app into a collaborative workspace: \n\n \n get_business_snapshot: understand the current business state. \n get_attention_items: inspect priorities and recommended next steps. \n get_project_context: investigate a specific project with bounded context. \n get_active_opportunities: review potential work and follow-up opportunities. \n prepare_follow_up: create a local draft requiring human approval. \n \n\n The tools and the human interface use the same in-memory state. The agent can work with explicit project identifiers and structured context, and its draft becomes visible in the app without a reload. This reduces the need to copy project details into a separate conversation and manually transfer the result back. \n\n How it was built \n\n The standalone challenge edition uses React, TypeScript, and Vite, with deployment on Netlify. It registers five tools through browser WebMCP and connects them to the shared demo state. The repository includes source code, synthetic fixtures, local setup and validation commands, and an MIT license. The human interface also works in a standard browser; agent tool use requires a WebMCP-compatible environment. \n\n Design challenges and lessons \n\n The central design challenge was making agent action useful while keeping its scope clear. Read tools expose bounded business context, while the action tool only creates a local draft. The shared-state design makes the result visible to the human and keeps review part of the workflow. It demonstrates that useful human-agent collaboration depends on clear capabilities and visible outcomes as much as on natural-language interaction. \n\n Impact and next steps \n\n The intended audience is small project-based businesses whose owners juggle delivery, client follow-ups, and new work. This demo shows a concrete path from identifying an issue to preparing the next action. Future work could add persistent state, editing and approval workflows, and carefully scoped live integrations. \n\n Challenge scope \n\n I Wood Build Home Base existed before the challenge. This submission is a new standalone synthetic edition; the five-tool WebMCP integration, shared demo state, safety boundary, and challenge presentation are the challenge-specific work. All business data is fictional. There are no real customer records, live integrations, external APIs, or persistent storage. \n\n \n\n \n Built With \n\n react \n \n\n \n Try it out \n\n \n \n \n iwb-webmcp-challenge.netlify.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n ben Rawson \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n ben Rawson \n started this project\n \n —\n \n 3 days ago \n \n \n\n
