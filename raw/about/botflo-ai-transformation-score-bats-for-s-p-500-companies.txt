BATS — BotFlo AI Transformation Score — is a 0–100 rubric for how seriously an S&P 500 company talks about AI transformation: a total, a sector read, and fifteen dimensions (including hype ). Long reports cite the transcript. The catalog at score.botflo.com is basically a big sortable table. That’s fine if you already know the ticker and just want to open one report. It doesn't work quite as well if you ask something like “average BATS score for healthcare sector” or “industrials ranked by hype” — you’re scrolling, filtering in your head, maybe exporting to Excel. What you actually want is a query and a chart, not another row in a grid. This page puts the season snapshot in the browser: a gallery of 25 charts, DuckDB for ad-hoc SQL, and WebMCP so an agent can drive the query surface instead of guessing at clicks. Gallery — fixed views of the snapshot (25 chart cards). SQL tab + charts — you or an agent asks a question; the page switches to SQL, runs it in-browser, draws only chart types that fit the result. Company report — click a ticker in the result table and you land on the full BATS write-up at score.botflo.com. In the demo I use UnitedHealth: 79 , tied for the top in Health Care. It’s a slideshow-style report, not a wall of text — each claim links straight into the earnings transcript and highlights the line it came from. The Q&A section is broken out question by question, same drill. The company report also includes the general AI Transformation score as well as the sector specific AI score. People + agents (WebMCP). The page registers ten tools on document.modelContext || navigator.modelContext . The recorded demo uses WebMCP - Model Context Tool Inspector in Chrome, with a Gemini API key already stored in the extension. That client only works if Chrome WebMCP is on: chrome://flags/#enable-webmcp-testing . The extension is not mentioned in the video; the flag is not either. Prompts that actually ran: “Show me the top seven companies in the health care sector.” → SQL tab, result table, charts underneath. Click UNH → cited report. “Show me the top five companies in industrials sector by hype.” → hype is 0–6 ( hype_vs_execution_balance , dim 11). CHRW is 6/6 (talk, not execution). Any of the fifteen fields can be the sort key; the tools keep SQL on real columns. How I built it I built this as a new static page for the contest — no backend, no build step. The snapshot ships as three JSON files ( reports , scores , dims ); DuckDB-Wasm loads them in a worker so you can run SQL in the browser. The gallery is twenty-five fixed views I wired up ahead of time; the SQL tab is the escape hatch when you want something the gallery doesn’t cover. Chart tabs only light up when the result shape actually fits (seven rows can be a bar chart; four hundred tickers can’t). WebMCP tools register as soon as the page loads, but run_sql won’t do anything useful until DuckDB is up. Deployed on Cloudflare Pages. First deploy failed because I’d vendored duckdb-eh.wasm — 32 MiB, and Pages caps files at 25 MiB. Moved the Wasm bundle to jsDelivr and kept the repo static. For the demo I used Chrome with WebMCP turned on via chrome://flags/#enable-webmcp-testing , plus WebMCP - Model Context Tool Inspector talking to Gemini. That flag isn’t optional; without it the extension can’t reach document.modelContext . The gallery and SQL tab work fine for a human with no WebMCP at all — the agent loop just doesn’t. How I used WebMCP Instead of making the model guess at DOM clicks, I exposed what the page already does as ten tools: peek at the schema ( get_schema ), set gallery filters ( set_filters ), browse or jump to a chart ( list_charts , show_chart ), pick a ticker or sector ( select_mark ), open the cited report ( open_report ), run SQL and flip chart views ( run_sql , list_active_views , set_sql_view ), or pull back a small result slice ( get_result ). In the video I drive all of that through WebMCP - Model Context Tool Inspector — type a prompt, watch the SQL tab update, charts appear underneath. Flip the Chrome flag off and the extension has nothing to talk to. The bit that actually felt different from a normal chatbot: we’re looking at the same screen. I’m not pasting the snapshot into Gemini and hoping it remembers column names; the agent calls run_sql , the query runs in DuckDB on my machine, and we both stare at the same table. If I disagree with a ranking I can see the SQL. If I want the transcript I click through to score.botflo.com. The agent isn’t sitting on a private copy of the S&P file. Challenges Deploy. Cloudflare Pages rejected the first build because duckdb-eh.wasm was 32 MiB and their cap is 25 MiB per file. Obvious fix in hindsight — host the Wasm on jsDelivr, ship only HTML/JS/JSON from Pages. Chart choice. I didn’t want fifteen chart types always visible; most would be nonsense for a given result. Seven health-care rows → bar chart or table, both fine. Four hundred tickers → maybe a histogram, definitely not a packed bubble chart. So the SQL tab recommends views and grays out the ones that don’t fit. WebMCP plumbing. This isn’t “install an SDK and you’re done.” The page registers tools on document.modelContext , but the client that calls them is a Chrome extension that only works when WebMCP testing is enabled in flags. Forget the flag and you get a perfectly good viz site with no agent path — which is fine, but it tripped me up while testing. What I learned WebMCP is worth it when the agent’s job is to change what you see — run a query, filter a sector, scroll to a chart, open a report. It’s not worth it if you just shovel the whole dataset into the model’s context and treat the tools as decoration. The whole point of DuckDB in the browser is that the agent queries a few rows at a time and you verify on screen, not that it memorizes 451 companies. Built with DuckDB-Wasm (jsDelivr), WebMCP ( document.modelContext || navigator.modelContext ), Chrome WebMCP testing flag, WebMCP - Model Context Tool Inspector , Gemini (via that extension), Cloudflare Pages, Observable Plot, vanilla JavaScript, SQL, BotFlo BATS snapshot. How to test Video doesn’t show this setup. Do it in this order: Chrome. Open chrome://flags/#enable-webmcp-testing and enable WebMCP . Restart Chrome. The Inspector won’t work without this.
