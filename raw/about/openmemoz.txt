Like Comment Story Updates 00 01 02 03 04 05 06 07 08 09 10 11 Inspiration Content discovery is fragmented. The same story surfaces across multiple apps, each optimizing for engagement rather than what the reader actually wants. Long-form content on YouTube has incredible depth, but finding the right video takes longer than watching it. And none of these platforms are agent-native. The vision was a consolidated personal content library where AI agents curate open sources and the reader decides what to read. Not another algorithmic feed, but a place where agents search the web, summarize videos, discover discussions on Bluesky and Mastodon, and organize it all into a newspaper the reader can actually use. WebMCP made it possible. Chrome 150 shipped document.modelContext.registerTool() , which lets a web page expose structured tools to any AI agent visiting it. No extensions, no API keys. The browser becomes a User-Agent Generated Content (UAGC) platform — users direct, agents curate. What it does OpenMemoz exposes 36 WebMCP tools to any visiting AI agent. The agent reads the current edition, searches stories, discovers content from YouTube, Bluesky, and Mastodon, writes original articles, embeds videos, manages reader preferences, and reshapes the newspaper layout. Everything happens through the browser's native tool-calling protocol. The reader experience is a newspaper: a hero story with an embedded YouTube video, a sidebar with text stories, a mid-row section, a video feature row, and a below-fold masonry grid. Thirteen color palettes, four visual styles (flat, glass, neumorphic, paper), two layout modes. The agent experience is a structured workflow. Here is what a typical interaction looks like: User tells ChatGPT: "Discover trending YouTube videos, read the transcript of the best one, write a summary, and add it as my hero story." Agent calls discover_youtube_content to find trending videos Agent calls get_youtube_video to read the full transcript of the top result Agent writes an original summary from the transcript, calls add_story with pinAsHero: true The newspaper layout recalculates instantly: new hero with embedded video, sidebar adjusts, masonry reflows The page is the interface. The agent is the editor. The reader stays in control. How we built it The entire system runs client-side as a Next.js PWA. There is no backend for content curation. The AI agents visiting the page are the backend. Server-side API routes exist only as thin CORS proxies for YouTube, Bluesky, and Mastodon. The flow above shows one real interaction: the user asks for trending content → the agent discovers document.modelContext and its 36 tools → calls discover_youtube_content → picks the best video → calls get_youtube_video to read the full transcript → writes an original summary → calls add_story → source validation checks the allowlist (~90 approved) and banned list (~280 blocked) → edition data updates in localStorage → the layout rule engine rescores and reflows → the page updates instantly, live. The agent can also use its own web search to find content from any source and call add_story directly — the discover tools are convenience shortcuts, not the only path. Personalized interests via AI conversation Tell the agent what you want to learn — "This week I want to learn about LLMs and quantum computing" — and it sets your topic interests via set_user_interests . The interests persist in localStorage and influence what the agent curates next. The agent can search anywhere on the web, write original articles in its own words, and add them via add_story . WebMCP tools Every tool is registered through the browser's document.modelContext.registerTool() API. The registration function runs on page load and registers all 36 tools in parallel: // src/lib/webmcp.ts const modelContext = document.modelContext ?? (navigator as any).modelContext; // Chrome 146-149 compat if (typeof modelContext?.registerTool !== "function") return; modelContext.registerTool({ name: "openmemoz.add_story", description: "Add a new story. Page updates IMMEDIATELY.", inputSchema: { type: "object", properties: { headline: { type: "string" }, excerpt: { type: "string" }, section: { type: "string" }, sourceName: { type: "string" }, youtubeVideoId: { type: "string" }, pinAsHero: { type: "boolean" }, }, required: ["headline", "excerpt", "section", "sourceName"], }, execute: (args) => { /* validate source, create story, update edition */ }, }, { signal: abortSignal }); Tool descriptions do double duty as agent instructions. When search_stories returns zero results, its description guides the agent to discover tools. When discover_youtube_content finds a video, its description tells the agent to read the transcript with get_youtube_video and write an original summary before adding. The descriptions chain tools into workflows — they need the same care as system prompts. Source validation OpenMemoz only accepts content from approved sources. Every add_story call validates the source URL against two lists before the story is accepted: // src/lib/curatedSources.ts export const APPROVED_SOURCES = [ { domain: "nasa.gov", licenceBasis: "public-domain-usgov" }, { domain: "youtube.com", licenceBasis: "youtube-embed-tos" }, // ~90 total across government, CC, open API, video, social ]; export const BANNED_DOMAINS = ["nytimes.com", "wsj.com", /* ~280 total */]; Layer Sources Legal basis Government SEC, Fed, NASA, NOAA, BLS, NIH, CDC Public domain (17 USC 105) Creative Commons The Conversation, Global Voices, VOA, Wikipedia CC licence terms Open APIs Hacker News, YouTube, Bluesky, Mastodon Permissive API / embed ToS Provenance tiers Every story carries a provenanceTier in its data schema. Tier 1 means the text comes directly from the source (a government press release, a CC-licensed article). Tier 2 means the AI synthesized the summary. The agent knows the difference. // src/lib/types.ts export interface Story { storyIdentifier: string; headline: string; excerpt: string; section: string; provenanceTier: 1 | 2; // 1 = source text (quotable), 2 = AI-synthesized sourceName: string; sourceUrl: string; licenceBasis: string; // legal basis for redistribution youtubeVideoId?: string; isHeroPinned?: boolean; } Layout rule engine The layout engine assigns stories to slots the way a newspaper editor would. No empty space, no mixed-height rows. The hero is scored automatically based on visual impact: // src/lib/layoutRuleEngine.ts function scoreHeroCandidate(story: Story, index: number): number { if (story.isHeroPinned) return 100; let score = 0; if (story.youtubeVideoId) score += 5; if (story.imageUrl) score += 3; if (story.provenanceTier === 1) score += 2; return score; } The engine produces a structured layout: hero + sidebar, then a uniform mid-row (all-thumbnail or all-text to avoid dead space), then brief strips in full rows of 4, a video feature row, and a below-fold masonry grid packed with a greedy shortest-column algorithm. Challenges we ran into WebMCP is brand new and barely documented. Chrome 150 shipped document.modelContext.registerTool() with no tutorials and few examples. We discovered edge cases through trial: tools fail silently when descriptions are too long, agents call tools in unexpected orders, and Chrome 146 through 149 used navigator.modelContext instead of document.modelContext . Our code handles both entry points. AI agents are unpredictable editors. The first time we asked ChatGPT to "add some tech stories," it added 47 stories in a row, all in the Tech section, most from banned domains. We built guardrails layer by layer: source validation against ~90 approved and ~280 banned domains, duplicate detection by headline slug, and rate guidance baked into tool descriptions. The agent still needs coaching, but it cannot publish from the New York Times. Newspaper layout is harder than it looks. Our first layout was a 3-column masonry grid. It looked like a Pinterest board, not a newspaper. Real newspapers have hierarchy: the hero is visually dominant, sidebar stories complement it, mid-row stories are uniform height, and the below-fold grid fills every pixel. We built a rule engine that enforces these constraints automatically. YouTube video verification is a rabbit hole. We curate static editions with YouTube video embeds. Matching video IDs to story topics turned out to be fragile. A story about the Federal Reserve was showing a Linkin Park music video. The fix was YouTube oembed API verification and strict video-to-topic matching. Tested with ChatGPT Codex and Chrome DevTools. No vendor lock-in, no API keys What is novel: content safety as infrastructure Most AI content platforms enforce safety through prompts. Prompts can be overridden, ignored, or forgotten. OpenMemoz enforces safety in code. The allowlist (~90 approved sources) and banned list (~280 blocked domains) are not features. They are infrastructure. When any AI agent calls add_story , the source URL is validated against both lists in the tool's execute function. No prompt engineering can bypass it. No agent, regardless of provider, can publish from a banned domain. This is simple by design. Simple means any page can adopt the same pattern. The allowlist/banned list becomes a composable, forkable content safety standard for the AI-native web. An agent visiting any WebMCP page with this pattern gets the same guardrails automatically. Why this matters: Provenance is structural. provenanceTier lives in the data schema, not a UI label. Tier 1 text is quotable. Tier 2 must cite sources. The agent knows the difference at the data level. The page is the tool surface. WebMCP tools are registered in the browser. Any AI agent that can open a webpage gets the same tools, the same validation, the same guardrails. Safety scales with autonomy. Whether a human requests "add Real Madrid content" or an autonomous agent runs a beat on a schedule, the allowlist/banned list enforces the same rules. Content safety is structural, not procedural. The agent is the delivery adapter. format_for_delivery packages content as briefings, social posts, newsletters, or structured data. The agent decides the destination — present in chat, email it, post to social media, or populate another WebMCP page. OpenMemoz is the content platform; the agent is the universal delivery layer. What we learned Tool descriptions are prompt engineering. The biggest leverage in our WebMCP implementation was not the execute functions — it was the description strings. Each description guides the agent to the next tool: discover_youtube_content tells the agent to call get_youtube_video for the full transcript, get_youtube_video tells it to write an original summary and call add_story . The descriptions chain tools into workflows without any orchestration code. They need the same care as system prompts. Source validation is table stakes. Within minutes of testing with ChatGPT, the agent tried to add stories from the New York Times, Washington Post, and Bloomberg. Without the curated sources system, the platform would have been a copyright lawsuit generator. Building source validation into the data model, not as an afterthought, was the most important architectural decision we made. Layout is editorial judgment. A masonry grid is not a newspaper layout. Real newspapers have hierarchy, rhythm, and visual balance. Building the layout rule engine taught us that newspaper design is a set of hard constraints (no empty cells, no mixed-height rows) applied with soft judgment (hero scoring, section diversity). The rule engine encodes the constraints. The AI provides the judgment by curating the content. Architecture The entire system runs client-side. What's next for OpenMemoz OpenMemoz is designed as an open-core platform, not a hackathon demo. The Apache 2.0 codebase is the foundation. Creator access program. The ~90 approved sources are a starting point. The next step is partnering with content creators (YouTubers, independent journalists, newsletter writers, Bluesky authors) who are willing to explicitly grant redistribution rights. Creators get attribution and traffic. Readers get a broader content ecosystem. The goal is to grow from ~90 to 500+ approved sources. Community-curated source lists. Right now the approved sources are hardcoded. Next: community-contributed source lists that anyone can fork and customize. A climate researcher curates climate sources. A teacher builds a current-events list for assignments. Source lists become shareable, forkable, and versioned. Server-side AI curation. Cloud-hosted agents that do real AI curation on a schedule — searching the web, writing original summaries, making editorial choices. Fully autonomous operation without requiring the user to keep a browser tab open. Server-side generation and hosted tier. Scheduled Cloud Functions that fetch from approved source APIs daily. Free self-hosted PWA with community source lists. Paid tier with cloud sync, premium sources, and cross-device push editions.
