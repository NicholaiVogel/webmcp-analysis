Events are spread across venue websites, cultural institutions, clubs and organizers. Stadtoskop started as an attempt to turn this fragmented information into a visual and playful way to discover local culture. \n\n While building it, another question became increasingly important: How should AI agents discover local culture? \n\n Today, an agent often has to search the web, interpret different websites and reconstruct information that already exists as structured data. \n\n WebMCP offers a much cleaner approach. \n\n What it does \n\n Stadtoskop is a local culture discovery platform starting in Leipzig, Germany. It organizes events, venues and categories into structured data while keeping links to their original public sources. \n\n For the WebMCP Challenge, Stadtoskop adds an agent-accessible discovery layer. \n\n Instead of scraping or visually interpreting the website, an AI agent can use WebMCP tools to search Stadtoskop directly — for example to find live music, cultural events or places matching a user's interests. \n\n The goal is simple: \n\n People explore the city visually. Agents explore the same city through structured tools. \n\n How we built it \n\n Stadtoskop already has a React Native frontend, a Node.js backend and a PostgreSQL/PostGIS database containing structured event and venue information. \n\n The WebMCP integration exposes selected discovery capabilities as clearly defined tools. These tools connect the agent-facing web experience with the same underlying cultural data used by Stadtoskop. \n\n This means the WebMCP layer does not create a second database or duplicate the discovery logic. It provides another interface to the existing Stadtoskop ecosystem. \n\n Challenges \n\n Local event data is messy. Names change, events repeat, venues move, and information can differ between sources. \n\n A major part of Stadtoskop has therefore been about making discovery data reliable enough to be useful while still preserving the connection to official public sources. \n\n The WebMCP challenge adds another interesting requirement: deciding which parts of that data model should become simple, useful tools for an AI agent instead of exposing the complexity of the entire system. \n\n What's next \n\n The WebMCP prototype is only the beginning. \n\n The long-term idea is for Stadtoskop to become a local cultural discovery layer that can be used both by humans and AI assistants. \n\n An agent could eventually answer questions such as: \n\n “What can I do with my kids in Leipzig this weekend?” \n\n or: \n\n “Which bands playing in Leipzig during the next two weeks should I listen to?” \n\n WebMCP provides a promising way to make that interaction direct, structured and useful. \n\n \n\n \n Built With \n\n node.js postgresql react typescript webmcp \n \n\n \n Try it out \n\n \n \n \n api.stadtoskop.de \n \n \n \n\n \n\n \n\n \n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Stefan Gast \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Stefan Gast \n started this project\n \n —\n \n a day ago \n \n \n\n
