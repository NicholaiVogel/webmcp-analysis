A normal chat can recommend an answer, but the reasoning often disappears into prose and the page on screen drifts out of sync. \n\n I built BuildBrief Studio to explore a better workflow—one where a person and an AI agent collaborate through the same visible, reviewable workspace. \n\n What it does \n\n BuildBrief Studio turns a rough structure request into a transparent preliminary project brief. The visual worksheet and six imperative Website Tools share one validated configuration. An agent can: \n\n \n discover structures in a synthetic catalog; \n read the person's current visible choices; \n compare two or three complete candidates against a budget; \n apply a partial recommendation to the worksheet; \n identify constraints that still need human verification; and \n create a copyable preliminary brief. \n \n\n Write tools update the visible UI before returning and leave exact field-level receipts. If the person changes a value afterward, the revision advances and the old brief is visibly marked stale. \n\n Why WebMCP fits \n\n WebMCP is the product interface, not an add-on beside it. The agent acts through explicit tools while the person watches the same worksheet change. This makes agent actions observable, reversible, and easier to review than recommendations buried in a chat transcript. \n\n Together, a person and agent can move from an imprecise request to compared alternatives, a selected configuration, documented assumptions, and a usable handoff artifact—without creating a hidden agent-only state. \n\n How I built it \n\n The app is built with Astro, React, and TypeScript and deployed on Cloudflare Pages. It registers six imperative tools from the top-level page using document.modelContext.registerTool : \n\n \n search_catalog \n get_build_state \n compare_builds \n apply_build \n check_constraints \n create_build_brief \n \n\n The tools use strict JSON Schema, runtime validation, truthful read/write annotations, structured results, and AbortSignal-aware execution. The tool layer and visible React controls share the same state adapter. \n\n Every price comes from a bundled synthetic catalog and deterministic formula. There is no login, personal information, external API, or production pricing system. Permit, access, anchoring, snow-load, and site conditions remain explicit human-review items. \n\n Challenges and learning \n\n The hardest part was keeping the visible interface and agent-readable state synchronized while making every mutation auditable. I also had to prevent incompatible configurations, distinguish catalog fit from real-world feasibility, and make stale generated briefs obvious after manual edits. \n\n As a beginner working with WebMCP, I learned how careful tool schemas, validation, annotations, lifecycle handling, and visible receipts turn an AI interaction into a dependable product workflow. OpenAI Codex helped me implement, debug, test, and harden the project, but I reviewed the generated work against the running app and its automated tests. \n\n What's next \n\n The hackathon build deliberately uses synthetic data and stops before any production quote or permitting decision. The next step is to apply this human-and-agent collaboration pattern to my real carport business, with authenticated data, server-side pricing, audit trails, and the necessary engineering and compliance checks. \n\n \n\n \n Built With \n\n astro cloudflare-pages playwright react typescript webmcp \n \n\n \n Try it out \n\n \n \n \n norcal-buildbrief-webmcp.pages.dev \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Mike Ruiz \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n\n\n\n\n\n\n\n\n \n \n\n \n\n \n \n \n \n \n Devpost \n \n About \n Careers \n Contact \n Help \n \n \n \n\n \n \n
