A survey can look complete while still containing leading language, double-barrelled questions, unclear timeframes, sensitive questions without an opt-out, conflicting response options, or unnecessary requests for personal information. \n\n These issues are often identified through manual reviews, long checklists, and repeated back-and-forth between researchers, product teams, and stakeholders. The process takes time, depends heavily on reviewer experience, and can still produce inconsistent results. \n\n SurveyGuard was inspired by a simple question: \n\n What if a person and an AI agent could review and improve a survey together inside the same live workspace? \n\n Instead of requiring an agent to interpret buttons, scrape page content, or guess how the survey application works, SurveyGuard exposes clearly defined survey actions through WebMCP. The agent can inspect the survey, identify risks, explain findings, and perform approved actions while the person remains in control. \n\n What SurveyGuard does\nSurveyGuard is a WebMCP-enabled survey quality workspace that helps people and AI agents collaboratively review surveys before publication. \n\n The current MVP allows users to: \n\n Create, edit, and delete survey questions\nConfigure question types and response options\nValidate survey questions against defined quality checks\nIdentify personally identifiable information\nDetect leading or loaded wording\nFlag potentially double-barrelled questions\nIdentify sensitive questions that may need a “Prefer not to answer” option\nDetect unclear reference periods\nFlag exclusive options such as “None of these” in multi-select questions\nReview findings by severity\nApply recommended corrections\nMonitor a dynamic survey-readiness score\nGenerate a concise survey-readiness report\nFindings are organized into three levels: \n\n Blocking: A high-risk issue that should be addressed before publication\nNeeds review: An issue requiring human judgment or revision\nSuggestion: A non-blocking quality improvement\nSurveyGuard uses fictional survey content in the demonstration and does not depend on private company data, confidential research, or customer information. \n\n Why WebMCP is a strong fit\nSurvey review is not just a question-and-answer experience. It requires an agent to inspect structured survey content, understand validation results, modify specific questions, add response options, and confirm how those actions changed the survey. \n\n Without WebMCP, an AI agent may have to infer this structure from the visual interface and navigate the application indirectly. That approach can be slow, fragile, and difficult to verify. \n\n With WebMCP, SurveyGuard exposes narrow and intentional tools that describe exactly what an agent can do. The agent works with the same survey and application state that the user sees. \n\n The MVP includes the following site tools: \n\n get_survey_summary\nlist_questions\nvalidate_survey\nrewrite_question\nadd_prefer_not_to_answer\ngenerate_readiness_report\nFor example, a user can ask an agent to: \n\n Validate this survey, explain the highest-risk issue, and help me fix it. \n\n The agent can call the validation tool, return structured findings, explain the most important issue, and then use an appropriate write tool after the user approves the change. \n\n This creates a more reliable experience than asking the agent to guess how to manipulate the interface. \n\n Human-agent collaboration\nSurveyGuard is designed around human review rather than unattended automation. \n\n The application separates inspection from modification: \n\n The agent retrieves the current survey structure.\nThe agent runs structured validation.\nThe agent explains the identified issues.\nThe user reviews the recommendation.\nAn approved change is applied through a specific WebMCP tool.\nThe interface updates so the user can verify the result.\nSurveyGuard recalculates the readiness score and remaining findings.\nThe agent provides speed and consistency, while the user maintains responsibility for context, judgment, and final approval. \n\n This is particularly important in survey design because whether a question is appropriate can depend on the research objective, intended audience, jurisdiction, and sensitivity of the subject. \n\n How I built it\nSurveyGuard was built as a React-based web application with a responsive three-panel review experience: \n\n A question list for navigating the survey\nAn editor for reviewing wording, question type, and response options\nA validation panel for displaying findings and recommended actions\nThe validation engine evaluates each question using transparent, deterministic rules. Each finding includes: \n\n A unique issue code\nA severity level\nA short title\nAn explanation\nA recommended correction or action when appropriate\nThe interface calculates a survey-readiness score based on the number and severity of unresolved findings. The score updates as users edit questions or apply corrections. \n\n WebMCP tools are registered through document.modelContext.registerTool(). Each tool defines: \n\n A specific name\nA focused description\nA narrow input schema\nRequired parameters\nRead-only annotations where applicable\nAn execution handler connected to the survey’s existing application logic\nThe tools return structured results so an agent can understand what happened and communicate the result to the user. \n\n The application also preserves a normal visual workflow for people and can display a preview state when WebMCP is not available in the current browser environment. \n\n Challenges I faced\nDesigning useful tool boundaries\nOne challenge was deciding how much authority each tool should have. A single broad tool that could change the entire survey would be flexible, but it would also be harder to control and verify. \n\n I chose narrower tools such as rewrite_question and add_prefer_not_to_answer. This makes each action easier for the agent to select, easier for the user to understand, and easier to test. \n\n Separating blocking issues from recommendations\nNot every survey-quality concern should prevent publication. Treating every finding as equally severe would create unnecessary friction and reduce trust in the validator. \n\n To address this, SurveyGuard separates blocking issues, review items, and optional suggestions. \n\n Keeping the human in control\nA technically successful agent action is not necessarily the right research decision. SurveyGuard therefore treats agent recommendations as reviewable actions and clearly communicates that human approval is recommended before publication. \n\n Managing shared application state\nWebMCP tools and the visible interface need to operate on the same current survey. Tool outputs, question edits, validation results, and readiness scoring must remain consistent after every action. \n\n The MVP connects tool execution to the same underlying state used by the visual interface so changes can be seen and verified immediately. \n\n Working within a short build window\nThe challenge required prioritizing a focused, demonstrable workflow. Instead of attempting to build a complete survey-authoring platform, I concentrated on the core WebMCP experience: inspect, validate, explain, improve, and verify. \n\n What I learned\nBuilding SurveyGuard reinforced several important lessons: \n\n Agent-native applications need explicit actions, not just an AI chat box.\nNarrow tools are easier to understand, secure, test, and verify.\nRead-only and write actions should be clearly separated.\nTool descriptions and input schemas are part of the product experience.\nAgents should return enough information for users to verify outcomes.\nHuman approval is especially important when context changes what “correct” means.\nDeterministic validation and agent reasoning can complement each other.\nThe visible interface should remain useful even when WebMCP is unavailable.\nA readiness score is useful only when users can understand which findings affect it.\nMost importantly, I learned to think of WebMCP as a collaboration layer between the website, the user, and the agent rather than simply another integration API. \n\n Accomplishments\nI am proud that the MVP demonstrates a complete human-agent workflow rather than adding WebMCP as a superficial feature. \n\n SurveyGuard includes: \n\n A functional survey editing experience\nTransparent validation rules\nMultiple issue severities\nActionable recommendations\nA dynamic readiness score\nStructured read and write tools\nHuman-review safeguards\nFictional demonstration data\nA workflow that can be explained and demonstrated clearly in under three minutes\nWhat’s next\nThe current MVP establishes the foundation for a broader survey-quality platform. Future improvements could include: \n\n Importing surveys from JSON, CSV, or common survey formats\nAdding duplicate and overlapping response-option detection\nChecking answer scales for balance and consistency\nMapping questions to research objectives\nSupporting configurable validation policies\nAdding multilingual survey review\nShowing an audit record of human and agent changes\nAdding approval workflows for high-risk modifications\nComparing original and revised question wording\nExporting a complete readiness report\nCreating reusable validation templates for different survey types\nExpanding browser-based WebMCP evaluations and automated tool testing\nThe longer-term vision is to make high-quality survey design more accessible while preserving human accountability. \n\n SurveyGuard demonstrates how websites can become meaningfully better when people and agents work together through clear, structured, and verifiable tools. \n\n \n\n \n Built With \n\n css css3 framer github html5 javascript lucide motion react tailwind vercel vite webmcp \n \n\n \n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Samb Sadashiv \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n 1 \n \n \n\n\n \n 1 person likes this:\n \n\n \n \n \n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Samb Sadashiv \n started this project\n \n —\n \n 5 days ago \n \n \n\n
