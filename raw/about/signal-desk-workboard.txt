However, that system relies on private authentication and persisted chat/media data. It is intentionally local-only: publishing it would expose sensitive data and would not be a reliable fit for a serverless deployment. \n\n That constraint became the inspiration for Signal Desk. \n\n Instead of pretending that private WhatsApp data should be pushed to the public web, we built a safe, fictional, browser-only workboard that represents the workflow after a message becomes an operational case. It lets us demonstrate the meaningful question: how can people and AI agents work on the same case safely? \n\n What it does \n\n Signal Desk is a fictional support workboard where a person can create, review, edit, and move cases through New, Triage, Investigating, and Resolved. \n\n The important difference is that the page also exposes focused WebMCP tools. An agent can list cases, open a case, create a new case, update its record, and propose a stage move using structured site capabilities rather than guessing from screenshots or clicking around blindly. \n\n The human remains the decision-maker. When an agent wants to create, edit, or move a case, Signal Desk creates a visible pending action instead of silently changing the board. The person can approve or cancel it. After approval, the agent reads the actual board state back to verify the outcome. \n\n This means the product supports both kinds of work: \n\n \n Humans can use the normal visual interface. \n Agents can use WebMCP to work through the same case model. \n Important changes remain visible, reversible before approval, and verifiable afterward. \n \n\n How we built it \n\n We separated the original private WhatsApp concept from the deployable demonstration. \n\n The original ingestion idea stays local, where private authentication and persisted conversations belong. Signal Desk is the public, safe companion: it uses fictional data that lives only in the browser and can be deployed to Vercel without exposing real messages, media, credentials, or customer information. \n\n We built a case workboard with rich case details, notes, formatting, case creation, manual editing, stage movement, and a visible activity history. We then implemented WebMCP tools for the same operations. \n\n For state-changing tools, we added an approval workflow: \n\n \n The agent proposes an action. \n The website returns an awaiting approval state and an approval ID. \n A person can approve or cancel the specific action. \n The agent confirms the approved action. \n The agent reads back the resulting case or board state before claiming success. \n \n\n Challenges we faced \n\n The biggest challenge was not making an agent able to act. It was making agent action trustworthy. \n\n A tool that can move a case directly is convenient, but it can also hide a consequential decision. We designed the approval state so that creating a case, changing its content, and moving it to Resolved are explicit, separate decisions. \n\n We also learned that an approval alone is not enough. The agent must verify the result after the action completes. During testing, we improved the workflow so the agent does not merely report “done”; it checks the updated record or board state and reports evidence of the outcome. \n\n What we learned \n\n WebMCP is valuable because it gives an agent a clear contract with a webpage. The agent does not need private backend access, fragile screen automation, or permission to control everything. The website declares the useful actions, their inputs, and their safety boundaries. \n\n Signal Desk shows how an ongoing, message-driven workboard project can become agent-interactive and deployment-ready without exposing the private WhatsApp layer behind it. \n\n The goal is not to replace people with automation. It is to turn scattered reports into shared, structured work—where agents can help move work forward and people retain authority over the decisions that matter. \n\n \n\n \n Built With \n\n chatgpt javascript \n \n\n \n Try it out \n\n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n KaiWen Tee \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n KaiWen Tee \n started this project\n \n —\n \n 2 days ago \n \n \n\n
