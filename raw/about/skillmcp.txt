In local agents and development environments, these skill files can be connected directly to an agent or project and reused whenever needed. \n\n However, the experience is very different when using general-purpose web LLMs. \n\n Users often have to upload the same skill file again, paste long instructions into a conversation, or manually manage which instructions they want the model to follow. \n\n I wanted to bring the SKILL.md experience from local agent environments into web LLMs . \n\n Instead of repeatedly copying instructions, I wanted users to be able to install Skills once, manage them in a personal library, and let the web LLM access the active Skills directly. \n\n That idea became SkillMCP . \n\n What it does \n\n SkillMCP is a platform for storing, installing, managing, and using SKILL.md-based Skills with web LLMs . \n\n Users can browse a Skill Marketplace, discover Skills created for different tasks, and install them into their personal Library. \n\n Installed Skills can be enabled or disabled, edited, duplicated, or customized for different workflows. \n\n SkillMCP currently provides: \n\n \n A SKILL.md-based Skill Marketplace \n Skill search and category browsing \n Personal Skill Library management \n Skill installation \n Skill enable / disable controls \n Skill editing, duplication, and deletion \n SKILL.md previews \n A Skill creation interface \n Korean and English UI support \n Per-user Skill state management \n WebMCP integration for web LLM access \n \n\n The main idea is not simply to store SKILL.md files on a website. \n\n The web LLM can directly access the user's Skill Library and retrieve the instructions from currently enabled Skills through WebMCP. \n\n Without WebMCP, users would still have to open SkillMCP, copy the contents of a Skill, return to the LLM, and paste it manually. \n\n SkillMCP removes that step by making the website itself accessible to the AI. \n\n In that sense, WebMCP acts as the bridge between SKILL.md and web-based LLMs . \n\n How we built it \n\n The first version of SkillMCP started with a very small goal: \n\n Store Skills on the web and allow an LLM to retrieve them. \n\n As development continued, I realized that a simple Skill repository would not be enough. \n\n If users were going to use Skills continuously, they also needed a way to manage what they had installed, which Skills were active, and how those Skills could be customized. \n\n That led to the Marketplace and Library structure. \n\n The Marketplace allows users to discover and install public Skills, while the Library gives each user a dedicated space to manage their installed Skills. \n\n I also built a Skill Creator so users can create and edit SKILL.md-based workflows directly from the platform. \n\n The product experience was partly inspired by platforms such as Steam Workshop. \n\n Just as users can discover, install, and manage mods, SkillMCP allows users to discover, install, and manage reusable AI Skills. \n\n The frontend was built with React , and the backend manages user accounts, Skill data, personal Libraries, and enabled or disabled states. \n\n The most important integration was WebMCP . \n\n Through WebMCP, the webpage exposes the user's current Skill state to the LLM. This allows the AI to access the same Skill Library that the user is managing through the interface. \n\n Instead of building a completely separate AI-specific backend workflow, the goal was to make the existing web application itself usable by both the user and the AI. \n\n Challenges we ran into \n\n One of the biggest challenges was keeping the Skill state consistent between SkillMCP and the web LLM. \n\n Displaying Skills in a Marketplace was relatively straightforward. \n\n The harder part was ensuring that the LLM could retrieve exactly the Skills enabled by the currently logged-in user. \n\n For example, multiple users can install the same Skill, but each user must have an independent enabled or disabled state. \n\n If a user edits a Skill, the LLM must also receive the latest version instead of an older copy. \n\n Because of this, Skill IDs, user Libraries, activation states, and Skill contents all had to be designed as part of one consistent data flow. \n\n Another challenge was making SkillMCP more than a simple prompt marketplace . \n\n The project is not designed around one-time prompts that users copy into a chat. \n\n A Skill represents reusable instructions that can define how an AI should perform a task, what rules it should follow, and what type of result it should produce. \n\n The key difference is that these Skills can be managed persistently and accessed directly by a web LLM through WebMCP. \n\n There were also many product-level challenges beyond the initial prototype, including authentication, multilingual UI, Skill management, user-specific data, state synchronization, and making the service feel like a complete product rather than a technical demo. \n\n Accomplishments that we're proud of \n\n The part I am most proud of is that SkillMCP evolved from a small SKILL.md experiment into a working web platform. \n\n Instead of only demonstrating a WebMCP tool call, the project now includes a complete user flow: \n\n discover a Skill → install it → manage it in the Library → enable it → make it available to a web LLM \n\n I am also proud that WebMCP is connected to the core purpose of the project rather than being added only as a demonstration feature. \n\n SkillMCP was created specifically because I wanted SKILL.md to work more naturally in web LLM environments, and WebMCP made it possible to connect the user's web-based Skill Library directly to the AI. \n\n The project also grew to include: \n\n \n A public Marketplace \n Personal user Libraries \n Skill creation and editing \n Persistent Skill state \n Multilingual support \n User authentication \n A deployed web service \n WebMCP-based Skill access \n \n\n Most importantly, the project demonstrates that a web application can become more than an interface for a human user. \n\n It can also become an extension layer that the AI itself can interact with. \n\n What we learned \n\n The biggest thing I learned from this project is that WebMCP is not simply a way to add AI-accessible actions to a website. \n\n When a web application exposes its existing user state and functionality to an LLM, it can remove many of the manual steps that normally exist between a user, a website, and an AI. \n\n In SkillMCP, that manual step was repeatedly transferring SKILL.md instructions into the LLM. \n\n By exposing the user's active Skills through WebMCP, the website can handle that connection instead. \n\n I also learned that the user experience around AI instructions is just as important as the instructions themselves. \n\n As the number of Skills grows, users need ways to search, organize, activate, edit, and understand them. \n\n That is why SkillMCP gradually became a Marketplace and Library system rather than remaining a simple file storage tool. \n\n Most importantly, I learned that the same web interface can serve both humans and AI . \n\n The user manages Skills through the UI, while the LLM can access the same underlying state through WebMCP. \n\n That shared environment opens up many possibilities beyond this project. \n\n What's next for SkillMCP \n\n The next step is to make SkillMCP more autonomous and more deeply integrated with web LLMs. \n\n Future features include: \n\n \n Allowing web LLMs to search the Skill Marketplace directly \n Recommending Skills based on natural-language requests \n Allowing AI to install and enable Skills \n Allowing AI to create or modify Skills \n Combining multiple Skills into reusable workflows \n Detecting conflicts between Skill instructions \n Skill versioning and update management \n Creator profiles and community features \n Better Skill discovery and ranking \n Integration with more web-based AI platforms \n \n\n The long-term goal is to make SKILL.md usable beyond specific local agent environments. \n\n I want SkillMCP to become a shared Skill layer where users can discover, install, manage, and reuse AI workflows across web-based LLM environments . \n\n SkillMCP brings SKILL.md from local agents into the web LLMs people already use every day. \n\n \n\n \n Built With \n\n ai amazon-web-services amazoneec2 css git github html5
