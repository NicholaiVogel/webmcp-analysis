A 95% reduction, measured on Google Cloud Run. \n\n The friction \n\n I ran out of credit on a paid model. Mid-project. The agents stopped thinking and the work stopped. \n\n That accident exposed something I had never questioned: every single agent action was going through a large model — including the actions we already knew by heart. Read the inventory. Give the status. Run a written procedure. Each one cost money, took seconds, and could answer differently twice in a row. For work that is not speculative at all. \n\n What we built \n\n A deterministic front door that decides before the model. \n request → guardrails (pure code)\n ├── known capability → circuit runs, ZERO model calls\n └── no match → Gemini 3.5 Flash decides, explicitly\n \n The model is not removed. It is moved to where it earns its cost . \n\n Measured, not claimed \n\n 200 mixed agent requests, handed over as one asynchronous batch. The caller gets a job id in ~100 ms and walks away. \n\n \n \n path \n count \n median \n model calls \n \n \n \n answered by a circuit \n 180 \n 9 ms \n 0 \n \n \n refused by a guardrail \n 10 \n 0 ms \n 0 \n \n \n escalated to Gemini 3.5 Flash \n 10 \n 5 899 ms \n 10 \n \n \n\n 10 model calls instead of 200. That figure is a count , not a timing: it does not move with hardware, network or load. GET /metrics publishes both counters live, so the claim is a measurement anyone can reproduce. \n\n A fleet, not one agent with many prompts \n\n 21 agents, each with a written specification, a declared scope and an engine. 9 of them are bound to no model at all — deterministic code only. \n\n POST /delegate splits a broad request across the agents whose specifications cover each piece: \n\n \n \n agent \n piece \n outcome \n \n \n \n Jimmy — the test bench \n run the regression tests \n done, no model \n \n \n Victor — security \n audit the secrets \n done, no model \n \n \n Lois — review \n review the wording \n done, no model \n \n \n Chloe — assistant \n publish the article \n refused \n \n \n\n The refusal names its own cause: "Chloe may not publish: its specification grants may_publish = false." Separation of concerns is enforced in code, not suggested in a prompt. A failing sub-agent marks only its own piece; the rest continue. \n\n Guardrails that actually refuse \n\n A safety check must return the same verdict twice in a row. A check whose answer varies is an opinion, not a control. So the guardrails are plain Python: a deny list that does not negotiate, and writes that refuse unless explicitly confirmed. \n\n An independent oracle recomputes every expected value in a separate program. It caught a real fabrication in our own repository: a dataset claimed 5468 , the oracle computed 712 , and the reasoning code had 5468 hard-coded so it "agreed" with the fake. Two lies confirming each other. A checker that shares code with the thing it checks is not a checker. \n\n Architecture \n\n \n Model : Gemini 3.5 Flash through Vertex AI, via the Google GenAI SDK \n Serving : FastAPI on Google Cloud Run \n Second deployment : the governed platform itself on Compute Engine — 93 Odoo modules, 21 circuit templates, 67 control gates, 58 skills \n \n\n Mandatory disclosures \n\n Pre-existing. The Living Map discovery mechanism and the Circuit orchestration model come from an earlier Odoo-based project that has been running in production for a month: 1 580 circuit runs, 2 912 gate crossings, 2 130 human decisions of which 513 were refused . \n\n Built during the submission period. The deterministic router, the Gemini fallback through the GenAI SDK, the asynchronous batch endpoint, the delegation to sub-agents, the independent-oracle wiring, /metrics observability, both Cloud deployments, and an audit script that fails the build when a claim in the README is not corroborated by the files on disk. \n\n Honest limits. The circuit used in the demo reads a 478-entry living map — real work, but modest. A circuit querying a business database would be slower and the ratio smaller. The "small reasoning model" is a prototype: it selects among hand-written strategies. It is not a trained model, and calling it one would repeat exactly the overclaim the oracle exists to catch. \n\n What I learned \n\n Constraints are a filter, not only a loss. Running out of credit removed the solutions I could previously afford, and left the ones that stand on their own. I would never have built this with money in the account. \n\n \n\n \n Built With \n\n agentic-ai agents artificial-intelligence autonomous-agents azure cloud devtools enterprise-ai finops gemini geminiapi gemma google-cloud-run google-genai governance guardrails llm mcp odoo open-source python redis security webmcp workflow-automation \n \n\n \n Try it out \n\n \n \n \n control-tower-491595433989.europe-west9.run.app \n \n \n \n 34.155.174.180 \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n All Things Agentic Hackathon \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Monsieur Fotso \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Monsieur Fotso \n started this project\n \n —\n \n 5 days ago \n \n \n\n
