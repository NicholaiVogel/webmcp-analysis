An agent can work with the user's knowledge through structured tools rather than treating the page like an opaque visual interface. \n\n The project is designed around privacy as well: knowledge can remain within the user's browser instead of requiring a traditional backend to store everything. \n\n This creates a different model for AI + web applications: \n\n Web App → exposes capabilities → AI Agent → performs useful work \n\n rather than: \n\n AI Agent → scrapes/interprets UI → tries to control Web App \n\n How we built it \n\n AgentDOM was built as a modern web application with a local-first architecture. \n\n We created the knowledge workspace and then integrated WebMCP so that the application could expose agent-facing tools alongside its normal human-facing interface. \n\n The agent interaction layer allows compatible AI agents to discover the available capabilities and invoke them using structured inputs and outputs. \n\n We also kept the architecture lightweight and browser-focused so that the project could demonstrate that an application does not necessarily need a large backend or complex agent infrastructure to become agent-ready. \n\n Why WebMCP matters \n\n WebMCP changes the relationship between websites and AI agents. \n\n Instead of every agent having to independently figure out how a website works, the website can explicitly describe the actions it supports. \n\n For AgentDOM, this means the application can provide tools specifically designed for working with knowledge. \n\n This makes agent interaction more predictable, easier to reason about, and potentially much more reliable than UI automation. \n\n What we learned \n\n Building AgentDOM taught us that making an application agent-friendly is not simply about adding an AI chatbot. \n\n The more interesting part is designing the interface between the application and the agent . \n\n We learned to think about: \n\n \n What capabilities should an application expose to an agent? \n What should the tool inputs and outputs look like? \n How can agents interact with structured application state? \n How can we keep the human experience simple while making the application machine-readable? \n How can local-first applications participate in the emerging agentic web? \n \n\n WebMCP also made us think differently about the web itself: websites can become active participants in agent workflows rather than simply being pages that agents navigate. \n\n Challenges \n\n One of our biggest challenges was figuring out how to bridge the gap between a normal web application and an agent-facing tool interface. \n\n We had to think carefully about which application capabilities should become tools and how an agent should interact with them. \n\n Another challenge was keeping the experience useful for both humans and agents. We didn't want to build something that was only impressive in an agent demo; the application still needed to work naturally as a normal web workspace. \n\n We also had to work within the limitations and emerging nature of WebMCP while building a practical demonstration around it. \n\n What's next \n\n AgentDOM is an experiment in what an agent-ready web could look like. \n\n We want to explore more sophisticated tools, richer agent workflows, and ways for more web applications to expose their capabilities directly to agents. \n\n Our goal is simple: \n\n \n Make the web easier for agents to understand and safer for users to control. \n \n\n \n\n \n Built With \n\n typescript vite webmcp \n \n\n \n Try it out \n\n \n \n \n agentdom-one.vercel.app \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Arjun K R \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n\n \n Aby varghese \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Aby varghese \n started this project\n \n —\n \n 2 days ago \n \n \n\n
