That project sparked my own interest in robotics. I later built and operated an SO-101 follower arm using its 3D mesh rigs ( RoboBuddy AI ). \n\n For the WebMCP Challenge, I wanted to make robotics exploration more approachable: one browser workspace that humans and agents can use side by side, without a separate project-specific API-key workflow. My original idea was to program robotic arms for scientific lab operations. Then MicroDuck arrived and offered a playful, immediately understandable way to demonstrate agent-accessible web capabilities. \n\n What I built \n\n RoboBuddy IDE is a browser-based robotics workspace with a code editor, simulation controls, and a 3D MicroDuck policy simulation. Through a bounded WebMCP tool surface, agents can inspect the modeled state and make focused, visible changes—such as moving the duck, interacting with the ball and scene, or adding temporary measurement cues. \n\n The experience is designed to be understandable and reversible. Actions stay inside the browser demo, and temporary visual cues disappear on refresh. RoboBuddy IDE does not claim physical hardware control through this WebMCP demo. \n\n How I built it \n\n I used GPT-5.6-Sol in Codex as a development collaborator to build the IDE interface, integrate the MicroDuck model, and develop WebMCP functions for the duck, related objects, and 3D environment. \nRoboBuddy IDE was built during the submission period. It builds on lessons from earlier RoboBuddy robotics experiments, but the submitted browser IDE, WebMCP collaboration surface, and MicroDuck experience are new work created for this challenge.\nThe goal was to build useful, comprehensible, expandable capabilities that a human can observe alongside the agent. \n\n What I learned \n\n WebMCP made the application feel less like a page to automate and more like a set of intentional shared capabilities. Pairing each agent action with visible state makes it easier to see what changed, why it matters, and how to reset the experiment. That makes the experience easier to trust, teach with, and extend. \n\n Challenges \n\n The main constraints were time and the weekly limits on my Pro account. Technically, GPT-5.6-Sol enabled very fast iteration. The careful challenge was maintaining honest boundaries between a browser simulation and physical robotics while keeping the demo inviting for a broad audience. \n\n What comes next (current) \n\n This experience inspired me to explore WebMCP in my other learning and science projects, including Lab Studio , AssayLens , and RoboStudio Circuits . Even if I cannot submit them all, they show how human-visible, bounded agent capabilities can extend across robotics, science, and education. \n\n \n\n \n Built With \n\n chatgpt codex github gpt-5.6-sol gpt-5.6-terra huggingface microduck robot three.js \n \n\n \n Try it out \n\n \n \n \n jivishov.github.io \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Emil Jivishov \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Emil Jivishov \n started this project\n \n —\n \n a day ago \n \n \n\n
