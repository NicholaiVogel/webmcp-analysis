We then built spatial logic around that representation so the agent can work with higher-level design concepts instead of having to manually reason about every pixel. \n\n The architecture separates creative intent from geometric execution . \n\n The agent can express an intention such as: \n\n \n “Place the title above the hero image with some breathing room.” \n \n\n The canvas can then determine the appropriate geometry, validate the result, and keep the composition within the canvas. \n\n This makes the system less dependent on any single model or AI client. \n\n Challenges we ran into \n\n The hardest problem was spatial reasoning . \n\n Our first instinct was to let the agent control objects directly through coordinates. That worked for simple actions but quickly became unreliable as designs became more complex. \n\n We discovered that an agent can make individually reasonable decisions that produce a terrible overall composition. \n\n For example, every object might be correctly created, but their combined layout could still contain overlaps, inconsistent spacing, or broken hierarchy. \n\n The solution was to stop treating the canvas as a passive surface and start treating it as an environment with structure, constraints, and state . \n\n Accomplishments that we're proud of \n\n We're proud that Auxweave goes beyond simply asking an AI to generate a design. \n\n We created a system where an external agent can interact with a live creative environment through WebMCP and operate on structured design elements. \n\n We're especially proud of the idea behind the architecture: \n\n The model provides creative intent. The environment provides spatial intelligence. \n\n This means the same canvas can potentially work with different agents without requiring every model to independently learn how to reason about our editor. \n\n What we learned \n\n Our biggest lesson was that better agents aren't always the answer—sometimes the environment needs to become more understandable to the agent. \n\n We learned to think of tools as an interface between an AI's reasoning and the real world. If that interface exposes only low-level operations, the model has to solve too much itself. \n\n Good agent environments should provide: \n\n \n Structured state \n Meaningful abstractions \n Clear relationships \n Deterministic constraints \n Feedback when an action fails \n \n\n That changed how we think about building AI-native applications. \n\n What's next for Auxweave \n\n Auxweave is only the beginning. \n\n We want to evolve the canvas into a more capable agent-native creative environment where multiple agents can reason about composition, typography, assets, branding, and visual hierarchy while humans remain in control. \n\n We're also interested in making the underlying spatial interface more general-purpose, so that other web-based creative applications can expose their environments to agents in the same way. \n\n Ultimately, we want Auxweave to explore a simple idea: \n\n If AI agents are going to work on the web, the web needs better environments for them to work in. \n\n \n\n \n Built With \n\n css typescript \n \n\n \n Try it out \n\n \n \n \n aux-weaver.vercel.app \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n https://www.aux-weaver.vercel.app \n The right url\n \n \n\n \n \n \n \n \n \n\n \n Mario Caleb \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n\n \n Ai Longer \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Mario Caleb \n started this project\n \n —\n \n a day ago \n \n \n\n
