But this creates a new problem: who controls the agent's decisions?\nI realized that while we're building AI agents that can "do things," we haven't built proper guardrails for them. An agent with unlimited purchasing power is a financial risk waiting to happen.\nThe WebMCP Challenge was the perfect opportunity to solve this. WebMCP lets websites expose structured tools to agents instead of forcing them to guess their way through a UI. I built SpendShield to show what agent-native web apps should look like: agents that act within clear boundaries, with humans in control. \n\n What it does \n\n SpendShield is an AI procurement guardrail that lets agents search, compare, and propose purchases while humans define financial boundaries and approve consequential actions.\nThree-tier guardrail system:\n| Level | Condition | Action |\n|-------|-----------|--------|\n| 🟢 SAFE | ≤ ₦50,000 | Agent can act automatically |\n| 🟡 REVIEW | ₦50,001 - ₦100,000 | Agent proposes, human approves |\n| 🔴 BLOCKED | > ₦100,000 | Agent cannot proceed |\nHumans define: \n\n \n Monthly budget (e.g., ₦500,000) \n Maximum single purchase (e.g., ₦100,000) \n Approval threshold (e.g., ₦50,000) \n Preferred category (e.g., electronics)\nAgents can: \n Search product catalogs \n Compare options \n Check policy compliance \n Create human-readable proposals\nHumans control: \n Review proposals \n Approve or reject \n Track spending in real-time \n \n\n How we built it \n\n Tech Stack: \n\n \n Vanilla HTML + CSS + JavaScript (no frameworks needed) \n WebMCP API for agent tools \n Vercel for hosting \n MIT License \n Built entirely on Android using Termux\nWebMCP Implementation: \n \n\n I registered 6 WebMCP tools using the imperative API: \n document . modelContext . registerTool ( { \n name : "get_budget" , \n description : "Return budget and limits" , \n execute : async ( ) = > { /* ... */ } \n } ) ; \n \n The key insight was making the agent propose, not purchase. The agent cannot buy anything directly - it must create a proposal and wait for human approval for any purchase above the threshold. \n\n Challenges we ran into \n\n \n WebMCP Testing in Chrome\nTesting WebMCP requires enabling chrome://flags/#enable-webmcp-testing . Without this, the tools register but can't be called. I documented this clearly for judges. \n Building Without a Laptop\nThis entire project was built on an Android phone using Termux. I used: \n Termux for the terminal environment \n Nano for editing files \n Git for version control \n Vercel CLI for deployment \n Keeping It Simple\nWith only 4 days, I had to resist adding unnecessary features. No authentication, no database, no complex backend. The judges care about WebMCP leverage, not how many features you can cram in. \n Deployment on Mobile\nDeploying to Vercel from Termux required careful steps, but the Vercel CLI worked perfectly once I was logged in. \n \n\n Accomplishments that we're proud of \n\n ✅ Complete WebMCP Implementation- 6 real tools registered and working\n✅ Three-Tier Guardrail System** - Clear visual status (Safe/Review/Blocked)\n✅ Human-Agent Collaboration- Agents propose, humans approve\n✅ Real-Time Budget Tracking- Updates immediately on approval\n✅ Live Demo - Deployed to Vercel and working: https://spendshield-eta.vercel.app \n✅ Open Source - MIT License, public on GitHub\n✅ Built on Android- Entire project from a phone in 4 days \n\n What we learned \n\n \n WebMCP Changes How We Think About Web Apps\nInstead of building for humans OR agents, we should build for both. WebMCP gives us a standard way to expose capabilities. \n Guardrails > Automation\nAn agent that can do everything is dangerous. An agent that works within clear boundaries is powerful. The human should always control consequential decisions. \n Keep It Focused\nYou don't need 50 features. You need one feature that works perfectly and demonstrates the technology clearly. SpendShield does one thing: procurement with guardrails. \n Mobile Development Is Viable\nBuilding a complete web app on Android is possible with the right tools. Termux, Git, and Vercel made it happen. \n \n\n What's next for SpendShield \n\n \n Real Product Integration\nConnect to real e-commerce APIs (Shopify, WooCommerce) so the agent can search real products. \n Multi-Agent Support\nMultiple agents with different roles and permissions. \n Analytics Dashboard\nTrack spending patterns, savings, and policy violations over time. \n More Guardrails \n Department-level budgets \n Project-based spending limits \n Approval workflows (manager → finance → VP) \n Vendor whitelists/blacklists \n Natural Language Policy\n"Don't spend more than 10% on office supplies" - the agent understands and enforces. \n WebMCP 2.0 Features\nAs the WebMCP standard evolves, SpendShield will evolve with it.\nBuilt for the WebMCP Challenge - Shaping the agent-native web. \n \n\n \n\n \n Built With \n\n ai chrome css git html javascript license mit open procurement source termux vercel webmcp \n \n\n \n Try it out \n\n \n \n \n spendshield-eta.vercel.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Sule Bashir \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Sule Bashir \n started this project\n \n —\n \n 6 days ago \n \n \n\n
