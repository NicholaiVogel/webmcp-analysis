An agent may understand what a user wants, such as a powerful programming laptop under a specific budget, but interacting with a website through visual elements alone can be inefficient and fragile. \n\n I wanted to explore how WebMCP could make a website expose its real capabilities directly to AI agents while preserving a great experience for human users. \n\n That idea became ShopWise AI — a collaborative shopping experience where humans browse products visually while AI agents can discover structured tools to search products, inspect details, compare options, and manage a real shopping cart. \n\n What it does ShopWise AI is a modern AI-commerce web application with a product catalog across categories including laptops, smartphones, headphones, and smartwatches. \n\n Human users can: \n\n \n Browse a large product catalog visually \n Search for products \n Filter by category and price \n Sort products \n View detailed product information \n Compare multiple products \n Add products to a shopping cart \n Change quantities and remove items \n \n\n AI agents in a compatible WebMCP environment can interact with the same real application capabilities through native WebMCP tools. \n\n The six tools implemented are: \n\n \n search_products \n get_product_details \n compare_products \n add_to_cart \n get_cart \n clear_cart \n \n\n How we built it ShopWise AI was built as a React and TypeScript application using Vite. \n\n The application uses: \n\n \n React \n TypeScript \n Vite \n CSS \n Lucide React icons \n Vercel for deployment \n GitHub for source control \n Native browser WebMCP APIs \n \n\n The product catalog and shopping logic run entirely in the frontend with real local application state. \n\n The UI includes a premium dark interface with responsive product cards, search and filtering controls, a shopping cart drawer, product comparison functionality, and an Agent Collaboration panel. \n\n Challenges we ran into One of the biggest challenges was connecting WebMCP tools to the real React application state. \n\n The WebMCP tools needed to perform actual operations such as searching products, comparing products, adding items to the cart, and clearing the cart. We had to ensure these operations used the same real business logic and state as the visual user interface instead of returning simulated or hardcoded results. \n\n Another challenge was avoiding stale React state inside WebMCP tool callbacks. Since React components re-render as application state changes, the WebMCP integration needed access to the latest product, filter, cart, and comparison state. \n\n We also needed to prevent duplicate tool registration caused by React StrictMode and safely detect whether the current browser supported WebMCP. \n\n Finally, the application had to remain fully functional in ordinary browsers where document.modelContext is unavailable. We implemented graceful feature detection so the website continues working normally while accurately reporting WebMCP availability. \n\n During deployment, we also verified that the production build succeeded and that the live Vercel application could load correctly without environment-specific dependencies. \n\n Building ShopWise Al helped me understand how websites can evolve beyond interfaces designed only for humans. \n\n WebMCP makes it possible for websites to expose structured, meaningful capabilities to Al agents while keeping the existing human interface intact.\nI learned the importance of:\nDesigning tools around real user problems\nConnecting agent capabilities to real application logic\nManaging application state safely\nProviding structured inputs and outputs\nDesigning human and Al collaboration instead of replacing one with the other\nBuilding graceful fallbacks for unsupported browsers\nWhat's next \n\n Future versions of ShopWise Al could support: \n\n Personalized shopping preferences \n\n Persistent shopping carts \n\n User accounts \n\n Real e-commerce APIs \n\n Product recommendations \n\n Multi-agent shopping assistance \n\n Price
