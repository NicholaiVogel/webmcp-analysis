Recovering one lead can require several repetitive steps: identify the opportunity, understand the request, prepare a response, qualify the need, find availability, obtain approval, book the appointment, and update reporting. \n\n Palm92 Lead Recovery OS explores a more useful open web where a person and an AI agent can complete that workflow together without surrendering human control. \n\n What it does \n\n Palm92 exposes seven structured browser-native WebMCP tools: \n\n \n get_unrecovered_leads \n get_lead_details \n prepare_follow_up \n recover_lead \n find_available_appointments \n prepare_appointment \n get_recovery_summary \n \n\n An agent can discover missed enquiries, inspect structured lead details, draft a follow-up, record an explicit fictional customer response, qualify the requirement, check appointment availability, and prepare an appointment. \n\n The agent cannot complete the final booking. Palm92 pauses at a visible human approval checkpoint. Only the person can approve the final demonstration booking, after which the dashboard updates. \n\n The governing principle is: AI investigates. Humans decide. \n\n Why WebMCP \n\n This workflow is a strong fit for WebMCP because it involves connected browser actions, structured business data, business context, and a consequential final decision. Instead of forcing an agent to infer controls from page layout, Palm92 makes safe capabilities explicitly discoverable through document.modelContext.registerTool . \n\n The tools share the same in-browser state as the human-facing dashboard. Inputs use narrow JSON schemas and tool annotations describe their effects. This creates a coherent experience in which the agent handles investigation and preparation while the human retains authority. \n\n Challenge-period work \n\n Palm92 existed as a lead-recovery dashboard before the challenge. During the challenge period it was meaningfully extended with seven client-side JavaScript WebMCP tools, shared browser state, structured schemas, tool annotations, an agent-driven recovery sequence, automated checks, and a human-only approval boundary. The dated commit history and CHALLENGE_CHANGELOG.md distinguish this work from the earlier dashboard. \n\n Demo result \n\n The demonstration uses the fictional Daniel Reed kitchen-quote enquiry, valued at £2,400. After the approved recovery flow: \n\n \n Calls recovered increase from 61 to 62 \n Appointments increase from 23 to 24 \n Recovered pipeline value increases from £7,050 to £9,450 \n \n\n All customer names, telephone numbers, records, and values are fictional demonstration data. No real customer is contacted and no external calendar is booked. \n\n How it was built \n\n Palm92 is a browser-based JavaScript application hosted on ChatGPT Sites. WebMCP tools are registered client-side through document.modelContext.registerTool . The tool layer and interface use the same state, so agent actions remain visible and understandable to the person. \n\n Codex supported implementation planning, WebMCP tool refinement, debugging, safety checks, automated testing, repository preparation, demo editing, and validation of the end-to-end workflow. ChatGPT was used to test agent discovery and execution through the in-app browser's Site tools. \n\n How to test \n\n \n Open the live application in the latest ChatGPT desktop app using GPT-5.6 Sol or GPT-5.6 Terra. \n Select Site tools in the address bar and inspect the seven Palm92 tools. \n Ask the agent to find today's highest-value unrecovered lead and help recover it. \n Let the agent inspect the lead, prepare the follow-up, qualify the opportunity, check availability, and prepare the appointment. \n Confirm that the agent stops before booking and requests human approval. \n Approve using the visible Palm92 control. \n Confirm that the dashboard updates once to 62 recovered calls, 24 appointments, and £9,450 pipeline value. \n \n\n No credentials are required. \n\n Limitations and next steps \n\n The current build uses fictional in-browser demonstration data and does not contact customers, update an external CRM, or book an external calendar. A production version would require secure identity, permissions, encrypted server-side integrations, consent controls, durable audit storage, monitoring, and configurable organisational policies. \n\n \n\n \n Built With \n\n chatgpt chatgpt-sites codex css html javascript webmcp \n \n\n \n Try it out \n\n \n \n \n palm92-lead-recovery.faithfulord1.chatgpt.site \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Faith Wright \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n\n\n\n\n\n\n\n\n \n \n\n \n\n \n \n \n \n \n Devpost \n \n About \n Careers \n Contact \n Help \n \n \n \n\n \n \n
