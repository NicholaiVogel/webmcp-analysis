To be more precise, AI dramatically influenced how employers look to the job market. And many jobs became less demanding leading people to loose their jobs. And of course they are pushed to change their job, what they do and learn completely another sphere. But the process of changing the job, learning new things becoming more and more confusing as there are more technologies, instruments are being used day-by-day. That's why people try to use AI to get help in what to learn. But standard generative AI chat bots that provides the pathway, information in plain text format can not be as visual as people can need and thats why they keep being in confuse. But this project - my WebMCP solves this problem.\n \n What it does \n The name itself is Career Switch MCP, however there is a big future behind it. Its only related to career only for now, in the future, I am planning to make it broader - giving AI agents hands to visualize what they are trying to explain - anything. So,... the application provides an interactive, visual skill tree canvas powered by the WebMCP protocol. Instead of reading plain text guides, users can interact with dynamic skill nodes. Browser-based AI agents directly invoke registered WebMCP tools (`build_skill_tree` and `highlight_skill_gaps`) to render customized roadmaps and instantly highlight missing skills or prerequisites in red.\n \n How we built it \n\n Frontend Framework: * Next.js and React for rendering the core web application.\n Canvas Visualization: * React Flow to display interactive nodes, edges, and animated connections. \n\n \n AI Integration:** Native WebMCP API ( document.modelContext ) to expose web-level tools directly to AI agents. \n Styling & UI:** Tailwind CSS for modern design and clean devtools inspector layouts. \n Deployment:** Hosted live on Vercel.\n## Challenges we ran into\nImplementing smooth integration with the newly introduced WebMCP browser protocols. \n Dynamically mapping unstructured AI context calls into organized graph node structures in React Flow without causing state conflicts. \n Synchronizing visual highlight states (skill gaps) seamlessly between WebMCP tool execution logs and the UI.\n## Accomplishments that we're proud of\nSuccessfully building a fully working prototype that bridges browser-native AI agents with visual UI canvases. \n Creating an intuitive user experience that transforms confusing text into an actionable visual roadmap. \n Registering functional tools inside document.modelContext that AI agents can invoke in real time.\n## What we learned\nDeepened my understanding of browser-native AI protocols and WebMCP tool registration. \n Learned how to effectively optimize React Flow graphs for real-time state updates triggered by agent actions. \n Mastered structuring project documentation and submission workflows under strict hackathon deadlines.\n## What's next for Career switch WebMCP\nWhile currently focused on career pathing, the long-term vision is to make this platform completely generalizable. I am planning to expand the WebMCP integration to allow AI agents to visually render anything - from complex software architecture diagrams and decision trees to educational mind maps. \n \n\n \n\n \n Built With \n\n javascript next.js react react-flow tailwand-css vercel webmcp \n \n\n \n Try it out \n\n \n \n \n career-switch-web-mcp.vercel.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n I worked on the both sides - frontend and backend. modelContext was completely new thing for me.
