Coordinators spend valuable time reconciling those sources to answer a deceptively simple question: what does this subject need next? ProtocolOS began with the idea that a protocol should be an operational workflow that people and browser agents can understand together—not just a static document. \n\n What it does \n\n ProtocolOS turns research protocols into shared, agent-ready workflows. It organizes multiple synthetic studies, subjects, stages, visits, assessments, samples, tasks, and completion criteria in one polished workspace. \n\n Coordinators can: \n\n \n See today's priorities across multiple studies \n Understand a subject's current stage, visit, and outstanding work \n Build and publish a visual protocol workflow \n Generate a visit checklist from the published workflow \n Complete tasks while keeping related records synchronized \n Check whether a subject is ready to advance, with explicit reasons when advancement is blocked \n \n\n All demo records are fictional and use generic IDs such as SUB001. ProtocolOS contains no real protected health information. \n\n How WebMCP creates real utility \n\n Without WebMCP, an agent would have to infer operational state from pixels and page text. That is fragile when a missed assessment, sample, or sign-off can change whether a visit is complete. \n\n ProtocolOS registers fourteen imperative tools through document.modelContext.registerTool(). They cover portfolio summaries, priorities, workflow inspection and publishing, subject status, assessments, visits, samples, missing tasks, readiness, checklist creation, task completion, and guarded stage advancement. \n\n Read operations are marked read-only. Mutations are explicit and update the same React state shown to the coordinator. Every response includes structured results, synthetic-data indicators, workflow provenance, and a compact technical receipt. \n\n Human and agent collaboration \n\n A coordinator can ask, “What does SUB001 need today?” The agent retrieves the current stage and visit, incomplete tasks, assessments, sample requirements, and next action. It can create the checklist and complete an approved item. The visible workspace updates immediately, and the activity trail records who changed what and when. \n\n Crucially, the model does not decide whether a subject advances. ProtocolOS evaluates the published completion gates and returns a clear allowed-or-blocked decision with the exact remaining requirements. The workflow remains the source of truth while the agent accelerates coordination. \n\n How we built it \n\n ProtocolOS is a responsive React and TypeScript application styled with Tailwind CSS and hosted with OpenAI Sites. Synthetic seed data powers a multi-study dashboard, subject records, a visual workflow builder, visit checklists, activity history, and an agent workspace. WebMCP actions are registered directly in the live page so a compatible browser agent can use the product's own operational contract. \n\n Challenges we ran into \n\n The hardest part was making agent actions and visible UI state feel like one system instead of a chat demo layered on top of a dashboard. We also had to model advancement safely: status checks must be useful and read-only, while actual transitions remain explicit, auditable, and governed by published rules. \n\n Designing a workflow builder that stays flexible across study types was another challenge. We avoided study-specific terminology and made stages, visits, requirements, and gates configurable. \n\n Accomplishments that we're proud of \n\n We built a polished multi-study workspace where fourteen WebMCP actions operate on the same state people see. The challenge demo shows retrieval, checklist creation, synchronized completion, audit history, and a guarded workflow decision in under three minutes. \n\n What we learned \n\n WebMCP is most compelling when tools represent meaningful domain actions rather than page-navigation shortcuts. Clear schemas, workflow provenance, read/write separation, and visible state synchronization make an agent experience more trustworthy and useful. \n\n Judge demo \n\n \n Ask: What does SUB001 need today? \n Ask: Create SUB001's visit checklist. \n Ask: Mark task T-001-3 complete for SUB001. \n Ask: Can SUB001 advance to the next stage? \n \n\n The final check is intentionally blocked and explains the remaining tasks, assessment, and samples. If the demo has already been used, choose Reset challenge demo in the Agent workspace. \n\n What's next for ProtocolOS \n\n Next, ProtocolOS can add protocol import, reusable workflow templates, role-based approvals, integrations with validated research systems, and configurable audit exports—while preserving the same human-visible, workflow-governed approach. \n\n \n\n \n Built With \n\n openai react tailwind \n \n\n \n Try it out \n\n \n \n \n protocolos-webmcp.christian-lopez-1.chatgpt.site \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Christian Lopez Blanco \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Christian Lopez Blanco \n started this project\n \n —\n \n 3 days ago \n \n \n\n
