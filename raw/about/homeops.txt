Traditional maintenance apps also create another system the homeowner must constantly update. \n\n HomeOps creates one shared household-maintenance workspace that both a person and an AI agent can understand. \n\n HomeOps tracks recurring household responsibilities such as HVAC filter replacement, smoke-detector testing, dryer-vent cleaning, and water-heater flushing. \n\n For each item, it stores: \n\n \n The last service date \n The recurring maintenance interval \n The calculated next due date \n Overdue status \n Estimated completion time \n Useful notes, such as filter sizes or service instructions \n \n\n Through WebMCP, an agent can: \n\n \n Read the current household-maintenance record \n Find overdue and upcoming work \n Look up the history of a specific item \n Create a prioritized maintenance-session proposal \n Wait for the homeowner to approve it or request a revision \n Read the homeowner’s decision \n Record completed maintenance after explicit human confirmation \n Add a new recurring responsibility after explicit human confirmation \n \n\n The homeowner sees the same shared information in the visual interface. Agent actions and human decisions are also displayed in an activity history. \n\n The central HomeOps workflow is collaboration rather than uncontrolled automation. \n\n A homeowner can ask: \n\n \n Audit my home for the next 30 days and propose the best three-task work session. \n \n\n The agent reads the maintenance record, identifies urgent work, and creates a visible proposal. \n\n It then stops. \n\n The homeowner can approve the proposal or request a revision, such as asking for only the two shortest tasks. The agent can read that decision through a separate WebMCP tool before continuing. \n\n HomeOps also prevents an agent from recording completed service or adding a recurring maintenance item unless explicit human confirmation is included in the tool call. \n\n This allows the agent to take useful initiative while keeping meaningful decisions under human control. \n\n HomeOps registers seven structured tools: \n\n \n homeops_get_state \n homeops_list_due \n homeops_lookup_item \n homeops_propose_session \n homeops_get_plan_status \n homeops_log_service \n homeops_add_item \n \n\n Each tool includes: \n\n \n A focused natural-language description \n A narrow JSON input schema \n Required fields and validation limits \n Read-only or state-changing annotations \n A dedicated execution handler \n \n\n Without WebMCP, an agent would need to inspect page text, locate interface elements, and guess which sequence of clicks changes the correct record. \n\n With WebMCP, the website explicitly tells the agent what capabilities are available, which inputs are valid, and which operations modify state. \n\n The visual interface and the WebMCP tools operate on the same household data. \n\n HomeOps is a lightweight browser application built with HTML, CSS, and JavaScript. \n\n The application: \n\n \n Registers WebMCP tools directly in the browser \n Stores household records in browser local storage \n Calculates overdue and upcoming maintenance dynamically \n Displays agent proposals and human decisions in one interface \n Uses constrained schemas for safer tool calls \n Requires no account, external database, paid API, or API key \n Includes a fallback demonstration using the same tool handlers when experimental WebMCP browser support is unavailable \n \n\n The working application is deployed publicly, and its complete source code is available in a public MIT-licensed GitHub repository. \n\n The main challenge was designing a useful human-agent workflow rather than simply exposing buttons to an agent. \n\n We wanted the agent to make meaningful progress while preserving clear human control. That led to the proposal-and-approval workflow: the agent may analyze the household record and recommend a plan, but the homeowner makes the final decision. \n\n Another challenge was defining tools narrowly enough for an agent to choose the correct action reliably. We used descriptive names, limited responsibilities, strict schemas, bounded values, and explicit human-confirmation requirements for durable changes. \n\n Because WebMCP is experimental, we also made the core application functional in ordinary browsers while exposing its full structured tool layer in supported environments. \n\n \n Seven functional WebMCP tools \n A working public application \n Shared state between the interface and agent tools \n A visible human approval and revision loop \n Explicit confirmation requirements for important changes \n Auditable human-agent activity \n Persistent browser-based household memory \n Responsive desktop and mobile design \n No paid API or account requirement \n Public MIT-licensed source code \n \n\n WebMCP is most valuable when it does more than make an existing button easier for an agent to press. \n\n It allows a website to become a shared workspace where a person understands the context visually while an agent receives precise and structured capabilities. \n\n We also learned that good human-agent collaboration needs explicit intermediate states. “Proposed,” “approved,” and “revision requested” give both sides a reliable understanding of what should happen next. \n\n The best agent experience is not necessarily the one with the most autonomy. It is the one with useful capabilities, reliable, shared context, clear boundaries, and understandable stopping points. \n\n Future versions could add: \n\n \n Optional calendar and reminder handoffs \n Shared household-member roles \n Appliance manuals and model information \n Maintenance receipts and service records \n Seasonal maintenance templates \n Parts and supply lists \n Contractor coordination \n Proactive maintenance briefings \n Optional encrypted cloud synchronization \n \n\n The broader vision is a household operations layer where people remain in control while agents help organize, remember, and coordinate the work required to maintain a home. \n\n \n\n \n Built With \n\n agents ai apis css3 github html5 human-in-the-loop javascript json localstorage open schema vercel web webmcp \n \n\n \n Try it out \n\n \n \n \n homeops-webmcp.vercel.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n John Elwood \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n John Elwood \n started this project\n \n —\n \n 3 days ago \n \n \n\n
