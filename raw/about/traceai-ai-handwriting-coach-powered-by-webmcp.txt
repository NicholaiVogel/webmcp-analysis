Settings & Controls : Configuration for voice guidance, learner profiles, and WebMCP agent autonomy. Inspiration Watching young children learn to write can be both fascinating and heartbreaking. I often observed children drawing letters like "D" or "B" from bottom to top, or making awkward reverse loops. Visually, the final result might look somewhat acceptable on a static worksheet, but motor-memory-wise, a bad habit was already taking root. Existing handwriting apps on tablets simply check whether pixels overlap with a template. They don't understand how the child traced it, in which direction, or why they made a mistake. Meanwhile, parents and teachers simply don't have enough hours in the day to sit 1-on-1 for every single stroke. When OpenAI announced the WebMCP standard, a lightbulb went off: what if an AI didn't just passively look at a screenshot, but had direct, structured API tools on the web page to analyze mathematical stroke trajectories and dynamically adapt the canvas with live visual guides? That was the spark that drove me to build TRACEAI. What it does TRACEAI is an AI-native web application designed to act as an attentive, encouraging handwriting coach for kids. Here is how the experience works in practice: Child practices on a joyful, tactile canvas: Children can practice uppercase letters (A-Z), numbers (0-9), and basic geometric shapes across 3 distinct difficulty modes (Trace, Copy, and Memory). Instant 5-Dimension Trajectory Evaluation: As soon as a child lifts their pen or finger, TRACEAI analyzes the stroke geometry across 5 criteria: Direction & Stroke Order, Positioning, Precision, Continuity, and Line Respect. Autonomous AI Coaching via WebMCP: An AI agent inspects the child's learning history through registered WebMCP tools (get_weak_letters(), analyze_trace()). Real-time Interface Adaptation: When the agent detects an issue—for example, struggling with the curved stroke direction on the letter "D"—it calls generate_exercise("D", "direction"). The web page instantly reacts by drawing pulsating directional guide arrows and speaking warm, supportive vocal guidance. Gamified Positive Reinforcement: Points, stars, streak tracking, audio chimes, and confetti celebrations keep the child smiling and motivated. Built-in WebMCP Inspector: For hackathon judges and developers, an inspector panel provides live insight into the agent’s inner monologue, tool calls, JSON payloads, and a 1-click end-to-end demo scenario. How we built it I engineered TRACEAI as a solo project to be ultra-fast, responsive on touch devices (tablets/smartphones), and 100% compliant with the emerging W3C WebMCP standard: WebMCP Standard Tooling: I registered 8 structured tools directly onto document.modelContext.registerTool() with explicit JSON schemas. I also implemented a lightweight fallback polyfill so the app runs smoothly in both WebMCP-enabled browsers and standard modern browsers. Client-Side Geometric Engine (trace-analyzer.js): I built a vector analysis pipeline that calculates directional angle variances, Dynamic Time Warping (DTW) path distances, and bounding-box alignments in under 5ms right in the browser. Reactive Canvas & Visual Overlays (app.js): Built with pure HTML5 Canvas and Vanilla JavaScript. Dynamic arrow overlays and smooth Bezier curve approximations make the interface feel alive without heavy rendering libraries. Multi-Sensory Audio System: Utilizes the Web Speech API for natural text-to-speech coaching advice and the Web Audio API for rewarding synthesizer chimes and fanfares. Modern Glassmorphic UI: Crafted using modern, responsive CSS with cheerful, kid-friendly color palettes, accessible contrasts, and smooth micro-animations. Challenges we ran into Distinguishing Shape from Direction: A child drawing the letter "O" clockwise vs. counter-clockwise results in almost identical static shapes, but completely different motor habits. Designing a lightweight vector angle differential that accurately detects inverted stroke sequences was my trickiest algorithmic hurdle. Designing Agent-Friendly Tools: I initially tried passing raw coordinate streams to the LLM, but quickly realized that overwhelmed the context window and caused unnecessary latency. I shifted to a high-signal tool design where analyze_trace() and get_weak_letters() return clean, structured metrics (0.0 to 1.0 scores and explicit weakness classifications like "direction" vs "precision"), allowing the agent to reason instantly. Rendering Dynamic Guidance on Canvas: Translating the agent's high-level command (generate_exercise('D', 'direction')) into animated, pulsating SVG/Canvas arrows that follow the exact path of each letter required fine-tuning my character vector templates. Accomplishments that we're proud of A Real Closed-Loop Web Agent: Successfully building an AI experience where the agent doesn't just answer questions in a sidebar, but actively manipulates the application state and visuals to solve an educational challenge. Zero-Dependency Performance: Running the entire application (analysis, rendering, speech, tools) smoothly on client-side Vanilla JS with instant load times. The WebMCP Inspector & 1-Click Scenario: Enabling judges and testers to see the agent reasoning in real time and test the entire workflow with a single click. What we learned The sheer power of WebMCP: Moving away from DOM scraping and screenshot interpretation towards clean, declarative web tools is a paradigm shift for web development. It makes AI agents hundreds of times faster, deterministic, and much more resilient. How to bridge early-childhood pedagogy with autonomous agent decision-making.
