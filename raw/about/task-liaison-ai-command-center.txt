When a GKE node pool fails or a Cloud SQL database spikes, the resolution process is usually a messy combination of frantic Slack messages, manual Jira routing, and repetitive UI clicks. I wanted to see if the new WebMCP standard could transform an LLM from a passive conversational chatbot into an active, operational partner that orchestrates incident workflows directly on the canvas. \n\n What it does \n\n Task-Liaison is an AI-orchestrated command center for infrastructure escalations. Instead of clicking through menus, engineers talk to the board. The application uses a three-column Kanban layout: \n\n \n The Command Center: Unassigned, critical incidents. \n The Priority Reward Exchange: An incentivized bounty market where the AI can dynamically price and route tasks. \n Active Engineering Workloads: Real-time on-call assignments. \n \n\n By exposing strict JSON-schema React state mutations to the LLM's runtime environment, the AI can map cascading blast radiuses, re-route workloads between engineers to prevent burnout, and stage mock Infrastructure-as-Code (Terraform/Bash) patches. Crucially, the system enforces Human-in-the-Loop execution: the AI stages the complex configurations, but human engineers retain physical click-approval authority to apply the patches. \n\n How we built it \n\n Task-Liaison is a frontend-only React application built on the Next.js framework and styled with Tailwind CSS. The core innovation lies in leveraging the document.modelContext API. I registered custom JavaScript tools ( post_bounty_to_market , propose_ticket_swap , analyze_blast_radius , stage_remediation_script ) with rigid input schemas. When the user types a natural language command, the LLM extracts the parameters, maps them to the schema, and triggers instantaneous React state mutations without any backend database. \n\n Challenges we ran into \n\n Maintaining the state synchronization between a non-deterministic AI and a deterministic frontend UI was the biggest hurdle. During development, local hot-reloading would frequently wipe the WebMCP tool registrations from the AI's memory, causing the LLM to fall back into "chatbot mode" where it would hallucinate actions instead of firing the API tools. I had to implement strict lifecycle management using React useRef and useEffect hooks to ensure the JSON contracts remained tethered to the agent's context window. \n\n Accomplishments that we're proud of \n\n I am exceptionally proud of the closed-loop execution flow. When a user tells the AI to "stage a mock Terraform script for INC-102," the AI perfectly formats the code block, injects it into the specific React component, and generates an actionable "Approve & Execute" button. Successfully blending AI-driven state mutations with human-driven React onClick events proves that AI can be trusted in enterprise operational environments if constrained by the right UI boundaries. \n\n What's next for Task-Liaison \n\n The next step is backend integration. While this MVP handles state in the browser to prove the WebMCP concept, the natural evolution is tying the execute blocks to authenticated webhooks—allowing the AI to actually update live Jira tickets, trigger PagerDuty alerts, or execute validated Terraform plans directly against a GCP environment. \n\n \n\n \n Built With \n\n ai-agent llm next.js react tailwind-css typescript vercel webmcp \n \n\n \n Try it out \n\n \n \n \n task-liaison.vercel.app \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n I built the entire project from scratch.
