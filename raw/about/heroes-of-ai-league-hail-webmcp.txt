The WebMCP Challenge gave us the opportunity to bring those capabilities directly into the browser and explore a new question: what if a website could clearly tell an AI agent what it can do instead of forcing the agent to guess through clicks and DOM automation? \n\n What it does \n\n HAIL is an AI readiness platform centered around assessments. Users complete structured assessments, receive results, and turn those results into practical next steps and playbooks. \n\n For WebMCP, we added browser-native tools that agents can discover and execute directly in Chrome and compatible browsers. \n\n These tools let agents interact with both simple and advanced forms, fill assessment data, trigger actions, and work with the live website in a structured way. \n\n We are also experimenting with new browser workflows such as print, fill, and load , testing how agents can move information into forms, prepare outputs, and interact across different browser states. \n\n HAIL now supports four interaction layers: classic UI, MCP, Skills, and WebMCP . \n\n How we built it \n\n We kept the existing HAIL website and assessment UI intact, then added WebMCP capabilities alongside it. \n\n Instead of replacing the human experience, we exposed selected actions as structured browser tools. This allows an agent to understand available operations, provide the required inputs, and execute them directly within the page. \n\n We designed the tools around real assessment workflows, including form filling and more complex interactions, while continuing to support our existing MCP endpoints and Skills. \n\n Challenges we ran into \n\n One of the biggest challenges was deciding what should remain a normal UI interaction and what should become an explicit WebMCP tool. \n\n Forms also become much more interesting once they move beyond simple text inputs. Assessments can include validation, multiple steps, different field types, dependencies, and changing browser state. \n\n Another challenge was designing tools that are useful for agents without simply exposing every internal implementation detail of the website. \n\n We also explored workflows such as printing, loading data, and filling more advanced forms, which pushed us beyond the typical "agent fills a few inputs and clicks submit" use case. \n\n Accomplishments that we're proud of \n\n We are proud that HAIL now works across multiple interaction models without requiring separate products. \n\n A human can use the classic interface. An external agent can use MCP. Repeatable workflows can use Skills. And a browser-based agent can now discover and execute WebMCP tools directly on the site. \n\n We are especially excited about making assessments agent-ready while preserving the normal web experience. \n\n What we learned \n\n WebMCP changes the relationship between agents and websites. \n\n Traditional browser agents often need to inspect the page, infer intent from the DOM, find the correct controls, and hope the interface has not changed. \n\n With WebMCP, the website can expose its capabilities explicitly. \n\n We learned that this can make agent interactions more reliable, more understandable, and potentially safer—especially for structured workflows such as assessments and forms. \n\n We also learned that the most interesting opportunities are not always simple automation. Workflows like print, fill, and load suggest a much broader set of browser-native agent experiences. \n\n What's next for Heroes of AI League (HAIL) - WebMCP \n\n Next, we want to expand HAIL's WebMCP capabilities beyond the initial assessment workflows. \n\n We plan to support richer multi-step forms, more advanced assessment interactions, better result and playbook workflows, and additional experiments around loading, filling, printing, and transferring structured information. \n\n We also want to explore how WebMCP, MCP, and Skills can work together as one agent experience. \n\n Our longer-term goal is for HAIL to become a website that works equally well for humans and AI agents: one experience, multiple interfaces, and clear structured capabilities available wherever the interaction happens. \n\n \n\n \n Built With \n\n cursor \n \n\n \n Try it out \n\n \n \n \n heroleague.ai \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n everything innovator and engineering @ heroleague.ai \n \n\n \n \n \n \n \n \n\n \n Razvan B. \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Razvan B. \n started this project\n \n —\n \n 6 days ago \n \n \n\n
