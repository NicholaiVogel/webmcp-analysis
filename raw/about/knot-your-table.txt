Once something is outside the viewport, the agent has very little idea what is out there or which direction to explore. I even had to build extra navigation UI just to help humans find far-away objects. For AI bulk editing, the usual approach was a dedicated LLM call through something like OpenRouter: package up some context, ask for one transformation, apply the response. It works, but it is still basically an isolated LLM call, not an agent continuously working with the live app state. \n\n Recently, my best friend has been planning a wedding with 80+ guests and kept complaining about seating. The painful part was not dragging names onto tables. It was keeping all the invisible rules in her head: these people are vegetarian, these friends should sit together, these 2 people should not sit together, and then something changes at the last minute and you have to reshuffle everything again. \n\n That felt like a very natural problem to explore with a canvas app + WebMCP. \n\n What it does \n\n Knot Your Table is a visual wedding seating planner where the human gets a clean, playful canvas and the agent gets access to the structured data underneath it. \n\n A user can say: \n\n \n “Keep the vegetarians mostly together, keep my college friends together if possible, and family tables should be closest to the stage.” \n \n\n The agent can reason across the whole wedding, including guests and tables that are completely offscreen, make coordinated changes, validate the result, and summarize what changed. \n\n The key idea is that the user should not have to see every relationship, dietary preference, constraint, table capacity, or room coordinate at once. That information is useful for the agent, but overwhelming for the human. The user gets to focus on visual arrangement, judgment calls, and checking whether the result feels right, while the agent handles the grunt work. \n\n How I built it \n\n I built Knot Your Table as a client-side visual planner with a shared application state that both the canvas and WebMCP tools use. \n\n I registered a set of WebMCP tools that let the agent: \n\n \n understand the seating plan \n manage planning rules \n modify guests and seating \n verify and present seating changes \n \n\n The agent is not clicking pixels or dragging from one coordinate to another. It is operating on the actual data underneath the UI in verifiable ways. \n\n Human edits and agent edits also stay in sync. If I manually move someone because I prefer where they are, the agent immediately sees that new state and can work around it without me having to explain what I just changed. \n\n Challenges I ran into \n\n One of the hardest parts was deciding what not to expose. \n\n It would have been easy to create dozens of tiny overlapping WebMCP tools, but that not only increases the initial build complexity, it also gives the agent too many similar choices to make. A larger, overlapping toolbox introduces more variance into the agent’s decisions, which can make the same user request behave differently over time and ultimately make the product feel less predictable and trustworthy. The challenge was finding a small set of semantic actions that were broad enough to handle different requests while still being clear and predictable. \n\n The other challenge was visual design. I do not have an art background, and I wanted the app to feel more like a fun wedding-decorating experience than an AI dashboard. Getting the canvas to feel playful, readable, and still functional took a lot of iteration. \n\n Accomplishments that I'm proud of \n\n The human and agent are actually working on the same live plan. A person can manipulate the room visually, while the agent can reason over information that may be hidden or far outside the current viewport. That makes the interaction feel much more natural than either manually doing everything in the canvas or sending a one-off LLM request and trying to merge the result back into the app afterward or filling out and managing complex forms of rules. \n\n I am also happy with how much complexity we were able to keep out of the visible interface. The product can support fairly rich operations without turning into a wall of filters, rule builders, and bulk-edit controls. \n\n What I learned \n\n The biggest thing I learned is that WebMCP can change how we think about web interfaces. \n\n A functionally rich app does not need to expose every operation visually. The visible UI can be the tip of the iceberg: the human sees the part that is useful and enjoyable, while the agent handles much of the operational complexity underneath. \n\n That creates a cleaner division of labor. The human focuses on judgment, visual thinking, and verification. The agent handles the tedious coordination needed to make the whole plan work. \n\n What's next for Knot Your Table \n\n Next, I want to share Knot Your Table more broadly as a free tool and see how real couples actually use it. I’m especially interested in which seating problems come up repeatedly, where the agent is genuinely useful, and where the interaction still feels confusing or unpredictable. \n\n From there, I’d like to gradually expand it beyond seating into a fuller wedding planning suite, while keeping the same idea: let the human focus on the visual, social, and creative decisions they care about, and let the agent handle the repetitive coordination underneath. \n\n \n\n \n Built With \n\n html5 konva netlify react typescript vite webmcp zustand \n \n\n \n Try it out \n\n \n \n \n knot-ur-table.netlify.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n I did it all :) \n \n\n \n \n \n \n \n \n\n \n Sophia Liu \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Sophia Liu \n started this project\n \n —\n \n 2 days ago \n \n \n\n
