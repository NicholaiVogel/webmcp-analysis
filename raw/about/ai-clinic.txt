But when it needs a structured screening tool, the experience breaks. \n\n You leave the conversation, search for a test, complete it on another website, then bring the result back. \n\n We wanted to remove that gap. \n\n What if a health website wasn't just readable by an AI — but actually usable by it? \n\n What it does \n\n Medtests makes structured health screening tools available to AI agents through WebMCP. \n\n An agent can discover available screenings, retrieve the questions, guide the user through them, score the answers, and return the structured result. \n\n For example, instead of only answering: \n\n "Could these symptoms be ADHD?" \n\n an AI can use Medtests to start a relevant screening flow and guide the user through it. \n\n The user doesn't have to figure out which page to open or copy information between an AI and a website. \n\n How we built it \n\n We turned Medtests from a traditional website into an agent-accessible website using WebMCP. \n\n The browser exposes five tools: \n\n \n list_screenings \n get_screening \n score_screening \n get_crisis_resources \n get_chat_analysis_protocol \n \n\n The tools are registered through the browser's WebMCP interface using document.modelContext.registerTool(...) . \n\n The application is written in JavaScript and deployed on Cloudflare Workers with Wrangler, with deployment through GitHub. \n\n The important architectural decision was simple: \n\n Instead of building another chatbot, we made the website itself callable by AI agents. \n\n Challenges we ran into \n\n Health screening is a good example of why agent interfaces need structure. \n\n An agent shouldn't have to scrape a webpage and guess what a button, question, or score means. \n\n We had to turn human-facing interactions into explicit tools with predictable inputs and outputs, while keeping the existing website useful for humans. \n\n We also had to separate screening from diagnosis. Medtests provides structured screening tools and results — not medical diagnoses. \n\n Accomplishments that we're proud of \n\n We built a working WebMCP layer on top of a real health website. \n\n The same resource can now serve two users: \n\n Humans can use the website. Agents can use the tools. \n\n No separate AI product is required. \n\n That is the part we're most excited about. \n\n What we learned \n\n WebMCP changes what a website can be. \n\n For the last 30 years, websites have primarily exposed interfaces for humans: pages, forms and buttons. \n\n Agents need something different: capabilities with names, schemas and structured results. \n\n Once those capabilities exist, the website stops being something an AI merely reads. \n\n It becomes something the AI can use. \n\n What's next \n\n Medtests is the first use case. \n\n The bigger idea is to make useful parts of the web agent-native — so an AI can move from explaining what someone could do to actually helping them do it. \n\n The web was built for humans to click. WebMCP lets agents act. \n\n \n\n \n Built With \n\n cloudflare github javascript mcp webmcp wrangler \n \n\n \n Try it out \n\n \n \n \n medtests.de \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n Dr. Dominik Dotzauer \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Dr. Dominik Dotzauer \n started this project\n \n —\n \n a day ago \n \n \n\n
