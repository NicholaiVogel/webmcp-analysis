WebMCP exposes these capabilities as structured tools rather than requiring the agent to interact through simulated clicks or copied text. \n\n The application exposes tools for actions such as: \n\n \n Adding entries \n Drawing winners \n Updating entries \n Resetting exclusions \n Performing multi-winner draws \n \n\n This makes Drawboard an example of an agent-native web application: the AI can operate the application through its own structured interface while the human can still use the normal UI. \n\n Challenges we ran into \n\n The main challenge was designing tools that represent meaningful application actions rather than simply exposing low-level UI interactions. \n\n We also needed to make sure that actions performed by the agent produced exactly the same state changes as actions performed by a human through the interface. \n\n Weighted draws and multi-winner draws added another layer of complexity because the agent needs to provide structured parameters while the application remains responsible for the actual randomization logic. \n\n Accomplishments that we're proud of \n\n We are particularly proud that the WebMCP integration is not a separate demo layer. \n\n The agent is interacting with the real application state. \n\n A particularly simple but powerful example is the winner update: after drawing a winner, the agent renames the entry and adds a trophy emoji. The change immediately appears in the application. \n\n Drawboard also demonstrates several different types of agent interaction in a single workflow: creating data, using parameters, executing an action, modifying existing data, resetting state, and performing a multi-result operation. \n\n What we learned \n\n We learned that making a website agent-friendly is more than exposing a few buttons as tools. \n\n The most useful WebMCP tools correspond to meaningful operations in the application's domain. \n\n We also learned that sharing the same underlying logic between the human interface and WebMCP makes the application much easier to reason about and keeps agent actions consistent with normal user interactions. \n\n Most importantly, WebMCP changes the relationship between AI agents and websites: instead of the agent merely observing an interface, the website can provide the agent with a structured way to actually use it. \n\n What's next for Drawboard \n\n The next step would be to make Drawboard more flexible and useful for real-world scenarios. \n\n Possible additions include saving and loading draw configurations, importing larger lists, creating reusable draw presets, supporting more advanced weighting rules, and adding additional WebMCP tools for managing complete draw sessions. \n\n The long-term idea is simple: make everyday web applications not only usable by humans, but genuinely usable by AI agents. \n\n \n\n \n Built With \n\n agentic-ai ai-agents automation javascript openai react webmcp \n \n\n \n Try it out \n\n \n \n \n imagelens.vercel.app \n \n \n
