People repeatedly ask: What happens next? Who can I trust? Which profiles fit my path? Cove is designed as a fertility journey operating system: one calm workspace for intended parents, surrogates, egg donors, sperm donors, and qualified human reviewers. For the WebMCP Challenge, we asked a more ambitious question: what if an AI agent could work with Cove's live interface through page-defined tools, understand a signed-in user's current context, and help them move forward without taking away human control? What it does Cove exposes purpose-built WebMCP tools from the pages where the work happens. On the intended-parent dashboard, the agent can call cove_get_parent_journey to read the user's application status, selected family-building paths, candidate-access status, current stage, and recommended next action. A companion tool can bring the guided next-step timeline into view so the user and agent stay grounded in the same screen. In the authorized candidate directory, the agent can: call cove_find_candidate_profiles to filter and rank profiles by candidate type and state; call cove_open_candidate_profile to open a selected profile and return only the details available to that parent; and call cove_prepare_introduction to prepare an introduction note without submitting it. Every tool updates the same interface the person sees. The agent does not create a parallel experience: filters change, results appear, profiles open, and the introduction review dialog is prepared directly in Cove. The final introduction remains a human decision. The tool explicitly returns submitted: false , and the intended parent must review and choose whether to continue. How we built it Cove is a React and TypeScript application deployed on Cloudflare. Supabase provides authentication, PostgreSQL data, storage, and row-level access controls for role-scoped platform data. We created a small WebMCP registration layer around document.modelContext.registerTool . Each page registers only the tools that make sense in its current context and uses an AbortController to cleanly remove them when the React view unmounts. Inputs use explicit JSON schemas and application-level validation. Candidate searches constrain type, validate two-letter state codes, and cap result counts. Tool annotations distinguish read-only operations from operations that change the visible page. The tool output is intentionally narrow: it returns first names, fit explanations, availability, and access-appropriate summaries—not private contact information. Most importantly, WebMCP is connected to the product's real state and interaction model. The candidate search tool uses the same loaded profile set, filters, sorting, access rules, and UI components as a person using Cove manually. Challenges we ran into The hardest problem was not registering tools—it was choosing the correct boundary between assistance and authority. A fertility platform contains consequential decisions and sensitive information. A broadly capable agent would be the wrong design. We instead made every tool role-aware, schema-constrained, and scoped to the page. Search can organize authorized choices; it cannot reveal hidden fields. An agent can prepare an introduction; it cannot submit one. We also had to keep agent actions visible. A successful tool call should never leave the user wondering what changed, so Cove scrolls to the relevant section, updates filters and status copy, and opens the same review surfaces a person would use. Accomplishments that we're proud of WebMCP tools are embedded in a functioning multi-role fertility platform rather than a standalone demo. Agent results and the human-facing interface remain synchronized. Authorization and data minimization are part of the tool design. The most consequential action in the demo ends at a clear review boundary. The experience reduces navigation and repetitive coordination while preserving informed human decisions. What we learned WebMCP is most powerful when a site publishes small, domain-specific capabilities instead of asking an agent to infer intent from pixels and DOM structure. The tool schema becomes a product contract: it says what an agent may do, what it may return, and where a human must remain responsible. We also learned that good agentic UX is visible UX. Users should see the filters, profiles, explanations, and prepared actions—not just receive a hidden background response. What's next for Cove Next we plan to extend the same model to Journey Rooms, match-meeting scheduling, document and medical-record status, and contextual support. Routine questions and reversible actions can be automated; eligibility, matching, consent, and other high-stakes decisions will continue to belong to qualified people. The long-term goal is simple: help each user understand what is happening, what they need to do, and when a human is needed —without making them chase updates across disconnected systems.
