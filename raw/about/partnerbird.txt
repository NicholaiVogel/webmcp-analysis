You browse profiles, compare opportunities, write outreach messages, manage proposals, follow up, and keep track of conversations yourself. \n\n At the same time, AI agents are becoming much more capable, but they are often limited to giving advice beside the product rather than actually participating in the workflow. \n\n PartnerBird started from a simple question: what would a partnership platform look like if both the human and their AI agent were first-class users? \n\n WebMCP made that idea much more practical. Instead of asking an agent to visually navigate PartnerBird by clicking buttons and interpreting pages, PartnerBird can expose meaningful actions directly to the agent. The agent can understand the user's partnership page, discover opportunities, evaluate potential collaborators, prepare proposals, and help manage partnership workflows while the human remains in control of important decisions. \n\n The goal is not to replace the person building the relationship. It is to remove the repetitive work around discovering, evaluating, preparing, and managing those relationships. \n\n What PartnerBird does \n\n PartnerBird is an agent-native platform for managing business partnerships and collaborations. \n\n Users can create partnership pages that explain who they are, what they are looking for, what they can offer, and the types of collaborations they are interested in. \n\n Through WebMCP, an AI agent can interact with those partnership workflows directly. \n\n For example, a user could ask: \n\n \n Find partnership opportunities that would be a good fit for my SaaS and shortlist the strongest ones. \n \n\n The agent could search PartnerBird, inspect relevant partnership profiles, understand what each person is looking for, compare compatibility, and return a shortlist. \n\n The user could then say: \n\n \n Prepare a collaboration proposal for the top two. Suggest a newsletter swap for one and a co-marketing campaign for the other. \n \n\n Instead of only generating text in chat, the agent can create those proposals inside PartnerBird. \n\n From there, the human and agent can continue working together to revise proposals, evaluate responses, organize partnership opportunities, and manage the collaboration workflow. \n\n The broader idea is that PartnerBird becomes a shared workspace between the person and their agent. \n\n Why WebMCP matters \n\n Without WebMCP, an agent would need to understand PartnerBird largely through the visual interface. \n\n With WebMCP, PartnerBird can expose structured capabilities representing the actual concepts within the product, such as searching for partners, reading partnership profiles, evaluating opportunities, preparing proposals, updating proposals, and managing collaboration workflows. \n\n This creates a much more reliable interaction model. \n\n More importantly, WebMCP changes the role of the agent. \n\n Instead of being a chatbot sitting beside PartnerBird, the agent becomes an active participant inside the partnership workflow. \n\n The human provides goals, context, preferences, judgment, and final approval. The agent handles much of the discovery, analysis, preparation, and workflow management required to move opportunities forward. \n\n How I built it \n\n PartnerBird was already being developed as a platform centered around partnership pages, collaboration opportunities, user profiles, dashboards, and an AI-assisted partnership experience. \n\n For the WebMCP Challenge, I am extending that existing experience with a WebMCP layer that exposes selected PartnerBird capabilities as structured tools for agents. \n\n Rather than creating a completely separate agent backend, the WebMCP tools are designed to connect to PartnerBird's existing application logic and workflows. \n\n An important part of the implementation is separating actions based on their consequences. \n\n Low-risk actions such as discovering opportunities, reading profiles, comparing potential partners, and preparing drafts can be highly agent-assisted. \n\n Actions that affect another user or create a meaningful commitment should remain visible to the user and, where appropriate, require human approval. \n\n This creates a workflow where autonomy increases productivity without removing human judgment from important relationship decisions. \n\n Challenges \n\n One of the biggest challenges is deciding what should actually become a WebMCP tool. \n\n Technically exposing actions is relatively straightforward. Designing the right agent experience is harder. \n\n If every button in the interface simply becomes a tool, WebMCP does not add much value. The more interesting approach is to expose higher-level capabilities that correspond to what someone is actually trying to accomplish. \n\n For example, the user does not necessarily care about navigating several screens to create a proposal. Their intention is simply: \n\n \n Prepare a partnership proposal for this person. \n \n\n Designing around these intentions makes the agent experience much more natural. \n\n Another challenge is balancing agent autonomy with human control. Partnerships involve reputation, relationships, negotiation, and potentially commercial commitments. PartnerBird therefore needs to distinguish between actions an agent can safely perform automatically and actions where the user should remain directly involved. \n\n What I learned \n\n Building PartnerBird around WebMCP changed the way I think about web application design. \n\n Traditional web applications are primarily designed for humans operating graphical interfaces. \n\n The emerging agentic web introduces another layer. Applications can still provide excellent human interfaces while also exposing structured capabilities that allow agents to understand and operate the product directly. \n\n That means developers increasingly have to think about two interaction surfaces: \n\n the interface humans see and the capabilities agents can understand. \n\n WebMCP provides a bridge between those two worlds. \n\n The most interesting opportunities appear when the agent is not simply automating clicks, but collaborating with the human around a shared application state. \n\n What's next \n\n The longer-term vision for PartnerBird is to make partnerships increasingly agent-native. \n\n An agent should eventually be able to understand what its user is trying to accomplish, continuously identify relevant partnership opportunities, evaluate compatibility, prepare collaboration ideas, organize proposals, surface conversations that need attention, and help move successful partnerships forward. \n\n The human remains responsible for the relationships and important decisions. \n\n The agent becomes the operational layer that helps make more of those relationships possible. \n\n PartnerBird's WebMCP experiment is an early step toward that idea: a web where people do not simply use applications themselves, but increasingly use them together with agents. \n\n \n\n \n Built With \n\n auth codex css github javascript neon next.js openai openrouter postgresql react stripe tailwind typescript vercel webmcp \n \n\n \n Try it out \n\n \n \n \n www.partnerbird.com \n \n \n \n www.partnerbird.com \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n I designed the PartnerBird concept, product experience, and WebMCP workflow, including how agents discover, evaluate, and manage partnership opportunities.
