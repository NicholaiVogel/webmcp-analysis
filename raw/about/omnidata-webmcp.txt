We envisioned a native client-side data workspace where humans enjoy responsive charts while AI agents access structured, type-safe tools to run SQL queries and data audits directly alongside the user. \n\n What it does \n\n OmniData WebMCP is a collaborative, agent-native data analytics platform: \n\n For Humans: Provides interactive Recharts dashboards, real-time dimension remapping, preset switching, data completeness diagnostics, and raw tabular data views. \n\n For Agents: Exposes native WebMCP tools (run_sql_query, audit_dataset, switch_preset) via document.modelContext.registerTool. \n\n Shared Experience: When an agent executes an analytical query or switches datasets, the visual UI, data grid, and execution logs update instantly in real time. \n\n How we built it \n\n Framework & UI: Next.js 14, React, Tailwind CSS, and Recharts for responsive visualizations. \n\n In-Browser Analytics Engine: DuckDB WASM for executing high-performance SQL queries directly in the browser's virtual filesystem. \n\n State & Sync: Zustand for lightweight, cross-component state synchronization across tables, canvas charts, and execution logs. \n\n WebMCP Integration: Native browser tool registration using document.modelContext.registerTool with JSON Schema definitions for input validation. \n\n Challenges we ran into \n\n WASM Catalog Synchronization: Ensuring DuckDB WASM correctly registers JSON datasets into virtual tables before user or agent SQL queries run. \n\n Environment Fallbacks: Implementing safe optional chaining and fallback mechanisms so the application runs seamlessly even when WebMCP flags (chrome://flags/#enable-webmcp-testing) are disabled. \n\n Accomplishments that we're proud of \n\n Built a zero-latency, privacy-focused analytics stack where all data processing and AI tool execution happen entirely client-side. \n\n Created a cohesive dual-persona experience where human actions and agent tool calls operate on the exact same underlying state without desynchronization. \n\n What we learned \n\n Exposing explicit WebMCP schemas produces faster, more accurate agent outputs than relying on LLM web scraping or screen understanding. \n\n Designing web apps for dual human-agent interaction requires predictable, reactive state pipelines. \n\n What's next for OmniData WebMCP \n\n Adding drag-and-drop CSV and Parquet file upload support with dynamic DuckDB schema generation. \n\n Expanding the WebMCP toolset to allow AI agents to generate custom multi-metric charts and run automated statistical anomaly detection. \n\n \n\n \n Built
