And can the work become easier for the users as, complex [part will be handled by the AI agent, and the approval part will be under the Humans. * \n \n\n Traditional websites are primarily designed for human interaction. An AI agent may be able to read information or navigate the interface, but it does not have a reliable, structured way to use the website's capabilities. \n\n This inspired us to build AgentCart , a WebMCP-powered marketplace where humans and AI agents can shop together. \n\n Our goal was to explore what happens when a website is designed not only for humans, but also as an active tool interface for AI agents. \n\n \n\n What it does \n\n AgentCart allows a user to give an AI agent a natural-language shopping goal. \n\n For example: \n\n \n "Find me the best laptop for programming under ₹70,000. Prioritize performance and battery life." \n \n\n The agent can then: \n\n \n Search available products \n Filter them according to the user's requirements \n Inspect product specifications \n Compare the strongest candidates \n Find the best available offer \n Add the selected product to the cart \n Calculate the final price \n Request human approval before completing the purchase \n \n\n AgentCart currently exposes eight WebMCP tools: \n\n \n search_products \n filter_products \n get_product_details \n compare_products \n find_best_offer \n add_to_cart \n calculate_cart_total \n request_purchase_approval \n \n\n The WebMCP integration is implemented using: \n\n document.modelContext.registerTool() \n\n A key part of AgentCart is human-in-the-loop control . The agent can research, compare, optimize, and prepare a purchase, but it cannot complete the simulated purchase without explicit human approval. \n\n No real payment or transaction takes place. \n\n \n\n How we built it \n\n AgentCart was built using React, TypeScript, Vite, Tailwind CSS, and Zustand . \n\n We created a structured electronics product catalog containing product information such as price, brand, category, rating, stock, specifications, features, and offers. \n\n The WebMCP integration is implemented in the frontend using document.modelContext.registerTool() . Each tool has a defined name, description, input schema, and execution function. \n\n We designed the tools around the actual shopping workflow rather than exposing only a single generic AI action. \n\n The application also includes an Agent Activity panel that makes the agent's workflow visible to the user, for example: \n\n search_products → filter_products → compare_products → find_best_offer → add_to_cart → request_purchase_approval \n\n We used Git and GitHub for source control and deployed the application using Vercel . \n\n The final purchase flow is simulated so that the complete human + agent interaction can be demonstrated safely. \n\n \n\n Challenges we ran into \n\n One of our biggest challenges was making WebMCP tool registration reliable. \n\n Because the application can initialize more than once, we needed to prevent duplicate tool registrations. We implemented registration safeguards and checks for already-registered tools. \n\n Another challenge was making the agent workflow respond differently to different natural-language requests. We did not want every prompt to produce the same demonstration. \n\n We therefore implemented dynamic handling for: \n\n \n Product categories \n Budget limits \n Ratings \n Battery requirements \n Cheapest-product requests \n Comparison requests \n Offers \n Purchase and approval workflows \n \n\n We also had to carefully separate agent autonomy from human control . The agent can perform research and prepare a cart, but the final consequential action requires explicit human approval. \n\n Finally, we focused on making the WebMCP functionality understandable through the user interface instead of hiding the interaction behind the scenes. The Agent Activity panel helps users see what the agent is doing. \n\n \n\n Accomplishments that we're proud of \n\n We are proud that AgentCart goes beyond simply demonstrating that WebMCP tools can be registered. \n\n We built a complete shopping workflow around multiple meaningful WebMCP tools, connecting product discovery, filtering, comparison, offer optimization, cart preparation, and human approval. \n\n We are especially proud of the human + agent collaboration model . The agent handles the repetitive research and optimization work while the human remains responsible for the final purchase decision. \n\n We also built the project as a working, deployed web application rather than only a technical proof of concept. \n\n Most importantly, we created an experience where the WebMCP implementation directly changes what the website can do with an AI agent. \n\n \n\n What we learned \n\n Building AgentCart taught us that making a website agent-ready is very different from simply adding an AI chatbot. \n\n We learned how WebMCP can allow websites to expose structured capabilities that AI agents can use directly. \n\n We also learned that tool design matters. Clear tool names, descriptions, input schemas, and appropriate read-only or state-changing behavior are important for reliable agent interaction. \n\n Another important lesson was the importance of human-in-the-loop design . Giving an agent the ability to research and prepare actions does not mean it should automatically perform every consequential action and the important action like the approval and payment processing should be taken by Human only. \n\n We also learned how frontend state management, WebMCP tool execution, dynamic workflows, and user-facing activity visualization can be combined into one agent-ready web experience. \n\n \n\n What's next for AgentCart \n\n AgentCart currently focuses on demonstrating the core WebMCP-powered shopping experience with electronics. \n\n The next step would be expanding the marketplace with more product categories and richer real-world data. \n\n We would also like to explore more advanced agent capabilities such as personalized preferences, multi-item shopping goals, budget optimization, shipping comparisons, and more sophisticated approval controls. \n\n Beyond shopping, the same WebMCP interaction pattern could be applied to other multi-step web experiences such as travel planning, restaurant reservations, service marketplaces, and productivity applications. \n\n Our broader vision is a web where websites are not only pages that humans read and click, but active environments that AI agents can work with while humans remain in control. \n\n \n\n Final Thought \n\n Before WebMCP, an AI agent could tell you what to buy. \n\n With WebMCP, the web can actually work with the agent. \n\n AgentCart is our exploration of what that future could look like. \n\n \n\n \n Built With \n\n css document.modelcontext git github javascript react
