Engineers investigating an outage often jump between logs, deployment history, configuration changes, dashboards, runbooks, and communication tools while trying to determine what actually went wrong. \n\n TraceDesk explores what incident response could look like when a web application is designed for both humans and AI agents from the beginning. \n\n What it does \n\n TraceDesk is an AI-powered incident response workspace where humans and agents investigate software outages together. \n\n The workspace combines incident details, service health, logs, recent deployments, configuration changes, evidence, hypotheses, and remediation plans in one interface. \n\n Using WebMCP, an AI agent can directly access structured TraceDesk capabilities such as searching logs, inspecting deployments, reviewing configuration changes, adding evidence, updating hypotheses, and preparing remediation plans. \n\n The human remains in control of consequential actions. \n\n Why WebMCP \n\n Without WebMCP, an AI agent would need to interpret the visual interface, find buttons, navigate panels, and infer how to interact with the application. \n\n TraceDesk instead exposes meaningful application capabilities directly as structured WebMCP tools. \n\n This allows the agent to focus on investigating the incident rather than figuring out how to operate the website. \n\n Humans use the visual workspace while agents use structured tools, but both collaborate on the same incident state. \n\n Human + agent collaboration \n\n A human can ask an agent to investigate an outage and determine the most likely root cause. \n\n The agent can then use TraceDesk's WebMCP tools to gather evidence from logs, deployments, service health, and configuration changes before adding its findings back into the shared workspace. \n\n The human can review the evidence, confidence, and proposed remediation before approving any high-risk action. \n\n How we built it \n\n TraceDesk is built with TypeScript, Next.js, React, Tailwind CSS, WebMCP, and the OpenAI API. \n\n WebMCP tools are registered by the application and mapped to real TraceDesk functionality. The OpenAI API provides incident analysis and structured reasoning over technical evidence. \n\n The application is deployed on Vercel and the source code is publicly available on GitHub. \n\n Challenges \n\n The main challenge was designing WebMCP tools that represent meaningful product capabilities rather than simply exposing UI controls. \n\n We also focused on separating autonomous investigation from actions that should require human approval. \n\n What we learned \n\n WebMCP changes the way a web product can be designed. Instead of treating AI as a chatbot added on top of an existing application, the application itself can expose structured capabilities that agents understand and use directly. \n\n What's next \n\n TraceDesk could eventually connect to real observability platforms, deployment systems, incident-management tools, and infrastructure providers, allowing agents to investigate real production incidents while preserving human oversight. \n\n \n\n \n Built With \n\n api css javascript next.js openai react tailwind typescript vercel webmcp \n \n\n \n Try it out \n\n \n \n \n tracedesk.vercel.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n Solo developed. \n \n\n \n \n \n \n \n \n\n \n Niko DiCarlo \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n Niko DiCarlo \n started this project\n \n —\n \n 2 days ago \n \n \n\n
