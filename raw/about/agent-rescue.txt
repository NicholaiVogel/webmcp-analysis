Providers hit rate limits, services become unavailable, and switching resources can mean losing completed work. Agent Rescue explores a better model: let an AI agent diagnose and plan recovery while keeping consequential decisions under human control. \n\n What it does \n\n Agent Rescue is an AI Reliability & Recovery Control Room built around a shared human-agent workflow. \n\n In the demo, Research Brief #247 reaches 73% completion when Provider Alpha fails with an HTTP 429 rate limit. Agent Rescue preserves the checkpoint, diagnoses the failure, discovers available providers, evaluates recovery options, and recommends a recovery path. \n\n Before changing providers, the system stops at HUMAN APPROVAL REQUIRED. \n\n After approval, Agent Rescue switches providers, resumes from the preserved 73% checkpoint instead of restarting, and verifies the job at 100% RECOVERED. \n\n How we used WebMCP \n\n WebMCP gives the agent structured capabilities instead of forcing it to guess its way through the visual interface. \n\n Agent Rescue exposes seven tools: \n\n \n get_job_status \n inspect_failure \n list_available_providers \n recommend_recovery \n switch_provider \n resume_job \n verify_completion \n \n\n The human interface and WebMCP tools operate on the same application state. The agent can observe, diagnose, compare options, recommend recovery, resume work, and verify results while the human retains control over the consequential provider-switch decision. \n\n How we built it \n\n The challenge prototype is a deterministic single-file web application with an explicit recovery state machine, structured tool contracts, an audit trail, provider comparison, checkpoint preservation, and a mandatory human-approval interlock. \n\n The deterministic scenario makes the complete recovery sequence reproducible for judging without requiring accounts, API keys, or external AI-provider credentials. \n\n What's next \n\n The same architecture can extend from the deterministic challenge prototype to real multi-provider AI infrastructure, helping individuals and organizations preserve work, control failover, reduce wasted resources, and improve AI reliability. \n\n \n\n \n Built With \n\n aiagents css html human-in-the-loop javascript netlify webmcp \n \n\n \n Try it out \n\n \n \n \n benevolent-daifuku-9da31b.netlify.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n BigSteve Anderson \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n \n \n\n\n \n \n \n\n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n BigSteve Anderson \n started this project\n \n —\n \n 6 days ago \n \n \n\n
