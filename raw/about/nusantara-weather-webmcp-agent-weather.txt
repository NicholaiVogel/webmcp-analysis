Yet checking the weather often still means opening multiple apps, searching for a city, interpreting forecast charts, and deciding what the information actually means for a trip or daily activity. \n\n We wanted to explore a different experience: what if people could simply tell a weather agent what they need, and the agent could understand their intent, find the relevant weather information, and take action for them? \n\n That idea became Nusantara Weather - WebMCP Agent Weather . \n\n The project was inspired by the emerging WebMCP vision of a web where humans and AI agents can interact through real, useful tools. Instead of building another static weather dashboard, we wanted to create a weather interface that acts as a bridge between human intent and structured weather actions . \n\n A user should not need to know which forecast API to call or which data points matter. They should be able to say: \n\n \n “Find the safest dry window to travel in Bandung this afternoon.” \n \n\n And the application should understand the request, gather the relevant weather data, analyze it, and present a useful answer. \n\n What it does \n\n Nusantara Weather combines a beautiful weather dashboard with an agent-ready WebMCP interface . \n\n Users can explore weather across Indonesia by selecting a city or searching for a city through the Find a city interface. The main dashboard highlights five major cities for a clean and focused experience, while typing into the search bar reveals additional Indonesian cities as suggestions. \n\n The application can also understand natural-language weather requests through WebMCP tools. \n\n For example: \n\n \n “Find the next dry window in Jakarta.” \n\n “Compare Bandung and Surabaya for rain today.” \n\n “What is the safest time to travel in Bali this afternoon?” \n \n\n The agent can use registered WebMCP tools to retrieve weather information, compare locations, identify upcoming rain windows, and follow the user's intent. \n\n The project includes tools such as: \n\n \n get_indonesia_weather — retrieves current and forecast weather for a selected Indonesian city. \n compare_indonesia_weather — compares weather conditions between cities. \n find_next_rain_window — identifies upcoming periods with higher or lower rain probability. \n follow_weather_prompt — interprets a natural-language request and drives the application according to the user's intent. \n \n\n The key idea is that the user describes the goal, while the agent handles the interaction with the web application . \n\n How we built it \n\n We built Nusantara Weather as a lightweight web application with a strong focus on progressive enhancement and agent interoperability. \n\n The frontend provides: \n\n \n A modern weather dashboard \n Indonesia-focused city search \n Top-city recommendations \n Forecast and rain information \n Natural-language prompt interaction \n Agent activity and decision feedback \n Responsive UI for different screen sizes \n \n\n For weather data, the application uses live forecast information from Open-Meteo. \n\n For the agent layer, we implemented the WebMCP Imperative API using the required tool registration pattern: \n await document . modelContext . registerTool ( { \n name : "get_indonesia_weather" , \n description : "Get weather conditions and forecast for an Indonesian city." , \n inputSchema : { \n type : "object" , \n properties : { \n city : { \n type : "string" , \n description : "Indonesian city name" \n } \n } , \n required : [ "city" ] \n } , \n execute : async ( input ) = > { \n // Fetch weather data\n // Update application state\n // Return structured weather information\n } \n } ) ; \n \n This means the application is not only designed for humans clicking buttons. It exposes structured capabilities that an AI agent can discover and execute. \n\n The architecture follows a simple flow: \n\n Human prompt → Agent intent → WebMCP tool → Weather data → Decision → UI update \n\n We also designed the application with progressive enhancement in mind. The weather website remains usable as a normal website, while WebMCP-enabled environments can interact with the same application through agent-accessible tools. \n\n Challenges we ran into \n\n One of the biggest challenges was designing an interface that works well for both humans and agents. \n\n Traditional web interfaces are usually built around clicks, buttons, forms, and navigation. Agents need something more structured: clearly defined tools, predictable inputs, meaningful descriptions, and structured outputs. \n\n Another challenge was handling natural-language intent. \n\n A request such as: \n\n \n “When should I leave for Bandung if I want to avoid rain?” \n \n\n doesn't directly map to a single API call. The system has to translate the user's goal into a sequence of actions: \n\n \n Identify the destination. \n Understand the requested time period. \n Retrieve forecast data. \n Evaluate rain conditions. \n Determine the most suitable window. \n Present the result in a human-friendly way. \n \n\n We also wanted the interface to stay visually simple even though the application supports a large number of Indonesian cities. Instead of showing every city immediately, the frontend focuses on five major cities and reveals additional cities dynamically through search suggestions. \n\n Finally, WebMCP is an evolving part of the web platform, so we had to think carefully about compatibility and progressive enhancement rather than assuming every browser has the same capabilities. \n\n Accomplishments that we're proud of \n\n We are proud that Nusantara Weather is more than a weather visualization. \n\n It demonstrates how a web application can become agent-interactable without sacrificing the human experience . \n\n Some highlights we are especially proud of: \n\n \n We implemented real WebMCP tool registration with document.modelContext.registerTool() . \n We created multiple purpose-built weather tools instead of exposing one generic API endpoint. \n We added a natural-language follow_weather_prompt workflow that connects user intent to application behavior. \n We created an Indonesia-focused city dataset with coverage across major regions and islands. \n We designed the city search so the interface stays clean while still supporting many locations. \n We built the product around decisions and actions rather than simply showing raw forecast numbers. \n We created a polished visual identity for the project, including a custom Indonesia weather favicon. \n \n\n Most importantly, we believe the project demonstrates a compelling direction for the open web: \n\n websites that are understandable not only to humans, but also to intelligent agents. \n\n What we learned \n\n We learned that building an agent-friendly web application requires a different way of thinking about product design. \n\n It is not enough to expose data. The application needs to expose capabilities . \n\n A useful agent tool should answer questions like: \n\n \n What does this tool do? \n What input does it expect? \n What result will it return? \n Can the action change application state? \n Is the result meaningful enough for an agent to reason about? \n \n\n We also learned that natural-language interfaces work best when the underlying system is structured and predictable. \n\n The prompt may be unstructured, but the execution should not be. \n\n That led us to a design principle we will continue using: \n\n Unstructured human intent in, structured actions out. \n\n Finally, we learned that great agent experiences should not replace good human interfaces. The strongest experience is one where humans can interact directly while agents can use the exact same web capabilities programmatically. \n\n What's next for Nusantara Weather - WebMCP Agent Weather \n\n Nusantara Weather is only the beginning. \n\n Our next step is to make the agent significantly more capable of understanding real-world context. \n\n We want users to eventually be able to ask things like: \n\n \n “I have a flight from Jakarta to Bali tomorrow. When is the safest time to leave for the airport?” \n \n\n or: \n\n \n “I'm planning an outdoor event in Bandung this weekend. Find the best day and explain why.” \n \n\n From there, Nusantara Weather could combine weather with additional web capabilities such as: \n\n \n Traffic and travel conditions \n Flight and transportation information \n Local events \n Air quality \n Flood and severe-weather alerts \n Tourism information \n Location-based recommendations \n \n\n We also want to expand the agent from simply answering questions into planning and coordinating actions . \n\n The long-term vision is a weather agent that understands what someone is trying to accomplish, gathers the relevant information from the open web, explains its reasoning clearly, and helps the user make a better decision. \n\n Ultimately, Nusantara Weather is our exploration of a larger idea: \n\n The future web should not only be something humans browse. It should be something humans and intelligent agents can collaborate with. \n\n \n\n \n Built With \n\n html5 openmeteo webmcp \n \n\n \n Try it out \n\n \n \n \n indonesia-weather-webmcp.vercel.app \n \n \n \n\n \n\n \n\n \n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n David Pratama \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n Love to code & code everyday \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n 1 \n \n \n\n\n \n 1 person likes this:\n \n\n \n \n \n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n David Pratama \n started this project\n \n —\n \n 10 days ago \n \n \n\n
