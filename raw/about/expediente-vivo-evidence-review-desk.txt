Claims, allegations and evidence can easily be confused, while exact provenance gets lost. A normal chatbot sees presentation text, not the application's canonical IDs, evidence types or safety boundaries. What it does Expediente Vivo opens a verified synthetic dossier and gives a human and an agent the same evidence-review workspace. Through WebMCP, the agent can: call get_dossier_summary to read structured matter status and real attention-item IDs; call inspect_assertion to inspect classification, uncertainty, review flags and exact provenance; call focus_evidence to open the cited evidence visibly on the live page; and call propose_review_status to create a reasoned, pending review proposal. The interface then shows AGENT PROPOSAL · Pending human review . Only the person can press ACCEPT or REJECT . That decision updates the separate proposal record, never the canonical assertion or its evidence. Why WebMCP is essential WebMCP gives the agent a stable, typed vocabulary— matter_id , assertion_id , evidence state and provenance—and safe actions defined by the application itself. A detached API would not connect the agent to the evidence currently visible in the browser. A chatbot or DOM scraper would have to infer semantics from presentation markup and use brittle selectors. Here, the page explicitly declares what the agent may read and do. The agent can inspect, navigate and propose on the same live dossier the human sees, while the final decision remains a visible human action. The human–agent workflow A reviewer asks the agent to find an item needing attention. The agent reads the dossier summary, chooses a real assertion, inspects its structured evidence, focuses the exact cited fragment in the interface, and creates a bounded workflow proposal. The human reviews the same evidence and accepts or rejects the proposal. Canonical provenance remains intact throughout. How we built it The browser registers four top-level tools through document.modelContext.registerTool . Tool outputs reuse the open synthetic dossier's existing structured data; no model is rerun and no facts are invented. Read tools return typed application state, focus_evidence performs only a visible page-view change, and propose_review_status writes to a separate tab-local proposal queue. The public challenge deployment contains only the packaged synthetic dossier and source PDFs. It has no login, uploads, database, live inference, OCR, private storage access or external actions. Tests cover tool discovery, invalid IDs, provenance integrity, non-promotion of allegations, proposal separation and explicit human decision. Prior work and challenge work Pre-existing baseline: the underlying Expediente Vivo document-intelligence engine, dossier schema, provenance rules, synthetic fixtures and original case interface existed before this challenge. The tagged pre-webmcp-baseline commit records that boundary. Judges should not score those components as new work. Built for the WebMCP Challenge: the top-level WebMCP integration; four typed site tools; shared human–agent review state; visible evidence focusing; agent review proposals; the explicit human ACCEPT/REJECT boundary; WebMCP observability; safety tests; and the public synthetic-only challenge packaging. The timestamped delta is documented in the repository. Codex assisted with implementation, testing and documentation. The entrant remains responsible for the project ideas, source, rights and submission. Challenges and lessons The hardest design decision was deciding what must never become an agent tool. ACCEPT and REJECT are deliberately absent from WebMCP. Human-in-the-loop safety is enforced as a capability boundary, not presented as a promise in the interface. We also learned that useful agent collaboration needs a precise handoff: structured inspection → exact visible evidence → bounded proposal → explicit human decision. Accomplishments Four working, non-trivial WebMCP tools on a coherent public app. Exact evidence provenance remains unchanged after proposal, accept or reject. A deterministic synthetic demo that requires no account or credentials. A clear distinction between documentary state, agent proposal and human decision. What's next A production version could add authenticated, persistent proposal history and organization-specific review policies. Those features were intentionally excluded from this focused challenge slice.
