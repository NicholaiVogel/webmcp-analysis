Most websites will not implement WebMCP themselves anytime soon. AlphaX was born from a simple question: what if I could turn any existing website into a reliable, agent-ready surface — while keeping the human firmly in control? \n\n Instead of waiting for every site to add tools, AlphaX acts as a universal mediation layer. It analyzes a page, synthesizes high-quality WebMCP tools, registers them live, and lets agents use them under strict human supervision. \n\n What it does \n\n AlphaX lets you: \n\n \n Paste any URL \n Automatically generate structured WebMCP tools from the page \n Review and approve those tools \n Register them via document.modelContext.registerTool \n Let agents call the tools while you supervise every sensitive action \n Maintain full provenance and audit logs \n \n\n It supports three supervision modes (Strict, Supervised, Autonomous) so the human always remains sovereign. \n\n How I built it \n\n AlphaX is a full-stack system: \n\n \n Frontend : React + TypeScript + Zustand + Tailwind \n Backend : Express + Playwright (controlled browser) \n Tool Synthesis : Groq + Gemini + a strong heuristic fallback \n Persistence : Supabase \n WebMCP : Full imperative registration with polyfill support \n \n\n The system extracts page structure, generates tools, registers them dynamically, translates tool calls into Playwright actions, and streams live feedback and provenance to the operator. \n\n Challenges I ran into \n\n \n Making tool generation reliable across very different websites \n Keeping Playwright stable in a production environment \n Designing a supervision model that feels safe without becoming annoying \n Balancing power-user features with first-time clarity for judges \n Deploying a Playwright-heavy backend alongside a Vite frontend \n \n\n What I learnt \n\n Building a meta-layer on top of WebMCP taught us how important human-in-the-loop design is. Agents become far more useful when they operate on real websites through clean, schema-validated tools — but only when the human retains clear control and visibility. \n\n What's next \n\n \n Better multi-step goal planning \n Improved tool quality through learning from successful runs \n Chrome extension for deeper same-origin mediation \n Support for authenticated sessions and multi-site orchestration \n \n\n \n\n \n Built With \n\n express.js gemini groq node.js playwright react supabase tailwind-css typescript vite webmcp zustand \n \n\n \n Try it out \n\n \n \n \n alphax-chi.vercel.app \n \n \n \n GitHub Repo \n \n \n \n\n \n\n \n\n \n \n Submitted to\n \n\n \n \n \n \n \n\n \n \n The WebMCP Challenge \n \n\n\n \n\n\n \n\n \n \n\n \n \n Created by\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n BigFred007 Morah \n \n \n\n \n\n \n \n \n \n\n \n \n \n \n \n \n \n \n \n\n \n \n \n \n \n\n \n\n \n\n\n \n \n \n \n \n\n \n \n \n \n \n \n \n \n \n Like\n 1 \n \n \n\n\n \n 1 person likes this:\n \n\n \n \n \n \n \n\n \n\n\n \n \n \n \n Share this project:\n \n\n\n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n \n \n \n \n \n \n\n \n\n \n \n \n \n\n \n \n \n\n \n \n \n \n \n\n\n\n \n \n \n Updates \n\n \n \n \n \n \n\n \n \n \n \n \n \n BigFred007 Morah \n started this project\n \n —\n \n 2 days ago \n \n \n\n
