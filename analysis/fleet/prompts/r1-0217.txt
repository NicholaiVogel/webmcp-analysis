## WebMCP Leverage — what does WebMCP change for this product?
Judge the delta WebMCP makes to reliability, precision, structured state access,
shared human-agent state, repeatability, and capability. Tool COUNT is not leverage.
- 9-10 TRANSFORMATIVE: the intended experience is impractical without the structured
  agent surface; human and agent share live product state; the collaboration could not
  be replicated comparably well by a general agent driving the UI.

  experience via structured tools; same outcome otherwise possible with real friction.
- 3-4 MINOR DELTA: generic browser automation achieves comparable outcomes; WebMCP is
  a convenience layer.
- 1-2 COSMETIC: exposes an action a UI button already offers; no meaningful change.

## Execution — is the actual product coherent, intentional, complete for its scope?
Stage 1 scores EXECUTION_CLAIMED: coherence/intentionality/completeness as evidenced by
the packet (description + packaging + video frames/transcript). Thin evidence caps the

sums.

- 7-8: strong coherence and intentionality; central workflow appears functional; minor
  unfinished edges.

  end-to-end.
- 3-4: thin prototype; contradictions between surfaces; placeholder content.
- 1-2: non-functional or incoherent for its claimed scope.

## Creativity & Ambition — novelty of concept and interaction model
Judge ONLY: novelty of the concept, novelty of the interaction model, originality
relative to existing concepts, ambition, memorable/surprising use of the medium, and
the depth with which the concept is pursued. WebMCP indispensability belongs under
WebMCP Leverage, NOT here: a project can be extremely creative even if another agent
API could theoretically have enabled something similar.

  and coherently; memorable.
- 7-8: fresh synthesis or notably original interaction; ambitious for a hackathon.
- 5-6: competent take on a known category with a real new angle.
- 3-4: derivative; novelty mostly surface details.
- 1-2: clone/template with trivial changes.

Give your AI agent a computer in your browser. Use the same apps to write, draw, analyze data, and work with files. Like Comment Story Updates The Harbor release brief in Documents, with its exported PDF open in Preview. A Canvas diagram and project handoff with source files and a question for the user. Why I built it I wanted to give an AI agent its own personal computer. While exploring WebMCP, I started playing with the idea of a virtual operating system inside the browser. Each app could expose its own tools, letting the agent use a whole desktop to do different kinds of work. DeskInTab is that experiment. The agent gets a computer to work in, and you can use the same apps beside it. What it does DeskInTab brings everyday computer work into one browser desktop. You and your agent can: Take notes in Markdown or plain text, write formatted documents, read PDFs, and export reports. Analyze data in spreadsheets with formulas and charts. Sketch ideas and edit diagrams together in Canvas. Use Terminal to search files, extract document text, transform data, and run Bash pipelines. Browse and organize files, track tasks, and save project decisions and next steps. Turn JSON data into small apps with search, filters, and links to the original sources. The apps share one filesystem. A chart from Sheets can go into a document, and Terminal can process the files you see in Finder. You can open the agent's work, change it yourself, and continue together. Home saves preferences and reusable instructions. Projects keeps handoffs so an agent can leave a question for you and a later session can pick up your answer. Files persist after a browser reload. The video shows one example, planning a release for the fictional Harbor reading app. The agent works through interview notes, spreadsheet analysis, a release brief and PDF, tasks, and a Canvas roadmap. Why WebMCP fits The desktop exposes 89 WebMCP tools. Each tool calls the same application services as the human controls, so agent actions change the apps and files you have open. This lets the agent combine several apps in one task while you follow and edit the work. How it works Svelte 5 and TypeScript provide the interface. ZenFS stores the shared filesystem in IndexedDB. ZetaOffice handles documents and spreadsheets, Excalidraw handles drawings, and just-bash runs Terminal commands inside the browser without host or network access. What I learned Passing tool tests didn't guarantee that an agent could discover the full catalog. A client size limit blocked discovery until repeated schemas shared references. Tests now check the full payload and verify that every validation rule survives. Two desktop tabs can conflict over stored files. A Web Lock prevents that, and saved versions make edits recoverable. What's next Improve Office startup and workbook autosaving, and make project handoffs easier to find. The app currently keeps one workspace in your browser. Workspace packs let you back it up or move it.
