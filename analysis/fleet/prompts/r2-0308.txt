# FROZEN SCORING RUBRIC (pre-registered before any Stage 1 review)

Scores are integers 1-10 on each of the FOUR official criteria. Every score carries:
rationale, evidence_surfaces, confidence (0-1). Reviewers use the full scale and these
band anchors verbatim. Category neutrality is absolute: a game, art piece, music tool,
CRM, weird toy, and developer tool are all eligible for 10/10 on every criterion if they
satisfy that criterion exceptionally well FOR WHAT THEY ARE TRYING TO BE.
No aesthetic penalties. Signs of hurried AI work matter only as actual product-quality
problems (incoherence, broken flow, placeholder content), never as style.

## WebMCP Leverage — what does WebMCP change for this product?
Judge the delta WebMCP makes to reliability, precision, structured state access,
shared human-agent state, repeatability, and capability. Tool COUNT is not leverage.
- 9-10 TRANSFORMATIVE: the intended experience is impractical without the structured
  agent surface; human and agent share live product state; the collaboration could not
  be replicated comparably well by a general agent driving the UI.
- 7-8 MAJOR DELTA: without WebMCP a general agent is markedly less reliable/precise
  here; the agent is central to the product, not a bolt-on.
- 5-6 MEANINGFUL DELTA: existing capability packaged into a genuinely better product
  experience via structured tools; same outcome otherwise possible with real friction.
- 3-4 MINOR DELTA: generic browser automation achieves comparable outcomes; WebMCP is
  a convenience layer.
- 1-2 COSMETIC: exposes an action a UI button already offers; no meaningful change.

## Execution — is the actual product coherent, intentional, complete for its scope?
Stage 1 scores EXECUTION_CLAIMED: coherence/intentionality/completeness as evidenced by
the packet (description + packaging + video frames/transcript). Thin evidence caps the
score (end-to-end credit requires end-to-end evidence) and lowers confidence.
Stage 2 may rescore as EXECUTION_OBSERVED; latest evidence-backed score replaces, never
sums.
- 9-10: all surfaces agree; central workflow demonstrably completes; states handled;
  feels finished for its stated scope.
- 7-8: strong coherence and intentionality; central workflow appears functional; minor
  unfinished edges.
- 5-6: plausibly real with visible gaps; scope unclear or core not demonstrated
  end-to-end.
- 3-4: thin prototype; contradictions between surfaces; placeholder content.
- 1-2: non-functional or incoherent for its claimed scope.

## Creativity & Ambition — novelty of concept and interaction model
Judge ONLY: novelty of the concept, novelty of the interaction model, originality
relative to existing concepts, ambition, memorable/surprising use of the medium, and
the depth with which the concept is pursued. WebMCP indispensability belongs under
WebMCP Leverage, NOT here: a project can be extremely creative even if another agent
API could theoretically have enabled something similar.
- 9-10: genuinely novel concept or interaction model; ambitious scope pursued deeply
  and coherently; memorable.
- 7-8: fresh synthesis or notably original interaction; ambitious for a hackathon.
- 5-6: competent take on a known category with a real new angle.
- 3-4: derivative; novelty mostly surface details.
- 1-2: clone/template with trivial changes.
"That the category exists" is never a penalty; judge the submitted concept.

## Potential Impact — credible value for the intended audience
Judge: is there a real audience; is there a real problem, desire, or use case for that
audience; does the demonstrated solution genuinely address it. NO commercial adoption,
monetization, market pull, or startup viability is required. Entertainment, play, art,
creative expression, learning, niche hobby use, experimentation, and community value
are legitimate forms of impact. A tiny audience fully justifies a top score.
- 9-10: specific real audience with a real problem/desire; solution demonstrably
  addresses it; credible value, appeal, usefulness, or meaning for that audience.
- 7-8: clear audience and problem, good fit, credible value.
- 5-6: identifiable audience, looser fit or partial address.
- 3-4: speculative audience or strained fit; impact mostly aspirational.
- 1-2: no coherent audience/problem pairing.
Audience size is NOT a multiplier.

## Aggregate & ranking
aggregate = leverage + execution + impact + creativity (4-40). Nothing else enters.
Tie-breaks: Leverage, then Execution, then Impact, then Creativity, then higher
combined evidence confidence, then slug alphabetical. See PROTOCOL.md Ranking section.

Like Comment Story Updates Inspiration Most AI agents are fluent in text, but people understand complex ideas faster when they can see structure, position, emphasis, and relationships. Existing collaboration tools usually force one side to compromise: people work through visual interfaces while agents imitate mouse clicks, or agents produce plain text that people must mentally reconstruct. We wanted a medium native to both. CharDesk began with a simple idea: What if the canvas were visual to people, but still made of tokens an agent could read and edit precisely? What CharDesk does CharDesk is a shared visual workspace for humans and AI agents. An agent can create or update a Blackboard through WebMCP. The result immediately appears as a live Unicode canvas that a person can inspect, navigate, and continue discussing with the agent. The same canvas can combine: Unicode and ANSI art Markdown and fenced code Mermaid diagrams Tables, JSON, and YAML Mathematical expressions Scientific plots and Vega-Lite Spatial layouts and character-based slides This makes CharDesk useful for explaining concepts, visualizing research, mapping systems, designing interfaces, presenting stories, and maintaining a shared project workspace. For example, someone can ask: “Explain how a GPU renders one frame.” The agent can turn that request into a structured visual scene containing a pipeline diagram, memory relationships, annotations, and styled interface elements—not just another long answer in chat. Why it is better with WebMCP Without WebMCP, an agent would need to guess how to operate the interface or manipulate individual canvas cells. CharDesk instead exposes focused workspace tools for discovering, creating, reading, writing, patching, deleting, and validating Blackboard files. The source remains authoritative; the canvas is a live projection of it. This gives each participant the representation they work with best: Human sees relationships, hierarchy, and visual emphasis ⇅ CharDesk Blackboard ⇅ Agent reads and edits structured, diffable text Agents can also call chardesk_read_materials to learn the visual language from worked examples. The tool teaches not only how to call the API, but how to compose an effective scene. How we built it CharDesk has a protocol-neutral tool layer shared by two thin host adapters: Standard WebMCP for compatible Chrome environments The imperative WebMCP capability supported by ChatGPT Site Tools Both adapters expose the same underlying Blackboard operations, so product behavior does not depend on a particular browser integration. A Blackboard stores source files and layout metadata. Changes are compiled through a shared rendering pipeline into a fixed character grid. This pipeline handles Unicode width, CJK characters, Nerd Font glyphs, ANSI styles, structured diagrams, and multidimensional layouts. The browser keeps the latest valid canvas mounted while an agent edits the source. If an intermediate update is invalid, CharDesk returns diagnostics without replacing the visible scene with a broken or empty state. The same format also works outside the browser through the CharDesk CLI, making projects portable, inspectable, renderable, and friendly to normal version-control workflows. Challenges we faced One unexpected challenge was tool ownership across browser tabs. Opening several CharDesk pages could cause identical tools to be registered multiple times, leaving the agent unable to choose a target. We built an origin-level gateway lease so only one page exposes the tools, with automatic takeover when that page closes. Chrome and ChatGPT also expose different subsets of the evolving WebMCP API. Instead of spreading compatibility checks throughout the product, we isolated those differences behind capability adapters backed by one canonical tool definition. Another challenge was timing: some hosts inject WebMCP after the application has already loaded. CharDesk therefore uses an adaptive registration handshake rather than assuming the API exists at startup. Finally, we learned that exposing tools is not enough. An agent may know how to write a file without knowing how to create a compelling visual explanation. Embedding CharDesk’s materials and examples as a callable tool gave browser agents the missing creative context. What we learned The most important lesson was that agent-native design is not simply automation layered onto an existing UI. A better pattern is to give agents a precise, structured representation while giving people a rich visual projection of the same underlying artifact. WebMCP makes that relationship discoverable directly from the website, without requiring agents to reverse-engineer the interface. CharDesk explores what becomes possible when the web page is no longer just something an agent operates, but a shared medium in which the human and agent can think together.
