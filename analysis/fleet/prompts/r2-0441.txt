What WebMCP actually tells the page A WebMCP tool gets its arguments and an AbortSignal . What it doesn't get is anything like: who initiated this action; whether an agent was involved; which session or conversation caused it; whether a person actually interacted with the UI. The browser creates an internal execution ID, but that ID is used for things like cancellation. It isn't exposed to the page as an identity or provenance signal. So from the application's point of view, several very different things can collapse into the same event: "This action happened." And that's the problem we're exploring. What we built We built Relay , a small append-only record system designed around provenance rather than pretending provenance exists. That makes the provenance problem visible instead of hiding it. We added WebMCP to Relay Relay exposes six WebMCP tools: four tools for reading the existing corpus; two tools for proposing and approving new records. The important part isn't the number of tools.
