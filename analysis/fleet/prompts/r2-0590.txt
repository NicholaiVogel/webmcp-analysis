# FROZEN SCORING RUBRIC (pre-registered before any Stage 1 review)

Scores are integers 1-10 on each of the FOUR official criteria. Every score carries:
rationale, evidence_surfaces, confidence (0-1). Reviewers use the full scale and these
band anchors verbatim. Category neutrality is absolute: a game, art piece, music tool,
CRM, weird toy, and developer tool are all eligible for 10/10 on every criterion if they
satisfy that criterion exceptionally well FOR WHAT THEY ARE TRYING TO BE.
No aesthetic penalties. Signs of hurried AI work matter only as actual product-quality
problems (incoherence, broken flow, placeholder content), never as style.

## WebMCP Leverage — what does WebMCP change for this product?
Judge the delta WebMCP makes to reliability, precision, structured state access,
shared human-agent state, repeatability, and capability. Tool COUNT is not leverage.
- 9-10 TRANSFORMATIVE: the intended experience is impractical without the structured
  agent surface; human and agent share live product state; the collaboration could not
  be replicated comparably well by a general agent driving the UI.
- 7-8 MAJOR DELTA: without WebMCP a general agent is markedly less reliable/precise
  here; the agent is central to the product, not a bolt-on.
- 5-6 MEANINGFUL DELTA: existing capability packaged into a genuinely better product
  experience via structured tools; same outcome otherwise possible with real friction.
- 3-4 MINOR DELTA: generic browser automation achieves comparable outcomes; WebMCP is
  a convenience layer.
- 1-2 COSMETIC: exposes an action a UI button already offers; no meaningful change.

## Execution — is the actual product coherent, intentional, complete for its scope?
Stage 1 scores EXECUTION_CLAIMED: coherence/intentionality/completeness as evidenced by
the packet (description + packaging + video frames/transcript). Thin evidence caps the
score (end-to-end credit requires end-to-end evidence) and lowers confidence.
Stage 2 may rescore as EXECUTION_OBSERVED; latest evidence-backed score replaces, never
sums.
- 9-10: all surfaces agree; central workflow demonstrably completes; states handled;
  feels finished for its stated scope.
- 7-8: strong coherence and intentionality; central workflow appears functional; minor
  unfinished edges.
- 5-6: plausibly real with visible gaps; scope unclear or core not demonstrated
  end-to-end.
- 3-4: thin prototype; contradictions between surfaces; placeholder content.
- 1-2: non-functional or incoherent for its claimed scope.

## Creativity & Ambition — novelty of concept and interaction model
Judge ONLY: novelty of the concept, novelty of the interaction model, originality
relative to existing concepts, ambition, memorable/surprising use of the medium, and
the depth with which the concept is pursued. WebMCP indispensability belongs under
WebMCP Leverage, NOT here: a project can be extremely creative even if another agent
API could theoretically have enabled something similar.
- 9-10: genuinely novel concept or interaction model; ambitious scope pursued deeply
  and coherently; memorable.
- 7-8: fresh synthesis or notably original interaction; ambitious for a hackathon.
- 5-6: competent take on a known category with a real new angle.
- 3-4: derivative; novelty mostly surface details.
- 1-2: clone/template with trivial changes.
"That the category exists" is never a penalty; judge the submitted concept.

## Potential Impact — credible value for the intended audience
Judge: is there a real audience; is there a real problem, desire, or use case for that
audience; does the demonstrated solution genuinely address it. NO commercial adoption,
monetization, market pull, or startup viability is required. Entertainment, play, art,
creative expression, learning, niche hobby use, experimentation, and community value
are legitimate forms of impact. A tiny audience fully justifies a top score.
- 9-10: specific real audience with a real problem/desire; solution demonstrably
  addresses it; credible value, appeal, usefulness, or meaning for that audience.
- 7-8: clear audience and problem, good fit, credible value.
- 5-6: identifiable audience, looser fit or partial address.
- 3-4: speculative audience or strained fit; impact mostly aspirational.
- 1-2: no coherent audience/problem pairing.
Audience size is NOT a multiplier.

## Aggregate & ranking
aggregate = leverage + execution + impact + creativity (4-40). Nothing else enters.
Tie-breaks: Leverage, then Execution, then Impact, then Creativity, then higher
combined evidence confidence, then slug alphabetical. See PROTOCOL.md Ranking section.

The agent uses the capabilities exposed by the LiquidHR website to find Sophie, retrieve her current goals, open actions and skill-development signals, and create three grounded discussion topics. The manager sees that exact same draft in the human interface. This is not a chatbot creating a separate copy of HR data. The human interface and the agent operate on the same application state. State-aware WebMCP capabilities One of the ideas I especially wanted to explore was whether the capability surface itself could follow the workflow. Initially, the application exposes three tools. Once a valid conversation draft exists for the currently selected employee, LiquidHR dynamically exposes a fourth WebMCP capability: add_follow_up_action The agent can then add a bounded follow-up action to the existing draft. When the manager finally reviews and saves the conversation, that temporary capability disappears again. The capability lifecycle is therefore: 3 → 4 → 3 The application's state determines what the agent can do next. Human judgment remains human Final save is deliberately not exposed as a WebMCP capability. The agent can retrieve context, organize information, prepare the draft and add a follow-up action, but the manager must perform the final Review & save action in the human interface. That creates a deliberate human-confirmation boundary around the judgment-bearing transition. The agent doesn't bypass the application. The application teaches the agent how to use it safely. Why WebMCP Without WebMCP, a general-purpose assistant often has to work through a second interface, copied data, brittle browser interaction or a separately designed API. WebMCP lets the web application expose a structured capability contract directly to the browser agent. The tool names, descriptions, input schemas, annotations, authorization rules and lifecycle are defined by the application itself. That means the agent does not have to guess which buttons to click or infer hidden application state. It receives capabilities that reflect what the application can safely do at that moment. Shared application architecture The human UI and the WebMCP callbacks use the same: workspace facade → actor and manager-scope policy → domain service → shared draft state → synthetic repository Employee lookup is restricted to the fictional manager's authorized scope. Direct employee context access is validated again before information is returned. The project also contains an out-of-scope synthetic employee for authorization testing. All company, employee and activity data is fictional. Implementation The project uses the imperative WebMCP API through: document.modelContext.registerTool(...) The application uses object JSON Schemas, tool descriptions, annotations, structured results and lifecycle-managed registrations. The first three capabilities remain available for the workspace lifecycle. The fourth capability is dynamically registered only when a valid matching draft exists and is removed after the draft is discarded or saved. The application is built with Next.js, React and TypeScript and deployed publicly on Vercel. No production HR backend, real employee data or external AI API is embedded in the challenge application. What I proved The live end-to-end flow demonstrates: real WebMCP capability discovery and execution natural-language interaction with application-defined tools scoped employee access grounded development context shared state between human and agent dynamic state-aware capabilities a visible activity trail a deliberate human confirmation boundary The complete natural-language flow was also tested against the public application using ChatGPT's browser with a WebMCP-capable runtime. Potential impact Managers frequently spend time gathering goals, open actions and development signals before a useful conversation can even begin. An agent can remove much of that repetitive retrieval and preparation without taking over the manager's judgment. The same pattern can extend far beyond HR: applications can expose safe, contextual capabilities to agents while retaining their own business rules, permissions, workflow state and human approval boundaries. Human judgment. Agent speed. Inspiration I came into this challenge from a UX/UI and product design background. At first I kept asking: what can an agent do on a website? While building Attune, a better question took over: What should the person and the agent do together? A person may be better at looking at a design, moving something by eye, and deciding what feels right. An agent can help with exact values, repeated edits, relationships, checks, and multi-step work. The useful part is when both work on the same object , without the person having to explain that object again and again. That became Attune. What Attune does Attune is a shared workspace for designing physical products . The person gets the visual canvas. The browser agent gets WebMCP tools. Both work on the same underlying design. If I already selected something, I should not need to describe which part I mean. If the design already knows a measurement, the agent should not guess it from the screen. If I change something myself, the agent should continue from the new state. The goal is not “AI, finish the whole design for me.” It is closer to: I decide → the agent helps → I adjust → Attune checks → we continue. Why WebMCP here? A 2D engineering sketch is more than pixels. It contains entities, dimensions, constraints, groups, solver state, versions, and relationships between parts. A small edit can also affect what happens later. Without a structured interface, an agent has to reconstruct too much of that from the visible UI. With WebMCP, Attune can give the agent direct actions over the same design state the person is using. That lets the agent answer four useful questions: What am I working on? What can I change here? What would this change affect? What can happen next? Attune also does not expose one giant toolbox on every page. Design tools appear while editing. Manufacturing tools appear later.
