=== RUBRIC (frozen) ===
# FROZEN SCORING RUBRIC (pre-registered before any Stage 1 review)

Scores are integers 1-10 on each of the FOUR official criteria. Every score carries:
rationale, evidence_surfaces, confidence (0-1). Reviewers use the full scale and these
band anchors verbatim. Category neutrality is absolute: a game, art piece, music tool,
CRM, weird toy, and developer tool are all eligible for 10/10 on every criterion if they
satisfy that criterion exceptionally well FOR WHAT THEY ARE TRYING TO BE.
No aesthetic penalties. Signs of hurried AI work matter only as actual product-quality
problems (incoherence, broken flow, placeholder content), never as style.

## WebMCP Leverage — what does WebMCP change for this product?
Judge the delta WebMCP makes to reliability, precision, structured state access,
shared human-agent state, repeatability, and capability. Tool COUNT is not leverage.
- 9-10 TRANSFORMATIVE: the intended experience is impractical without the structured
  agent surface; human and agent share live product state; the collaboration could not
  be replicated comparably well by a general agent driving the UI.
- 7-8 MAJOR DELTA: without WebMCP a general agent is markedly less reliable/precise
  here; the agent is central to the product, not a bolt-on.
- 5-6 MEANINGFUL DELTA: existing capability packaged into a genuinely better product
  experience via structured tools; same outcome otherwise possible with real friction.
- 3-4 MINOR DELTA: generic browser automation achieves comparable outcomes; WebMCP is
  a convenience layer.
- 1-2 COSMETIC: exposes an action a UI button already offers; no meaningful change.

## Execution — is the actual product coherent, intentional, complete for its scope?
Stage 1 scores EXECUTION_CLAIMED: coherence/intentionality/completeness as evidenced by
the packet (description + packaging + video frames/transcript). Thin evidence caps the
score (end-to-end credit requires end-to-end evidence) and lowers confidence.
Stage 2 may rescore as EXECUTION_OBSERVED; latest evidence-backed score replaces, never
sums.
- 9-10: all surfaces agree; central workflow demonstrably completes; states handled;
  feels finished for its stated scope.
- 7-8: strong coherence and intentionality; central workflow appears functional; minor
  unfinished edges.
- 5-6: plausibly real with visible gaps; scope unclear or core not demonstrated
  end-to-end.
- 3-4: thin prototype; contradictions between surfaces; placeholder content.
- 1-2: non-functional or incoherent for its claimed scope.

## Creativity & Ambition — novelty of concept and interaction model
Judge ONLY: novelty of the concept, novelty of the interaction model, originality
relative to existing concepts, ambition, memorable/surprising use of the medium, and
the depth with which the concept is pursued. WebMCP indispensability belongs under
WebMCP Leverage, NOT here: a project can be extremely creative even if another agent
API could theoretically have enabled something similar.
- 9-10: genuinely novel concept or interaction model; ambitious scope pursued deeply
  and coherently; memorable.
- 7-8: fresh synthesis or notably original interaction; ambitious for a hackathon.
- 5-6: competent take on a known category with a real new angle.
- 3-4: derivative; novelty mostly surface details.
- 1-2: clone/template with trivial changes.
"That the category exists" is never a penalty; judge the submitted concept.

## Potential Impact — credible value for the intended audience
Judge: is there a real audience; is there a real problem, desire, or use case for that
audience; does the demonstrated solution genuinely address it. NO commercial adoption,
monetization, market pull, or startup viability is required. Entertainment, play, art,
creative expression, learning, niche hobby use, experimentation, and community value
are legitimate forms of impact. A tiny audience fully justifies a top score.
- 9-10: specific real audience with a real problem/desire; solution demonstrably
  addresses it; credible value, appeal, usefulness, or meaning for that audience.
- 7-8: clear audience and problem, good fit, credible value.
- 5-6: identifiable audience, looser fit or partial address.
- 3-4: speculative audience or strained fit; impact mostly aspirational.
- 1-2: no coherent audience/problem pairing.
Audience size is NOT a multiplier.

## Aggregate & ranking
aggregate = leverage + execution + impact + creativity (4-40). Nothing else enters.
Tie-breaks: Leverage, then Execution, then Impact, then Creativity, then higher
combined evidence confidence, then slug alphabetical. See PROTOCOL.md Ranking section.

Like Comment Story Updates the landing page Inspiration I’m learning robotics, and one of the most frustrating parts has been getting an AI to understand what is actually happening on the board in front of me. I was constantly taking screenshots, copying serial logs, and pasting telemetry into ChatGPT just to explain the physical world. The WebMCP Challenge gave me a different idea what if the browser itself could become the bridge between the agent and the hardware? Ohmni came from that. Using WebMCP and Web Serial, the agent can inspect the board through real tools in real time and you see the result of your action in front of you instead of relying on screenshots and copied logs. What it does Ohmni is a browser based hardware debugging workbench where AI agents and humans diagnose physical device problems together. Using WebMCP, Ohmni exposes hardware capabilities as structured tools an agent can call directly. The agent can inspect reset history, measure supply voltage, read telemetry, run controlled diagnostic tests, collect evidence, and build a diagnosis from real measurements instead of guessing from screenshots or pasted logs. For safety, read only tools can run autonomously, while actions that can affect hardware require explicit human approval. When a physical change is needed, such as moving a jumper or reseating a connection, the agent hands that step back to the human and then retests the device to verify whether the fix actually worked. Ohmni also supports real hardware through Web Serial apis , alongside a deterministic virtual ESP32 environment that lets anyone experience the full diagnostic workflow without needing a physical board. How we built it We built Ohmni with React, TypeScript, Vite, and Bun, using WebMCP as the core interface between the AI agent and the hardware workbench. Device capabilities are exposed through document.modelContext as structured tools. Read-only tools can run directly, while actions that may affect hardware pass through a human approval gate before execution. A device adapter handles both the deterministic virtual ESP32 environment and real hardware over Web Serial. Telemetry is streamed into the browser in real time, and each diagnostic action produces evidence that the agent can use to form, test, and verify hypotheses. We also added dynamic tool registration, capability filtering, safe disconnect handling, and an evidence trail so the system stays useful, inspectable, and safe throughout the debugging process. Challenges I ran into The hardest part was making agent access to hardware useful without making it unsafe. Some tools only read data, while others can actually change device state, so I had to design a clear safety boundary and pause physical actions for human approval. But giving an autonomous LLM write access to a live DOM is inherently dangerous: Hallucination & Prompt Injection: Agents might apply unvetted, destructive mutations across the entire page. Race Conditions (TOCTOU): If an agent takes 10 seconds to analyze a component while a user is actively clicking and mutating the DOM, applying the patch blindly will corrupt UI state. We built AriaLens to solve this: an agent-native developer studio where humans and AI agents collaborate safely on live DOM accessibility remediation with strict Human-in-the-Loop Authority Boundaries , Optimistic Concurrency Locks , and Adversarial Honeypots . What it does AriaLens turns the browser into an interactive, agent-guided accessibility workbench: Live Accessibility Introspection: Using WebMCP, the agent inspects computed accessibility trees, AccName 1.1 calculations, and keyboard focus trap boundaries directly through audit_accessibility_tree . Human-in-the-Loop Authority Boundary: Destructive mutation tools ( commit_a11y_fix ) are never exposed upfront . The agent can only stage speculative changes via stage_aria_remediation . Staged changes render in an IDE-style visual code diff awaiting human sign-off. Optimistic Concurrency Lock (W3C § 6.3): Patches are cryptographically bound to an Epoch Lock recorded at audit time. If a user interacts with or mutates the DOM before commit, the epoch advances and the patch is safely rejected with a STALE_EPOCH_CONFLICT . The Honeypot Gauntlet (W3C § 6.4): To guard against rogue or jailbroken behavior, AriaLens mounts hidden bypass tools ( bulk_apply_all_fixes ). Any agent attempting to bypass human approval is intercepted, blocked, and flagged in the live audit log. Export as Git Patch: Staged remediations can be downloaded with one click as standard unified .patch files, enabling developers to review in browser and commit directly to their local Git repositories. How we built it WebMCP Protocol Integration: Built directly against the emerging W3C WebMCP draft specification using document.modelContext.registerTool() . We implemented ephemeral capability mounting via AbortController lifecycles to dynamically attach and detach tools based on human gate approval. Architecture & State Machine: Powered by React 19 , TypeScript , and Vite , with Zustand orchestrating the optimistic concurrency state machine and telemetry logs. Accessibility Evaluation: Backed by axe-core 4.10 , AccName 1.1 computation models, and automated WCAG 2.2 AA heuristics. Developer Interface: Designed with a high-density, dark-mode developer experience inspired by Linear and Vercel, featuring real-time latency badges, sub-pixel antialiasing, and structured code diff views. Challenges we ran into Solving TOCTOU Concurrency: Bridging the gap between asynchronous LLM inference (5–15 seconds) and synchronous DOM events required architecting a zero-overhead optimistic locking protocol (Epoch Locks) that cleanly rejects stale mutations without freezing the browser. Ephemeral Tool Lifecycle: Designing tool registration so that commit capabilities remain invisible to LLM tool discovery until explicitly authorized by a human, and immediately unregister after single execution. Clean Agent Steering: Calibrating tool descriptions and input schemas so that models prioritize structured attribute staging rather than attempting raw HTML string rewrites. Accomplishments that we're proud of Strict W3C WebMCP Compliance: Directly implemented and validated Sections 6.3 (Concurrency) and 6.4 (Untrusted Content) of the WebMCP draft specification. Enterprise-Grade Utility: Going beyond a toy demo by enabling instant .patch unified diff generation for real-world engineering workflows. Security-First Agent Design: Proving that agent-native web applications can grant high-level reasoning capabilities to AI without ever compromising runtime safety or human authority. What we learned Agents perform exponentially better when constrained by formal capability state machines rather than natural language prompt boundaries. WebMCP represents a paradigm shift: websites are no longer passive documents for LLMs to scrape, but active APIs where humans and agents co-operate with cryptographic guarantees. What's next for AriaLens Headless CI/CD WebMCP Runner: An automated GitHub Action that spins up headless Chrome with WebMCP enabled to audit staging deployments and open pull requests automatically.
