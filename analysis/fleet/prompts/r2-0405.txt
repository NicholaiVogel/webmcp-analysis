# FROZEN SCORING RUBRIC (pre-registered before any Stage 1 review)

Scores are integers 1-10 on each of the FOUR official criteria. Every score carries:
rationale, evidence_surfaces, confidence (0-1). Reviewers use the full scale and these
band anchors verbatim. Category neutrality is absolute: a game, art piece, music tool,
CRM, weird toy, and developer tool are all eligible for 10/10 on every criterion if they
satisfy that criterion exceptionally well FOR WHAT THEY ARE TRYING TO BE.
No aesthetic penalties. Signs of hurried AI work matter only as actual product-quality
problems (incoherence, broken flow, placeholder content), never as style.

## WebMCP Leverage — what does WebMCP change for this product?
Judge the delta WebMCP makes to reliability, precision, structured state access,
shared human-agent state, repeatability, and capability. Tool COUNT is not leverage.
- 9-10 TRANSFORMATIVE: the intended experience is impractical without the structured
  agent surface; human and agent share live product state; the collaboration could not
  be replicated comparably well by a general agent driving the UI.
- 7-8 MAJOR DELTA: without WebMCP a general agent is markedly less reliable/precise
  here; the agent is central to the product, not a bolt-on.
- 5-6 MEANINGFUL DELTA: existing capability packaged into a genuinely better product
  experience via structured tools; same outcome otherwise possible with real friction.
- 3-4 MINOR DELTA: generic browser automation achieves comparable outcomes; WebMCP is
  a convenience layer.
- 1-2 COSMETIC: exposes an action a UI button already offers; no meaningful change.

## Execution — is the actual product coherent, intentional, complete for its scope?
Stage 1 scores EXECUTION_CLAIMED: coherence/intentionality/completeness as evidenced by
the packet (description + packaging + video frames/transcript). Thin evidence caps the
score (end-to-end credit requires end-to-end evidence) and lowers confidence.
Stage 2 may rescore as EXECUTION_OBSERVED; latest evidence-backed score replaces, never
sums.
- 9-10: all surfaces agree; central workflow demonstrably completes; states handled;
  feels finished for its stated scope.
- 7-8: strong coherence and intentionality; central workflow appears functional; minor
  unfinished edges.
- 5-6: plausibly real with visible gaps; scope unclear or core not demonstrated
  end-to-end.
- 3-4: thin prototype; contradictions between surfaces; placeholder content.
- 1-2: non-functional or incoherent for its claimed scope.

## Creativity & Ambition — novelty of concept and interaction model
Judge ONLY: novelty of the concept, novelty of the interaction model, originality
relative to existing concepts, ambition, memorable/surprising use of the medium, and
the depth with which the concept is pursued. WebMCP indispensability belongs under
WebMCP Leverage, NOT here: a project can be extremely creative even if another agent
API could theoretically have enabled something similar.
- 9-10: genuinely novel concept or interaction model; ambitious scope pursued deeply
  and coherently; memorable.
- 7-8: fresh synthesis or notably original interaction; ambitious for a hackathon.
- 5-6: competent take on a known category with a real new angle.
- 3-4: derivative; novelty mostly surface details.
- 1-2: clone/template with trivial changes.
"That the category exists" is never a penalty; judge the submitted concept.

## Potential Impact — credible value for the intended audience
Judge: is there a real audience; is there a real problem, desire, or use case for that
audience; does the demonstrated solution genuinely address it. NO commercial adoption,
monetization, market pull, or startup viability is required. Entertainment, play, art,
creative expression, learning, niche hobby use, experimentation, and community value
are legitimate forms of impact. A tiny audience fully justifies a top score.
- 9-10: specific real audience with a real problem/desire; solution demonstrably
  addresses it; credible value, appeal, usefulness, or meaning for that audience.
- 7-8: clear audience and problem, good fit, credible value.
- 5-6: identifiable audience, looser fit or partial address.
- 3-4: speculative audience or strained fit; impact mostly aspirational.
- 1-2: no coherent audience/problem pairing.
Audience size is NOT a multiplier.

## Aggregate & ranking
aggregate = leverage + execution + impact + creativity (4-40). Nothing else enters.
Tie-breaks: Leverage, then Execution, then Impact, then Creativity, then higher
combined evidence confidence, then slug alphabetical. See PROTOCOL.md Ranking section.

The repository contains the complete source code, synthetic demonstration data, execution instructions, a BSD 3-Clause license, trademark boundaries, challenge provenance, and an automated test suite. Sixteen tests cover the complete human-agent experience, including validation, authority, privacy, Ready Pass rules, referral behavior, sponsorship separation, and Undo. No login, private service, production database, third-party runtime SDK, or real participant information is required. Challenges The hardest challenge was not registering the tools. It was defining trustworthy boundaries between agent capability and human authority. We had to ensure that: an AI-generated draft could not automatically become official; personal planning could not rewrite the organizer-controlled source of truth; commercial interaction could never purchase completion of, or satisfy, an official requirement; a Ready Pass could not be claimed before readiness had been verified; every consequential action required human confirmation; and the previous state could be restored through Undo. We also designed the tool schemas to remain narrow enough for reliable agent use while supporting a complete product experience rather than merely a technical proof of concept. What we learned WebMCP is most valuable when tools expose meaningful product state instead of merely duplicating interface buttons. A strong agent-ready experience requires three elements working together: structured access to authoritative state; explicit authority and confirmation boundaries; and visible outcomes shared by both the person and the agent. We also learned that personalization does not require changing the official source of truth. The official guide can remain stable while the agent creates a contextual path for each participant. Challenge-period work OCHECK existed before the challenge as a product concept, brand, business model, and private MVP for official guides. The WebMCP Challenge Edition was created during the submission period as a separate, standalone implementation. Work completed during the challenge period includes the 13 browser-native tools, AI Guide Forge, explicit outcome contracts, draft validation, human-confirmed publication, separate organizer, participant, and partner perspectives, Ready Pass verification, privacy-preserving sponsor signals, audit history, Undo, synthetic data, and automated testing. The public repository includes a timestamped commit history and HACKATHON.md , which clearly distinguishes OCHECK’s previous work from the new WebMCP implementation. Potential impact Events are the first use case, but the underlying problem arises wherever people must reconstruct an official process from fragmented information: events, education, travel, onboarding, public services, healthcare preparation, compliance, and professional workflows. OCHECK proposes a web in which agents do not replace authority. Instead, they help people understand and act upon a governed source of truth provided directly by the organizer. Like Comment Story Updates 1 Inspiration I built blnq.studio because front-end work had become a pile of tabs: an editor, a dev server, a browser, DevTools, an accessibility checker, a design spec, and now an AI chat window that can't see any of them. Every one of those handoffs is where quality leaks out — especially accessibility, which is the first thing dropped when you're moving fast and the last thing an AI agent notices, because it can't see what it built. I wanted a single tab where the code, the live preview, the audit and the AI all look at the same thing. WebMCP was the missing piece: it lets the editor tab itself become the tool surface an agent uses, so the loop closes without any extra setup. What it does blnq.studio is a browser-based editor purpose-built for front-end: code, preview, ship — all in one tab. Live multi-file editing — Monaco under the hood, real HTML/CSS/JS files with folders and ES module imports, no build step. The preview updates as you type. Accessibility first — every preview refresh runs the pour engine against WCAG 2.0–2.2 A/AA plus best-practice rules. The A11y panel lists each violation with its impact, a plain-English fix and the exact element. Colour-contrast checks are built into the editor, not bolted on afterwards. Multi-device preview — switch viewports, check every breakpoint, see the FPS overlay, all without leaving the tab. Design systems your AI respects — drop a DESIGN.md at the project root and the editor treats it as the source of truth: colour and font literals that drift from your tokens get flagged, so AI-written CSS stays inside the system instead of inventing new values. Baseline compatibility — a built-in tool tab tells you which features you're using aren't yet widely available across browsers. Collaborate and fork — real-time multi-cursor collaboration over Yjs, forks and merge requests, a community showcase. Ship from the editor — push to GitHub, deploy from the menu, or download the whole project as one self-contained HTML file. AI & MCP, on your terms — AI is optional. When you want it, connect Claude Code (or any MCP client) over the built-in MCP server, use the in-editor chat with your own model, or — new for this challenge — turn on WebMCP and let a browser-native agent drive the tab directly. WebMCP: the editor tab is the tool server Click Start WebMCP and blnq registers 30+ tools with the browser via document.modelContext . No MCP ID, no config file, no separate process. An agent running in the browser can then: Read and edit files by line range or find-and-replace, with undo snapshots and live edits landing in the editor and preview See what it built — blnq_screenshot returns a real PNG, plus element inspection, console errors and viewport switching Audit with blnq_check_preview , which returns JS errors, every WCAG violation with its element HTML and fix hint, and any design-token drift Interact — click, type, press keys, wait for elements — so it can tab through a form or open a modal and re-audit the new state Fix and re-audit until the report is clean The key design decision was that WebMCP isn't a separate integration. blnq has one shared tool registry; the MCP server and the WebMCP endpoint are two thin adapters over it. A tool added to the registry appears in both, and edits behave identically — same validation, same undo, same activity toasts, same prompt history — whichever transport the call came in on. How I built it blnq is an Express + Monaco + Yjs app with a plugin system; the MCP server, AI chat, Baseline and spellcheck tools are all plugins. The accessibility engine runs inside the preview iframe and posts results up to the editor, so the panel a human reads and the result an agent reads come from the same run. WebMCP was around 350 lines: a client module that fetches tool descriptors and calls registerTool() for each (with readOnlyHint annotations and MCP-shaped { content } results including images), and a server endpoint that Zod-validates and runs the shared handler. The endpoint is same-origin only and still requires the tab's random bridge ID; the browser handles user consent on its side. What I learned The accessibility audit turned out to be the most valuable thing blnq can hand an agent. A screenshot tells a model roughly what it built; a WCAG report with the offending element and a fix hint tells it exactly what to change. Structured, model-readable audit output beat any amount of prompt engineering. And WebMCP inverts the usual relationship: the page stops being something an agent scrapes and becomes something it calls . Once you have a decent tool registry, the browser becomes the integration layer for free.
