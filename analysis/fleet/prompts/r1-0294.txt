# FROZEN SCORING RUBRIC (pre-registered before any Stage 1 review)

Scores are integers 1-10 on each of the FOUR official criteria. Every score carries:
rationale, evidence_surfaces, confidence (0-1). Reviewers use the full scale and these
band anchors verbatim. Category neutrality is absolute: a game, art piece, music tool,
CRM, weird toy, and developer tool are all eligible for 10/10 on every criterion if they
satisfy that criterion exceptionally well FOR WHAT THEY ARE TRYING TO BE.
No aesthetic penalties. Signs of hurried AI work matter only as actual product-quality
problems (incoherence, broken flow, placeholder content), never as style.

## WebMCP Leverage — what does WebMCP change for this product?
Judge the delta WebMCP makes to reliability, precision, structured state access,
shared human-agent state, repeatability, and capability. Tool COUNT is not leverage.
- 9-10 TRANSFORMATIVE: the intended experience is impractical without the structured
  agent surface; human and agent share live product state; the collaboration could not
  be replicated comparably well by a general agent driving the UI.
- 7-8 MAJOR DELTA: without WebMCP a general agent is markedly less reliable/precise
  here; the agent is central to the product, not a bolt-on.
- 5-6 MEANINGFUL DELTA: existing capability packaged into a genuinely better product
  experience via structured tools; same outcome otherwise possible with real friction.
- 3-4 MINOR DELTA: generic browser automation achieves comparable outcomes; WebMCP is
  a convenience layer.
- 1-2 COSMETIC: exposes an action a UI button already offers; no meaningful change.

## Execution — is the actual product coherent, intentional, complete for its scope?
Stage 1 scores EXECUTION_CLAIMED: coherence/intentionality/completeness as evidenced by
the packet (description + packaging + video frames/transcript). Thin evidence caps the
score (end-to-end credit requires end-to-end evidence) and lowers confidence.
Stage 2 may rescore as EXECUTION_OBSERVED; latest evidence-backed score replaces, never
sums.
- 9-10: all surfaces agree; central workflow demonstrably completes; states handled;
  feels finished for its stated scope.
- 7-8: strong coherence and intentionality; central workflow appears functional; minor
  unfinished edges.
- 5-6: plausibly real with visible gaps; scope unclear or core not demonstrated
  end-to-end.
- 3-4: thin prototype; contradictions between surfaces; placeholder content.
- 1-2: non-functional or incoherent for its claimed scope.

## Creativity & Ambition — novelty of concept and interaction model
Judge ONLY: novelty of the concept, novelty of the interaction model, originality
relative to existing concepts, ambition, memorable/surprising use of the medium, and
the depth with which the concept is pursued. WebMCP indispensability belongs under
WebMCP Leverage, NOT here: a project can be extremely creative even if another agent
API could theoretically have enabled something similar.
- 9-10: genuinely novel concept or interaction model; ambitious scope pursued deeply
  and coherently; memorable.
- 7-8: fresh synthesis or notably original interaction; ambitious for a hackathon.
- 5-6: competent take on a known category with a real new angle.
- 3-4: derivative; novelty mostly surface details.
- 1-2: clone/template with trivial changes.
"That the category exists" is never a penalty; judge the submitted concept.

## Potential Impact — credible value for the intended audience
Judge: is there a real audience; is there a real problem, desire, or use case for that
audience; does the demonstrated solution genuinely address it. NO commercial adoption,
monetization, market pull, or startup viability is required. Entertainment, play, art,
creative expression, learning, niche hobby use, experimentation, and community value
are legitimate forms of impact. A tiny audience fully justifies a top score.
- 9-10: specific real audience with a real problem/desire; solution demonstrably
  addresses it; credible value, appeal, usefulness, or meaning for that audience.
- 7-8: clear audience and problem, good fit, credible value.
- 5-6: identifiable audience, looser fit or partial address.
- 3-4: speculative audience or strained fit; impact mostly aspirational.
- 1-2: no coherent audience/problem pairing.
Audience size is NOT a multiplier.

## Aggregate & ranking
aggregate = leverage + execution + impact + creativity (4-40). Nothing else enters.
Tie-breaks: Leverage, then Execution, then Impact, then Creativity, then higher
combined evidence confidence, then slug alphabetical. See PROTOCOL.md Ranking section.

Like Comment Story Updates Completed schedule booking screen aidra Inspiration Every year, WebAIM publishes the Screen Reader User Survey . In every edition, the #2 most cited barrier for screen reader users is "Interactive elements such as menus, tabs, and dialogs that don't behave as expected," second only to CAPTCHA. Compounding this, the WebAIM Million annual analysis tracked an average of 56.1 accessibility errors per home page in 2026, a 10.1% increase over the prior year. Inaccessible patterns such as drag-and-drop calendars, nested custom comboboxes, and unlabelled canvas widgets continue to create barriers for assistive technologies. Generic computer-use agents inherit many of these same failure modes. An agent that relies on vision, DOM inspection, clicking, or coordinate-based dragging can fail just as unpredictably when a complex widget has unexposed state or requires interactions that are difficult to interpret programmatically. I was inspired to build aidra to show how WebMCP (Web Model Context Protocol) can become an accessibility bridge. By exposing clean, typed, high-level tools directly inside the webpage, an AI agent can execute complex workflows without interacting with broken widgets. At the same time, every action can be narrated live through aria-live regions so the human remains informed and in control. What It Does aidra is an appointment booking portal built around one deliberately difficult interaction pattern: a drag-and-drop-only scheduling calendar with no click-to-select fallback. A user can complete the entire booking flow manually using a mouse or keyboard. They can also hand the workflow to an agent using natural language, such as: "Book me the earliest Tuesday morning appointment with Dr. Chen and add a note about my insurance card." Instead of trying to drag or click the calendar, the WebMCP agent uses 7 typed in-page tools: search_providers list_available_slots select_slot fill_intake_form submit_booking reschedule_booking cancel_booking These tools allow the agent to search providers, retrieve available slots, select an appointment, populate the intake form, and manage existing bookings without directly manipulating the inaccessible calendar widget. Every tool call is announced through an aria-live region and mirrored visually through an Agent Activity sidebar for sighted collaborators. Human Confirmation Is Enforced The agent cannot finalize an appointment. submit_booking only stages the appointment and opens an accessible confirmation dialog. The booking can only be finalized through an explicit human click on the Confirm button. This is enforced in the application logic, not simply described as a rule for the agent. Even if an agent calls submit_booking repeatedly, it cannot bypass the confirmation step because the only code path that marks an appointment as confirmed is the human-facing confirmation action. The agent handles the difficult interaction. The user retains authority over the action that matters. Why WebMCP? Without WebMCP, an AI agent has to perceive and manipulate the same interface a user does. That means guessing through pixels, DOM structure, focus states, and interaction patterns. With WebMCP, the webpage exposes semantic capabilities directly to the agent. Instead of asking: "Where is the calendar and how do I drag this appointment?" the agent can ask the page: "What providers are available?" "What appointment slots are available?" "Select this slot." The interaction becomes structured, typed, observable, and reviewable. This is what makes WebMCP particularly interesting for accessibility. The same abstraction that makes an agent more reliable can also make its actions easier for a human to understand and trust. How I Built It I designed aidra with a zero-build-step architecture for fast iteration, transparency, and auditability. Markup and UI: Semantic HTML5, Tailwind CSS via CDN, vanilla CSS custom properties, and native browser APIs. State Management: A centralized reactive store synchronizes manual DOM interactions and WebMCP tool executions through the same state and rendering pipeline. WebMCP Registration: I registered all 7 tools using document.modelContext.registerTool({...}) with strict JSON schemas and JSDoc @typedef annotations for editor-level type checking. WebMCP Compatibility: I built a small polyfill that detects whether document.modelContext is available natively and falls back to a local tool registry when it is not. Input Normalization: Tool arguments are normalized so each execute() function receives the same input shape across different invocation environments. Speech Pacing: I paced announcements so screen readers have time to finish communicating one action before the next tool executes. Live Observability: An in-page Agent Activity console streams tool invocations, parameters, and status changes so sighted collaborators can observe the agent working in real time. How it is built Vanilla ES modules. Like Comment Story Updates Places is a live floorplan. You pin what's non-negotiable. Then you and an agent rearrange the same room, the agent cannot move anyone you pinned. Inspiration Seating a company dinner is still a spreadsheet and an argument. The room matters. The rules matter. HR stays away from engineering. The CEO sits at the head of the center table. A few people need the aisle. A plus-one is still on the way. By the time the chart leaves the sheet, it is already wrong. A constraint solver dumps a list. A group chat dumps a thread. Neither is the room. I wanted one canvas where the host and the model share the same seats, and where “Mabel stays at the window” is not a prompt. It is a pin. Because she is pinned, move_guest is gone. WebMCP is a capability bus for a live page, not a cart API. Pins, aisle seats, and “do not sit together” pairs are page state. Scraping the SVG drops them. The agent has to call tools, and the tool list itself is the contract. The hundred-person problem is the category. The demo is twenty-two, same job, at a scale the canvas can prove. How I built it The page is ground truth. Drag, pin, plus-one, and every agent write go through the same executeCommand() in web/lib/places/commands.ts . A tool call moves a place-card on the SVG you are looking at. There is no backend, no login, and no API key. State lives in sessionStorage for the current tab. document.modelContext.registerTool exposes a stable read/rule set: get_room_state , list_violations , explain_guest , add_guest , list_constraints , add_constraint , remove_constraint . Selection, pins, and open violations abort the previous AbortController and register only the tools that make sense now. When Tools the agent can see A table is selected seat_guest_here , set_capacity , leave_empty_seats An unpinned guest is selected pin_guest , move_guest , swap_guests A pinned guest is selected unpin_guest only The room has violations fix_violations (never moves pins) There is no always-on move_guest(guestId, tableId) . You choose the contract. The agent works inside it. If document.modelContext is missing, the human controls still work. The header badge says so. The seed is a fictional Thursday: four tables, pixel-art guests, rules you can point at. Rex and Vivian cannot share a table. Arthur needs the aisle. Two chairs are held empty. Each load picks one of four opening problems ( ?seed=0 through ?seed=3 ) so a judge can share a messy room, not a blank grid. The solver is a deterministic hill-climb over pairwise swaps. It scores the room as $$S = \sum_{v} w(v),\quad w(v)=\begin{cases}10 & \text{hard}\ 3 & \text{preference}\end{cases}$$ then reports why it stopped: solved , blocked_by_pins , infeasible (with a proof), or no_arrangement_found . Same room, same answer, every time, which is what the tests and the timeline need. The stack is a Vinext/React page on ChatGPT Sites. Domain logic is isolated under web/lib/places/ . CI runs unit tests, WebMCP eval fixtures, typecheck, lint, and format. The evals replay tool traces against the real registrations without calling a model or spending a key. Challenges The tool list had to be the lock. A prompt that says “don't move pinned guests” is a suggestion. Unregistering move_guest is a lock. Getting that to update on every pin and selection, without racing the previous AbortController , was the WebMCP work. The fixture respect-pin-when-reflow-is-blocked forbids unpin_guest , move_guest , and swap_guests , and expects blocked_by_pins . Honesty beats a pretty rearrange. Hill-climbing gets stuck. A better arrangement may exist only if you move a pin. I had to distinguish “the pins are in the way” from “the hard rules are impossible” from “the search gave up.” The solver runs once with pins respected, once with pins relaxed, and only then returns blocked_by_pins with the guests at fault. It never overrides the host. The room had to stay a product. An empty grid is a proof of concept. A messy dinner is a job. Building a cast, a floorplan, a timeline, undo/redo, JSON import/export, and a PNG save took as much care as the tools. If the human half is a toy, the shared room is a toy. CI cannot pretend it is ChatGPT. Model selection is probabilistic and costs money. The eval fixtures describe representative journeys (read the room, fix it, pin blocks, plus-one, add a rule) and replay them deterministically. Live-browser trials still matter. They are not the merge gate. What I learned WebMCP is not “expose every action as a tool.” It is exposing the right contract at the right moment. The interesting part is what the agent cannot see. People are good at naming constraints. Models are good at searching a room. That split only works if both hands write to the same state. Same executeCommand() whether I drag a seat or the agent calls a tool. A pin is stronger than a system prompt. blocked_by_pins is a feature. The host stays in charge. Pin what's non-negotiable. Rearrange the rest together. Like Comment Story Updates main menu 2d sandbox 2d sandbox circuit sandbox physics sandbox chemistry sandbox Inspiration Ask a chatbot "why does increasing a make the parabola narrower?" and you get a paragraph — a description of a motion you never see. The understanding lives in actually watching the curve tighten while someone talks over it, the way a good tutor works at a whiteboard. The blocker was never the model's ability to explain; it was that the model had no hands. WebMCP is the missing piece: a web page can expose its own controls as tools, so the student's own agent can operate the page instead of describing it — no extension, no API key in the page, no faulty HTML scraping. What it does Smarterboard is a set of learning sandboxes that an AI agent can drive. There are four sandboxes. A 2D and 3D grapher lets you plot curves and surfaces animate a slider so a graph changes find roots and turning points and orbit shaded surfaces. A circuit lab lets you build circuits from batteries, resistors, LEDs, capacitors and more watch current flow and plot voltage over time on an oscilloscope. A chemistry sandbox lets you drag elements off the table build atoms from protons, neutrons and electrons and bond them into molecules. A physics sandbox lets you drop in ramps, tracks, balls and blocks while everything floats, then run the scene under gravity and friction and read back position, velocity, forces, energy and every collision. Each page registers its tools on document.modelContext so an AI agent can build a water molecule. Explain the bonds wire an LED so it lights safely launch a projectile or animate a parameter all while it narrates. The explanation and the thing being explained become the object. How we built it TypeScript and Vite were used, with no framework. Every engine has one place where state changes and the buttons a student clicks call the same code that an AI agent calls so the two can never drift apart. Math.js handles the math three.js draws the surfaces and canvas draws the circuits, atoms and physics scenes. The circuit lab runs a nodal analysis solver with time‑stepped models for capacitors, inductors and diodes. The physics lab is a rigid body engine with gravity, normal forces, friction and collisions. The chemistry lab fills electron shells the way a textbook does. There are close to ninety tools across the four sandboxes. We spent most of our time writing their descriptions because that text is the only thing the AI agent reads. Everything is deployed to GitHub Pages. Challenges we ran into We decided early not to write a LaTeX parser and instead normalize input into math.js, which saved us a day. The circuit solver required work from merging nodes to iterating diode states to stepping capacitors through time. Our oscilloscope moved slowly at first because we capped how far the simulation could move each frame. Switching to a fixed time step that follows the clock fixed that problem. We also learned some WebMCP details the way. The execute call wants the tool object and a stringified argument than a name and an object and tools from every open tab get merged together so two pages that both had a load preset tool collided. Accomplishments that we're proud of It is a product that an AI agent can genuinely run, not a chatbot with a few tools attached. The physics holds up. A capacitor reaches 63 percent of charge after exactly one time constant, sodium and chlorine form the right ions with full outer shells and a block slides down a ramp and speeds up under gravity the way it should. The page also tells the AI agent when something is wrong like an LED pulling much current and the AI agent can turn around and fix it. We got four tools working end to end in a few days and confirmed the whole AI agent round trip in a real browser. What we learned The tool description really is the prompt. Telling an AI agent when to reach for a tool matters more than the tool itself. Giving an AI agent an error it can correct is better than letting it fail.. Webmcp quietly changes the question from what a model can say to what a page can let it do. What’s next for Smarterboard Saving. Sharing a board with a link and a shared session where a student and an AI agent work on the same thing at once. Springs, pulleys and pendulums in the physics sandbox and AC analysis in the circuit sandbox. Deeper chemistry, with Lewis structures and balanced reactions.
