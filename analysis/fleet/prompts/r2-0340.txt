# FROZEN SCORING RUBRIC (pre-registered before any Stage 1 review)

Scores are integers 1-10 on each of the FOUR official criteria. Every score carries:
rationale, evidence_surfaces, confidence (0-1). Reviewers use the full scale and these
band anchors verbatim. Category neutrality is absolute: a game, art piece, music tool,
CRM, weird toy, and developer tool are all eligible for 10/10 on every criterion if they
satisfy that criterion exceptionally well FOR WHAT THEY ARE TRYING TO BE.
No aesthetic penalties. Signs of hurried AI work matter only as actual product-quality
problems (incoherence, broken flow, placeholder content), never as style.

## WebMCP Leverage — what does WebMCP change for this product?
Judge the delta WebMCP makes to reliability, precision, structured state access,
shared human-agent state, repeatability, and capability. Tool COUNT is not leverage.
- 9-10 TRANSFORMATIVE: the intended experience is impractical without the structured
  agent surface; human and agent share live product state; the collaboration could not
  be replicated comparably well by a general agent driving the UI.
- 7-8 MAJOR DELTA: without WebMCP a general agent is markedly less reliable/precise
  here; the agent is central to the product, not a bolt-on.
- 5-6 MEANINGFUL DELTA: existing capability packaged into a genuinely better product
  experience via structured tools; same outcome otherwise possible with real friction.
- 3-4 MINOR DELTA: generic browser automation achieves comparable outcomes; WebMCP is
  a convenience layer.
- 1-2 COSMETIC: exposes an action a UI button already offers; no meaningful change.

## Execution — is the actual product coherent, intentional, complete for its scope?
Stage 1 scores EXECUTION_CLAIMED: coherence/intentionality/completeness as evidenced by
the packet (description + packaging + video frames/transcript). Thin evidence caps the
score (end-to-end credit requires end-to-end evidence) and lowers confidence.
Stage 2 may rescore as EXECUTION_OBSERVED; latest evidence-backed score replaces, never
sums.
- 9-10: all surfaces agree; central workflow demonstrably completes; states handled;
  feels finished for its stated scope.
- 7-8: strong coherence and intentionality; central workflow appears functional; minor
  unfinished edges.
- 5-6: plausibly real with visible gaps; scope unclear or core not demonstrated
  end-to-end.
- 3-4: thin prototype; contradictions between surfaces; placeholder content.
- 1-2: non-functional or incoherent for its claimed scope.

## Creativity & Ambition — novelty of concept and interaction model
Judge ONLY: novelty of the concept, novelty of the interaction model, originality
relative to existing concepts, ambition, memorable/surprising use of the medium, and
the depth with which the concept is pursued. WebMCP indispensability belongs under
WebMCP Leverage, NOT here: a project can be extremely creative even if another agent
API could theoretically have enabled something similar.
- 9-10: genuinely novel concept or interaction model; ambitious scope pursued deeply
  and coherently; memorable.
- 7-8: fresh synthesis or notably original interaction; ambitious for a hackathon.
- 5-6: competent take on a known category with a real new angle.
- 3-4: derivative; novelty mostly surface details.
- 1-2: clone/template with trivial changes.
"That the category exists" is never a penalty; judge the submitted concept.

## Potential Impact — credible value for the intended audience
Judge: is there a real audience; is there a real problem, desire, or use case for that
audience; does the demonstrated solution genuinely address it. NO commercial adoption,
monetization, market pull, or startup viability is required. Entertainment, play, art,
creative expression, learning, niche hobby use, experimentation, and community value
are legitimate forms of impact. A tiny audience fully justifies a top score.
- 9-10: specific real audience with a real problem/desire; solution demonstrably
  addresses it; credible value, appeal, usefulness, or meaning for that audience.
- 7-8: clear audience and problem, good fit, credible value.
- 5-6: identifiable audience, looser fit or partial address.
- 3-4: speculative audience or strained fit; impact mostly aspirational.
- 1-2: no coherent audience/problem pairing.
Audience size is NOT a multiplier.

## Aggregate & ranking
aggregate = leverage + execution + impact + creativity (4-40). Nothing else enters.
Tie-breaks: Leverage, then Execution, then Impact, then Creativity, then higher
combined evidence confidence, then slug alphabetical. See PROTOCOL.md Ranking section.

The whole point of staging a write is that nothing reaches the pantry unchecked, so adding form fields to that screen is exactly where a safety property quietly dies. The rule we settled on: an edit is still input. Edits land on the staged payload, and the confirm handler re-runs the same sanitizer over all of it before applying — nothing is trusted for having been in the page. The item's name deliberately stayed read-only, because changing it changes whether the merge sees a duplicate, so the row would have to re-decide between "will add" and "already in your pantry" as you type. Accomplishments that I am proud of Added a full agent-facing tool surface without loosening the CSP by one character, connect-src 'none' on day one is still connect-src 'none' today. Every single write path, file import, sample data, or an agent's proposal goes through the identical "validate/sanitize/preview/confirm" gate. There is no separate, quieter door for a model to walk through. Allergy severity is never disclosed to an agent, matching exactly what Settings promises a human user and it's pinned by a test that stages a real conflict and asserts the severity string never appears in the output. 13 tools, off by default, verified against a real agent in real Chrome. The human-in-the-loop gate is a refining pass, not a rubber stamp. A vision model miscounts what it cannot see like six oranges in the photo is eight in the bag once the buried ones are counted. So an agent's proposed rows carry an editable quantity and unit and an Add tick: correct what it misread, drop what you don't want, then confirm, which is more efficient than throwing all the work away and doing a new call. What I learned The right mental model for handing an agent access to a personal-data app isn't "sandbox what it can see" it's "answer freely, stage everything that changes something" which turned out to generalize cleanly across a dozen tools built weeks apart. A local-first architecture, which we'd built for privacy reasons that had nothing to do with AI, turned out to be exactly what makes an app trustworthy to hand to an agent: there's no server in the loop to leak to in the first place. The most valuable thing a tool can do for a model is supply ground truth the model has no other way to get such as what's actually on your shelf, what's actually about to expire, and then get out of the way not try to out-reason the model on things it already knows better such as food chemistry, nutrition, spice profiles. "Approve or reject" is the wrong shape for a human-in-the-loop gate when the model's mistake is small and numeric. Forcing a binary choice on a proposal that is 90% right means the user either accepts a number they know is wrong or discards work that was mostly correct, and the first of those is what actually happens. Letting them fix it in place is better UX and a stronger safety argument: the human stops being a rubber stamp and becomes the one who ultimately decides and approves the unit and value. A persistent creative run that people and browser agents can inspect, pause, resume, and move into Canvas together. Like Comment Story Updates Creative work is not a single prompt. It moves through intent clarification, skill selection, model routing, asynchronous generation, review, and revision. Screen-driven agents are brittle in this environment: they can click the wrong model, lose a long-running job, repeat a paid request, or expose internal execution prompts. We wanted people and browser agents to share the same visible, recoverable workflow while the human keeps control of consequential creative choices. What it does The page registers six WebMCP tools for the current authenticated user: discover professional skills by workspace; start one real Agent, image, video, or audio run; read bounded public run status and result asset IDs; answer a pending Human-in-the-Loop question and resume the same run; list recent Canvas projects; create a visible Canvas project and return its stable URL. Mutating calls appear in the normal GenScape interface. Status recovery reuses the original run identity instead of silently creating another paid request. Tool results exclude system prompts, planning prompts, optimized execution prompts, provider channel IDs, credentials, routing diagnostics, and hidden model reasoning. How we built it We added a dependency-injected WebMCP layer on top of GenScape's existing authenticated client APIs. The imperative tools use document.modelContext.registerTool() , JSON Schema inputs, WebMCP annotations, one registration AbortSignal , and per-invocation cancellation signals. A React bridge owns registration for the signed-in page identity. Persistent Agent Run IDs connect start, status, Human-in-the-Loop answer, and resumed status. The Apache-2.0 public repository contains the competition adapter, clean standalone reference runtime, tests, and documentation. The existing VOZEB-PRO-derived GenScape host predates the challenge and remains under its existing BUSL/proprietary boundary; it is not copied or relicensed in the competition repository. The hosted demonstration integrates the new adapter with that existing host. The standalone runtime is explicitly a schema and lifecycle fixture and does not claim to generate paid AI media. Challenges The hardest boundary was returning enough state for an agent to make progress without leaking internal planning content. Long-running creation also required stable run identities, idempotent request identities, explicit Human-in-the-Loop state, and cancellation that stops pending browser requests without pretending an already accepted upstream task never happened. Accomplishments Six discoverable tools backed by the same visible workflows as the human UI. A complete start -> status -> answer -> status loop on one persistent run. Canvas creation with a stable URL. Registration removal on logout or page-owner change. Invocation cancellation forwarded through AbortSignal . Public result shaping with tests proving internal fields stay isolated. What we learned WebMCP works best when tools map to durable domain actions rather than UI controls. A reliable creative tool returns stable identities and visible state transitions, while the page remains the review and control surface. Browser-native tools are also a useful privacy boundary: the agent receives the public workflow state it needs, not the host's internal execution context. What's next Add tools scoped to the active Canvas selection, browser-mediated confirmation before high-cost generations, standardized output schemas when the proposal stabilizes, and progress notifications for long-running media work.
